## 2. R2-1：外部通知与清理移出注册表同步边界

当前 `PerformRebuildAsync` 持有 `_rebuildLock` 等待整个 `DoRebuildWork`，因此后者调用退休 Provider.Dispose 与 Changed 时，虽已退出 `_stateLock`，仍占用重建信号量。严格执行已有“锁外”要求：

- 捕获/构建/原子发布继续有清晰的串行与所有权边界，但实际外部 `Provider.Dispose` 与 `Changed` 委托不得在持有 `_stateLock` 或重建互斥信号量时执行。回滚的新实例清理也按同一所有权规则处理，不漏对象、不重复清理。
- 可让内部构建返回待清理集合与通知信息，在释放互斥后处理；不强制具体实现。通知可按原规范合并，订阅者通过快照读取当前版本；单个订阅者/Dispose 异常不阻断其它处理，安全日志规则不变。
- 释放互斥后仍要保证失败/取消路径恰好清理一次，Refresh 成功后的旧凭据解析屏障不退化。不要为了锁外回调放开并发构建导致半发布、旧代覆盖新代或错误清理被复用实例。
- Settings/SecretStore 事件回调按 §3.3 仅失效标记与调度；当前回调进入 `_stateLock` 与既定要求不符，需同步收紧，避免事件发送方等待发布临界区。无需引入新队列框架。

测试验证成功退休、回滚和 Changed 的锁边界，并保留旧租约跨重建/Registry.Dispose、失败不借出旧表、在途失效不丢的回归。可以用受控回调门闩证明后续刷新能够推进；禁止把生产同步等待加入回调作为修复。若使用测试内部检查，只检查同步是否仍被持有，不把私有字段名写成公开契约。

## 3. R2-2：让关键测试检出回归

以下是既有 R1 验收要求的补齐，不新增业务能力：

1. **后台执行**：从专用非线程池线程发起显式 Refresh、首次 Acquire、CreateTransient；在实际 SecretStore.Get/Factory.Create 内记录执行线程和线程池标记。不得用 await 后测试续体的 `Thread.CurrentThread.IsThreadPoolThread` 作为放行条件。瞬态不应读取 SecretStore。
2. **挂起后取消**：用受控 SynchronizationContext 确认 `MoveNextAsync` 已到达异步挂起点且尚未完成，再取消并放行续体，断言抛 OCE；保留枚举前取消的单独覆盖，并释放枚举器。
3. **后台不丢事件**：分别在 B 构建或凭据读取暂停时发布 C，覆盖 B 成功和失败。先等待后台 C 自行构建/发布的信号，之后才允许新的 Acquire/Refresh；不能用主动刷新补救缺失调度后声称验证了后台恢复。若已有等待者，要先取消并收尾，避免它替后台完成工作。
4. **同失败版本不忙循环**：先证明失败配置确实被后台尝试且失败，再验证没有重复尝试。原先两次 Task.Delay 后比较计数，可能把“一次也未执行”当作通过。门闩/日志或其它明确完成信号用于建立时序；完成之后可用有界观察窗口检查无重复，不能用延时猜测失败是否已发生。
5. **有界与清理**：所有用于暂停同步 Factory/Get 的门闩有超时；测试异常路径在 finally 放行并收尾任务。不能留下无界 `gate.Task.GetAwaiter().GetResult()`。草稿修改发生在调度之后、任务完成之前；显式刷新须等待旧凭据解析退出的屏障也要有受控验证。

在临时副本分别注入并证明测试能拒绝三个退化：构造改回调用线程；挂起后取消改回 EOF；设置事件不再调度后台。分别运行，避免叠加变异使另一处阻塞掩盖目标断言。仅临时副本使用变异，正式源码不得残留。无需引入变异测试框架。
