## 1. 背景

Iris 采用 Schema-First 开发：全部公共数据结构和接口已经在 `specs/CONTRACTS.cs` 中定稿（该文件已在 `net9.0`、`TreatWarningsAsErrors` 与 `latest-recommended` 分析器下编译通过，JSON 往返测试也已通过）。本工单搭建解决方案骨架，把契约原样落地到各项目中，并用架构测试把分层依赖规则“锁死”，为后续所有工单提供一个可编译、可测试的基线。

## 2. 目标

1. 创建 5 个源码项目 + 5 个测试项目组成的解决方案，项目引用关系严格符合 ARCH §4.2。
2. 统一编译配置（SDK 版本锁定、集中包管理、可空引用、警告视为错误、分析器）。
3. 把 `specs/CONTRACTS.cs` 按 `// FILE:` 标记拆分到对应源文件，**签名零改动**。
4. 建立架构测试和契约冒烟测试，全部通过。

## 3. 必读规范

- `specs/ARCHITECTURE.md`：§0（铁律）、§3（技术栈）、§4（分层与依赖规则）、§15（目录树）、§16（编码规范）
- `specs/CONTRACTS.cs`：通读一遍，理解 FILE 标记
- `specs/settings.example.json`：本工单的测试会用到

## 4. 范围

**包含（In Scope）**
- 安装 .NET 10 SDK，创建 `global.json`
- 解决方案、10 个项目、项目引用、公共编译配置、集中包管理
- 契约拆分落地（PART A → Iris.Core，PART B → Iris.Providers）
- 架构测试 + 契约冒烟测试
- `.gitignore`、`.editorconfig`、`README.md`、`GEMINI.md`（附录 A）、`git init` 并完成首次提交

**不包含（Out of Scope）** —— 本工单**不要**做以下任何事情：
- 任何接口的业务实现（Orchestrator、Provider、SettingsService 等全部留给后续工单）
- DI 注册扩展方法（`AddIrisCore` 等），留到各自的工单中创建
- Iris.App 的任何 UI 工作（保留 WPF 模板自带的 MainWindow，能编译运行即可）
- Serilog、Hosting、WPF-UI 等第三方运行时库（本工单只引入测试相关的包）

3. 在 `F:\Iris` 下执行 `git init`；用 `dotnet new gitignore` 和 `dotnet new editorconfig` 生成两个配置文件。

### 6.6 契约落地（核心步骤）

对 `specs/CONTRACTS.cs` 中的每个 `// FILE: <path>` 段落：

1. 在 `<path>` 创建文件（PART A 的路径都以 `src/Iris.Core/` 开头，PART B 的路径都以 `src/Iris.Providers/` 开头）。
2. 把块级 `namespace X { ... }` 改为文件级 `namespace X;`，去掉外层大括号，并把段落内的 `using Iris.Core.xxx;` 移到文件顶部（放在 namespace 声明之前）。
3. 补充该文件需要、但 ImplicitUsings 不包含的 using：`System.Text.Json`、`System.Text.Json.Serialization`、`System.Text.Json.Nodes`、`System.Diagnostics.CodeAnalysis`（按需添加，不要多加——IDE0005 会报错）。
4. 其余内容（类型、成员、特性、默认值、XML 注释、枚举数值）**逐字保留**。

完成后自检：在 `src/Iris.Core` 与 `src/Iris.Providers` 中统计公开类型的数量，应与 CONTRACTS.cs 中的类型数一致；用 diff 工具逐段比对，确认只有 namespace 格式和 using 位置不同。

### 6.7 测试

**Iris.ArchitectureTests / DependencyRulesTests.cs**
1. `Core_ReferencesNoForbiddenAssemblies`：`typeof(Iris.Core.Errors.ErrorCode).Assembly.GetReferencedAssemblies()` 中不得出现 `PresentationFramework`、`PresentationCore`、`WindowsBase`、`System.Windows.Forms`、`Microsoft.Windows.SDK.NET`，也不得出现任何以 `Iris.` 开头的程序集。
2. `Providers_Infrastructure_PlatformWindows_ReferenceOnlyCore`：这三个程序集引用的 `Iris.*` 程序集只能是 `Iris.Core`。
3. `ProjectReferences_MatchArchitecture`：从测试程序集所在目录向上查找 `Iris.slnx` 以定位仓库根目录，解析 5 个 src 项目的 csproj（`System.Xml.Linq`），断言每个项目的 `ProjectReference` 集合**恰好等于** 6.5 表中列出的集合。（这条测试很重要：未被代码实际使用的项目引用不会出现在程序集元数据中，只有检查 csproj 才能发现。）
4. `Core_ProjectSettings`：Iris.Core.csproj 的 TFM 为 `net10.0`，并且不包含 `UseWPF` / `UseWindowsForms`。
5. `PlatformWindows_DoesNotUseWpf`：Iris.Platform.Windows.csproj 中不包含 `UseWPF` / `UseWindowsForms`。

**Iris.Core.Tests / Contracts/**
1. `AppSettingsSerializationTests`
   - `Default_RoundTrip_IsStable`：`new AppSettings()` 用 `IrisJson.Options` 序列化 → 反序列化 → 再序列化，两次输出的字符串相等。
   - `EmptyJson_YieldsDefaults`：反序列化 `"{}"` 后，`Hotkeys.Count == 7`，`Ocr.Providers` 的 Id 依次为 `ocr-baidu`、`ocr-windows`，`Translation.PrimaryTargetLanguage == "zh-Hans"`。
   - `SpecExample_Deserializes`：在测试 csproj 中加入 `<None Include="..\..\specs\settings.example.json" Link="Fixtures\settings.example.json" CopyToOutputDirectory="PreserveNewest" />`；反序列化该文件后，`Translation.Providers.Count == 2`，第二个 Provider 的 `Kind == Anthropic` 且 `Model == "claude-opus-5"`；**再次序列化的结果与文件内容一致**（比较前统一换行符为 `\n` 并去掉末尾空白）。
   - `Enums_SerializeAsStrings`：序列化结果中包含 `"theme": "System"` 与 `"modifiers": "Alt, Control"`。
2. `ErrorCodeTests`
   - `Values_AreUnique`；`NonZeroValues_AreInDefinedRanges`（所有非 0 值都在 1001–5999 之间）。
   - `IrisException_ToErrorInfo_MapsAllFields`。
3. `ProviderCredentialsTests.ToString_DoesNotLeakSecrets`：构造 `new ProviderCredentials("sk-abc", "sec-xyz")`，`ToString()` 的结果中不包含 `sk-abc` 和 `sec-xyz`。
4. `SecretKeysTests`：`SecretKeys.ApiKey("tp-1") == "provider/tp-1/api-key"`，SecretKey 同理。
5. `GeometryTests`：`PixelRect.Contains` 的边界（包含左上角，不包含右下角）；`IsEmpty` 在宽或高 ≤ 0 时为 true。

**Iris.Providers.Tests / Wire/**
1. `ChatCompletionRequest_Serialize_OmitsNulls`：只设置 Model、Messages 和 `Stream = true`，用 `ProviderJson.Options` 序列化后的 JSON 中不包含 `temperature`、`max_tokens`、`max_completion_tokens`、`stream_options` 这几个键。
2. `ChatCompletionChunk_Deserialize_ReadsDeltaAndReasoning`：反序列化 `{"choices":[{"index":0,"delta":{"content":"你好","reasoning_content":"思考"},"finish_reason":null}]}`，两个字段都能正确读出。
3. `ErrorEnvelope_Code_AcceptsStringOrNumber`：`"code":"insufficient_quota"` 与 `"code":429` 都能反序列化成功。
4. `BaiduOcrResponse_Deserialize_ErrorAndSuccess`：错误体 `{"error_code":110,"error_msg":"Access token invalid or no longer valid","log_id":3141592653589793238}` 与成功体（包含 2 条 `words_result`，其中一条带 `location`）都能正确解析。

**Iris.Infrastructure.Tests / Iris.Platform.Windows.Tests**：各放一个 `SmokeTests.Placeholder` 测试（直接断言 true），确保项目能被测试运行器发现，后续工单会替换。
