### 实现

- Core 新增 `ScreenshotTranslateHandler`、`ScreenshotOcrHandler`、`SilentScreenshotOcrHandler`，经实际 `ActionDispatcher` 注册，托盘增加三个动作；`HotkeyCoordinator` 按已注册 Handler 开放既有配置绑定，静默默认禁用不变。普通 OCR 仅填翻译窗口原文，截图翻译提交自动翻译，静默 OCR 不取得翻译操作、不创建窗口。
- 可见入口捕获前取得原 caller 操作租约，以同一身份发布固定 loading 与成功／默认错误；捕获取消不显示新窗口，失败通知不强开结果窗。仅一次 OCR 服务调用，选区右下角作物理 Anchor；成功文本保持原样，空白／错误不覆盖原文。
- 精确同步 CCR-033 两个 request bool 与 `IScreenshotOcrFeedback`，删除未发布独立 OCR 展示声明。`TranslateWindowOperation.IsCancellationRequested` 直接检查原 caller 及内部 CTS，Presenter／VM 接受和复制前均使用真实状态；属性重入、文本修订、新意图、隐藏及停止拒绝迟到副作用。
- 原文复制与备用提示仅在 `ApplyRequest` 完成后的最终 UI 接受点各认领一次。复制接入已有“一个实际写入、一个最新待写入”队列，附操作工作引用与原文修订，归还调用方租约不取消窗口已接管的实际写入；剪贴板错误安全显示并保留原文。固定备用提示立即显示，托盘不可用则丢弃，无匿名缓存。
- OCR 更新原文后立即刷新翻译命令可用性，可通过现有翻译按钮继续。没有独立 OCR 窗口或截图预览。
- 静默反馈在 UI 接受点直接检查原 caller 和 App 停止状态，仅显示 UTF-16 Length 计数或默认错误。内部 `ScreenshotOcrCancellation` 保有转发取消回调的实际任务直至退出，清理异常安全上报，不将其当取消吞掉。

- 新 Handler 激活了构造依赖环：Screenshot → Preparation → 热键／鼠标协调器 → Dispatcher／Handler。已将 Preparation 的这两个内部依赖改为操作时解析；生产仍使用同一真实 ScreenshotService，原直接依赖构造保留供既有组合夹具使用。截图准备及 Registry 算法不变。
