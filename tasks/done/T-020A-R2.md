## 2. R2-1：不能把清理失败吞掉后当作清理完成

TranslateWindowIntegrationTests.cs 在 431、554、984、1102 行附近的 ShutdownAsync 使用无条件空 catch。修正这些涉及本单的清理：

- 若只有清理发生错误，必须使测试失败并保留该错误；不得静默返回成功。
- 若业务断言与清理都失败，两者都要可观察，可以集中收集/聚合异常或保留主异常并附加次要清理诊断；不要用无条件空 catch 解释为“保留原错误”。
- 放行自有闸门、归还 caller/snapshot、等待自己的 Presenter/设置会话/后台工作退出，再释放对应容器。清理失败不意味着获得了释放仍活跃依赖的资格。
- 清理多个独立自有资源时，用最外层 finally 确保旁观窗口/静态委托恢复等不会因较早清理异常而跳过。不要全局关窗口、禁用全部测试并行或改生产默认配置。

新增受控关闭失败验证：让测试自己创建的窗口一次拒绝关闭，确认真实关闭错误会被清理流程记录/传播且不能被当作成功；在测试最外层移除拒绝处理器、重试并完整完成自身清理，使故障验证本身不泄漏窗口/任务。保留旁观窗口隔离断言。不要只 mock 一个与真实 ShutdownAsync 无关的 throw。

## 3. R2-2：Host 在所有分支均先完成异步停止再 Dispose

检查并修复两个现有方法：

1. RealCompositionRoot_AppHostBuilder_ResolvesSameInstance_AndAppBootstrapperStopAsync_DrivesTranslateWindowShutdown：当前仅正常路径执行 StopAsync。展示后任何断言失败也必须进入自有停止并等待，再释放 Host。
2. AppBootstrapper_StopAsync_WithInFlightConsumerAndCopy_GracefullyShutsDown：当前 using(host) 位于外层 finally 的闸门放行之前，且 stopTask 只在 try 内可见。将闸门、Presenter、Bootstrapper、stopTask 的所有权范围调整到清理可访问；finally 先放行、发起或等待真实停止，再释放 Host，最后恢复 AppShutdowner。

增加一个真正提前失败分支，确认未到正常 StopAsync 行时清理也会启动停止；在工作仍挂起时不提前 Dispose 依赖。停止途中失败应有明确诊断和自有恢复，不能将超时或原任务遗忘作为结束条件。使用 CancellationToken.None 或独立清理令牌，不能复用已取消的测试令牌跳过清理。

允许提取小型 test-only 清理辅助方法以避免复制嵌套 try/finally，但必须被实际用例调用，且故障测试覆盖该真实清理路径。不改生产接口来迎合测试。

## 二、实施内容与设计决策

### 1. 测试专用结构化清理收集器 `OwnedCleanup`
- **新建文件**: `tests/Iris.App.Tests/TestSupport/OwnedCleanup.cs`。
- **核心契约**:
  - `Step(string name, Action action)` / `StepAsync(string name, Func<Task> action)`：记录并执行自有资源的收尾步骤；如果抛出异常，捕获记录并继续后续独立清理步骤（确保后续资源不因先前异常而泄漏）。
  - `Skip(string name, string reason)`：当发生前置退出故障（例如窗口未完全关闭、后台流式工作尚未退出）时，记录跳过释放对应依赖（如容器 `ServiceProvider`、`IHost`、临时测试目录）。
  - `ThrowIfFailed(Exception? primaryException = null)`：
    - 若只有主体断言抛出 `primaryException` 且清理全成功，原样 rethrow `primaryException`（不包装）。
    - 若主体成功但清理出现故障，抛出 `AggregateException`，明确列出清理失败步骤与原因（彻底根除吞错误报）。
    - 若主体与清理均失败，抛出聚合异常，保留主体异常为首个内部异常，紧跟所有清理异常，确保两者均完全可见。

### 2. `TranslateWindowIntegrationTests.cs` 清理架构重构
- **消除空 catch**: 彻底移除 431、554、984、1102 行及全文件所有 `catch {}` 吞噬 `ShutdownAsync` 异常的模式，全部接入 `OwnedCleanup`。
- **提取小型清理辅助方法**:
  - `CleanupCompositionAsync(OwnedCleanup cleanup, TranslateWindowPresenter? presenter, ServiceProvider? sp, string? tempDir)`:
    - 步骤 1: `ShutdownAsync(CancellationToken.None)`；
    - 步骤 2: 仅在 Shutdown 成功后，才释放 `sp`；若退出失败，调用 `cleanup.Skip("DisposeServiceProvider", "ShutdownAsync did not complete cleanly")` 保持容器不被释放；
    - 步骤 3: 仅在前面退出成功后，才安全删除自有测试临时目录。
  - `CleanupHostAsync(OwnedCleanup cleanup, IHost? host, Task? pendingStopTask, string? tempDir)`:
    - 步骤 1: 若 `pendingStopTask` 尚未启动，由清理主动调用 `bootstrapper.StopAsync(CancellationToken.None)`；等待停止任务彻底完成；
    - 步骤 2: 仅在 Stop 成功完成后，才 `host.Dispose()`；
    - 步骤 3: 仅在 Stop 成功后，才安全删除临时目录。
  - `BuildTestHost(...)`: 封装真实 `Host` 构建工厂，统一注入所有单例测试替身与探针，隔离环境。

### 3. Host 测试的退出顺序与生命周期
- 在 `RealCompositionRoot_AppHostBuilder_ResolvesSameInstance_AndAppBootstrapperStopAsync_DrivesTranslateWindowShutdown` 与 `AppBootstrapper_StopAsync_WithInFlightConsumerAndCopy_GracefullyShutsDown` 中：
  - 将 `host`、`bootstrapper`、`stopTask`、`holdingGate` 的变量作用域提升到 `try/finally` 块外；
  - `finally` 中首先放行自有闸门（避免后台工作死锁阻塞）；
  - 调用 `CleanupHostAsync`，保证即使在 `StopAsync` 调用之前发生断言失败，清理逻辑也会发起并完整等待真实的 `bootstrapper.StopAsync(CancellationToken.None)`，待流式工作退出后才释放 `host`；
  - 最外层 `finally` 恢复全局 `AppShutdowner` 委托。

### 4. 新增 3 个受控失败与清理顺序测试
1. `HostCleanup_EarlyFailureBeforeStopAsync_CleanupStartsRealStop_AndDisposesHostOnlyAfterWorkExited`:
   - 验证在测试主体未到达 `StopAsync` 行即提前断言失败时，`CleanupHostAsync` 能够自行启动真实 `StopAsync`，使在途流式工作收到取消并退出；
   - 探针验证在 Host 被 Dispose 的瞬间，`workExited=True`, `viewModelReleased=True`, `windowReleased=True`, `stopCompleted=True` 均成立。
2. `HostCleanup_StopFailsBecauseOwnedWindowRefusesClose_IsReported_HostKept_ThenRecoveredByRetry`:
   - 验证自有窗口挂载 `Closing += CancelEveryClose` 拒绝关闭导致真实 `StopAsync` 失败时，`OwnedCleanup` 准确记录并抛出异常，测试不会误报通过，且 `host` 不会提前被释放；
   - 在最外层移除拒绝处理器并重试 `StopAsync`，确保测试本身完整退出且无任何残留窗口/任务。
3. `CompositionCleanup_OwnedWindowRefusesClose_FailureIsPropagated_ContainerKept_ThenRetriedAndOnlookerSurvives`:
   - 验证真实组合根下窗口拒绝关闭时，清理步骤抛出 `InvalidOperationException` 并由测试捕获验证，容器与临时目录未被提前释放；
   - 最外层重试后成功退出，同时断言验证同进程旁观窗口存活且不受影响。
