## 2. R1-1：PerMonitorV2 覆盖实际采集，清理失败不能被重试掩盖

当前 SetThreadDpiAwarenessContext 在 EnumDisplayDevices/EnumDisplayMonitors/GetMonitorInfo **之后**执行，只覆盖查询窗口的创建与 DPI 读取。必须在依赖坐标的原生采集之前建立正确作用域；不能假定所有调用线程本来就是 PerMonitorV2。

此外，当前 queryFailed 分支即使存在 cleanupFailures，仍返回 false 触发下一轮。受控反例：

- 首次 GetDpiForWindow=0，恢复旧 context 失败；第二轮成功，却把已污染的 -4 当成旧 context，最终返回成功，原 context 丢失。
- 首次查询失败且 DestroyWindow 失败；第二轮成功，仍返回有效快照，但第一个查询窗口未释放。

要求：

- 保存真实原始 context，并让作用域覆盖设备/矩形采集及查询 HWND 生命周期；过程中不 await，不修改进程全局 DPI。
- 重试只适用于干净结束的采集不一致/查询失败。清理失败必须终止成功出口，保留主失败并安全记录清理失败，不能靠下一轮成功抹掉它；恢复失败时也不能把当前 context 当作原始值重新记账。
- 可把整个有界采集重试放入一次 DPI 作用域，或采用明确等价的所有权结构。不要引入通用全局重试/资源框架。
- fake 必须能逐次注入失败，不能只提供“以后永远失败”开关。覆盖：首次查询失败 + 首次恢复失败但后续调用可成功；首次查询失败 + 首次销毁失败但后续可成功；仅查询失败且清理成功后允许正常重采。
- 断言坐标采集时的 context、最多两次业务采集、返回状态、所有自身 HWND 的清理记录及原始 context 的恢复目标。仅调用了一次 Restore 或最终拿到非空列表不算证明。

实际混合 DPI 本轮没有环境，不需要修改用户显示器配置来复现；先用真实实现驱动的适配器断言调用顺序和状态。

## 3. R1-2：拒绝显示器侧同名冲突

当前只检查设备表的同名 StateFlags 冲突，没有检查 rawMonitors 的同名信息。两个同名显示器带不同 HMONITOR/Bounds/WorkArea 时，被发布为两张记录；与规范“不发布同名冲突快照”不符。

- 在创建 DPI 查询窗口/发布结果前检查显示器侧同名冲突，名称比较仍为 OrdinalIgnoreCase；冲突丢弃整次快照，最多重采一次，持续冲突则 Unknown。
- 不通过简单去重/保留第一个来掩盖两份不同几何。完全相同的重复条目可以显式去重，或统一视为不一致，但策略要固定并测试。
- 回归包含同名不同几何/句柄、仅大小写差异的冲突，以及首次冲突后下一次一致的恢复。保留合法不同名称的多屏与镜像/远程筛选行为。

## 4. R1-3：异常退出也必须记录次要清理错误

GetForegroundApp 中 QueryFullProcessImageName 抛出已有 IrisException，再 CloseHandle 返回 false 时，异常跳过 finally 后的日志处理，清理失败丢失。MonitorEnumerator 的 catch 直接 rethrow，也会跳过其后统一处理 cleanupFailures 的代码。

在这些异常路径也遵守同一规则：主失败保留，次要释放/恢复失败安全记录 API 与数值错误；不能只有正常返回或 bool 失败路径有日志。回归实际调用生产方法，注入已存在的主失败与清理失败，断言主错误及日志。不要把原始异常对象、窗口标题或进程路径放进日志，也不要为修日志更改失败分类或加入外部通知。
