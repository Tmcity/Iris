## 一、实施概况与架构对齐

依据 `specs/KEYBOARD_SIMULATION.md` 与 ARCH v1.30，已在 `Iris.Platform.Windows` 中实现内部键盘模拟子系统，并在 `tests/Iris.Platform.Windows.Tests` 与 `tests/Iris.App.Tests` 中建立完整测试与维护：

### 1. 内部数据模型 (`src/Iris.Platform.Windows/Selection/`)
- `KeyboardCopyTarget`：目标窗口不可变标识 (`HWND Hwnd`, `uint ProcessId`)。提供 `IsValid` 校验。
- `KeyboardCopyOutcome`：执行结果枚举 (`Inserted`, `NotReady`, `TargetChanged`, `Busy`, `NativeFailure`, `Cancelled`, `Stopped`)。明确 `Inserted` 仅表示输入序列完整进入目标窗口输入队列，不代表已拿到文本选区。
- `KeyboardCopyResult`：执行结果封装，记录 `KeyboardCopyOutcome Outcome`, `bool MayHaveCopied`, `bool HasPendingRelease`。

### 2. 窄 Native 适配器 (`INativeKeyboardInputAdapter` / `Win32KeyboardInputAdapter`)
- 在 `src/Iris.Platform.Windows/NativeMethods.txt` 中引入 `SendInput`。
- `INativeKeyboardInputAdapter`：隔离 Win32 原生调用，包含 `IsKeyDown(VIRTUAL_KEY)`, `SendKey(VIRTUAL_KEY, bool isKeyUp)`, `GetForegroundWindow()`, `GetWindowThreadProcessId(HWND, out uint)`, `IsWindow(HWND)`, `GetCurrentProcessId()`。
- `Win32KeyboardInputAdapter`：
  - `IsKeyDown`：调用 `PInvoke.GetAsyncKeyState((int)key)` 并检查最高位 `& 0x8000 != 0`。
  - `SendKey`：构造标准 CsWin32 `INPUT` 结构（`INPUT_TYPE.INPUT_KEYBOARD`, `wVk = key`, `KEYBDINPUT_FLAGS.KEYEVENTF_KEYUP` 或 `0`），`Marshal.SizeOf<INPUT>()` 经实测为 40 字节（x64），以 `cInputs = 1` 提交 `PInvoke.SendInput`，严格校验返回值等于 1。
  - 其余方法透明路由至 CsWin32 PInvoke 方法。

### 3. KeyboardSimulator 实现细节
- **零提前 I/O 与构造安全**：构造函数纯赋值，不执行任何 Win32 原生操作或线程启动。
- **DI 注册**：在 `PlatformWindowsServiceCollectionExtensions.AddIrisPlatformWindows` 中使用 `TryAddSingleton` 注册 `INativeKeyboardInputAdapter` 与 `KeyboardSimulator`，注入并复用全局 `TimeProvider` 与 `ILogger<KeyboardSimulator>`。
- **单活动准入控制**：使用 `SemaphoreSlim(1, 1)` 守护核心操作。若已有 `CopyAsync` / `RetryCleanupAsync` / `StopAsync` 在执行，后续 `CopyAsync` 立即返回 `Busy`（`MayHaveCopied = false`, `HasPendingRelease` 为当前状态）。
- **修饰键释放轮询**：
  - 监听列表：`VK_LCONTROL`, `VK_RCONTROL`, `VK_LMENU`, `VK_RMENU`, `VK_LSHIFT`, `VK_RSHIFT`, `VK_LWIN`, `VK_RWIN`, `VK_C`。
  - 使用 `TimeProvider.CreateTimer` 每 10ms 检查一次按键状态。
  - 若在 500ms 超时到达前所有按键均释放，则继续执行；
  - 若 500ms 超时或中途 CancellationToken 触发，立即返回 `NotReady` 或 `Cancelled`，**严格遵循规范：绝不强行向系统补发任何 KeyUp**。
- **目标重验证**：
  - 在开始前验证目标有效性（HWND 存在、PID 匹配、HWND 为当前前台窗口、非当前应用自身 PID）；
  - 在每次发出 `KeyDown` 前（即发送 `LCtrl down` 前与发送 `C down` 前）重新获取当前前台窗口与 PID 验证；
  - 一旦目标变化，立即中止后续 KeyDown，并启动有界补偿释放已确认接纳的按键。
- **单 INPUT 确认与状态责任追踪**：
  - 严格按照顺序：`LCtrl down` -> `C down` -> `C up` -> `LCtrl up`。
  - 每次发送 `cInputs = 1` 的单个 INPUT 事件并验证返回值等于 1。
  - 使用 `_heldKeys` (`HashSet<VIRTUAL_KEY>`) 严格记录当前已压下且未确认抬起的键。
  - 只有在 `C down` 确认成功后，`mayHaveCopied` 才置为 `true`。
- **有界单次补偿与未释放保护**：
  - 当任一原生调用失败或目标窗口中途变化时，立即启动单次有界补偿（Bounded 1-pass compensation）。
  - 按照压键逆序（`VK_C` 先释放，随后 `VK_LCONTROL` 释放）逐个发送 KeyUp。
  - 若补偿成功，清理释放责任；若任一键补偿释放仍失败，保留在 `_heldKeys` 中，`_hasPendingRelease = true`，禁止后续发起新的完整 Copy，后续 Copy 均返回 `Busy`。
- **重试与停机清理**：
  - `RetryCleanupAsync`：针对残留的 `_heldKeys` 再次尝试单次逆序释放；成功后清除 `_hasPendingRelease`。
  - `StopAsync`：永久关闭准入 `_isStopped = true`，等待正在运行的 Copy 退出，并尽最大努力尝试清理解除所有残留 KeyUp。
  - `DisposeAsync` / `Dispose`：协同清理未托管资源与信号量，符合 `IAsyncDisposable` / `IDisposable` 规范。
- **规范与代码健康**：
  - CA1848 结构化日志支持（使用 source-generated `[LoggerMessage]` partial 方法）。
  - CA1513 使用 `ObjectDisposedException.ThrowIf`。
  - 零日志输出用户输入内容或机密。

## 四、安全与系统边界说明

1. **单事件发送与输入交错/目标竞态边界**：
   - Windows 原生 `SendInput` 在注入单一事件时虽然是原子地放入系统硬件输入队列，但在多线程与并发用户操作环境下，物理硬件输入、IME 转换窗口或焦点瞬态切换（例如 Alt-Tab 或全局弹窗）可能在 `LCtrl down` 与 `C down` 之间穿插发生；
   - 本实现通过在每次 `KeyDown` 注入前强制重新校验当前前台窗口 HWND 与 PID 进行防御。若前台发生漂移，立即中止后续 KeyDown 并启动有界逆序补偿释放已确认压下的按键；
   - 尽管如此，Win32 系统的单会话硬件输入队列无法彻底消除极端并发物理击键带来的交错可能。若目标窗口具有更高的完整性级别（UIPI，User Interface Privilege Isolation，例如管理权限提升的窗口），标准权限下的 `SendInput` 将被系统静默丢弃或拦截（返回 0），本实现会将其判定为 `NativeFailure` 并保留状态，但无法且不宣称能绕过 Windows 安全边界。
2. **终端与特权应用限制**：
   - 某些特定终端仿真器（如某些配置下的 ConHost、Windows Terminal 或管理员权限进程）可能对非硬件真实击键进行过滤，不保证选区必能送入剪贴板。
3. **自动化安全铁律执行**：
   - 自动化测试全程使用 `FakeNativeKeyboardInputAdapter` 与 `FakeTimeProvider`，严禁真实 SendInput、严禁真实读取用户键盘、严禁挂接全局 Windows Hook、严禁访问系统剪贴板与配置密钥；
   - 本轮未执行 `build/measure-startup.ps1`，未真实联网。
