## 2. R3-1：全部查询与保存结果采用一致的有效性规则

当前 _queryGeneration 只随构造/Reload 的 QueryAutoStartStatusAsync 递增，保存/重试直接调用协调器查询，没有失效旧查询。独立反例：

1. 构造查询捕获“已一致”，暂存其 UI 回调。
2. 用户保存 LaunchAtStartup=true，JSON 提交，fake SetEnabled 失败；CanRetryAutoStart=true。
3. 放行旧回调，CanRetryAutoStart 变 false，但 Current=true、注册=false。

要求：

- 统一初始查询、Reload、保存、重试及相关已保存意图变更的结果资格；后续操作开始/状态更新必须使不再适用的旧查询失效。不能只修构造这一处或只对失败分支加特殊判断。
- 在 UI 真正执行回调时检查操作/查询身份及对应的已保存状态；提交后的失败事实不能被更早的“无待应用”结果覆盖，成功状态也不能被过期的失败结果反向覆盖。
- Query 仍在后台执行；不通过同步等待或注册表写入使读取结果“追上”配置。不把停止/取消的查询当成一次有效“一致”结论发布。
- 继续区分 JSON 保存成功与系统应用失败；无关保存和 Reload 不应抹掉待应用事实。

正式回归至少覆盖：初始/Reload 查询回调迟到后保存失败；旧查询迟到后重试成功；查询期间最新已保存意图变化；停止后结果丢弃。检查 Current、fake 实际注册状态、CanRetryAutoStart 与展示状态的一致性，不只比较代次数值。

## 3. R3-2：所有关闭路径都持有未完成查询，确认实际关闭后再释放

R2 只在显式 Shutdown 排干工作。普通 Close 的 OnWindowClosed 和 Presenter.ShowAsync 的 catch 仍直接 Dispose；而 VM 构造已启动异步查询。独立探针在 IsEnabled 挂起时得到 scope-disposed=True、query-pending=True、shutdown-complete=True、session-retained=False。

- 把普通 X/Cancel/Esc、Show/解析失败回滚、正常退出接入同一会话清理责任：停止接纳并请求取消，观察全部已接纳后台查询及必要 UI 收尾，然后释放它们依赖的 scope。
- 用户关闭后可以先隐藏窗口，但未完成清理的会话必须仍有明确所有者；后续 Presenter.ShutdownAsync 必须等待它，不能因 ActiveSession 置 null 而遗忘。也可以保留窗口到异步清理完成再关闭，UI 消息循环不能被同步阻塞。
- Show 失败时仍回收自有 HWND；如果 VM 已创建并启动查询，scope 必须等查询退出后释放。ShowAsync 的异步失败清理要被调用方完整观察，不能在 catch 中启动未等待的清理任务。
- 失败回滚不会保证 Close 成功。当前 CloseAndCleanupCore 的 finally 在 Closing 被取消时仍 Dispose；移除“无条件关闭成功”的假设。只在确已关闭且工作结束后结束所有权；取消/异常时保留必要管理状态，明确观察失败，不吞掉后返回成功，也不把存活窗口的 VM/scope 销毁。
- 保留正在进行的并发 Shutdown 共享同一完成状态；发生关闭失败后仍能受控完成后续清理。只在本设置会话范围内解决，不建全局后台任务框架。

正式回归使用真实 Dispatcher/非激活自有窗口，分别在构造查询、Reload 查询挂起时：普通关闭后立即退出；Show 失败；显式 Shutdown。放行前不得释放 scope，也不得报告全部退出；放行后查询/VM 任务完成并关闭窗口、释放 scope。再注入 Closing 取消/失败，验证存活窗口保留有效依赖、错误被观察，随后允许关闭并完成清理。每个失败测试都在 finally 中释放自己的门闩和窗口。

  - 成功完成关闭后方才执行 `scope.Dispose()`，并显式触发 `CleanupCompleted` 事件。
- **修改文件**：`src/Iris.App/Settings/SettingsWindowPresenter.cs`
  - 监听 `session.CleanupCompleted`，在会话真正清理完成时才将 `_activeSession` 重置为 null，确保在普通关闭或 Show 失败但在异步排干进行中，Presenter 始终保持对活跃会话的追踪。

## 实施与更正说明（针对 R4 工单）

更正 R3 报告中关于“Show 失败完整异步清理”“关闭失败已被退出调用方观察”“全部闭环”的过度表述：
1. **Show 失败异步清理**：R3 实现中 catch 块使用的是未等待的 `_ = session.ShutdownAsync()`，导致 Show Task 在后台初始查询排干前提前以 Faulted 状态结束，未完成异步等待闭环。R4 已更正为在 catch 块中显式 `await session.ShutdownAsync().ConfigureAwait(true)`，确保调用方直到本次创建的所有工作排干且资源释放后才观察到最终失败。
2. **关闭失败被退出调用方观察**：R3 实现中 `Presenter.ShutdownAsync` 捕获异常后记录日志并正常返回成功，导致调用方误以为退出成功；同时隐藏窗口在取消关闭时被误判为已关闭并提前释放 scope。R4 已更正为窗口关闭必须以确切 Closed 为准，取消关闭时保留原生句柄与依赖并向 `Presenter.ShutdownAsync` 及 `AppBootstrapper.StopAsync` 传递异常，阻止依赖过早销毁并允许重试。
3. **STA 线程 Join 超时行为**：更正此前报告中“STA Join 超时强制中断”的表述：实际代码中为超时抛出 `TimeoutException`，不存在强制杀线程行为。
