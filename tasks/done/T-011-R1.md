## 1. 目标与范围

修复 T-011 已批准行为的实现缺陷，不改变公开签名、凭据协议或分层。保留现有契约同步、DI/启动、读取兼容和正确的基本租约逻辑。不得开始 T-012、配置写入协调器或 OCR 注册表；不修改已验收 Provider/Settings/DPAPI 业务实现，不新增包。

## 2. 必须修复

### R1-1（P1）：不可变快照集合

常驻与瞬态的 Providers 必须为拥有独立集合所有权、不能经 IList/数组等途径修改的只读视图；不得泄露 Registry 内部 List。内部引用跟踪集合也须保持稳定，避免枚举条目与释放对象不一致。可共享已冻结的集合，不要求每次 Acquire 重复复制。

### R1-2（P1）：刷新屏障与失效状态

不能在开始构建时把 dirty 清零并让 Acquire 绕过正在执行的刷新。明确失效代次、已发布代次、进行中工作及失败状态的同步协议（可采用版本计数或等价设计）。Acquire 必须等待它应观察的刷新完成，并在发布/借出之间重新检查状态；已知失败不能被当作成功旧状态。旧租约继续有效与新 Acquire 返回陈旧状态必须区分。

失败后保留未应用状态；后续显式 Refresh/Acquire 可重试或明确返回安全失败，不得静默借出旧代。后台不得对同一失败配置无限重试；刷新期间新事件不能被 catch 清零抹掉，更新版本到来仍能继续。显式 Refresh 仍须满足旧凭据解析全部退出的清理屏障。

修改现有 `Rollback_WhenFactoryFailsMidway_CleansUpNewlyCreatedInstances_AndPreservesOldState` 的错误断言：保留原租约可用，不再要求失败后的新 Acquire 成功返回旧表。报告明确说明这一已有测试的语义修正。

### R1-3（P1）：统一构建、发布、取消与 Dispose 所有权

新实例从 Factory 返回到成功转交所有权之前，所有异常/取消/Registry.Dispose 路径均应恰好清理一次，清理范围必须涵盖最终发布检查。最后一次同步 Factory 调用返回后也要检查取消和 disposed，再决定是否发布。同步 Factory 无法中途终止时，返回后清理，不能将其当作取消成功。

对 `_activeInstances` 的读取、复用、退休和 Dispose 清空建立一致同步，不能一边无锁查 Dictionary 一边 Clear。不得复用已退休/已释放对象。实际 Provider.Dispose 在锁外，已有租约跨 Registry.Dispose 仍有效。瞬态路径同样覆盖 Factory 创建后、设置读取/快照构建失败以及取消/Dispose 交错，不得漏对象或在关闭后转交新租约。

### R1-4（P2）：后台执行与元数据

显式 Refresh、首次 Acquire、CreateTransient 的凭据读取/批量构造在后台执行；仅使用 ConfigureAwait(false) 不能保证切换线程。瞬态草稿在调用边界捕获并冻结后再调度，不能因 Task.Run 延迟捕获而引入草稿别名竞态。

复用 Provider/InstanceId 时，用本次 Profile 创建注册项。仅改变单项 Order 时，注册项与 Snapshot.Settings 应一致，Changed 按已批准规则通知；旧快照保持原 Profile。

### R1-5（P2）：凭据与占位 Provider 边界

CredentialSetId 严格全字符串匹配，拒绝合法 ID 后附 LF 等额外字符；非法格式不读取 SecretStore。拒绝未知嵌套对象/数组内的重复 JSON 属性，继续允许不含重复属性的未知字段。仍然不回退 legacy、不输出原始输入。

占位 Provider 在异步挂起后观察到取消必须抛 OperationCanceledException，不得以成功 EOF 结束。保留非取消时 NotConfigured 和 TestAsync 的既定行为。

## 3. 测试与验收

所有测试不联网，使用受控 Factory/SecretStore、TaskCompletionSource/门闩和有界超时保证交错。不能仅以快速任务 Task.WhenAll 声称完成竞态覆盖，也不靠 Thread.Sleep 猜时序。

- 常驻/瞬态集合通过强转尝试修改均失败；后续租约完整且释放计数正确。
- A 已发布，B 构造暂停时 Acquire 不成功返回 A；B 失败后新 Acquire 不伪装成功，已有 A 租约可用；恢复后成功取得 B。
- B 构造/凭据读取暂停期间再发布 C，分别覆盖 B 成功和失败，确保 C 事件不丢失；同一失败版本无后台忙循环。
- 构造期间 Dispose/取消、部分构造后失败、等待屏障时取消、瞬态创建期间 Dispose/取消：新对象清理恰好一次，原租约最后释放才清理旧对象。
- 使用专用调用线程或受控 SynchronizationContext 验证耗时工作在后台；草稿调度后修改不会影响捕获结果。
- 单项 Order 变化不重建，注册项新值、旧快照旧值及 Changed 均符合预期。
- 尾随 LF、嵌套重复属性（包括数组内对象）拒绝；合法未知字段兼容；受控异步续体取消抛 OCE。
- 保留 T-011 其它选择/凭据/租约/隐私/DI/启动回归。

执行 Release 构建（零警告）及全量测试；关键有门闩的竞态测试连续运行 5 轮，逐轮提供实际汇总。次数不是正确性证明，报告仍须写明每个受控交错。
