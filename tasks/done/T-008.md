## 1. 背景

T-009（OpenAI 兼容）、T-010（Anthropic）、T-028（百度 OCR）都要调用远程 HTTP 服务。本工单先把它们共用的基础设施做好：
- **SSE 流解析**：大模型的流式输出协议。
- **HTTP 错误 → `IrisException` 映射**：把各种失败统一成 Iris 的错误码和中文提示。
- **服务端错误信息脱敏**。
- **动态代理**：代理设置修改后无需重启即可生效。
- **两个命名 HttpClient** 及其重试策略。

规范写在 **ARCH v1.9 §5.2、§11.2、§11.3、§12.4、§12.5**。其中有几条是架构师实测后定下的，务必先读：
- **SSE 解析直接包装 .NET 10 自带的 `System.Net.ServerSentEvents.SseParser`**（共享框架中已有，不需要引入 NuGet 包）。架构师已实测它能正确处理 CR / LF / CRLF、BOM、注释行、多行 data、多字节字符被拆开读入等情况，不要自己手写解析器。
- **必须移除 IHttpClientFactory 默认的日志处理器**：它会在 Information 级别记录完整 URL，而百度 OCR 的 `access_token` 就放在查询字符串里。本工单有一个专门的隐私测试来验证这一点。

## 6. 实现要求

### 6.1 SseParser 与 LimitedReadStream

```csharp
internal static class SseParser
{
    public const long DefaultMaxResponseBytes = 32L * 1024 * 1024;

    /// <summary>
    /// 包装 System.Net.ServerSentEvents.SseParser。不拥有 stream（不会释放它）。
    /// 读取的字节总数超过 maxResponseBytes 时，抛 IrisException(InvalidResponse)。
    /// </summary>
    public static IAsyncEnumerable<SseEvent> ReadEventsAsync(
        Stream stream, CancellationToken cancellationToken, long maxResponseBytes = DefaultMaxResponseBytes);
}
```
- 类名与 .NET 的 `SseParser` 重名，用别名引用：`using NetSse = System.Net.ServerSentEvents;`。
- 映射：`SseEvent(item.EventType, item.Data, item.EventId)`。异步迭代器的 CancellationToken 参数加上 `[EnumeratorCancellation]`。
- `LimitedReadStream`：只读包装流，重写 `Read(byte[]…)`、`Read(Span<byte>)`、`ReadAsync(byte[]…)`、`ReadAsync(Memory<byte>…)` 并累计已读字节数；超过上限时抛 `IrisException(InvalidResponse, …, detail: "响应超过 {上限} 字节")`；不释放内部流；`CanSeek` / `CanWrite` 均为 false。
- 已知行为（写进类的 XML 注释，并用测试固定下来）：流末尾不完整的事件（最后没有空行）会被**丢弃**；只有 `event:` 没有 data 的事件，其类型会延续到下一个事件（.NET 解析器与 WHATWG 规范的偏差，对 OpenAI 和 Anthropic 没有影响）。

### 6.2 HttpErrorMapper

```csharp
internal static partial class HttpErrorMapper
{
    public static (ErrorCode Code, bool Retryable) MapStatus(int statusCode, string? providerErrorCode);

    /// <summary>纯函数：按 ARCH §11.2 从响应体中提取信息、脱敏、截断，构造异常。T-009 处理“200 响应中携带错误体”时也使用它。</summary>
    public static IrisException FromBody(int statusCode, string? body, string providerId, IReadOnlyList<string?>? knownSecrets);

    /// <summary>读取响应体的前 64 KB，然后调用 FromBody。</summary>
    public static Task<IrisException> FromResponseAsync(
        HttpResponseMessage response, string providerId, IReadOnlyList<string?>? knownSecrets, CancellationToken cancellationToken);

    /// <summary>按 ARCH §11.2 的异常映射表转换；不应该被映射的异常（用户取消、编程错误）返回 null。</summary>
    public static IrisException? TryMapException(Exception exception, string providerId);

    public static IrisException Timeout(string providerId, TimeSpan timeout);
}
```
- 严格按 ARCH §11.2 的两张表和“错误信息提取”规则实现。
- `TryMapException` 遇到 `OperationCanceledException` 一律返回 null：是用户取消还是超时，由 Provider 根据自己的 CTS 判断（T-009 会写出这个模式）。
- 截断规则：按 `Rune` 截断，不得把代理对截成两半；最多 300 个字符，超出部分以 `…` 结尾。

### 6.3 SecretRedactor

`public static string Redact(string text, IReadOnlyList<string?>? knownSecrets = null)`：严格按 ARCH §12.5。先替换已知密钥（按长度从长到短，只替换长度 ≥ 8 的），再应用三个 `[GeneratedRegex]`。

### 6.4 DynamicWebProxy

- 构造函数：`(ISettingsService settings, ILogger<DynamicWebProxy> logger)`。严格按 ARCH §12.4。
- 本地地址判断写成纯函数 `internal static bool IsLocalAddress(Uri uri)`，便于单独测试。IP 网段判断使用 `IPAddress.TryParse` 与 `IPNetwork.Contains`（.NET 8+）。
- `Credentials` 的 setter 抛 `NotSupportedException`。
- “只记一次 Warning”：用 `Interlocked` 维护一个标志位；日志中**不写**代理地址。

### 6.5 HttpLoggingHandler 与 LlmRetryDelay

- `HttpLoggingHandler : DelegatingHandler`：注入 `ILogger<HttpLoggingHandler>`。在 Debug 级别记录 `{Method} {SafeUrl} → {StatusCode}（{ElapsedMs} ms）`；发生异常时，在 Debug 级别记录 `{Method} {SafeUrl} 失败：{ExceptionType}` 后重新抛出。`SafeUrl = uri.GetLeftPart(UriPartial.Path)`。不记录请求头和请求体。
- `LlmRetryDelay.Compute(HttpResponseMessage? response, TimeProvider timeProvider) : TimeSpan`：
  - 有 `Retry-After`：秒数形式 → `min(秒数, 5s)`；日期形式 → `min(日期 − now, 5s)`，结果为负时取 0。
  - 没有 `Retry-After`：返回 `[0.8s, 1.2s]` 区间内的随机值（`Random.Shared`）。

### 6.6 AddIrisProviders

```csharp
public static class ProvidersServiceCollectionExtensions
{
    /// <summary>注册 Providers 层的 HTTP 基础设施。调用方须事先注册 ISettingsService 与日志。</summary>
    public static IServiceCollection AddIrisProviders(this IServiceCollection services);
}
```
严格按 ARCH §11.3，要点：
- `TryAddSingleton(TimeProvider.System)`；`DynamicWebProxy` 注册为单例；`HttpLoggingHandler` 注册为瞬态。
- 两个客户端都要：`ConfigurePrimaryHttpMessageHandler`（SocketsHttpHandler，配置见 ARCH）、`ConfigureHttpClient`（无限超时 + User-Agent）、`RemoveAllLoggers()`。
- **处理器顺序**：先 `AddResilienceHandler` / `AddStandardResilienceHandler`，再 `AddHttpMessageHandler<HttpLoggingHandler>()`。先添加的在外层，所以日志处理器位于重试**内层**，每次尝试都会记录一次。
- `iris.llm` 的重试：`HttpRetryStrategyOptions { MaxRetryAttempts = 1, ShouldHandle = …, DelayGenerator = … }`。`ShouldHandle` 按 ARCH 的条件判断（`HttpRequestException`，或状态码为 408 / 429 / 5xx）；`DelayGenerator` 调用 `LlmRetryDelay.Compute`。
- 在 `AppHostBuilder` 中调用 `AddIrisProviders()`（放在 `AddIrisCore()` 之后）。

## 7. 测试要求

**SseParserTests**（用 `MemoryStream` 构造输入；为多字节字符分片的场景写一个每次只返回 1 个字节的测试流）：
1. OpenAI 夹具（ARCH §9.1 中的 5 个事件，包括 `[DONE]`）→ 5 个事件，data 与原文一致，EventType 均为 `"message"`。
2. Anthropic 夹具（ARCH §9.2 中的 6 个事件）→ EventType 依次为 `message_start` … `message_stop`。
3. CRLF、单独 CR 作为换行都能正确解析；开头有 BOM 能正确解析。
4. 注释行被忽略；多行 data 用 `\n` 连接；`data:x`（冒号后没有空格）→ `"x"`；`data:  x` → `" x"`。
5. 每次只读 1 个字节，并且汉字被拆开读入 → 数据完整。
6. 流末尾不完整的事件被丢弃（固定已知行为）。
7. 只有 `event: ping` 没有 data，后面紧跟一个只有 data 的事件 → 后者的 EventType 为 `"ping"`（固定已知行为）。
8. 响应超过上限（例如把上限设为 1 KB，输入 2 KB）→ 抛 `IrisException(InvalidResponse)`。
9. 枚举过程中取消 → 抛 `OperationCanceledException`。

**LimitedReadStreamTests**：4 种 Read 重载都会计数；刚好等于上限时不抛；超过 1 字节即抛；释放包装流不会释放内部流。

**HttpErrorMapperTests**：
- `MapStatus`：用 `[Theory]` 覆盖 ARCH 状态码表中的每一行（包括 301、418 → BadRequest、599 → ProviderUnavailable、429 + `insufficient_quota` → QuotaExceeded 且不可重试）。
- 信息提取：OpenAI 形式、Anthropic 形式（`{"type":"error","error":{"type":"overloaded_error","message":"Overloaded"}}`）、`{"error":"string"}`（Ollama）、`{"detail":"…"}`、`{"error_msg":"…"}`、HTML 页面（压缩空白）、空响应体 → `Detail` 分别符合预期；`error.code` 为数字时也能识别 `insufficient_quota`（通过 `error.type`）。
- 截断：400 个字符 → 300 个字符 + `…`；第 300 个字符处恰好是 emoji 的代理对时不被截断成两半。
- 脱敏：响应体中包含已知密钥 → `Detail` 中不出现该密钥。
- `FromResponseAsync`：响应体超过 64 KB 时只读取 64 KB（构造 1 MB 的响应体，断言耗时和结果都正常）。
- `TryMapException`：`HttpRequestException` → NetworkUnavailable 且可重试；`IOException` → NetworkUnavailable；`JsonException` → InvalidResponse；`OperationCanceledException`、`InvalidOperationException` → null。
- `Timeout` → ErrorCode.Timeout，可重试，`Detail` 中包含秒数。

**SecretRedactorTests**：已知密钥被替换（包括同一文本中出现多次）；长度 < 8 的已知密钥不替换；三个正则各至少 2 个用例（例如 `Incorrect API key provided: sk-proj-AbCdEf1234567890` → `sk-***`；`?access_token=24.abc&x=1` → `access_token=***&x=1`；`Authorization: Bearer eyJhbGciOi…` → `Bearer ***`）；knownSecrets 为 null 或包含 null 元素 → 不抛异常。

**DynamicWebProxyTests**（`ISettingsService` 用替身）：
- None → `GetProxy` 为 null，`IsBypassed` 为 true。
- Custom，公网主机 → 返回代理 Uri；`BypassProxyOnLocal = true` 时，`localhost`、`127.0.0.5`、`10.1.2.3`、`172.20.0.1`、`192.168.1.5`、`169.254.1.1`、`[::1]`、`[fd00::1]`、`[fe80::1]`、`intranet`、`printer.local` → 直连；`172.32.0.1`、`8.8.8.8`、`api.openai.com` → 走代理。
- `BypassProxyOnLocal = false` → 上述本地地址也走代理。
- 两次调用之间修改设置 → 立即生效。
- Custom 地址无效（绕过规范化，直接在替身中返回无效值）→ 返回 null，连续调用只记 1 条 Warning，日志中不含该地址。
- System 模式：`localhost` 在 `BypassProxyOnLocal = true` 时直连（System 模式的其他行为依赖本机配置，不做断言）。
- 设置 `Credentials` → 抛 `NotSupportedException`。

**LlmRetryDelayTests**（`FakeTimeProvider`）：`Retry-After: 2` → 2 s；`Retry-After: 60` → 5 s；日期为 3 秒后 → 3 s；日期为过去的时间 → 0；没有该头 / 响应为 null → 连续调用 100 次，全部落在 [0.8, 1.2] 秒之间。

**HttpClientPipelineTests**（构造真实的 `ServiceCollection`：`AddLogging`（接入 `FakeLogCollector`，最低级别 Trace）+ `ISettingsService` 替身 + `AddIrisProviders()`；然后用 `services.AddHttpClient(name).ConfigurePrimaryHttpMessageHandler(() => mockHttp)` 替换主处理器）：

    public async Task Privacy_SensitiveQueryParameters_AreNotLogged()

## 3. 与工单的偏差

1. **C7-1 遗留项落地**：
   - 工单 6.8 节要求修正 `SoftLineBreakMerger` 的编号列表正则表达式为 ARCH v1.9 §7.5 中的 `^\d{1,3}(?:[.)]\s|、)`。已完成更新，并在 `tests/Iris.Core.Tests/Text/SoftLineBreakMergerTests.cs` 中补充了要求覆盖的全部用例（`1.5 kg` 与 `3.14 today` 正常合并；`1) a` / `2) b` 与 `1、第一` / `2、第二` 保留换行）。
2. **C7-2 遗留项落地**：
   - 工单 6.8 节要求在 `PromptRenderer`、`TextPreprocessor`、`PromptTemplateProvider` 构造函数中增加 `ArgumentNullException.ThrowIfNull` 参数校验。已完成修改，并在对应的单元测试中补充了 null 入参断言。
3. **`Microsoft.Extensions.Http.Resilience` (10.10.0) 的 API 链式调用适配**：
   - 在该版本中，`IHttpClientBuilder.AddResilienceHandler(...)` 返回的是 `IHttpResiliencePipelineBuilder`，无法直接继续链式调用 `IHttpClientBuilder` 的扩展方法。
   - 实现适配：先保留 `var llm = services.AddHttpClient(HttpClientNames.Llm)...` 实例，对其调用 `llm.AddResilienceHandler(...)`，随后通过 `llm.AddHttpMessageHandler<HttpLoggingHandler>()` 注册日志处理器。这样严格保证了 ARCH §11.3 规定的“弹性管道在外层、日志处理器在内层，每次尝试均记录一次日志”的执行顺序。
4. **xUnit v3 异步测试代码规范规则 xUnit1051**：
   - 项目启用了 xUnit 代码分析规则 `xUnit1051`（异步方法必须传入 CancellationToken）。单元测试中的 `ReadAsync`、`GetAsync`、`PostAsync`、`MoveNextAsync` 等异步调用均传入了 `TestContext.Current.CancellationToken`。
5. **代码分析规范调整（CA1873、CA2215、CA1835）**：
   - `HttpLoggingHandler` 中通过先提取局部变量 `var exceptionType = ex.GetType().Name;` 再传入 Source Generator 日志方法，避免 CA1873。
