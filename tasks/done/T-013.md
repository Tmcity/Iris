## 1. 目标

实现 ITranslationOrchestrator，使一次请求在固定配置下并行调用多个 Provider，输出有序归属的事件，完整处理失败/取消/消费者退出，并接入已实现的缓存与真实历史仓储。这是 M1 的完整翻译流程，不实现 WPF 翻译窗口或热键。

## 2. 实现范围

- 新增 Core/Translation/TranslationOrchestrator.cs 及少量必要的 internal 执行计划、结果/预算帮助类型；所有请求状态保持局部，不放入单例的“当前请求”字段。
- 按 CCR-006 同步 CONTRACTS.cs 与两个 Core 落地文件的注释；不改变公开签名、事件字段、设置格式或默认值。
- AddIrisCore 以 TryAddSingleton 注册 ITranslationOrchestrator，默认 TimeProvider 可 TryAddSingleton，允许测试注入受控时钟。
- Core 受控单元测试、Core DI 测试、App.Tests 中的真实缓存/历史纵向集成测试。允许 Core.Tests 引用中央已存在的 Microsoft.Extensions.TimeProvider.Testing 测试包；不增加生产依赖。
- 不修改已验收的 Provider、Registry、缓存、历史仓储、Settings/DPAPI 业务实现，不实现动作分发/UI/平台功能。需要接口变更时先提出，不能自行改签名。

## 3. 核心要求

1. **惰性与捕获**：方法/枚举器创建无业务 I/O；首次枚举检查取消、捕获请求及 ProviderIds，并在第一个 await 前捕获缓存 Generation。随后借用 Registry 快照；全部执行参数和 PreparedPrompt/Key 固定于该快照，不能等待并发名额后重新取模板。
2. **精确选择**：null/空集合/显式非空列表按规范区分；显式重复 ID 序数去重并保留首次顺序，不存在/禁用/未配置仍生成失败卡片。Descriptor 列表只读，事件归属固定为所选 ID。
3. **事件与隔离**：Started 唯一最先，单卡 Started→Delta*→一个终态，Finished 唯一最后；一个 Provider 失败不取消其它项。真实调用才占并发名额；缓存命中和本地失败无需等远程名额。
4. **流校验与资源**：最终 Chunk 的 Delta 不能丢；Usage 两个计数分别保留最后非 null 值；恰好一个 FinishReason，校验 EOF 并释放枚举器后才 Completed。异常/取消/提前结束都释放名额、枚举器与租约，不重复终态。
5. **预算与背压**：Channel=128/Wait；Delta 最大 4096 code unit；单 Provider 正文最多 1,048,576、本请求累计最多 4,194,304 code unit。追加前原子检查预算，超限为本地 InvalidResponse 失败，不把截掉的文本当正常结果。禁止无界旁路缓存队列。
6. **取消与收尾**：方法令牌/枚举令牌均生效。收尾点前取消或 break 取消并等待子任务，不写本次缓存/历史；所有生产者结束、事件正常读尽、最后取消检查通过才进入正常收尾。之后的迟到取消不撤回完成结果。
7. **副作用**：正常收尾时以原 Generation 尝试缓存新鲜完整成功结果；BypassCache 只跳过读。按 RecordHistory/快照 History.Enabled 保存成功项，按卡片顺序、保留 Truncated、含缓存命中。历史有独立 5 秒取消预算并等待真正退出；缓存/历史失败只安全记录，不改变翻译成功结果。
8. **错误**：请求级输入/选择错误首次枚举抛出；单项已知 IrisException 保留安全 ErrorInfo 并归一 ProviderId，未知异常用固定 Unknown。未发生请求取消的 OCE 只使该卡失败。不得记录原文/译文/Prompt/密钥或未知异常完整对象。

## 4. 必须验证的行为

### A. 输入、选择与冻结配置

- 创建序列/枚举器不访问 Registry、Provider、历史；空输入、超长、无可用项与非法请求在首次 MoveNextAsync 表现正确，无虚假的 Started/Finished。
- null 全量、空列表、显式全部缺失、混合有效/禁用/未配置、重复/大小写不同 ID 的顺序与卡片数；失败 ID 不调用 Provider 或缓存。
- 在请求首次枚举后的异步暂停点修改原 ProviderIds，不影响已捕获选择。
- 暂停 Registry 获取期间 Clear 缓存，之后成功结果仍携带旧 Generation，不能填回新代。
- 快照 A 获取后把全局设置改为 B；预处理、目标语言、并发度、模板和实际 Provider 请求仍用 A。验证 PreparedPrompt 与用于键的值一致，不能仅看最终译文。

### B. 多服务与事件

- 用有界门闩让多个 Provider 交错输出，断言每个 RequestId/ProviderId 归属、Started/终态顺序和最终计数，不依赖执行时的偶然顺序。
- 受控假 Provider 记录同时进入流的数量，证明上限确实生效；一个失败时其它继续。
- 缓存命中不调用 Provider，输出无 Delta 的 Completed；BypassCache 仍能更新缓存；缓存异常回退调用，缓存写失败不把成功变失败。
- 最终 Chunk 的 Delta、分散 Usage、Truncated、空流/空白结果/缺结束标志/重复终态/终态后数据等分支。
- 未知异常带假敏感值、IrisException 内部异常带假敏感值时，输出及日志不泄漏；异常里错误的 ProviderId 不串到另一卡片。
- 两次并发 TranslateAsync 的取消、队列、预算和结果彼此独立。

### C. 取消、资源与有界输出

- 仅取消枚举器令牌也会停止所有子任务；取消排队/读流/背压写入时不会留下挂起生产者。
- 消费者在 Started 后、部分 Delta 后、收到个别 Completed 后 break，均等待清理并释放租约，不写历史/新缓存。用清理门闩证明租约没有提前释放，而非只数 Dispose 次数。
- 超过 128 个可产生事件的慢消费者场景形成背压，不能无限积压；Delta 分片和正文预算边界精确，超限停止相应 Provider、其它项仍可在剩余预算内继续。
- 成功流完成并进入历史保存后再取消用户令牌，仍返回 Finished，不把已完成结果报告为取消；独立历史超时只记 Warning。用受控时钟/门闩，不等待真实 5 秒猜时序。
- 所有测试门闩有超时和 finally 放行/收尾，枚举器采用 await using，避免测试自身遗留任务。

### D. 真实组合验证

在 App.Tests 中用临时目录构建真实 Core + Infrastructure 服务集合，注册假 SecretStore/ProviderFactory（无 HTTP），通过真实 Settings 配置两个服务，初始化真实 SQLite：

2. 同样请求再次命中缓存，Provider 调用次数不增加，历史按已验收规则去重。
3. 单卡 BypassCache、RecordHistory=false 只调用指定项，不改变历史。

同时保留真实 AppHostBuilder ValidateOnBuild 检查和重复 AddIrisCore 单例测试。单位测试可用历史替身，生产组合根必须使用真实仓储。

## 2. 关键设计与交错机制

1. **受控交错与归属断言**：
   - 在 `TranslateAsync_LatchControlledInterleaving_MaintainsCorrectAttributionAndEventSequencing` 中，通过三组 `TaskCompletionSource`（`aStartedGate`、`bYieldedDeltaGate`、`aFinishGate`）控制 Provider A 与 Provider B 交叉产出 Delta：
     - Provider A 启动并发送信号后等待 B 产生第一个 Delta；
     - Provider B 收到信号后产出 Delta，通知 A 结束，并紧接着完成；
     - Provider A 收到放行信号后完成；
   - 断言两者的 `RequestId` 一致、各自事件的 `ProviderId` 与文本累积严格归属于对应的卡片，终态计数准确（Succeeded=2, Failed=0）。
2. **并发上限与信号量回收**：
   - 在 `TranslateAsync_ConcurrencyLimit_EnforcesMaxConcurrentProviders` 中，设置 `MaxConcurrentProviders = 2`，同时发起 4 个 Provider；
   - 每个 Provider 进入流时原子递增 `activeCount` 并通过 CAS 记录 `maxActive` 峰值；
   - 证明 `maxActive <= 2`，且其中一个 Provider 抛出网络异常退出后，其它 Provider 正常接替并发槽位完成翻译。
3. **缓存代次隔离与迟到写入拒绝**：
   - 在 `TranslateAsync_CacheClearDuringRegistryAcquisition_RejectsStaleGenerationWrite` 中，在编排器请求注册表快照的异步暂停点，外部执行 `cache.Clear()`（使得缓存 `Generation` 递增）；
   - 随后放行快照获取与执行，编排器以旧 Generation 尝试写入缓存，被 LRU 缓存原子拒绝；
   - 后续相同文本的再次请求证明 Provider 再次被调用（未读到过期代次的脏数据）。
4. **慢消费者背压控制**：
   - 在 `TranslateAsync_SlowConsumer_EnforcesBackpressureOnChannel` 中，Producer 产生 200 个分片，Channel 容量为 128；
   - 消费者读取前 2 个事件后故意延时 100ms，断言 Producer 在 Channel 填满后受阻于 `WriteAsync`，暂停点生成的事件数显著小于 200；
   - 随后消费者恢复全部消费，断言所有事件完整且最后产出 `TranslationFinished`。
5. **租约延迟释放与清理门闩**：
   - 在 `TranslateAsync_EarlyConsumerBreak_CancelsWorkersAndReleasesLease_DoesNotWriteHistoryOrCache` 中，消费者在收到首个 Delta 后主动 break；
   - Snapshot 的 `OnDispose` 回调挂接门闩检查 worker 是否已退出；
   - 证实工作任务真正完成清理后快照租约才被 Dispose，且未写入任何缓存和历史记录。
6. **历史独立超时预算**：
   - 在 `TranslateAsync_HistoryTimeout_CancelsHistoryTokenAfter5Seconds_AndLogsWarning_StillFinishes` 中，通过受控 `FakeTimeProvider` 推进 5 秒，触发历史保存的独立 5s CTS 超时；
   - 证明编排器捕获超时、记录 Warning，并依然向调用方输出合法的 `TranslationFinished`。
