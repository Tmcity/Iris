## 3. 必须实现的原语

- CaptureSnapshotAsync：稳定完整快照及 version，空剪贴板合法；支持格式/数量/字节预算严格按规范。借用 HGLOBAL 不释放，原始字节独立保存，不打开文件或解码/重编码内容。
- ReadVersionAsync：同一成功 Open 帧内取得 sequence、owner HWND/PID，不拼接跨时刻观察，0/回绕按相等性处理。
- TryClearAsync：在同一 Open 帧核对 expectedVersion，再最后检查取消和 Empty；不匹配 Changed 且零写入，成功返回清空后版本。
- TryRestoreAsync：先准备所有 GMEM_MOVEABLE 数据，Open 后同帧核对 expectedVersion 并提交；不匹配零 Empty/Set。成功 Set 的块交系统，未发布块仍归本服务，部分失败安全可见。
- StopAsync / RetryCleanupAsync / DisposeAsync：永久关闭准入，完整等待工作/消息循环/原生资源；清理失败保留同线程责任、禁止新业务操作并可重试。同步 Dispose 不阻塞或遗弃活跃资源。

结果与快照 ToString/日志不能输出内容、标题、文件列表或内容摘要。快照释放/借用关系必须防止排队恢复期间清零数据；不能给调用方可修改的缓冲。

## 2. 实施结果与范围

本次实现内部 ClipboardSnapshotService，提交基线为 `43fcf47a455063a483d563c01b78127653e321fa`。只增加 Platform.Windows/Clipboard 原生底座、窄适配器、NativeMethods/DI 接线及对应测试/helper。R6 的生产冻结仅适用于已完成历史工单；本次未改写既有 Win32ClipboardService、NativeClipboardAdapter、INativeClipboardAdapter、KeyboardSimulator 或 UiaSelectionReader。

- `ClipboardSnapshot.cs`：内部版本、状态/结果和快照；版本按 sequence/owner HWND/PID 完整相等比较，0 与回绕合法。ToString 只给类型/格式计数/状态。字节列表为服务自建的私有副本，无可修改缓冲返回；TryRestore 在排队前借用，调用方 Dispose 只标记释放，最后借用结束才清零数据。已释放/跨服务快照以 InvalidArgument 拒绝。
- `ClipboardSnapshotService.cs`：支持格式预检、完整有界原始字节捕获、版本与枚举复核、条件清空/恢复；准备全部 GMEM_MOVEABLE 块后才 Open/比较/Empty/Set。保留枚举顺序；借用句柄不 Free；成功 Set 立即移除本地所有权。部分 Set 失败返回安全异常，未发布块仍逐项清理，不宣称原子回滚。
- `ClipboardSnapshotService.Worker.cs`：单个惰性 MTA、可取消有界队列、message-only owner、原生帧同步执行。队列容量取内部常量 QueueCapacity；超载安全 ClipboardBusy，尚未出队的取消可立即移除并完成。Stop 入口永久关闭准入，取消回调在后台锁外执行；等待实际操作、清理、线程 Join、唤醒句柄释放及已接纳任务终态。并发 Stop 共享在途 Task，Retry/Dispose 共用原生清理尝试。同步 Dispose 对未 Join 的 worker 拒绝，不遗弃资源。
- `IClipboardSnapshotNative.cs` / `NativeClipboardSnapshotAdapter.cs`：复用既有基础原生适配器但不改变其实现；新增枚举/有界格式名、owner/PID、原始字节复制、PeekMessage/DispatchMessage 和 MsgWaitForMultipleObjectsEx 等外部边界。常规产品无桌面切换；可选初始化动作仅供独占 helper 在 worker 创建 HWND 前绑定该 helper 的自有桌面。
- DI 惰性注册；构造/解析不创建 HWND、线程或访问剪贴板。没有新增生产项目、包、公开 Core API、Handler/UI 或 C2 接线。

Open 仅执行最多 10 次总尝试，失败尝试之间以可取消等待间隔 30ms；等待发生在未 Open 时。单格式/总量/格式项上限分别使用规范的 33,554,432 / 67,108,864 / 64，复制前检查并使用 checked 算术。未知注册格式、GDI/私有等不支持格式先拒绝，不读取 payload；不解码文本/图像，不打开 HDROP 文件。

Close/Unlock/Free/Destroy 等失败逐阶段保留责任，成功阶段不重做；借用内存未解锁时保留原 Open 帧。清理失败阻断新业务，Retry 在原线程处理未完成阶段；Stop 后重试不重新开放准入。异常仅包含固定阶段及数值码，不保留 native 原始消息或异常链。提交前取消零写入；Empty 成功后继续全部 Set/Close/本地清理。读取在 Close 阶段遇 Stop 也撤销发布，已提交写入则报告实际 Applied。

## 3. 自动化证据范围

被测对象为实际 service/worker，fake 仅实现 IClipboardSnapshotNative 外部边界。它记录 native 调用线程/apartment、帧状态、内存借用/锁定/转移/释放，不实现产品队列、提交、停止或重试状态机。

实际断言涵盖：

- 构造与 DI 惰性、单 MTA/单线程原生访问及消息泵调用；全部支持格式的原始字节和顺序，快照副本不受原数据修改影响。
- 空快照、sequence 0/回绕、owner 改变、延迟呈现后序列/格式变化；不支持格式在 Get 前拒绝；数量与字节边界、零大小/无效 Get/锁定/复制/枚举/owner 查询故障。
- Open 后外部版本变化零 Empty/Set；恢复准备失败零写入；最后检查取消与 Empty 后取消的差异；部分 Set 后系统所有权不被 Free。
- Unlock 保留借用句柄与帧、Unlock/Free 复合失败、Close/Free/Destroy 复合失败继续其它清理，原线程 Retry 与永久停止；native 异常包含敏感正文和 inner chain 时安全脱敏。
- 初始化/实际 Get/Close/Set/Destroy entered 后的 Stop/取消/并发 Retry/Dispose；排队借用、及时排队取消、队列满拒绝；Stop 返回时任务已终态和线程已 Join。
- 正常 Stop 场景与 body 异常注入复用 BlockedLifecycle 实际执行段；finally 恢复所有故障并先放行门闩，再等待实际任务/Stop/Retry/Dispose。body 与 cleanup 注入错误均保留，worker 已收尾。没有依赖全局取消或固定 Delay 猜测 entered。

原生集成新增 helper 的 `--snapshots` 分支，仍通过原 IsolatedStationCoordinator 新建 CWF_CREATE_ONLY 非交互窗口站。其 coordinator 线程同步准备自有原始注册格式数据，service worker 在创建任何 HWND 前显式 SetThreadDesktop 到同一自有桌面；结束先等待 service Dispose/线程 Join，再由原 coordinator 恢复环境。测试父进程只启动自有 helper 并完整等待退出与 stdout/stderr；不存在退回 WinSta0、复用已有站或备份用户剪贴板后测试的路径。

本环境创建独占站返回 error=183，新增原生快照集成与既有原生剪贴板集成都如实跳过。因此上述真实 Win32 多格式往返、真实窗口消息处理与 worker 桌面绑定运行效果**未验证**；已编译对应路径，fake/service 验证与实际 helper 创建失败记录不能替代原生成功证据。
