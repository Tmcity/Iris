## 2. 在任何同步 work 前登记完整退出屏障（P1）

当前 _runningTask = RunLoopAsync(newWaiting) 先求值 RunLoopAsync，之后才赋值。work 的同步前半段重入 Drain 时 _runningTask 仍为 null，Drain 提前返回。同步完成路径还会在 finally 清空字段后又被赋回已完成 Task，HasActiveWork 永久为 true。只登记 _runningItem 不能证明完整退出任务已登记。

- 在锁内为将要运行的循环/批次登记稳定的完成屏障及身份，再在锁外执行任何 work 或 Cancel；Drain/关闭必须能观察“已准入但执行函数尚未返回 Task”的阶段。
- 同步完成、同步抛错、取消、重入 Enqueue/Drain、循环交接均正确完成屏障。旧循环退出只能清理自己的身份，不能将同时接纳的新循环状态清空。
- 保持一个实际运行加一个最新等待项，取消等待项完成返回 Task；观察实际工作与清理退出，不用单个早完成代理作整个队列退出证明。
- HasActiveWork 在同步成功/失败、异步结束及 Drain 后准确回到 false；并发调用准入与 Drain 期间也须真实反映活动。

正式回归至少包含：work 同步调用 Drain（只捕获其 Task，不在同一 work 内 await 造成自等），确认 work 未退出时 Drain 未完成，再放行 work；同步成功与同步异常后的空闲状态；已有重入峰值/取消回调/等待替换回归；旧循环收尾与新调用交接。所有闸门在 finally 放行。

   - 使得当外部工作在同步阶段重入 `DrainAndCancelAllAsync` / `DrainAndCancelInFlightAsync` 时，能够立即获取到未完成的 `loopTcs.Task`，严守 Drain 不提前退出的屏障；
2. **按循环身份安全清理**：
   - 在 `RunLoopAsync` 的 `finally` 块中，检查 `if (_currentLoopId == loopId)`，只有属于当前循环的实例才清空 `_runningItem` 与 `_runningTask`，随后调用 `loopTcs.TrySetResult()`；
   - 杜绝了同步完成路径被后置赋值覆盖的问题，使 `HasActiveWork` 在同步完成、同步异常或 Drain 退出后准确恢复为 `false`。
