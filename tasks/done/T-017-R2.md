## 2. R2-1：退出测试只清理自己拥有的资源

AppBootstrapperTests.StopAsync_RealClipboardTranslateHandlerAndPresenter_WithUncooperativeClipboard_HoldsHostStopUntilReleased 的 finally 当前：

- 在 stopTask 真正完成之前恢复 AppBootstrapper.AppShutdowner；晚到的退出会调用原始全局委托。
- 对 stopTask.WaitAsync(2 秒, TestContext 取消令牌) catch 后吞掉，不能证明任务退出；若测试令牌已取消，清理可能立即跳过。
- 调用 WpfTestRunner.CleanupWindowsAsync，内部遍历 Application.Current.Windows 关闭**所有**测试窗口。共享 STA 可交错运行多个测试，该操作可能关闭其它用例窗口；这是代码证明的风险，尚未将它冒充上述首次失败的已确证根因。
- 手工 BuildServiceProvider 的 provider 没有 Dispose；测试可在进入读取后、stopTask 尚未赋值时失败，仍应收回这份 presenter/读取资源。

修正为：finally 首先放行自身剪贴板闸门，发起/完整等待自身停止和 presenter/coordinator 在途工作，再释放自身容器/窗口；最后恢复全局委托。清理等待不能使用已经取消的测试令牌或吞掉超时后当作完成。移除该测试内全局 CleanupWindowsAsync 调用，不关闭别的测试资源；保留 WpfTestRunner 的程序集级最终清理。不要全局禁用并行、修改生产默认行为或放宽可见性/迟到隔离断言。

## 3. R2-2：旧回调测试的闸门必须连接实际被测任务

HotkeyCoordinatorTests.SettingsQueue_DelayedFaultCallback_DoesNotClearNewConsumersProcessingFlag 当前在 CustomInvoke 的第 2 次调用中建立 faultTask，同时启动一个仅 await delayCallback1 的独立 Task.Run，然后立即 await faultTask。delayCallback1 不控制返回给协调器的任务，也不控制 OnDispatchCompleted；释放它不会延迟/释放旧完成回调。该测试名称与注释不能作为代次保护证据。

替换为受控实际交错。例如：B 的 callback 已执行并交还消费者资格，但 IUiDispatcher 返回的 B Task 被测试闸门持有；C 已安排新代次且其 callback 尚未执行；令 B Task fault，使真实 OnDispatchCompleted(B) 晚到；再提交 D，确认不会多建消费者、不会丢失最新 D，最后放行 C 完成实际处理。记录/等待真实回调处理的接缝可保持内部且窄，不另写参考状态机。每个测试 Task 都必须被跟踪和 finally 收尾。

需要有对应的回归敏感性证据：临时移除 OnDispatchCompleted 的旧代次保护时，此测试应失败；恢复生产代码后通过。临时变异不得进入提交。取消 Task 同样保持已有回归覆盖。

同类 SettingsQueue_BackgroundSubmitWhenConsumerAboutToIdle_DoesNotLoseUpdate 实际将闸门放在 callback 执行前，不是消费者即将空闲；请如实调整名称/报告范围，或补实际空闲交接测试，不使用注释夸大覆盖。
