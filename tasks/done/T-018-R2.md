## 1. 实施内容与缺陷修复

本轮严格遵守工单范围，未改动公共签名，未修改 Provider、翻译、剪贴板和桌面服务：

### R2-1：关停等待全部实际操作与必要 VM 收尾
- **协调器统一准入与退出**：
  在 `GeneralSettingsSaveCoordinator` 中实现统一准入方法 `TryAdmitWork(CancellationToken)` 与退出管理 `ExitWork(tcs, preCommitCts)`，内部使用 `HashSet<Task> _inFlightWork` 跟踪所有进行中操作（包含等待 `_gate` 串行权排队的工作）。
  统一关停协议 `StopAcceptanceAndCancelPreCommit()` 标记 `_isStopped = true` 并原子取消所有 pre-commit CTS；`WaitForActiveWorkAsync()` 循环排干 `_inFlightWork` 并确认 `_gate` 释放，彻底消除了未生效的 `_workLock` 与单一 `_activeExecutionTask` 字段清空造成的遗漏。
- **ViewModel 工作生命周期管理**：
  在 `SettingsViewModel` 中引入 `_admissionLock`、`_activeWork`、`_isStopped` 以及 `StopAcceptance()` 和 `WaitForActiveWorkAsync()`。
  在 `ExecuteSaveAsync` 和 `ExecuteRetryAutoStartAsync` 中登记工作任务，并在 `finally` 块中严格按照**先设置 `IsSaving = false`，再从 `_activeWork` 移除并触发完成**的顺序执行，确保外部等待方观察到任务完成时，ViewModel 状态已经完全就绪。
  在 `OnPropertyChanged` 中加入 `if (_disposed) return;` 保护，杜绝释放后产生悬挂通知。
- **Session 完整关停链**：
  `SettingsWindowSession.ShutdownCoreAsync` 先依次调用 `_saveCoordinator.StopAcceptanceAndCancelPreCommit()` 与 `_viewModel.StopAcceptance()`，随后依次等待 `_saveCoordinator.WaitForActiveWorkAsync()` 与 `_viewModel.WaitForActiveWorkAsync()`，待所有底层保存/重试/查询及 UI 收尾完全结束后，再在 UI 线程执行 `_window.ForceClose = true; _window.Close();` 并销毁 scope。
  `CloseAndCleanupCore` 中移除了 `_window.IsVisible` 的不必要分支判断，确保任何状态下的窗口都能无条件关闭与清理。

### R2-2：开机自启状态查询移出 UI 线程
- `GeneralSettingsSaveCoordinator` 新增异步查询 `QueryAutoStartPendingAsync(CancellationToken)`，内部通过 `Task.Run` 在后台线程池执行 `IAutoStartService.IsEnabled()` 并与配置对比，保留平台同步契约的同时杜绝阻塞 UI。
- `SettingsViewModel` 构造函数不再同步调用 `IsEnabled()`，初始状态设为 `false`，通过后台异步任务 `_ = QueryAutoStartStatusAsync()` 执行查询；`ExecuteReload()` 与 `ExecuteSaveAsync()` 同样通过异步查询更新状态，使用代际计数器 `_queryGeneration` 防范迟到结果覆盖最新状态，`on-ui` 降至 0。

### R2-3：Show 中途失败回滚已创建原生资源
- `SettingsWindowPresenter.ShowAsync` 在调用 `window.Show()` 发生异常时（包括 `SourceInitialized` 注入失败、导航失败等），在 `catch` 块中显式设置 `window.ForceClose = true; window.Close();` 彻底销毁原生 HWND 并从 `Application.Current.Windows` 移除，同时 Dispose 会话与 scope，避免产生残留窗口或 HWND 泄漏。

### R2-4：主题失败诊断安全脱敏
- `ThemeService.LogThemeApplyFailed` 的 `[LoggerMessage]` 签名移除 `Exception` 参数，改为仅记录主题名称与异常类型全名（如 `"Dark"` 与 `"System.InvalidOperationException"`），杜绝将原始 `Exception`、Message 或 Data 传递给日志接收器；假敏感标记 `fake-theme-private-marker` 不再通过异常链泄露。
