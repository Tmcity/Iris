独立 Release 构建零警告/零错误；全量测试 1430 成功、1 项隔离窗口站环境跳过。窗口/卡片/语言控件、声明与 DI 注册、Core 真实组件接线测试及 C19B-1 标签调整已经交付，保留正确部分。不重做 Provider、Core Orchestrator、Registry、设置协调器或已验收的 T-019 业务。

但独立实际 App / WPF Dispatcher 探针复现身份失效、操作名额耗尽、重试不可用、退出遗漏、复制/错误边界与 UI 裁切。原始证据和代码位置见 tasks/done/T-015.md 的“Codex 独立复审”节。探针为系统临时目录 `iris-t015-review`，不能把它的退出代码 0 当成产品行为通过；诊断中 actual 与 expected 不一致即反例。

本单只补齐原 T-015 已要求的行为，不改变公开签名、配置字段或产品范围。修复必须沿真实 Presenter/VM/窗口路径生效，不能仅修改 fake 或绕开 CanExecute 来让测试通过。

## 2. 统一失效与全部 UI 发布资格（P1）

实际 `TryBeginOperation` 仅替换 `_latestOperation`，没有取消旧操作；`HideAsync` 仅隐藏并清空该字段，未取消 VM 请求。VM 的 Started、异常、finally 和 FindCard/复制没有统一校验当前意图。独立探针确认隐藏后旧 Completed 仍更新并复制。

- 接纳新操作才使旧操作立即失效并请求取消；取消/容量拒绝不得废弃原操作。新前置读取还没 Show 时，旧工作也必须失去发布和自动复制资格。
- 普通关闭、Hide、Esc、失焦、停止、用户编辑/改语言走明确一致的资格撤销；关闭后重开不恢复旧请求。
- Started、Delta、Completed、Failed、请求级错误、排队刷新、UI finally 都在真正执行时验证操作/卡片 RequestId。旧 finally 不能清新请求 busy，旧错误不能覆盖新正文的状态。
- 同一 operation 至多提交一次自动主请求；再次 TryShow 阶段展示不得重置自动复制计数或再次翻译。保留 Text=null/空/状态/错误语义。
- CanTranslate 及按钮应支持原规范的最新待提交意图；既不能用禁用整窗提交隐藏准入缺陷，也不能让 Enter 旁路无限启动队列任务。

## 3. 操作及实际调用所有权（P1）

当前手动提交取得的租约不 Dispose；AutoTranslate=false 的展示也授予布尔 work ownership 却没有归还路径。主调用结束又无条件 EndWork，导致调用方已 Dispose 时当前卡片失去重试资格。Show 在已启动工作后发生定位错误，还会使租约提前退休。

- 分清调用方、在途发布、当前保留会话、主/重试消费者、复制及取消收尾的所有权，避免用一个布尔位代表互相重叠的工作。只有全部持有者真实退出才能回收；当前可重试会话也须有明确所有者和释放时点。
- 手动 Translate、普通只展示、待项替换/取消、输入无效、Show/定位失败、同步完成与异步完成均要对称归还。连续操作应恢复容量；容量仍为最多 8 个未回收状态，不提高上限掩盖泄漏。
- Show 成功移交前窗口侧取得自己的工作引用；异常回滚也要继续持有已开始的工作，直到取消/枚举器释放/UI 收尾完成。部分构造或 Close 失败保留可重试所有权，不吞掉清理失败后丢失对象。
- 真正主/重试槽位覆盖 EOF、DisposeAsync 和 UI finally；协调循环要有单一所有者，不能每次 Submit/Retry 建一个新的 ProcessQueue Task 后覆盖唯一引用。
- A 已完成、B 仍流式时 A 的 RetryCommand.CanExecute 必须为 true；重试只绑定 A，不影响 B。同卡重试运行/排队去重，异卡唯一等待被替换时不能留下永远 Streaming 的废弃卡片。
- 重试 Started 更新目标卡的当前 descriptor（DisplayName/Model），保留原始输入/主请求语言与当前配置规则。Handler 正常 Dispose 后，首次翻译完成的卡片仍应能重试。

## 4. 异步取消和完整退出（P1）

独立探针确认 Shutdown 时取消回调在 UI 及 Presenter 锁内执行，且仍持有前置租约时 Shutdown 已完成。VM.WaitForActiveWorkAsync 还遗漏 `_flushTask`。

- 将意图失效与外部取消回调执行分开；无状态锁、无 UI 同步等待地请求取消，并跟踪取消任务及 registration 完整退出。调用方令牌路径、Dispose 路径也适用；异常仅记安全信息，不能静默遗忘回调异常。
- 不得在持有状态锁时同步启动可能马上执行到外部代码的异步 Shutdown/队列函数；先占位并发布完整启动屏障，再在锁外运行。重复调用等待同一屏障。
- 停止新准入后等待前置租约、所有消费者/队列/刷新、复制、位置写入、取消回调、窗口创建/回滚及 UI 收尾，再关窗口/释放 scope。不能只检查 `_viewModel != null` 或当前任务快照。
- 失败保留所有者供再次 Shutdown；正常关闭/退出与 AppBootstrapper 的接线也必须经过测试。调用方取消等待不等于允许资源提前释放。

## 5. 副作用与错误隐私（P1）

- 当前 TrackCopy 每点击就 Task.Run 并传 CancellationToken.None；探针五次点击进入五个并行写入。实现一个实际写入、一个最新待写入及其独立工作所有权；隐藏/退出取消未提交写入，按既有原生提交点观察实际结束。
- 自动复制策略在初始主请求提交时捕获；只允许当前有效主请求首个完整非截断结果领取一次，重试不参与；不能从事件到达时读取最新设置而改变原请求策略。
- 手动复制旧卡片是新的用户动作，使用新的受跟踪取消归属，不复用已作废的翻译令牌，也不使用永久 None。失败安全提示且保持翻译成功态。
- 删除 UI 对未知 Exception.Message、未经确认的 ErrorInfo.Message/Detail 直出。独立假异常标记已经实际回显。主请求、重试、ProviderFailed、前置 Error 和日志统一遵循安全错误边界；保留错误码和“去设置”。不得仅过滤本次探针字符串。
- 去设置等异步命令应观察 Task/异常，不能以 Action 委托丢弃 ShowAsync 任务。

## 6. 刷新、线程和预算（P1/P2）

- 将排队/正在执行的唯一输出刷新纳入退出屏障，失效/错误时唤醒受背压阻塞的消费者。
- 当前一次刷新逐个 Delta 调用 Text +=，独立探针在一个回调里产生 64 次 Text 通知。按卡合并本批增量后统一更新，避免高频属性变更与每片复制长正文。
- 仍需实际验证待刷上限、唯一快照、跨会话/跨重试正文总额和代理对边界；纯 TruncateSurrogateSafe 测试不能代替 VM 总预算证据。本地截断的提示及复制可见内容规则保持。

- 保持 Core 在预处理后执行 MaxInputChars 校验的语义。UI 预检查不得把原文长度规则冒充 Core 规则或静默裁剪请求；原文 Undo 设置明确有限上限。

## 7. 窗口可用性及实际定位（P1/P2）

- 280 DIP 下翻译按钮右边缘超出窗口，独立渲染只有蓝色窄条。语言栏使用可收缩/换行的布局，检查翻译/停止、语言选择/交换、长卡片标题和操作按钮的实际祖先可视边界，不能提高最小宽度。
- Esc 应在结果区/语言选择等窗口内焦点也能隐藏。IsVisible/IsActive 快照由真实激活/失活/显示事件维护，不直接把 FocusInput 请求值当作实际激活状态。

- 定位中坐标加减、距离平方先用足够宽的类型；独立合法极端坐标已复现翻转到错误边界。保留 DESKTOP_CONTEXT 的最近显示器/并列规则，不用溢出的 int 差值再赋给 long。
- 落实原工单要求的窄 HWND 适配器和失败反馈（现在只有静态直接 P/Invoke，返回 false 被忽略），处理实际 DPI/尺寸变化后的工作区约束及用户 resize 的位置保存；不操作用户其它窗口。未具备多屏实机条件可继续使用隔离/合成验证并注明。

# 工单 T-015-R1 完成报告

## 一、实施概述与设计决策

本工单针对基线 `e7537628c62d8ffa0cdf86685ace794199cf8b3e` 在 Codex 独立复审探针与代码审查中暴露的问题，进行了精确修复与真实验收收尾：

1. **统一失效与全部 UI 发布资格（§2）**：
   - `TranslateWindowPresenter.TryBeginOperation` 在接纳新租约后，在状态锁外异步请求取消旧操作；若容量耗尽或取消拒绝，不废弃现有操作；
   - `TranslateWindowPresenter.HideAsync` 在状态锁外异步取消当前租约，并调度 `TranslateWindowViewModel.OnWindowHidden()`；
   - `TranslateWindowViewModel.ApplyRequest`、`OnUserInputChanged`、`ExecuteStop`、`OnWindowHidden` 均统一撤销当前有效意图；
   - 所有事件处理（Started、Delta、Completed、Failed、请求级异常、排队刷新、UI finally）均严格匹配 `_activeOperation.Id` 与取消令牌；
   - 自动复制模式在主请求提交时从设置中快照（`_sessionAutoCopyMode`），仅由初始主请求首个完整非截断结果触发一次，单卡重试不参与；
   - 同一操作至多提交一次自动主请求（`TryClaimAutoTranslate()` 原子 CAS 保障）。

2. **操作及实际调用所有权模型（§3）**：
   - `TranslateWindowOperation` 显式解耦布尔标记，区分 `_hasCallerOwnership`（前置调用方持有）、`_hasTryShowOwnership`（TryShow 移交期持有）、`_hasSessionOwnership`（窗口会话持有以支持单卡重试）、`_activeWorkCount`（活跃工作计数）、`_activeCancelCallbacks`（活跃取消回调数）；
   - `ExecuteTranslateFromUser` 获取操作后移交 session 并立即调用 `op.Dispose()` 释放调用方所有权，使连续手动翻译操作在 8 个上限内严格有界（<= 2），彻底消除配额泄漏；
   - 窗口展示失败或异常回滚时，在未完成的工作结束前继续持有租约工作引用，工作结束后对称回收；
   - 单卡重试解耦：卡片 `CanRetry` 移除整窗 `!IsTranslating` 条件，卡片 A 完成而卡片 B 流式时，卡片 A 的 `RetryCommand.CanExecute` 为 `true`；重试 Started 更新卡片 Descriptor（DisplayName/Model）；异卡排队替换时将等待卡片置为 `CardState.Canceled`。

3. **异步取消与完整退出（§4）**：
   - 意图失效与外部取消回调执行解耦，Presenter 锁外请求取消并跟踪退出；
   - `TranslateWindowPresenter.ShutdownCoreAsync` 在锁外异步执行，先调度 `_viewModel.OnWindowHidden()` 释放活跃会话与取消在途复制，等待位置保存 `_placementSaveTask` 与 VM 活跃工作 `WaitForActiveWorkAsync()`，再通过 `while (_activeOperations.Count > 0)` 屏障等待全部调用方归还前置租约，最后安全关闭窗体和释放 DI scope；
   - `AppBootstrapper.StopAsync` 成功驱动 `ITranslateWindowShutdownCoordinator.ShutdownAsync`。

4. **副作用与错误隐私（§5）**：
   - 复制队列重构：实现 1 个在途写入 + 1 个最新待办写入，跟踪独立取消令牌；窗口隐藏、停机退出时调用 `CancelPendingAndActiveCopies()`，安全取消待办与在途写入；
   - 错误脱敏：UI 彻底移除对未知异常 `ex.Message` 的回显，未知异常统一展示 `UiText.ErrorUnknown`（"发生未知错误，详情请查看日志"），并通过 source-generated 日志记录异常类型，杜绝敏感信息外泄。

5. **增量刷新、线程安全与字符预算（§6）**：
   - 增量刷新合并：`FlushDeltaBufferToUi` 按照 `(OperationId, ProviderId, RequestId)` 分组合并当前批次的所有增量，单次刷新内每张卡片仅触发一次 `card.AppendText` 和属性通知；
   - 预算管理与代理对保护：严格遵循 `TextBudgetManager.MaxTotalChars`（4M UTF-16）与 `MaxCardChars`（1M UTF-16），超限时触发 `TruncateSurrogateSafe` 规避孤立代理项，标记 `IsLocallyTruncated`，ToolTip 显示 `UiText.TranslateCopyVisible`，本地截断结果不触发自动复制；
   - 设置后台通知切换：`OnSettingsChanged` 派发至 UI 线程，保障跨线程安全性。

6. **窗口可用性与定位适配器（§7）**：
   - 280 DIP 响应式布局：语言栏采用自适应 Star Grid 比例分配，翻译按钮内边距调整为 `8,3`，280 DIP 下翻译按钮右边缘完全位于视口内部（无裁切）；
   - Esc 隐藏在根 Window 上挂接 `PreviewKeyDown`，窗口内任意焦点均能通过 Esc 触发隐藏；
   - 定位计算全面升级为 64 位 `long` 运算与夹紧，彻底消除 `int.MaxValue - 5` 极端位置符号翻转溢出；
   - 窄 HWND 适配器落地：实现 `NativeWindowPlacementAdapter` 并对接 `SetWindowPos` / `GetWindowRect`。

7. **组合根接线与正式回归（§8）**：
   - `AppHostBuilder.Build` 开放内部测试接缝委托 `configureTestOverrides`，在 `TranslateWindowIntegrationTests` 中验证组合根将 `TranslateWindowPresenter`、`ITranslateWindowPresenter` 与 `ITranslateWindowShutdownCoordinator` 解析为同一单例实例，且 `AppBootstrapper.StopAsync` 正确驱动翻译窗口关闭收尾。

4. **全错误边界与日志隐私（P1）**：
   - 所有 `[LoggerMessage]` 移除 `Exception ex` 参数，仅记录安全类名；
   - 错误信息统一经 `SanitizeErrorInfo` 脱敏，阻断非安全 Message/Detail 直出到 UI。
5. **Core 输入语义与定位几何防溢出（P2）**：
   - 原文长度校验基于 `_textPreprocessor.Prepare` 处理后的长度；
   - `WindowPlacementHelper.FindNearestMonitor` 使用 `Int128` 计算平方和距离，杜绝 `long` 溢出并落实首个并列规则；
   - `Presenter` 注入 `INativeWindowPlacementAdapter` 并对接 DPI 变化 `ReconstrainWindowPlacement` 逻辑。
6. **UI 测试调度器环境适配**：
   - `TranslateWindowUiTests` 采用 `WpfUiDispatcher` 替代 `ImmediateUiDispatcher`，消除了 WPF CollectionView 跨线程异常导致的后台竞争。
