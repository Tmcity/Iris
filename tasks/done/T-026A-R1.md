## 2. R1-01：有效发布须在第一个原生显示副作用前撤销准备

目前 TranslateWindowPresenter.TryShowAsync 先调用 ApplyPlacement，再 AdvanceLocked(showing:true)。已有 HWND 的 ApplyPlacement 会以 show:true 调用 SetWindowBounds；同 operation 再次有效 TryShow 时，在这个 native 边界 lease.Reason 仍是 None。实际输出：

```text
NATIVE_SHOW entered=True invalidatedBeforeShowFlag=False newerWindowVisible=True
```

把有效展示意图的接纳/锁外通知放在任何可能使窗口可见或激活的原生调用之前，并保持真实 UI 接受点及身份重验。不能只在最后 Window.Show 前通知，不能让过期/外来/已取消 operation 撤销有效截图，也不能在 owner 锁内调用订阅者或同步等截图归还。保留原 TryShow 发布身份、异常清理与较新展示保护。

回归至少使用实际 Presenter、已有但临时隐藏的窗口、同一个仍有效 operation；在 fake placement 的 show:true/activate 边界检查准备已撤销，并验证新展示最终可见。保留排队 Show、过期发布不撤销和新 operation 对照。

## 3. R1-02：旧恢复不得覆盖最后一次 Hide

目前 WindowPreparationIntent.Receipt.HasNewShow 只比较历史 _showVersion > receiptVersion；即使这个 Show 后又发生更晚的普通 Hide，仍被视为应保留的新 Show。独立探针在恢复的可见性边界同步执行实际 TryShow、再执行实际 Hide，然后才继续旧恢复的 Show：

```text
RESTORE_SHOW_THEN_HIDE entered=True newerShowAccepted=True hiddenBeforeOldShow=True finalVisible=True
```

修正可见性所有权/最新意图判定，让旧恢复不能复活最后已要求隐藏的窗口。不能改成无条件 Hide 所有较新展示；只有新的有效 Show 而没有后续隐藏时，该展示必须继续保留。涵盖正常恢复及已有 _undoRestore 的失败重试路径，保持新 session/关闭/Stop 不复活、ShowActivated 可靠还原、失败责任保留。

回归用 actual owner + 自有 Window，在 fake 可见性调用内部精确安排并确认 Show/Hide 已实际接受，检查真实 IsVisible。至少包括 Show→Hide（最终隐藏）、Hide→Show/仅 Show（保留较新显示）、撤销 Hide 失败后重试期间再次出现更新意图。不要仅断言方法调用次数或在未确认 UI 接受的后台任务上猜时序。

## 4. R1-03：关闭未完成的可见设置窗口不能被当作不存在

SettingsWindowPresenter.ObservePreparation 把 CurrentCleanupTask != null 视为 alive=false；Receipt.HideAsync 因此静默跳过仍可见的窗口，Prepare(true) 却能成功。独立探针用自有设置窗口的 Closing 拒绝完成关闭，等待真实 session.ShutdownAsync 失败后开始准备：

```text
FAILED_CLOSE_OWNER prepareSucceeded=True contentStillVisible=True
```

区分“没有需要隐藏的窗口”“有仍可见但不允许恢复/正在关闭的窗口”。hide=true 准备只有在应隐藏内容实际不可见时才可成功。对关闭进行中或失败的实际 session，可完整等待其关闭责任，或返回安全 CaptureFailed 并保留其原有可操作清理/重试；不能静默略过后报成功。不得靠清空 CurrentCleanupTask、重建 session/丢草稿、强行关闭借用窗口、泛化 alive=true 后在关闭期恢复旧窗口解决。保持 hide=false 的语义与不存在窗口的零创建路径。

回归覆盖实际 session 关闭失败和关闭仍被门闩阻塞两种情况；准备结果不得在内容仍可见时成功，清理完成后可继续，退出/关闭中不恢复窗口。finally 先撤销 Closing 注入/放行门闩，再完整等原 session 与准备的所有工作，保留主/清理错误。
