## 1. 目标与边界

实现 GdiScreenCapturer/IScreenCapturer：按真实物理显示器捕获原始虚拟桌面帧，按交集 CropAsync 成 PNG/JPEG/BMP，拥有线程/句柄/编码资源的完整失败重试和 App 退出。不是 UI 工单：不做 T-026 覆盖层/窗口隐藏恢复、OCR/预处理/Handler/托盘菜单/热键、设置页，不启动真实 Iris，不截取用户桌面。

先完整阅读 SCREEN_CAPTURE.md；它明确数据预算、单操作准入、同线程资源协议、异步终结和错误分类，不能以旧 ARCH 抓图草图覆盖新规范。只落地 CCR-023 已预置声明，其它公开契约、默认设置/JSON/包不变；保存已有成果，不重写 DesktopContext/MonitorEnumerator、剪贴板/UIA/鼠标/键盘/翻译。

## 2. 实施清单

1. 同步 Core CropAsync 声明与 CapturedFrame 注释/安全摘要；公开记录字段和 Capture 签名保持。实现实际 platform service、低层 native adapter、按需 worker 与内存编码边界；DI 注册同一实例，未使用时零线程/零 native 查询。
2. 使用 top-down 32bpp CreateDIBSection + 分显示器 BitBlt + GdiFlush + managed copy，不混用选入DC的 GetDIBits。正确负坐标/空洞/opaque alpha、快照比较和最多一次拓扑变化重试；数据预算必须在分配/原生调用前校验。
3. GetDC/ReleaseDC 同线程，维护 selected object/bitmap/DC/DPI 的真实责任。主/清理错误合并，失败资源留在原 worker 可重试；不得错误删除仍选中的 bitmap。取消/Stop 完整等 native 退出，最终确认线程停止；忙时不排队。
4. CropAsync 按 stride 与 long 半开交集复制，在后台调用真实 WinRT 内存三格式 encoder；PNG/BMP 无损，JPEG 0.9；所有异步 create/flush/read 真结束后才处置输入/流，不用 callerToken 表面取消越过清理。保持预算、完整短读检查与输出独立性。
5. AppBootstrapper 退出最先关闭截图准入，完整等捕获/编码/失败资源；错误阻止Host/Dispatcher错误终结，可同实例重试。与现有独立鼠标/选区收尾并存，不改其它业务语义。

## 5. 开发实施报告（2026-10-05，请求复审）

以上为签发工单全文。实施基线 3a8450e724e6a4bebcb0fd8d20e1a93371e8c237；本报告不代表架构师独立验收或 T-025 结案。

Core 仅同步 CCR-023：CropAsync、CapturedFrame 安全摘要/注释，原 Capture 签名及 Frame 字段/构造/解构保持。Platform 新增 GdiScreenCapturer、GdiCaptureWorker/Session、NativeGdiCaptureAdapter/Win32GdiCaptureApi、像素布局/预算校验、ScreenMemoryEncoder/WinRT I/O 边界；注册 IScreenCapturer 与同一具体单例。构造和未使用的 Stop/Dispose 零 native、零 worker；单独 Crop 不创建 GDI worker。

Capture 在专用后台线程临时进入 PerMonitorV2，复用 IDesktopContext.GetMonitors 的独立快照。验证 union/预算后创建 DC 和 top-down 32bpp DIB；GdiFlush 后清零 bits，按每块显示器的物理 offset 做 SRCCOPY|CAPTUREBLT，再次 Flush 后复制，所有 alpha 规范为255，空洞黑色。采样前后比较全部拓扑元数据且不依赖枚举顺序；变化只在完整清理后最多重试一次。

每个 GDI session 记录真实句柄、selection 和原 DPI context。同一线程恢复选择、删除 bitmap/memory DC、ReleaseDC、恢复 DPI；selection 恢复失败时允许先成功 DeleteDC 再 DeleteObject，不删除仍选中的 bitmap。失败也尽量完成独立安全清理，只撤销已成功释放的责任；遗留 session 留在原 worker，下一有效请求或 Retry/Stop 先重试旧责任。仅 CreateDIBSection/BitBlt 明示失败读取 LastError，其余使用固定阶段/返回值/HRESULT，保留主与全部清理错误。

Crop 按 long 半开交集和实际 stride 逐行复制到独立紧密 BGRA，输出不透明 alpha；所有大复制与编码在后台。使用真实 WinRT BitmapEncoder/InMemoryRandomAccessStream，PNG/BMP 无损，JPEG 显式0.9f，Bgra8/Ignore/96 DPI；Create/Flush/Read 均不使用 callerToken 提前脱离。先验 stream.Size 编码预算再分配输出，短读报错。reader/stream 分别记账，清理失败保留实际 session 和输入 buffer，可同实例重试。

Capture/Crop 共用单请求准入，忙时立即 CaptureFailed，不排队。取消/Stop 只撤销发布资格，已发出的 native/codec 操作和清理完整等待。公开任务完成之后才开放空闲槽和 drain 屏障，屏障不持有帧结果；worker 清空已执行命令对结果/委托的引用，避免空闲时缓存最后一帧。Stop 等实际线程退出信号并 Join 后才完成；同步 Dispose 不掩盖未停止工作。

AppBootstrapper 最先关闭截图准入，完整等待 GDI/编码收尾；即使截图清理失败仍执行原鼠标/选区独立清理，保留安全错误并阻止 Presenter/Host/Dispatcher 成功终结，支持原实例重试。未实现覆盖层、隐藏恢复、OCR/预处理、Handler、菜单/热键或新设置。
