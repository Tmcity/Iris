## 2. R5-1：Show 失败且清理失败时仍保留会话

反例：窗口 SourceInitialized 抛错；回滚 Close 又被 Closing 取消。当前 catch 虽 await 清理，但清理异常仅记日志，随后无条件将 _activeSession 置 null。结果 HWND 仍存活、scope 未释放，后续 Shutdown 却返回成功。

- 仅在本次会话已确认清理完成后解除其所有权；回滚失败仍由 Presenter 保留可重试的清理入口，不能只留下一个局部引用或日志。
- 后续 Shutdown 必须实际等待/重试该会话，并向调用方传递仍存在的关闭失败。新 Show 不得覆盖它或创建第二个不受管理的会话。
- Show 的原始失败与次要清理失败都应安全观察；不泄露异常原文/链，不把“已记日志”等同“资源已清理”。
- 检查尚未组装 Session 的局部回滚分支，沿用同一原则，不能吞 Close/等待失败后直接 Dispose 活跃资源。

正式回归同时注入 Show 失败 + Close 取消，断言 Presenter 保留会话、HWND/scope 存活、Shutdown 不能成功；移除故障后，同一会话可关闭且释放一次，所有权解除后才允许下一次创建。必须调用实际 Presenter/Session。

## 3. R5-2：ActiveSession 为空不代表没有已接纳的创建工作

反例：从后台发起 ShowAsync；真实 UI 窗口工厂已开始创建并持有 scope，但尚未发布 _activeSession。另一线程 ShutdownAsync 命中 active=null 分支直接返回成功，此时创建仍进行。

- Shutdown 的准入/等待基于完整的已接纳工作，不以 ActiveSession 是否为空作为唯一判断。即使当前没有已发布会话，也必须等待已登记的 _openTask 及其失败回滚真正退出。
- 关停先关闭新创建准入，再观察已有创建流程和它最终持有的资源；不能在根依赖可被销毁之后才完成窗口工厂/VM 构造/回滚。
- 保留共享创建任务与关停期间不再发布新窗口的行为，避免自等待或 UI 线程同步阻塞。完成标记要在实际流程退出后可观察，不只挪动字段赋值。

正式回归从后台调用既有“任意线程”展示端口，在真实 UI 工厂挂起，另一线程请求 Shutdown：放行前 shutdown 不完成且 scope 存活；放行后原 Show 的取消/失败及完整回滚都被观察，才报告关闭完成。再覆盖创建尚在 Dispatcher 队列中、尚未创建 Window 的情况。使用门闩并在 finally 全部放行，不使用任意睡眠建立顺序。

## 4. R5-3：并发 StopAsync 等待完整 Host 退出

当前 AppBootstrapper 在设置清理结束后就置 _stopped=1，后面仍要 StopSynchronousParts、await Host.StopAsync 和 AppShutdowner。后续 StopAsync 先检查 _stopped，直接返回 CompletedTask，绕过进行中的 _stopTask。

- 进行中的退出任务必须优先共享；“已接纳退出/开始清理”与“完整退出已完成”不能混用一个标志。
- Host.StopAsync 尚未结束时，所有并发调用仍未完成，AppShutdowner 未执行；结束后共同观察最终结果。保留 R4 设置清理失败时不销毁依赖、可重试的行为。
- 不扩展其它 Host 失败策略，不修改强制系统注销语义。仅修正常退出的完成信号与相应测试。

正式回归挂起 fake Host.StopAsync，再调用第二次 StopAsync，断言两次都 pending 并共享本轮任务/结果；放行后确认 Host 退出及应用退出委托执行一次。测试替换退出委托，不结束真实应用，并在 finally 恢复全局测试替身。
