## 1. 一次交付的完整目标

实现可工作的 UIA 选区读取路径：Platform 内部 UiaSelectionReader 父端、真实 COM 读取 worker、极小 Iris.UiaHost 隔离宿主、有界 IPC、超时/取消/退出与发布部署。完整阅读 UIA_SELECTION_READING.md，并按全部条款实施。

T-022A 已交付桌面上下文；T-022 总单现在拆 B（本单 UIA）与 C（后续剪贴板事务/组合）。本单不接剪贴板/KeyboardSimulator、不实现 SelectionTranslateHandler/划词设置页、不注册残缺的公开 ISelectionTextReader。B 通过不代表 T-022 总单或划词功能完成。

## 2. 已批准的结构与约束

1. 新增 src/Iris.UiaHost，TFM 与 Platform Windows 一致，Console/MTA、无 WPF/WinForms，只引用 Core/Platform；使用现有 CsWin32 COM 生成，不增加 NuGet 包。Platform 继续只引用 Core。
2. App 仅用 ReferenceOutputAssembly=false 构建/部署宿主，产物固定在 uia/ 子目录。更新 solution 与架构测试的准确依赖/包覆盖；禁止把新项目随意加入 unrestricted 白名单。
3. 所有新 API、目标/结果和 IPC 类型保持 internal；公开 Core 契约、默认设置和 JSON schema 零改动。可增加必要 InternalsVisibleTo 给宿主和既有测试项目。
4. 构造/Host.Build/DI/页打开不启动子进程或 UIA；一次只拥有一个启动/读取/清理上下文。Stop 永久撤销准入且真实等待进程/流退出，失败保留可重试，不重用成功屏障掩盖新工作。

## 3. 必须实现的行为

- 固定可执行路径、隐藏启动、重定向流，Ready 1500ms、请求响应 300ms、响应后退出宽限 1000ms；协议版本/RequestId/帧大小有界，超时不等于物理退出，Kill 后必须等本次自有进程退出。
- 取消初始化也保有实际启动任务与迟到 Process，不能丢所有者；不得按名称/PID 枚举杀进程或终止源应用。
- worker 在同一无窗口 MTA 初始化/使用/释放 UIA；验证前台/来源、IsPassword、TextPattern2/1、SupportedTextSelection 和 GetSelection；只读选中 ranges，caret/空白为空结果，不使用全文章或 Name/Value 代替。
- 最多 32 ranges、总计 65,536 UTF-16 code units，GetText 以剩余+1 有界读取，超限返回 TooLong；来源变化丢弃文本，Sensitive 不暴露文本。
- 父端成功只在结果身份仍有效、child/pipe 真正收尾后发布；迟到/坏帧/取消不回写新请求，错误不包含选区、窗口标题、原始异常或协议正文。

## 4. 交付与实现总结

### 4.1 新增模块与工程结构
- **CsWin32 声明补全**：在 `src/Iris.Platform.Windows/NativeMethods.txt` 中引入 `IUIAutomation`, `IUIAutomation2`, `CUIAutomation`, `CUIAutomation8`, `IUIAutomationElement`, `IUIAutomationTextPattern`, `IUIAutomationTextPattern2`, `IUIAutomationTextRange`, `IUIAutomationTextRangeArray`, `IUIAutomationTreeWalker`, `CoCreateInstance`, `CLSCTX`, `UIA_PATTERN_ID`, `UIA_PROPERTY_ID`, `SupportedTextSelection`, `IsChild`。
- **src/Iris.UiaHost**：独立 MTA 控制台宿主程序（`net10.0-windows10.0.19041.0`），无 WPF/WinForms，仅引用 Core 与 Platform.Windows，不增加新 NuGet 依赖。
- **App 部署与打包目标**：`src/Iris.App/Iris.App.csproj` 以 `ReferenceOutputAssembly="false"` 引用 `Iris.UiaHost`，并在 Build 和 Publish 后自动将宿主输出完整拷贝至 `$(TargetDir)uia` 与 `$(PublishDir)uia`。
- **架构规则与测试更新**：更新 `tests/Iris.ArchitectureTests/DependencyRulesTests.cs`（准确约束 UiaHost 依赖方向、二进制引用限制与禁用桌面框架规则）和 `PackageRulesTests.cs`（`AllowedPackages["Iris.UiaHost"]` 显式空白名单）。
- **Platform internal UIA 组件**：
  - `UiaSelectionStatus`、`UiaSelectionResult`：内部只读结果模型，非成功状态下绝对不携带文本，`ToString()` 绝不打印选区正文与窗口标题。
  - `UiaProtocol`：JSON 有界编解码器（1MB 帧上限）及流读取器（支持 Windows 匿名管道关闭与 UTF-8 BOM 过滤）。
  - `ITargetWindowValidator` / `RealTargetWindowValidator`：前台窗口有效性及所属进程核验。
  - `INativeUiaAdapter` / `RealNativeUiaAdapter`：MTA COM 会话封装，300ms 连接与事务超时，支持安全 COM 异常映射。
  - `UiaSelectionWorker`：前台检查、非 Iris 进程检查、无窗口 MTA UIA 选区读取（遍历最多 32 ranges，65,536 code unit 预算，`\n` 分隔，读后前台复验）。
  - `UiaSelectionReader`：父端客户对象，管理 1500ms Ready 预算、300ms 请求响应单调预算、1000ms 正常退出宽限、1000ms Kill 物理退出确认预算；单次并发锁定（重叠请求返回 Busy），支持 StopAsync 永久撤销准入，以及清理失败保留与 RetryCleanupAsync。
  - `IUiaProcessRunner` / `RealUiaProcessRunner`：支持重定向流、隐藏窗口启动、UTF-8 无 BOM 编码及 4KiB stderr 排空。

### 4.2 预算说明
- **300ms 请求预算说明**：300ms（`UiaProtocolConstants.RequestTimeoutMs`）仅为请求发出到收到 Reply 帧的**单调 UIA 请求响应预算**；宿主进程的冷启动与握手受独立的 1500ms Ready 预算（`UiaProtocolConstants.ReadyTimeoutMs`）约束。因此，本单不宣称完整的冷启动首次选区读取一定在 300ms 内完成。

### 7.5 四组阻断项与修正要求

1. **R1-01：读取准入、UI 线程、预算及发布身份。** `UiaSelectionReader` 第一次锁内检查 busy 后释放锁做 preflight，第二次只检查 stopped，允许重叠请求；旧 finally 无条件清掉活动槽。目标 native 校验和同步 `Process.Start` 可在调用 UI 线程发生，Ready 计时晚于 Start 完成。退出/清理期间的取消或 Stop 没有最终发布复核。必须先登记唯一上下文，再后台执行 native/process 操作，Ready 覆盖启动，对迟到 session 保有责任，最终发布再次检查取消/停止。
