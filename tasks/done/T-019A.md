## 1. 分期与范围

T-019 拆为 A（Core 提交/凭据/草稿调用）和 B（服务页及全窗口保存接线）。本单实现已声明的 ISettingsEditCoordinator，完成两种 Provider 的模型发现前置修订、DI、对应有效回归。

本单不修改 App 的设置窗口、VM、Presenter、常规保存/自启实现，不开放服务页，不接真实用户凭据、不实现 OCR Registry、不编辑 Prompt 正文，不改预设地址/模型，不新增包。架构师后续签发 B，并负责届时预设官方依据核查。A 通过不能结案 T-019 或宣称 UI 已可配置服务。

新增契约模型、端口及 IModelCatalogSource 注释已由架构师同步，直接按 CONTRACTS.cs 落地业务实现；不要重新设计签名。实现类 internal sealed，在 AddIrisCore 中 TryAddSingleton 注册；Core 不引用 App/Providers/Infrastructure/Windows 实现。

## 2. 捕获、校验与一次增量提交

- CommitAsync、TestDraftAsync、ListDraftModelsAsync 在调用入口同步捕获完整草稿；复制 Profile.ExtraHeaders、操作列表和排序列表，后续 UI 修改不能改变已排队输入。
- GeneralSettingsPatch 四字段按 T-018 的 Base/Target 冲突规则合并；未编辑字段保留最新值，日志级别严格五项。
- Profile Add/Update/Delete 组合、深度比较、不可任意切换引用、Add 的大小写重复 ID 检查及排序规则按 PROVIDER_EDITING.md §2；不可用 upsert 复活已删除项。
- Add/Delete 要附完整顺序意图；更新未改排序时保留最新 Order。最终冲突检查在 UpdateAsync.mutate 内，不能只在 staging 前检查。
- 新输入校验按正式规范 §3，包括禁用半成品、可保存但未配置的凭据状态、合法数值/地址/高级选项和已存在 Prompt。不能依赖 Normalize 静默修正本次目标，不能改 Normalizer。
- 只调用一次 UpdateAsync 联合发布本计划，不拆分常规/Profile/引用保存；无操作不制造设置版本。

## 3. 凭据 staging、发布屏障与回收

- Keep/Replace/Clear 按规范；新 Profile Keep 写新显式空凭据集，不读该新 ID 的 legacy 键。Replace/Clear 每次用新 cs-Guid，完整四字段 JSON 显式保留 apiKey/secretKey 的 null。
- ISecretStore 同步 Get/Set/Remove 在后台执行。每组凭据只一次 Set，不覆盖活动集合，不以多次 legacy Set 模拟事务。
- 维护本次全部 staged ID；提交前失败/冲突/取消，仅尽力回收本次仍无引用的新值，旧配置/旧值不变。同步 I/O 已开始就观察真实退出。
- UpdateAsync 正常返回后保留已提交事实，忽略迟到 caller 取消；调用全部已接入观察者，观察所有已启动任务退出，全部成功后再清理候选。
- 清理前核对最新全部翻译/OCR 引用，含禁用项、跨类别共享和 legacy 同 ID 使用者；不删除仍有人引用的值。坏显式引用不回退 legacy，不用非法引用原值构造删除键。
- 不在设置写锁内刷新 Registry，不等待旧翻译租约全部释放才回收存储值，不自行 Dispose Registry 借出的 Provider。

## 4. 结果与 RetryApply

严格使用 SettingsEditResult 的 Uncommitted/Applied/ApplyPending。输入/冲突/存储错误用安全 ErrorInfo；提交前取消完成暂存回收后抛 OCE；提交后失败必须返回 ApplyPending 和非 null 回执，不能回滚或说未保存。

回执使用 Core 私有实现，仅暴露 CommitId；不持有 plan、凭据、原 JSON、Provider、UI、租约，不创建无限全局回执字典。调用方负责持有，B 单再接窗口重开间的回执保留。

RetryApply 在同一串行权内刷新当前配置，重验引用并清理该回执剩余候选；不重新 Set、不提交旧草稿。新提交取代原配置后仍不能恢复旧引用或删当前值；同一回执成功后重试幂等，并发调用不重复清理。拒绝其它协调器/伪造回执。

## 5. 草稿测试与模型列表

- 已有 Keep 在短编辑权内校验 base 并复用 ProviderCredentialResolver；得到独立值后释放编辑权，再创建瞬态租约和调用网络。长测试不能阻塞后续配置提交。
- Replace/Clear 直接使用捕获的显式值，不写 SecretStore。显式坏引用不能被当成有效 None：在本地地址同样拒绝，不回退 legacy。
- TestDraft 调用实际 Provider.TestAsync；ListDraftModels 通过可选 IModelCatalogSource。工作真正退出后释放瞬态租约；取消不能通过 WaitAsync 遗忘仍在使用 Provider 的任务。
- 两种现有 Provider 的 ListModelsAsync 只检查端点/凭据资格，不再用包含 Model 条件的 Descriptor.IsConfigured 作统一 guard。空 Model 可以取列表，翻译/TestAsync 仍拒绝；不填虚构模型作绕过。
- 保留既有模型列表响应限制、分页、去重/排序、超时/取消、SDK 与 HTTP 管道；不重构无关 Provider 方法。无能力返回安全 NotConfigured，不造空列表冒充成功。
- 所有测试使用 fake HTTP/假凭据；默认不访问真实服务或本地用户服务。

## 6. 必须证明的回归

| 场景 | 关键断言 |
|---|---|
| 常规补丁 + 多 Profile + 排序 | 恰好一次发布，未编辑字段取最新，Current/Registry 结果一致 |
| 字典/列表排队后被调用方修改 | 实际提交与网络调用使用已捕获值 |
| 第二个凭据 Set 失败 / staging 后冲突或取消 | 配置/旧凭据不变，本次全部无引用 staged 值尽力回收 |
| Clear 且存在 legacy / 新 Profile Keep | 显式 null 两字段均存在，不读取/复活 legacy |
| 观察者一项失败、另一项仍运行 | 无提前旧值删除，所有已启动任务退出后返回已提交待应用 |
| 提交后 caller 取消 | 不返回未提交/OCE，后续状态准确 |
| disabled/OCR 共享集合或 legacy 同 ID | 保留共享值，最后引用移除且屏障通过后才回收 |
| 清理失败后重试，期间又有新提交 | 不重复 staging/发布，不恢复旧草稿、不删当前引用，成功后幂等 |
| Keep 草稿捕获与保存竞争、网络挂起 | 捕获不使用被回收值，网络阶段不占编辑串行权，租约不提前释放 |

| 缺 Key、非法端点、显式坏引用及无模型能力 | 安全错误，无不合格请求，不能把坏引用当本地免 Key |
| 假敏感标记经输入/失败路径 | 不进入 settings.json、日志异常参数、回执或 DTO 的 ToString |

测试必须调用实际协调器/Registry/Provider，通过受控端口与门闩建立时序；不能只断言手写事件列表。补一条 fake 端口的真实 DI 路径，确认构造无 I/O、重复 AddIrisCore 不重复注册、首次 Commit 才生效。所有任务/租约/临时文件在 finally 中有界收尾。

## 一、改动摘要

1. **配置发布协调器实现 (`src/Iris.Core/Settings/SettingsEditCoordinator.cs`)**:
   - 实现 `ISettingsEditCoordinator`，标记 `[SuppressMessage("Design", "CA1001")]`（单例信号量）。
   - **同步防御性捕获**: 入口深拷贝输入集合与嵌套字典（`ExtraHeaders`），隔离排队后调用方的并发修改。
   - **无操作识别**: `IsNoOp` 检查，无改动时不制造设置版本，直接返回 `Applied`。
   - **严格输入校验**: `ValidatePlan` 校验 General 四项、Profile 增删改组合、小写 ID 格式、超时/tokens/温度/Enabled/地址/相对路径/非敏感 Header/Token 格式/Haiku 无 Effort/PromptTemplateId 存在性，以及排序完整性。
   - **凭据 Staging 与回滚**: 支持 New Keep（新建显式空集合）、Replace（新 Guid 写 apiKey/secretKey）、Clear（写显式 null）。后台 `Task.Run` 执行，捕获异常或取消时尽力回收本次全部 `stagedSetIds`，取消时重抛 OCE。
   - **原子发布屏障**: 在 `_settingsService.UpdateAsync` 的 `mutate` 内做最终深度比较冲突判断（忽略 Order），成功后达成提交点并忽略迟到取消；并发通知所有 `_configurationObservers.RefreshAsync`，全部成功后才清理旧值，否则返回 `ApplyPending` + `SettingsApplyReceipt`。
   - **安全旧凭据清理**: 在编辑串行权内核对最新全部 Translation/Ocr 引用（含禁用项、跨类别、legacy 同 ID），确认无使用者后在后台删除；严格避免非法引用构造任意删除键。
   - **`RetryApplyAsync`**: 校验回执身份与幂等性，重新触发观察者刷新并清理剩余候选，不重新 stage、不恢复旧草稿。
   - **`TestDraftAsync` 与 `ListDraftModelsAsync`**: Keep 在短编辑权内核对解析凭据后释放锁；创建瞬态租约并在 finally 中释放；空模型可列出模型；坏引用返回安全 NotConfigured。
2. **Provider 模型列表前置检查修订**:
   - `src/Iris.Providers/Translation/OpenAICompatible/OpenAICompatibleTranslationProvider.cs`:
     - `ListModelsCoreAsync` 前置 guard 由 `!Descriptor.IsConfigured` 改为 `!CanListModels(_profile, _credentials)`，仅校验端点与凭据资格（或本地免 Key），不要求 Model 非空。
     - 保持 `Descriptor.IsConfigured`、`TranslateStreamCoreAsync` 和 `TestAsync` 对 Model 非空的严格要求。
   - `src/Iris.Providers/Translation/Anthropic/AnthropicTranslationProvider.cs`:
     - `ListModelsCoreAsync` 前置 guard 由 `!Descriptor.IsConfigured` 改为 `!CanListModels(_profile, _credentials)`，仅校验端点（若有）与 API Key，不要求 Model 非空。
     - 保持 `Descriptor.IsConfigured`、`TranslateStreamCoreAsync` 和 `TestAsync` 对 Model 非空的严格要求。
3. **DI 依赖注入注册**:
   - `src/Iris.Core/DependencyInjection/CoreServiceCollectionExtensions.cs`:
     - 注册 `services.TryAddSingleton<ISettingsEditCoordinator, SettingsEditCoordinator>();`。
