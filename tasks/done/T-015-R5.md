### 2. StatusMessage 通知重入后，旧 Error 仍覆盖较新会话（P1）

当前 ApplyRequest 在输入通知之后检查归属，但随后连续执行：

```csharp
StatusMessage = request.StatusMessage;
Error = request.Error != null ? SanitizeErrorInfo(request.Error) : null;
```

StatusMessage 的同步 PropertyChanged 可重入。独立反例让旧 A 带状态/NetworkUnavailable 错误，在 StatusMessage 通知中 B 通过公开 Presenter 端口成功发布无错误的新输入；A 恢复后先把旧错误写入 B，再在下一次检查发现失效并返回 false。B 仍是 ActiveOperation，但界面出现 A 的错误。

- 发布保护覆盖全部可观察字段及通知，不只 InputText。保证状态提交/通知产生重入后，旧操作不再写较新会话的 Error、StatusMessage、输入、执行快照或复制资格。
- 对每个可能重入的通知边界与后续副作用建立一致的归属约束；可整体提交 backing state 后通知，或采用等价安全方式。不要在状态锁内调用任意外部订阅者，不用最后返回 false 掩盖已经发生的旧状态写入。
- 补真实 Presenter/VM 回归：StatusMessage 通知中新 B 成功发布（B.Error 应保持 null），Error/HasStatus 等通知重入、通知中隐藏以及普通发布对照。保留原 InputText 重入和 CTS 测试。

### 3. 复制待项先 MarkWriteFinished 导致先 Dispose 后 Cancel（P2）

TrackCopy 替换 `_pendingCopy`，以及 CancelPendingAndActiveCopies 移除待项时，先调用 MarkWriteFinished。此时 CancelRequested 尚未设为 true，TryDispose 直接释放 CTS；锁外 RegisterCopyCancelTask 再尝试 CancelAsync，已经抛 ObjectDisposedException。普通“一个写入挂起，连续点击两次形成待项替换”即可观察该错误日志。

- 待项确定撤销时，在允许 MarkWriteFinished/最终释放前原子登记取消意图和任务所有者，之后锁外执行取消；不能先释放后补登记，也不能只忽略 ObjectDisposedException。
- 同一规则覆盖待项替换、隐藏取消待项，以及写入结束与取消登记相交的路径；保持 R4 已通过的写入/取消双向等待。
- 补真实复制队列测试：首个写入挂起，替换最新待项及隐藏取消待项；正常操作无提前 Dispose 错误日志，无取消工作遗忘，最终仅最新合法待项可执行，全部任务/CTS 自然退出。

## 二、实施内容

### 1. 状态一致提交与全属性通知重入防护（P1）

在 `src/Iris.App/Translation/TranslateWindowViewModel.cs` 中：
1. **原子提交 backing state**：
   在 `ApplyRequest` 的 `lock (_gate)` 内部，在接受 `operation` 为 `_activeOperation` 的同一原子事务中，一次性提交全部 backing 字段（`_inputText`、`_statusMessage`、`_error`），并记录各项字段的实际变更标识（`updateText`、`statusChanged`、`errorChanged`）。如果后续任何较新意图 B 重入接管，B 在进入 `_gate` 时原子覆盖全部 backing 字段为 B 的合法状态；
2. **每个通知边界与副作用执行前进行归属校验**：
   引入私有方法 `IsCurrentOperation(TranslateWindowOperation operation)`，在状态锁内严格校验 `!_disposed && ReferenceEquals(_activeOperation, operation) && !operation.CancellationToken.IsCancellationRequested`；
   在 `oldOp.DetachSession()` 之后、`InputText`、`InputLength`、`CanTranslate`、`StatusMessage`、`HasStatus`、`Error`、`HasError`、`ShowGoToSettingsForError` 的每一次 `OnPropertyChanged` 触发前后，以及在计算 `isNewMain`、捕获 `_sessionOriginalText`、`_sessionOrigin`、`_sessionAutoCopyMode`、`_autoCopyClaimed` 和调用 `SubmitMainTranslation` 之前，均执行 `IsCurrentOperation` 校验。
   一旦发生抢占（例如旧 A 在 `StatusMessage` 通知中被新意图 B 抢占），A 恢复执行后立即短路退出并返回 `false`，绝不执行后续字段的赋值或通知，绝不写入任何旧错误，绝不捕获较新意图的执行快照，绝不触发未授权的主翻译；
3. **程序化输入更新深度计数**：
   将 `private bool _programmaticTextUpdate;` 升级为 `private int _programmaticTextUpdateDepth;`（配合属性 `private bool _programmaticTextUpdate => _programmaticTextUpdateDepth > 0;`），在 `ApplyRequest` 及 `ExecuteSwapLanguages` 中通过嵌套安全的计数器维护，杜绝重入时标志位被内层 `finally` 提前复位的边缘竞态。

### 2. 复制待项取消登记先于写入完成与最终释放（P2）

在 `src/Iris.App/Translation/TranslateWindowViewModel.cs` 中：
1. **取消登记先于释放**：
   重构 `QueuedCopyItem` 的取消登记逻辑，引入 `TryRegisterCopyCancelUnderLock(QueuedCopyItem item)` 必须在 `_copyGate` 锁内执行。当待项确定撤销时（无论是 `TrackCopy` 中的待项替换，还是 `CancelPendingAndActiveCopies` 中的隐藏/退役取消）：
   - 在 `_copyGate` 锁内首先原子执行 `TryRegisterCopyCancelUnderLock`，将 `item.CancelRequested = true`、`item.IsCancelRegistered = true`，并将对应的 `cancelTcs.Task` 加入 `_copyCancelTasks`，将 `item.Cts` 登记至 `_cancelingCtsSet`；
   - 之后才调用 `item.MarkWriteFinished()`；
   - 在 `QueuedCopyItem.TryDispose()` 中，因 `CancelRequested` 已为 `true`，`(!CancelRequested || _cancelDone == 1)` 判定为 `false`，CTS 绝不会被过早 Dispose；
   - 随后在锁外安全执行 `RunCancelWorkerAsync(item, cancelTcs)`，调用 `await item.Cts.CancelAsync().ConfigureAwait(false)` 时 CTS 始终健康有效，彻底根除 `ObjectDisposedException`；
   - 取消完成后在 `RunCancelWorkerAsync` 的 `finally` 块中调用 `item.MarkCancelFinished()`，此时 `_writeDone == 1 && _cancelDone == 1`，才由 `TryDispose()` 执行最终的 `Cts.Dispose()`；
2. **Volatile 内存屏障保障**：
   `QueuedCopyItem.CancelRequested` 采用 `Volatile.Read` 与 `Volatile.Write` 操作底层的 `_cancelRequested` 整型标志，保证多线程与 CPU 缓存之间的完整可见性；
3. **覆盖全部取消路径**：
   相同原子顺序规则同时覆盖：
   - `TrackCopy` 替换最新待项；
   - `CancelPendingAndActiveCopies` 移除待项；
   - `ProcessCopyQueueAsync` 写入完成与外部 token 触发取消相交路径；
   - 保持 R4 已通过的双向写入/取消等待及 drain/Shutdown 退出屏障。

### 3. 针对性单元测试与回归测试补强

1. **Presenter 测试（`TranslateWindowPresenterTests.cs`）**：
   - `TryShowAsync_WhenReenteredDuringStatusMessage_NewerOperationWinsAndErrorNotOverwritten`：验证在 `StatusMessage` 同步通知中重入发布新意图 B 时，A 返回 `false`，B 返回 `true`，`vm.ActiveOperation` 为 B，`vm.Error` 保持 `null`（A 的错误绝不覆盖 B），B 具备会话归属权；
   - `TryShowAsync_WhenReenteredDuringHasStatus_NewerOperationWins`：验证在 `HasStatus` 通知中重入时，新意图 B 获胜且 A 的错误被完全隔离；
   - `TryShowAsync_WhenReenteredDuringError_NewerOperationWins`：验证在 `Error` 通知中重入时，新意图 B 获胜且 A 的副作用被短路；
   - `TryShowAsync_WhenHiddenDuringStatusMessage_AbortsCleanly`：验证在 `StatusMessage` 通知中调用 `HideAsync()` 时，旧操作 A 被安全拒绝，窗口隐藏，`ActiveOperation` 为 null。
2. **ViewModel 测试（`TranslateWindowViewModelTests.cs`）**：
   - `CopyCancellation_PendingReplacement_DoesNotThrowOrLogObjectDisposedException`：使用 `TestDiagnosticLogger<TranslateWindowViewModel>`，在首个复制在途挂起时连续触发两次卡片复制，验证待项替换过程无 `ObjectDisposedException` 异常抛出或日志记录，最终首项与最新合法待项正确执行写入；
   - `CopyCancellation_PendingHide_DoesNotThrowOrLogObjectDisposedException`：验证在在途复制挂起、待项排队时调用 `OnWindowHidden()` 取消待项，全流程无 `ObjectDisposedException`，所有工作自然 drain。
