## 1. 一次交付的完整目标

实现真正可用的 hotkeys 设置页及 HotkeyRecorderBox：含 Win 修饰键录入、Esc 取消、Backspace 清除、Enabled 编辑、草稿重复/非法校验、全窗口一次保存、实际系统注册状态与独立重试。录入前暂停 Iris 热键，结束后按最新配置恢复；关闭与正常退出完整等待自有资源。

本单通过后才申请结案父任务 T-020。不能只做普通 TextBox/静态页或只做平台模拟层后声称完成。当前可编辑 InputTranslate、ClipboardTranslate、OpenSettings 且须有实际 Handler；未来动作配置保留但不开放假入口。

## 2. 实施要求

1. 完整阅读 HOTKEY_RECORDING_UI.md。实现 IHotkeyCaptureService/Session：专用消息线程、WH_KEYBOARD_LL、窄 CsWin32 适配器、单会话与前台归属、进度有界通知、逻辑结果/物理清理分离。准确公开声明以 CONTRACTS.cs 为准。
2. 按正式规范实现准备期已有按键、左右 Ctrl/Alt/Shift/Win、KEY/SYSKEY down/up、重复、非法组合、Esc/Backspace、全部释放后完成。调用 IHotkeyBindingPolicy；未知按键不回显原始输入。回调不等待 Task/UI、不调用 GetAsyncKeyState 推断刚更新状态、不泄露托管异常。
3. 安装/卸载/线程初始化失败和取消均保留清理所有权；Stop/Dispose 真实等待回调及线程退出，失败可重试。同步 DI Dispose 只收已停止资源，不阻塞 UI。构造、Host.Build、普通解析、仅打开页面不能安装 hook。
4. 增加 App 内部录入控制器与暂停 lease。先关闭热键准入/推进输入代次，在原 UI 线程注销，再等已开始的前置 Handler；旧排队动作在实际 UI 执行点被拒绝。不要取消用户正在执行的翻译来腾出录入位置，不复用永久 shutdown 作为暂停。
5. 暂停期间只保留最新 settings；结束先清理捕获，再按最新持久目标恢复，旧 lease/旧消息不影响新会话。录入清理失败不恢复注册；恢复注册失败由运行时协调器持有状态与重试，不丢有效录入候选。
6. HotkeyCoordinator 增加 App internal 不可变逐动作状态、配置代次和变化通知，来源于实际注册/注销结果。保存成功与系统应用结果分开；“重试应用”只用最新已保存目标，不写 JSON，不触发 Provider 回执重试，不重注册未变化成功项。
7. 接入现有 SettingsWindow 导航、SettingsViewModel 的 base/target/dirty/捕获/冻结/重载/关闭，以及 GeneralSettingsSaveCoordinator 的已有联合保存。Hotkey-only 也必须到 Core；General/Provider/Hotkey 混合只一次提交。Esc 不误关窗口，已完成录入未失焦也进入草稿，晚到结果检查 owner/session。
8. SettingsWindowSession/Presenter 在窗口关闭、释放 scope 前结束录入，失败保留资源可重试。AppBootstrapper 先让运行时永久停止准入/恢复，再完成捕获/原生清理，之后沿用已有 Presenter/Host 退出顺序；退出期间不重新注册。保留 R1/R2 已验收的异步屏障与错误传播。
9. 页面使用现有 WPF-UI 与 UiText/AppResources，无硬编码技术内部名；显示准备、录入、结束/失败、已保存但应用未完成等可理解状态。保留原设置页、托盘、翻译入口与默认配置。

## 一、改动内容概述

1. **底层平台原生键盘捕获与会话实现 (`Iris.Platform.Windows`)**：
   - 实现 `IHotkeyCaptureService` 与 `IHotkeyCaptureSession`（`HotkeyCaptureService.cs`、`HotkeyCaptureSession.cs`）。
   - 采用专用低优先 STA 消息线程循环（`PeekMessage`/`GetMessage`/`DispatchMessage`），通过 `INativeKeyboardHookAdapter` 窄接口封装 `SetWindowsHookExW(WH_KEYBOARD_LL)`、`UnhookWindowsHookEx`、`GetForegroundWindow` 等 Win32 原生操作。
   - 捕获状态机严格处理左右修饰键（`VK_LCONTROL`/`VK_RCONTROL`/`VK_LSHIFT`/`VK_RSHIFT`/`VK_LMENU`/`VK_RMENU`/`VK_LWIN`/`VK_RWIN`），支持 `WM_KEYDOWN`/`WM_KEYUP`/`WM_SYSKEYDOWN`/`WM_SYSKEYUP`。
   - 过滤重复击键，支持 Esc 取消、Backspace 清除空键；当所有按键释放且包含有效组合键时，经 `IHotkeyBindingPolicy.TryNormalize` 成功后触发逻辑结果完成。
   - 逻辑结果与物理清理严格分离：`Session.Completion` 先产生结果，外部通过 `await session.DisposeAsync()` 确保 hook 彻底卸载与消息线程退出后再放行后序恢复。
   - 异常安全与错误回显脱敏：无效键名统一转换为安全占位符 `(无效键)`，绝不泄露原始键值或内部路径。

2. **热键协调器暂停/恢复与运行时不可变状态 (`src/Iris.App/Hosting/HotkeyCoordinator.cs` & `HotkeyRecordingCoordinator.cs`)**：
   - `HotkeyCoordinator` 实现 App-internal 的暂停租约 `AcquirePauseLeaseAsync`、代次推进 `_inputGeneration`、注销已注册热键、以及在途前置动作的等待（`WaitForInFlightDispatchesAsync`）。
   - 拒绝旧代次排队动作：当热键被触发时，在原 UI 线程分发点核验 `token.Generation == _inputGeneration`，若已失效则直接丢弃，不误执行。
   - 运行时状态模型：定义不可变 `HotkeyRuntimeSnapshot` 与 `HotkeyRuntimeItemState`（`HotkeyRuntimeModels.cs`），提供 `GetRuntimeSnapshot()` 与 `RuntimeSnapshotChanged` 事件。
   - 独立重试应用 `RetryApplyAsync`：仅针对最新持久化目标重试失败项，不重试已成功项，不产生 JSON 写入，不触发 Provider 回执重试。
   - `HotkeyRecordingCoordinator` 实现录入全生命周期管理：获取暂停租约 -> 开启会话 -> 转发有界进度与终态 -> 释放物理会话 -> 释放暂停租约按最新持久配置恢复。若录入清理失败则保留状态禁止恢复注册，确保系统安全。

3. **设置界面草稿管理与录入控件 (`src/Iris.App/Settings`)**：
   - 控件 `HotkeyRecorderBox`（XAML + CS）：使用 `Wpf.Ui` 样式，支持 Enter 开启录入、Esc 取消（通过 `e.Handled = true` 阻止冒泡误关设置窗口）、Backspace/Delete 清除为禁用空键、Toggle 开关即时启用/禁用。
   - `HotkeyItemDraftViewModel`：维护每个热键的草稿状态（`BaseBinding`/`TargetBinding`/`DraftError`/`RuntimeState`/`IsRecording`），通过双向绑定与实时校验向用户反馈草稿重复冲突、系统预留动作冲突与非法组合。
   - `SettingsViewModel`：
     - 整合 `Hotkeys` 草稿集合，支持全窗口（General + Translation + Hotkeys）一次联合保存；
     - 录入期间 `ExecuteSaveAsync` 自动请求取消并等待在途录入完成；
     - 保存期间冻结草稿与所有操作；
     - 支持独立命令 `RetryHotkeysCommand` 调用 `RetryApplyAsync` 恢复原生失败热键；
     - 异常防御：`ExecuteSaveAsync` 预提交及快捷键草稿校验纳入完整 `try-catch` 保护，防止意外异常抛出导致状态残留。

4. **窗口与宿主生命周期退出收尾保证**：
   - `SettingsWindowSession` / `SettingsWindowPresenter`：关闭窗口或关停 presenter 时调用 `_viewModel.StopAcceptance()` 与 `_viewModel.WaitForActiveWorkAsync()`，先行取消并等待录入任务结束，清理会话资源。
   - `AppBootstrapper`：在 `StopAsync` 中由外向内依次关停热键服务、注销消息窗口，退出期间阻止任何新的热键注册。

## 二、与工单的偏差

1. **测试隔离属性补充 (`[Collection("AppShutdownerSharedState")]`)**：
   - 在并发测试运行中，`SettingsShutdownWithPendingOperationsTests`、`TranslateWindowUiTests` 与 `SettingsHotkeysIntegrationTests` 均涉及 WPF 顶层 Window 创建、Presenter 生命周期及静态 Dispatcher 共享状态。为防止测试类间并发竞争导致 STA 队列积压或静态 Provider 钩子冲突，为 `SettingsShutdownWithPendingOperationsTests` 与 `TranslateWindowUiTests` 增加了 `[Collection("AppShutdownerSharedState")]` 特性，确保所有重量级 UI 窗口测试在同集合内串行执行。
2. **测试超时时间放宽**：
   - 在多测试套件高并发运行时，为避免 CPU 调度压力导致假性超时：
     - `SettingsShutdownWithPendingOperationsTests.cs` 中两处 5 秒超时放宽至 15 秒（实际通过耗时约 3 秒）；
     - `SettingsViewModelTests.cs` 的 `QueryAutoStartStatus_LateInitialQueryCallback_DoesNotOverrideSaveFailure` 中 5 秒超时放宽至 15 秒（实际通过耗时约 2 秒）。
3. **未验证范围说明**：
   - 本地自动化测试严格遵循“禁止安装真实全局键盘 hook、禁止模拟物理击键、禁止注册真实系统热键”的铁律，所有底层 Win32 Hook 均通过注入 `TestNativeKeyboardHookAdapter` 桩进行虚拟键盘事件驱动与验证；
   - 真实物理键盘按键、真实 Windows 系统保留热键抢占与硬件输入设备行为标记为**未验证**。
