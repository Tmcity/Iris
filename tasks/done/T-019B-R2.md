## 2. 保存成功后的草稿与控件归属（P1）

SelectedProfile setter 在 IsSaving 时拒绝赋值，但保存成功内部 LoadProfilesFromCurrent 正在这个阶段重建列表。旧选中对象被移出 Profiles，仍成为详情 DataContext，且旧对象保持 IsFrozen=true。独立实测保存成功后 SelectedProfile 不属于 Profiles，下一次名称编辑无效。

- 区分用户变更入口与内部提交后重建；内部同步必须在 UI 线程正确重新绑定当前草稿，不可通过提前打开整个窗口的编辑权限规避。
- 保存成功/ApplyPending 后 SelectedProfile 为新列表成员或明确 null；保留选中 ID（仍存在时），删除最后项应为空详情。列表、详情、PasswordBox、dirty、命令均反映最新 Current。
- 移除旧对象时撤销 OnEdited/事件与发布资格，清明文；不得留一个可写/冻结的孤立详情。下次编辑保存必须作用于新基线，连续保存可用。
- Profiles 仍暴露可直接修改的 ObservableCollection，保存期间调用 Clear 可绕过冻结并在 Uncommitted 后丢掉草稿。改为受控集合视图/入口，涵盖增删、移动、索引替换；不要只守护少数命令。窗口停止后同样不得接受新草稿变更。

## 4. 队列先登记所有权，再在锁外执行（P1）

R1 只拆分 Drain，仍在锁内调用 RunWorkAsync→work 与 _runningCts.Cancel()。独立实测同步 work 重入 Enqueue 会产生两个实际运行任务；外层退出后 Drain 在内层尚未退出时返回，破坏并发和退出保证。

- 锁只用于准入/状态转移，在执行任何 work/取消回调之前登记完整的运行所有权与完成屏障。外部委托/取消回调不得在锁内执行。
- 同步完成、同步抛错、取消回调抛错/重入、队列替换等路径不能覆盖另一个工作句柄，不能先完成代理再遗忘真实 finally。
- 维持一个实际运行加一个最新等待；Drain/关停必须观察所有已准入工作和必要清理退出。取消等待项完成其返回 Task；队列重入不能让 Drain 提前完成。
- 不用无限 Task.Run 或硬超时遗忘工作来规避阻塞；取消回调若需后台执行，应有明确且有界的所有权。

受控测试覆盖 work 同步重入、取消回调重入/抛错、同步完成、多次替换与 Drain 交错；记录真实活动峰值、底层退出顺序，finally 放行闸门。不要只 await 三个操作但不对峰值/被替换项作断言。

## 2. 实施改动要点

### 2.1 保存成功后草稿与控件归属及受控集合保护（P1）
1. **内部草稿选定机制（`SetSelectedProfileInternal`）**：
   - 在 `SettingsViewModel` 中引入专门的内部选定方法 `SetSelectedProfileInternal(TranslationProfileDraftViewModel? value)`，绕过普通用户交互时 `IsSaving` 拒绝修改的限制；
   - 在保存成功/ApplyPending 后的 `SyncBaselineFromCurrent` / `LoadProfilesFromCurrent` 内部重建流程中，保留当前选中草稿的 `Id`（若该 Profile 被删除则置 `null`），从重建后的新列表中检索同 ID 实例赋给 `_selectedProfile`；
   - 旧草稿实例从集合中移除时，彻底解绑 `OnEdited` 回调与 `PropertyChanged` 事件监听，清空明文密码引用，解除孤立草稿的通知资格；
   - 在保存退出的 `finally` 块中，统一解除新选中项及其余草稿的冻结状态（`p.IsFrozen = false`），确保保存完成后用户可立即连续编辑且编辑立即生效。
2. **集合受控包装类（`ControlledProfileCollection`）**：
   - 将 `Profiles` 的底层实现替换为 `ControlledProfileCollection`（继承自 `ObservableCollection<TranslationProfileDraftViewModel>`）；
   - 在 `IsSaving || _isStopped || _disposed || !CanEdit` 期间，拒绝外部直接调用的 `ClearItems()`, `InsertItem()`, `RemoveItem()`, `SetItem()`, `MoveItem()`；
   - 内部合法更新（如 `LoadProfilesFromCurrent` 重建或用户命令合法修改）通过 `using (AllowInternalMutation())` 作用域执行，杜绝在保存冻结或关停期间外部绕过控件清空草稿集合。

### 2.2 Prompt 列表刷新与用户意图保护（P1）
1. **增量 Reconcile 机制（`RefreshAvailablePrompts`）**：
   - 废除原先盲目的 `AvailablePrompts.Clear()` 与全量重新填充；
   - 采用增量同步算法比对当前模板选项集合与目标选项集合：保留已存在的模板选项对象，只移除已失效的项，只在对应位置插入新增项；
   - 避免了 WPF `ComboBox.SelectedValue` 双向绑定在控件数据源被 `Clear()` 时静默将草稿的显式 `PromptId` 清空为 `null`（“跟随默认”）的缺陷；
2. **缺失模板占位保留**：
   - 若草稿当前选中的显式模板在外部已被彻底删除，增补 `[已移除]` 占位提示项并保留该 ID，不静默覆盖为默认模板。

### 2.3 操作队列所有权与锁外执行、重入并发与 Drain 屏障（P1）
1. **锁的职责明确为准入与状态转移**：
   - `SettingsDraftOperationQueue` 的锁仅用于准入判定、等待项登记与运行项状态转移；
   - 外部 `work` 委托与取消回调（`cts.Cancel()`）彻底移至锁外执行，杜绝锁内调用外部代码引发死锁与重入并发突破；
2. **单运行项 + 单等待项所有权模型**：
   - 登记完整运行所有权（`_runningItem` 与 `_runningTask`），重入工作绝不产生并发运行（峰值严格为 1）；
   - 在运行循环退出时，`finally` 块严格清空 `_runningTask` 与 `_runningItem`；
   - `DrainAndCancelAllAsync` 正确观察并 `await` 在途工作的完全退出，不提前返回，维持严格的退出屏障。

### 2.4 异步服务重试的 UI 调度与退出屏障（P1）
1. **重试结果与异常处理严格调度至 UI**：
   - `ExecuteRetryPendingApplyAsync` 与 `ExecuteRetryAutoStartAsync` 中的状态变更、回执处理、异常捕获以及 `finally`（`IsSaving = false`）严格通过 `_uiDispatcher.InvokeAsync` 在 UI 线程执行；
   - 消除 worker 线程触发 `PropertyChanged` 或 `CanExecuteChanged` 的隐患；
2. **UI 调度纳入活跃工作退出屏障**：
   - `_activeWork` 令牌直到 UI 调度任务完成后才正式释放，确保窗口或 Host 关闭等待能完整覆盖 UI 收尾。
