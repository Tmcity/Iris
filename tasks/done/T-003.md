## 1. 背景

设置是 Iris 所有功能的输入。settings.json 会被用户手动编辑、会被杀毒软件短暂锁住、会遇到断电，也会随版本升级而变化。设置服务必须做到三点：**坏一个字段只影响这个字段**、**任何时刻写盘都不会产生半截文件**、**`Current` 永远满足不变量**。

架构文档 v1.2 的 §12.2 已经把加载管道、挽救规则、规范化规则（N1–N11）和写入细节写成规范；`ISettingsService` 的契约注释也已补充了语义澄清。本工单严格按这些规范实现。

另外包含 T-002 评审的 3 项整改（C-1 ~ C-3），以及 1 项新增的永久性架构测试（C-4）。

## 6. 实现要求

### 6.1 AtomicFile（Iris.Core/IO，命名空间 `Iris.Core.IO`）

```csharp
public static class AtomicFile
{
    /// <summary>原子写入：path + ".tmp"（FileOptions.WriteThrough，写完 Flush(true)）→ backupPath 非空且 path 已存在时复制为 backupPath → File.Move(tmp, path, overwrite: true)。</summary>
    public static Task WriteAllBytesAsync(string path, ReadOnlyMemory<byte> content, string? backupPath, CancellationToken cancellationToken);

    /// <summary>同上，内容按 UTF-8（无 BOM）编码。</summary>
    public static Task WriteAllTextAsync(string path, string content, string? backupPath, CancellationToken cancellationToken);
}
```

- 进入方法时先检查 `cancellationToken`；**一旦 tmp 写完、开始执行备份与替换，就不再响应取消**（保证不留下中间状态）。
- 每个文件操作（创建 tmp、复制备份、Move）遇到共享冲突 `IOException`（`HResult` 为 `unchecked((int)0x80070020)` 或 `unchecked((int)0x80070021)`）或 `UnauthorizedAccessException` 时，最多重试 5 次，间隔 50 ms。
- 最终失败：尽力删除 tmp（删除本身失败则忽略），抛 `IrisException(ErrorCode.StorageFailure, ErrorMessages.GetDefault(StorageFailure), inner, detail: path)`。
- 目标目录不存在时**不负责创建**（由调用方保证），直接按失败处理。

### 6.2 SettingsMigrationRunner

- 构造：`SettingsMigrationRunner(IEnumerable<ISettingsMigration> migrations)`；存在重复的 `FromVersion` → 抛 `InvalidOperationException`。
- `JsonObject Run(JsonObject root, int fromVersion, int toVersion)`：对 v = fromVersion … toVersion − 1，依次查找 `FromVersion == v` 的迁移并执行；找不到 → 抛 `InvalidOperationException($"缺少 schemaVersion {v} 的迁移")`。`fromVersion == toVersion` 时原样返回。

### 6.3 SettingsSalvager

- `static void Salvage(JsonObject root, ICollection<string> fixes)`，严格按 ARCH §12.2.1“挽救规则”的第 1–4 步执行（第 0 步由服务负责）。**先执行第 1、2 步（数组元素与热键），再执行第 3 步（整节）**，这样一个坏的 Provider 不会连累整个 `translation` 节。
- 解析 JSON 时使用 `new JsonNodeOptions { PropertyNameCaseInsensitive = true }`，与反序列化器的大小写不敏感保持一致（用户写成 `"General"` 也能被找到）。
- 单独反序列化某个元素或某一节时，使用 `IrisJson.Options`。
- 修复记录的格式：`"<JSON 路径>: <说明>"`，例如 `translation.providers[1]: 已移除（缺少必填字段或类型错误）`、`general: 已重置为默认值（类型错误）`、`hotkeys.3: 键名已规范为 ScreenshotTranslate`。

### 6.4 SettingsNormalizer

- `static AppSettings Normalize(AppSettings input, ICollection<string> fixes)`：纯函数，严格按 ARCH §12.2.1 的 N1–N11 执行，返回新实例（未发生任何修复时，**返回原实例**）。
- 修复记录的格式：`"<属性路径>: <旧值> → <新值>"`，例如 `Translation.MaxConcurrentProviders: 0 → 1`。**N10 的修复记录不得包含代理 URL 的内容**（URL 中可能带有账号密码），写成 `Network.ProxyMode: Custom → System（代理地址无效，已隐藏）`。
- 建议给每条规则写一个私有方法（`NormalizeHotkeys`、`NormalizeTranslation` ……），再加一个通用的 `Clamp` 辅助方法（同时处理 NaN / Infinity，并负责记录修复）。
- **不变量自检**：默认设置 `new AppSettings()` 与 `specs/settings.example.json` 都必须是“不动点”——规范化后修复记录为 0 条。

### 6.5 JsonSettingsService

```csharp
internal sealed class JsonSettingsService : ISettingsService, IDisposable
{
    public JsonSettingsService(
        IAppPaths paths,
        IEnumerable<ISettingsMigration> migrations,
        TimeProvider timeProvider,
        ILogger<JsonSettingsService> logger);
}
```

**LoadAsync**：严格按 ARCH §12.2.1 的管道执行，补充以下要点：
1. 调用第二次 → `InvalidOperationException`。
2. 文件不存在 → `Current = new AppSettings()`，用 `AtomicFile` 写入，结束。
3. 解析使用 `JsonNode.Parse(text, new JsonNodeOptions { PropertyNameCaseInsensitive = true }, new JsonDocumentOptions { CommentHandling = JsonCommentHandling.Skip, AllowTrailingCommas = true })`。
4. 版本 > 当前版本：复制为 `settings.v{n}.json`（已存在则跳过）、记 Warning、按管道继续加载，但**加载阶段不回写**（避免覆盖较新版本写入的字段；下一次 `UpdateAsync` 时才会以当前格式写入）。
5. 版本 < 当前版本：复制为 `settings.v{n}.bak.json` → 迁移 → 继续。
6. 无论哪种情况，在挽救之前都执行 `root["schemaVersion"] = AppSettings.CurrentSchemaVersion`（挽救规则第 0 步）。
7. 发生了迁移、挽救或规范化修复（且不属于第 4 条的情况）→ 用 `AtomicFile` 回写（备份为 `settings.json.bak`），修复清单以一条 Warning 日志输出（最多 50 条，超出部分写“……另有 N 条”）。
8. **损坏处理**：`File.Move` 到 `settings.corrupt-{yyyyMMddHHmmss}.json`（时间取 `timeProvider.GetLocalNow()`，InvariantCulture；重名时依次追加 `-1`、`-2`……）→ `Current = new AppSettings()` → 写入默认值（这一步失败只记 Error 日志）→ 抛 `IrisException(SettingsCorrupted, ErrorMessages.GetDefault(SettingsCorrupted), detail: 备份文件完整路径)`。
9. 文件读取失败（被锁超过重试次数等 IO 错误）→ 抛 `IrisException(StorageFailure)`；此时 `Current` 保持默认值，服务**不**进入已加载状态（允许调用方重试 `LoadAsync`）。

**UpdateAsync**：
1. 未加载 → `InvalidOperationException`。
2. `await _gate.WaitAsync(cancellationToken)`；在 `finally` 中释放。
3. `var next = mutate(old)`；返回 null → `InvalidOperationException`；mutate 抛出的异常原样向上传递。
4. `next` 与 `old` 引用相等 → 返回。否则先规范化（修复记 Debug 日志），再序列化；与缓存的 `_currentJson` 完全相同 → 返回。
5. `AtomicFile.WriteAllTextAsync(SettingsFile, json + "\n", backup: SettingsFile + ".bak", ct)`；失败 → 异常向上传递，`Current` 不变，不触发事件。
6. 更新 `_current` 与 `_currentJson` → **仍在锁内**，逐个调用 `Changed` 的处理器（`GetInvocationList()`），每个处理器单独 try/catch，异常记 Error 日志后继续调用下一个。

**其他**：
- `Current` 通过 `Volatile.Read` / `Volatile.Write` 访问。
- `Dispose` 释放 `SemaphoreSlim`。
- 日志：加载成功记一条 Information（路径、schemaVersion、修复条数）。**任何日志都不得输出整份 JSON**。
