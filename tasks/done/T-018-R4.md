反例：发起 LaunchAtStartup=true 保存，fake SetEnabled(true) 已进入但挂起；外部将 Current.LaunchAtStartup 改为 false；放行后实际注册=true，VM/Current=false，但 CanRetryAutoStart=false。

## 3. R4-2：等待旧会话清理后仍只能创建一个窗口

反例：初始查询挂起，关闭旧窗口；同时发起两次 Presenter.ShowAsync，两者都等待同一个旧清理；放行后实际共创建 3 个窗口（旧 1 + 新 2），有 2 个可见/开放会话，Presenter 仅持有最后一个。

- 在异步等待和创建交界建立一致的单窗口创建权，或共享同一次创建任务；每次 await 返回后重新核对当前会话/关停状态，不能只检查一次旧值。
- 重复 Show 的所有调用方最终复用同一新窗口和草稿；清理失败不能 catch 后继续覆盖仍需管理的旧会话。
- 每次创建尝试用自身的局部 window/VM/coordinator/scope/session 负责失败回滚；不能用当时全局 _activeSession 来清理另一次创建的资源。
- 关停发生在等旧会话期间时不得再创建窗口；不依赖 IActionDispatcher 的防重入修补 ISettingsWindowPresenter 自身契约，不跨 await 持有同步锁，不引入全局任务队列。

正式测试调用实际 Presenter 并用真实 Dispatcher：两次并发 Show 等待同一旧查询，放行后只创建一个新窗口、所有会话都可追踪；再覆盖等待期间 Shutdown、创建/清理失败以及后续重试。所有自有窗口在 finally 中清理。

## 4. R4-3：Show/关闭失败必须由调用方完整观察

### 4.1 Show 失败返回前完成该次创建的清理

R3 的 catch 仍是 `_ = _activeSession.ShutdownAsync()`。实测 Show Task 已故障完成，初始查询却仍 pending。保留 Presenter 引用是有效改进，但不满足 R3 原要求。

- ShowAsync 在失败路径等待本次创建的工作/资源清理，再把失败交给调用方；清理本身失败也须安全观察和保留必要所有权，不能启动未等待的任务后返回。
- 覆盖 VM 已创建并启动查询、但 Window/会话尚未完整接线的失败阶段。可把初始查询的显式启动放到会话已取得所有权之后，避免构造中启动难以回收的工作；保持公开契约不变。
- 正式测试先取得 Show Task，挂起查询并注入 SourceInitialized 失败；清理未完成时该 Task 不能结束。放行查询后观察最终失败、查询/VM 任务完成、窗口/句柄已回收、scope 已释放。现有“先 await Show 抛错，再检查查询仍挂起”的测试须改正，不保留这个错误语义。

### 4.2 关闭成功与可见性无关

- 以真正 Closed/确定的关闭状态确认窗口已销毁；隐藏且持有 HWND 的窗口、已构造但尚未显示的窗口也必须正确关闭，不能用 IsVisible=false 代替关闭。
- 取消/异常时保留存活窗口及其依赖，保留后续清理入口。不要只从 `!closedFired && IsVisible` 判断失败，不能无条件设置 _isClosed 或释放 scope。
- 分别测试可见和隐藏窗口的 Closing 取消；调用方应观察失败且 scope 保留，去除故障后可再次关闭并完成资源释放。另覆盖创建后尚未 Show 的回滚。

### 4.3 失败传到正常退出组合根，不能继续销毁依赖

- Session 的关闭失败传递给 Presenter.ShutdownAsync 调用方，不能只记录日志后返回成功；并发调用仍共享本轮结果，失败后允许受控重试。
- AppBootstrapper.StopAsync 收到设置清理失败时，**不调用 StopSynchronousParts、Host.StopAsync 或 AppShutdowner**。保留依赖，安全提示/记录“退出尚未完成”，并使后续正常退出尝试可重试；不能让 _stopped 的一次标记永久挡住重试。
- 这是原“失败不算完成、存活工作/窗口不提前释放”规则的组合根落实。强制系统注销/进程终止规则保持原范围，不承诺强制结束等待异步工作。
- 此路径日志只记录安全操作/异常类型，不传原异常正文/链。不要重写其它 Host 失败策略或其它模块。

正式组合根回归使用 fake 设置关闭端口、Host、退出委托与通知：第一次设置清理失败，确认依赖/Host/应用退出未开始；第二次解除故障后按正确顺序完成；并发退出请求不把尚未完成的一轮错误报成成功。不得调用真实用户应用退出。

# T-018-R4 实施与验证报告

## 1. 核心修复落地情况

### 1.1 R4-1：应用完成后核对最新已保存意图
- 在 `SettingsViewModel.ExecuteSaveAsync` 中，当收到协调器 `SavedAndApplied` 结果后，不再无条件将 `CanRetryAutoStart` 设为 `false`，而是核对已成功应用的目标值 `snapshot.TargetLaunchAtStartup` 与当前最新已保存意图 `_settingsService.Current.General.LaunchAtStartup`：
  - 若两者一致，将 `LaunchAtStartup` 选择与基线更新为最新值，`CanRetryAutoStart = false`，提示保存成功；
  - 若在 `SetEnabled` 挂起期间外部修改了已保存意图导致两者不一致，保持 `CanRetryAutoStart = true`，状态提示设为 `UiText.SettingsStatusSavedAutoStartStillPending`（“常规设置已保存，但开机自启应用状态尚未同步”），并将 `LaunchAtStartup` 选择更新为最新已保存意图，绝不将旧值写回 JSON 或覆盖新意图。
- 在 `SettingsViewModel.ExecuteRetryAutoStartAsync` 中，重试开始前捕获当前最新已保存意图 `targetStartup`；重试成功后同样校验 `targetStartup == _settingsService.Current.General.LaunchAtStartup`，不一致时保持 `CanRetryAutoStart = true` 并更新提示，防止陈旧重试结果抹消待应用资格。

### 1.2 R4-2：等待旧会话清理期间单任务共享与单窗口创建
- 在 `SettingsWindowPresenter` 中引入单任务并发共享机制 `_openTask`：
  - 当一个打开流程正在等待旧会话清理（`await oldSession.ShutdownAsync()`）或构造新窗口时，后续并发的 `ShowAsync` 调用共享等待该 `_openTask`，并在新窗口创建完成后派发导航激活。
  - 彻底杜绝了并发重开时各自分别创建新窗口的反例（实测探针从 `created=3 visible=2` 修复为 `created=2 visible=1 live-sessions=1`）。
  - 若在等待旧会话排干期间收到关闭请求（`_isShuttingDown`），安全终止后续新窗口创建并抛出 `OperationCanceledException`，不残留孤儿窗口。

### 1.3 R4-3：失败异步清理贯穿与正常退出组合根
- **§4.1 ShowAsync 失败完全排干**：
  - `SettingsWindowPresenter.ShowCoreAsync` 中的 catch 块显式 `await session.ShutdownAsync().ConfigureAwait(true)`，等待本次创建的所有异步查询排干、原生 HWND 销毁以及 `IServiceScope` 释放，确保调用方拿到的 `showTask` 在异步清理排干前绝不提前完成（实测探针 `show-complete=False show-faulted=False query-pending=True scope-disposed=False`）。
- **§4.2 确切 Closed 状态与隐藏窗口关闭取消保护**：
  - `SettingsWindowSession.EnsureWindowClosedOnUi` 移除 `IsVisible` 判断，完全以确切的 `Closed` 事件与原生 HWND 状态确认窗口销毁。无论窗口处于可见状态还是隐藏状态（持有 HWND 但不可见），若 `Closing` 被取消，保留原生 HWND 与当前 scope 存活，向调用方抛出 `InvalidOperationException`；故障解除后允许再次关闭并完成资源释放。
- **§4.3 异常透传与退出组合根**：
  - `SettingsWindowPresenter.ShutdownAsync` 将 Session 关闭失败抛给调用方，并发调用共享本轮任务，失败后重试允许启动新一轮关闭。
  - `AppBootstrapper.StopAsync` 捕获设置清理异常时，记录安全日志，**绝不调用** `StopSynchronousParts`、`_host.StopAsync` 或 `AppShutdowner`；保持 `_stopped = 0`，保留现有依赖生命周期并允许后续正常退出重试。并发退出请求共享本轮错误，绝不静默报成成功。
