## 5. 实现要求

### H-1：异常对象整体安全

1. 按 CCR-001 修改 ToErrorInfo：Detail=null 就保留 null，不回退到 InnerException.Message；其余字段不变。
2. HttpErrorMapper 对 HttpRequestException、IOException、JsonException 的映射不得挂原始 InnerException，不读 Message/Data/JsonException.Path 作为对外诊断。Detail 使用固定标签和安全元数据：异常类型、HttpRequestError 枚举/HResult/HTTP 状态/JSON 行号与字节位置等可用信息。保持现有 ErrorCode、Retryable、ProviderId 规则。
3. OpenAI Provider 直接 catch JsonException 的所有分支使用同一安全策略，包括模型列表、非流式响应、SSE JSON；不留下自己的原始异常链。
4. AnthropicIOException 的正常映射和兜底也遵守此策略；SDK API/SSE 错误正文继续交给 FromBody 提取和脱敏。保持 SDK 异常不挂入 InnerException、不传给日志器。
5. 用户取消、Provider 超时优先级与未知编程错误行为保持原约定；不要把所有 Exception 都吞掉或改成“未知错误”。

安全检查须检查完整 Exception.ToString()、InnerException 链、ToErrorInfo() 和日志，而不只检查 Detail。全部使用假凭据。

### H-2：统一安全 URL

增加一个 internal 纯函数，将绝对 URI 格式化为 scheme + host + 非默认端口 + path；去掉 UserInfo、Query、Fragment。HttpLoggingHandler 和错误文本里的绝对 URL 共用此规则。

| 输入 | 期望安全 URL |
|---|---|
| `https://alice:PASS@api.example/v1?access_token=TOKEN#FRAGMENT` | `https://api.example/v1` |
| `http://u:p@[::1]:8080/v1/a%20b?q=SECRET` | `http://[::1]:8080/v1/a%20b` |
| `https://api.example` | `https://api.example/` |
| `socks5://u:p%40ss@proxy.example:1080` | `socks5://proxy.example:1080/` |
| null 或相对 URI | 固定占位符，不回显原输入 |

不能直接使用 GetLeftPart(Path) 或带 userinfo 的 Authority。成功与失败日志都使用清理后的 URL，失败只写异常类型等安全字段，不传原始异常对象。

### H-3：服务端错误正文脱敏

- 保留 FromBody 的错误字段提取、状态码映射和 300 字符截断；先脱敏后截断。
- 对正文里的绝对 URL 完整去除 userinfo/query/fragment，连未知的查询参数也不保留；其余文案保留，便于诊断。
- 对调用方明确提供的所有非空已知凭据进行最长优先、Ordinal 精确替换，去掉“长度至少 8”的门槛。已产生的 `***` 不再被后续已知值替换，以免重复膨胀。未知凭据的形态识别仍采用现有保守规则。
- URL 清理先于已知值替换，避免短凭据恰好出现在 scheme 中而使后续 URL 识别失败。覆盖重叠已知值及短假凭据的场景。
- 明确授权修改旧的“短已知凭据不替换”“URL 保留查询参数”“保留 ***@”测试期望；这是已修订规范的预期行为，不是弱化测试。

### H-4：关闭自动重定向

- 两个生产命名客户端的 SocketsHttpHandler 均设置 AllowAutoRedirect=false。不增加手动跟随逻辑，不改变重试次数、代理和超时。
- 302/307 等 3xx 交给既有状态码映射，翻译 Provider 返回 InvalidResponse，不能请求 Location 指向的目的地。
- 不能仅用替换主 Handler 的 MockHttp 测试证明生产配置正确。用真实注册的 IHttpMessageHandlerFactory 创建两条处理器链（不发送请求），找到实际 SocketsHttpHandler，断言 AllowAutoRedirect=false。
- 再用 MockHttp 分别验证两个翻译 Provider 遇到 3xx 的映射及不跟随行为。OCR 尚未实现 Provider，只验证其命名客户端配置。

## 3. 核心改动实施细节

### H-1：异常对象整体安全
- **`HttpErrorMapper.TryMapException`**：
  - 对 `HttpRequestException`、`IOException`、`JsonException` 转换为 `IrisException` 时，显式设置 `innerException: null`，彻底断开原始内部异常链；
  - `Detail` 不读取 `ex.Message`、`ex.Data`、`jsonEx.Path`，改用 `SafeHttpDiagnostics` 生成的固定说明与安全元数据标签（异常类名、`HttpRequestError`、HTTP 状态码、HResult、JSON 行号与字节偏移量）。
- **`OpenAICompatibleTranslationProvider`**：
  - 4 处 `catch (JsonException ex)` 分支（模型列表反序列化、非流式响应 JSON 解析、非流式反序列化、SSE 流式 Chunk 解析）全部统一使用 `innerException: null` 与 `detail: SafeHttpDiagnostics.FormatJsonExceptionDetail(ex)`。
- **`AnthropicTranslationProvider`**：
  - `AnthropicIOException` 兜底映射分支改为 `detail: SafeHttpDiagnostics.FormatIOExceptionDetail(ioEx)`，同样保持 `innerException: null`，不将 SDK 异常附入内部异常或传给日志器。
- 取消与超时逻辑优先判定保持原有顺序不变。

### H-2：统一安全 URL（`SafeHttpDiagnostics`）
- 新建 internal 纯函数工具类 `src/Iris.Providers/Http/SafeHttpDiagnostics.cs`：
  - `ToSafeUrl(Uri? uri)`：保留 scheme、host（支持 IPv6 `[::1]`）、非默认端口、path（保留转义字符如 `%20`）；完整移除 UserInfo、Query、Fragment；null 或非绝对 URI 返回固定占位符 `<redacted-url>`，不回显原输入。
  - `ToSafeUrl(string? urlString)`：字符串包装方法。
  - `CleanUrlsInText(string text)`：使用正则安全识别文本中的绝对 URL，清理其中的 UserInfo、Query、Fragment 并保留句子标点。
  - `FormatHttpRequestExceptionDetail`、`FormatIOExceptionDetail`、`FormatJsonExceptionDetail`：安全元数据格式化函数。
- **`HttpLoggingHandler`**：
  - 请求与失败日志均统一使用 `SafeHttpDiagnostics.ToSafeUrl(request.RequestUri)`；
  - 失败日志不传递原始异常对象，仅记录异常类型、方法和耗时。

### H-3：服务端错误正文脱敏（`SecretRedactor`）
- `SecretRedactor.Redact` 执行顺序更新：
  1. 先调用 `SafeHttpDiagnostics.CleanUrlsInText` 清理文本中的所有绝对 URL，完整移除 UserInfo、Query、Fragment，避免短已知凭据替换损坏 scheme 导致查询参数泄漏；
  2. 针对所有非空已知凭据，按长度降序排序后，采用单遍非重叠序数精确匹配替换为 `***`，彻底移除了旧有的“长度至少 8”门槛；
  3. 已替换产生的 `***` 标记不再会被后续已知凭据重新替换，杜绝了重叠密钥的指数膨胀；
  4. 对未知凭据执行 `sk-*`、`Bearer *`、参数凭据等模式识别替换。

### H-4：关闭自动重定向
- 在 `src/Iris.Providers/DependencyInjection/ProvidersServiceCollectionExtensions.cs` 中，为 `HttpClientNames.Llm`（`iris.llm`）与 `HttpClientNames.Ocr`（`iris.ocr`）两个命名客户端的 `SocketsHttpHandler` 均显式配置 `AllowAutoRedirect = false,`。
- 302/307 等 3xx 重定向状态码由 `HttpErrorMapper` 映射为 `ErrorCode.InvalidResponse`，`Retryable = false`，不跟随重定向目的地。
- 在 `HttpClientPipelineTests` 中，使用真实 DI 容器与 `IHttpMessageHandlerFactory.CreateHandler` 创建真实处理器链，通过遍历 `InnerHandler` 定位到最终的 `SocketsHttpHandler`，断言生产配置的 `AllowAutoRedirect == false`，且不发送真实网络请求。
- 分别在 `OpenAICompatibleTranslationProviderTests` 与 `AnthropicTranslationProviderTests` 中，使用 MockHttp 返回 302/307 并设置目标 `Location`，断言 Provider 抛出 `ErrorCode.InvalidResponse`，且目标 `Location` 绝对未被请求。

## 2. R1-1：正文中的 URL 不得回显凭据（P1 修复）

### 2.1 缺陷原因与修复方案
在 `SafeHttpDiagnostics.CleanUrlsInText` 中：
1. **IPv6 结束符号修复**：此前清理尾部标点时将末尾的 `]` 当作标点无条件剥除，导致形如 `http://audit:PASS@[::1]` 的合法 IPv6 URI 结尾结构被破坏而无法解析，回退到 `return raw` 导致密码回显。修复方案：统计候选字符串中 `[` 与 `]` 的出现次数，仅当 `CountOccurrences(']') > CountOccurrences('[')`（即存在外部未配对的包围括号）时才剥除末尾 `]`，保证 IPv6 地址结构的完整性。
2. **不可解析 URL 替换为占位符**：此前当正文中匹配到 URL 模式但 `Uri.TryCreate` 失败（例如端口非法 `:bad`）时，直接 `return raw`。修复方案：根据 ARCH v1.13 铁律，对任何已识别为可疑 URL 但无法解析为合法绝对 URI 的候选文本，统一替换为安全占位符 `RedactedUrlPlaceholder`（`<redacted-url>`）及原后缀，绝不回显原候选文本，杜绝带凭据的不规则 URL 逃逸。
3. **单引号截断修复**：此前 `AbsoluteUrlRegex` 模式末尾包含 `'` 排除项，使合法 query 或 path 中的单引号（如 `?q=left'secret` 或 `/O'Brien`）过早截断 URL，导致单引号后的敏感查询片段留在文本中。修复方案：从正则表达式排除字符集中移除 `'`，并重构尾部标点剥离逻辑，仅在单引号属于外部成对包围引号（如 `'http://...'`）或孤立尾部引号时剥离，保留合法 URI 内部的单引号参与完整解析与清理。

## 3. R1-2：移除已知凭据匹配中的二次扫描（P2 修复）

### 3.1 复杂度分析与算法更正
- **原实现二次扫描瓶颈**：原 `SecretRedactor.Redact` 中，通过在文本中循环查找所有已知凭据的命中位置并收集到 `matchedSpans` 列表中。每当找到一个候选区间 `(start, end)` 时，都对所有历史已匹配区间执行一次 `matchedSpans.Any(s => s.Overlaps(...))` 检查。当输入包含 $K$ 个单字符重复凭据（命中数与文本长度同阶，$K \approx N$）时，重叠检查的总次数为 $\sum_{i=1}^K (i-1) = \frac{K(K-1)}{2} = O(K^2) = O(N^2)$。对于 64 KiB 的 HTTP 响应体，比较次数超过 20 亿次，造成约 0.9 秒的停顿。
- **新算法（基于首字符桶的向前单遍扫描）**：
  1. **首字符桶预处理**：对过滤掉空值与 `"***"` 并按长度降序排好的已知凭据 `validSecrets`，按首字符存入 `Dictionary<char, List<string>> byFirstChar`。每个桶内天然维持长度降序，保证最长已知值优先。
  2. **单遍扫描推进**：维护前向扫描指针 `pos`（从 0 至 `textSpan.Length - 1`）。
  3. **桶内切片匹配**：若当前字符在字典中命中候选桶，依次对桶内候选检查 `textSpan.Slice(pos).StartsWith(candidate.AsSpan(), StringComparison.Ordinal)`。一旦命中最长候选，立即向 `StringBuilder` 追加 `"***"`，并将指针直接跳过命中长度 `pos += candidate.Length`。由于指针单向跳跃推进，各个命中区间天然互斥且无重叠，完全不需要回溯检查或遍历历史区间，算法复杂度从 $O(N^2)$ 彻底降为 $O(N)$。
  4. **未命中推进**：若首字符未在桶中或切片未匹配任何候选，写入当前字符并前移 1 步：`sb.Append(ch); pos++`。

### 3.2 语义与约束保障
1. **Ordinal 匹配**：完全保持 `StringComparison.Ordinal` 严格序数比较，不引入任何大小写折叠。
2. **执行顺序**：`SafeHttpDiagnostics.CleanUrlsInText` 严格在已知凭据替换之前执行，防止短已知凭据恰好出现在 scheme 中破坏后续 URL 识别。
3. **无长度门槛**：继续对所有长度（包含 1 字符的短已知凭据）均执行精确替换，不增加长度限制。
4. **标记免疫**：由于单遍向前扫描且跳过已替换的 `"***"`，已生成的替换标记绝不会被后续逻辑重复替换。
