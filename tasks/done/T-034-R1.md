## 1. 保留范围

保留已正确同步的契约、依赖版本、V1/V2 DDL、基本写入/去重/收藏保护、摘要与详情模型、FTS/LIKE 路由和 DI 注册。C12-1 已接受，本单不再修改缓存代码或测试。不改公开签名、不新增包、不实施编排器/UI。

## 2. R1-1：先验证兼容性，再修改数据库

- 读取和验证 user_version / 当前版本必需结构必须先于 WAL 切换、DDL 或其它持久化修改。未来版本、损坏/不兼容库安全拒绝；受控测试中拒绝前后的数据库字节、版本、journal_mode 和已有内容应保持，不能只断言“文件存在”。可扩展内部连接工厂以支持只读预检，不扩大公开契约。
- 迁移前验证旧版本结构，不能先提交 V2 再发现旧库缺关键列；版本和 DDL 的提交边界一致，失败不得留下错误升级状态。保留每迁移一事务与有效 V1 数据升级。
- 完整核查受支持版本的必需结构：关键列/类型、主键、外键级联、FTS5 trigram、删除触发器及必要索引。不能只检查列名和一个叫 history_fts 的表存在。缺少必需结构时安全失败，不能默默修补/覆盖不明格式再声称兼容。
- WAL 核验不符合要求时不能仅 Warning 后标记初始化成功。

## 3. R1-2：统一错误边界与资源所有权

- 连接创建/打开、PRAGMA、BeginTransaction、SQL、提交和失败清理都必须在操作的安全错误边界内。当前 BeginTransaction 位于 try 之外，锁冲突会直接漏出 SqliteException。
- 所有存储故障对外使用安全 IrisException(StorageFailure)；原始异常消息/InnerException 不得回显源文、译文、搜索词、路径或模拟敏感值。日志只保留允许的元数据。覆盖 Message、Detail、ToErrorInfo 与完整 ToString/异常链；仅检查最外层 Message 不够。
- 取消优先按 OCE 处理；提交前取消回滚，已提交后不伪报失败/取消。批量写入中检查取消，清理失败不得覆盖主要结果。
- SqliteConnectionFactory 中连接 Open 或 PRAGMA 失败后也必须释放已创建的连接；只有成功返回才转交所有权。覆盖进行中/排队工作与 Dispose，不要销毁仍将在 finally Release 的 SemaphoreSlim 导致覆盖原始结果。
- 建议将重复操作出口收敛为少量内部帮助逻辑，避免每个方法遗漏一层，但不重写已验收业务规则。

## 4. R1-3：读事务与实际数据维护边界

- Query/Get 使用真正的读事务（Microsoft.Data.Sqlite 需明确 deferred:true 或等效只读快照），不能以默认 BeginTransaction 意外取得写保留锁。WAL 下暂停的读取不应阻止另一个连接提交普通写入；同时保证 Total/页、头/结果仍来自同一快照。
- SetFavoriteAsync 对不存在正 id 必须为 no-op；不得因请求不存在的 id 而修剪其它记录。用实际受影响行数或同事务存在性判断控制后续修剪。
- MaxEntries 在后台取得写门闩后、开始该写单元时读取一次最新设置；不要在排队前捕获旧上限。已开始的写单元可继续使用其快照，之后排队的写单元必须观察新上限。

## 5. R1-4：真实边界测试与报告更正

用临时真实文件数据库和有界门闩，至少覆盖：

1. future version + DELETE journal 拒绝时不变更文件/journal；不兼容 V1 不推进到 V2；缺删除触发器、外键或假 FTS 表被拒绝，不能导致删除后孤儿。
2. 中途触发器异常含假敏感值：事务回滚且完整异常链/日志不泄漏；外部写锁导致 BeginTransaction 失败也为安全 StorageFailure；打开/PRAGMA 失败后连接释放。
3. 写入已发生之后由 SQLite 测试函数/触发器或受控执行点触发取消，断言主表/子表/FTS 回滚。保留调用前取消测试，但不得将其称为“事务中取消”。
4. 暂停 Query/Get 的读取阶段，另一连接提交写入；读取结果保持一致快照且写入能推进。用受控时点验证 Total/页、头/结果一致，不能只做快速并发调用。
5. 101 条非收藏记录，最新上限 100，对不存在 id 的取消收藏不删除任何条目；另一个排队写任务须使用门闩后取得的新上限。
6. 专用调用线程在连接/SQL 实际执行位置记录线程身份，不可仅以“Add/Get 返回成功”验证后台执行。补启动成功/失败顺序的可复核测试，Host 能解析服务不等同于测试启动流程；可采用小型 internal 测试接缝，不需要真实弹窗或 UI 自动化。
7. 异常/超时路径 finally 放行门闩并收尾，避免测试挂住；Dispose 与在途操作不会重复关闭或用已销毁同步对象掩盖结果。

报告 §4 的 24 个测试名引用中有 22 个与实际方法名不对应；很多对应功能已有测试，问题是报告名称/证明范围不准确。必须从实际源码或测试发现输出提取真实名称，逐项说明实际交错，不要重命名测试来迁就原报告。

另外更正：未来版本测试没有断言字节/修改时间；损坏文件测试实际写入 8 字节而非报告的 1024；取消测试在调用前取消；后台线程测试没有使用 callerThreadId 断言。未执行的只读/启动顺序等项明确标为未验证，修复后用实际证据替换。
