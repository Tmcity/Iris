## 2. R1-01：回执不能把旧版本用于新的自身写入

实际 composite + C1 + keyboard、外部 native fake 已复现：原剪贴板含文本与 Rich Text Format；恢复 Empty 后第一个 Set 成功，紧接着 owner PID 观测失败。首轮安全抛错并保留 pending；解除故障后 Retry 返回成功且清空 pending，但原富文本格式未恢复、没有再次 Set。

原因：receipt.Version 仍是本次最新 Set 之前的值，CleanupCore 将它拿去比较，自己的成功写入造成的差异被当作外部 Changed，继而 Dispose 原快照。这不是安全的外部更新跳过，也不是报告里承诺的“未知版本保持可见失败责任”。

1. 精确区分实际 Empty/Set 成功、版本是否对应当前写入、全部目标格式是否已发布及 native 清理是否完成。每次自身写入后，旧 stamp 不能继续作为该状态的可信版本；版本查询失败不能留下看似仍有效的旧 stamp。
2. 尽量避免在已清空后、各 Set 之间引入可失败且并非发布数据所必需的身份查询。可在同一 Open 帧提交前确认本服务写入 owner 身份，写后记录与当前变更对应的序列；不得把旧 clipboard owner 当成本服务 owner，更不能在锁外猜测/替换 expectedVersion。
3. 对本次可控的暂时 OwnerPid 观测故障（其它调用健康、无外部复制），移除故障后应保留或恢复完整原始两种格式，不以“总是失败”替代可恢复行为。全部格式已实际发布而后续观测/Close 失败时，重试只做未完成收尾，不重复成功的恢复写入。
4. 若确实无法取得任何可信当前写入版本，必须保持安全失败和原快照责任；不能把自己造成的版本差异假装外部 Changed、清掉 pending。正常真实外部更新仍应零覆盖，不能为了恢复成功改成无条件写入。
5. 补 Clear/恢复 Empty、首个/中间/最后 Set 后版本观测失败，以及 Close 失败、真正外部更新对照。验证完整格式与原始字节、快照是否仍持有、pending/错误语义、零重复 Ctrl+C 与不重复已完成恢复。沿用实际实现，仅替换外部边界。

## 3. R1-02：条件文本 Changed 在预算内应重新观察

实际探针在首次文本 Get/CopyFrom 时只使同一来源 owner 的 sequence 增加一次，模拟合法延迟呈现；文本和焦点不变。当前在 100ms 预算中仅走了 20ms 就返回 null，原剪贴板也未恢复。官方文档明确延迟呈现可能在数据真正 render 时才增加 sequence。

1. ReadTextIfVersionAsync 返回 Changed 时不能把本次读取直接结束为普通无文本。只要原来源/焦点仍有效且预算尚未耗尽，回到原观察循环，重新验证 owner/稳定窗口/条件文本；不再发送 Ctrl+C、不重新清空剪贴板、不重置响应预算。
2. 若当前变为未知/其它 owner，立即停止该候选，零读取其 payload、保留外部内容；超时/取消/焦点变化仍不发布迟到文本。连续变化只在同一单调预算内观察，不无限重试。
3. 补一次/多次同来源延迟呈现、读取后变外部 owner、稳定后超时、取消对照；在一次变化且剩余预算充分时返回正确选区并条件恢复原快照，copies 始终为 1。

## 2. 实施与历史更正

基线 `65cafb1e9e32eacb77eb3f2414ac6ebadec1dbbe`。已完整阅读工单和 C2 报告第 9 节实际反例，保留其原始证据。

R1-01：`ClipboardSnapshotService.Commit` 仅在 selection receipt 路径，于成功 Open、比较 expectedVersion 后、Empty 前，通过本服务持有的 `_window` 查询自身 PID。该 PID 不是旧 clipboard owner 的 PID。之后 Empty/Set 每次实际成功，都先将旧 receipt.Version 置空，再用同一 Open 帧中的当前 sequence 与预先确认的本服务 HWND/PID 构成新 stamp。0/回绕仍是有效序列，不当作失败。

`ClipboardWriteReceipt.AllFormatsPublished` 单独表示全部目标数据已实际发布：合法空恢复在 Empty 成功后成立，其它恢复在最后一个 Set 成功后成立，不依赖之后版本查询或 Close 是否成功。组合器仍先执行实际 clipboard RetryCleanup，再判断已全部发布的恢复可以结束；它不再为已发布的数据重复 Empty/Set。部分发布且版本未知仍不能作为 Changed 处理或丢弃原快照，原有未知 expectedVersion 安全失败检查继续保留。

移除了每个 Set 之间不必要的 owner/PID 身份查询。因此复审中“第一个 Set 后 OwnerPid 失败”的条件现在不会打断发布：测试明确在恢复 Empty/首个/中间/最后 Set 后启用 OwnerPid 故障，并证明之后没有再进行该查询，完整文本/RTF/PNG 数据保持；不是吞掉查询异常或把残缺恢复报告为成功。提交前自身 owner 查询失败则零 Empty/Set，可在解除故障后重试。

R1-02：`ObserveClipboardAsync` 对条件文本 Changed 先检查返回版本是否仍属于原来源；未知/其它 owner 立即结束，不读取其 payload。同来源变化回到既有观察循环，重新检查来源/焦点、完整版本和稳定窗口，再条件读取。继续使用原 start timestamp 和响应预算，不重新复制、清空或重置计时。

更正原 C2 报告的过度结论：旧实现并非总能在未知版本时保留责任，后续自身 Set 后旧 stamp 会被误用，导致残缺富文本恢复被当作外部更新跳过；旧条件文本 Changed 也没有在剩余预算继续观察。本单修正这些行为，不改写历史原文或独立反例。
