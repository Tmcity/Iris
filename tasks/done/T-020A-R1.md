## 二、与工单的偏差及执行记录

1. **失焦对照测试中的 UI Dispatcher 渲染时序处理**：
   - 首次执行定向测试时，`Presenter_WindowDeactivation_BranchComparison_TrueCancelsAndHides_FalsePreservesAndCompletes` 中在后台任务刚发出信号时直接断言 `vm.Cards[0].State`，此时 UI Dispatcher 队列中待执行的 `_uiDispatcher.InvokeAsync` 回调尚未获得执行切片，导致断言观察到初始的 `CardState.Idle`。
   - 解决：在断言前增加微小的 Dispatcher 调度循环 `for (var i = 0; i < 50 && (...); i++) await Task.Delay(20);`，让出控制权以便 Dispatcher 执行卡片完成与流式状态更新，断言立即稳定通过。
2. **旁观窗口类型选择**：
   - 首次执行定向测试时，`RealCompositionRoot_MidWayFailure_CleanlyTearsDownResources_WithoutAffectingOnlookerWindow` 使用原生 `new Window()`，在测试运行器已挂载 WPF.UI 全局控件字典的环境下抛出 `在显示 Window 或调用 WindowInteropHelper.EnsureHandle 之后，无法更改 AllowsTransparency`。
   - 解决：遵循 WPF.UI 主题规范，将旁观窗口类型改为 `new Wpf.Ui.Controls.FluentWindow()`，窗口正常展现与存活验证完全符合预期。
