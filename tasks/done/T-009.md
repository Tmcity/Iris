## 1. 背景

这是 Iris 第一个真正调用大模型的 Provider。OpenAI Chat Completions 协议覆盖了 OpenAI、DeepSeek、通义千问、Kimi、智谱、SiliconFlow、Gemini 兼容端点、Ollama 等绝大多数服务，所以本工单的质量直接决定首个可用版本的体验。

T-008 已经提供了全部 HTTP 基础设施（SSE 解析、错误映射、脱敏、代理、带重试的 `iris.llm` 客户端）。本工单只负责协议本身：构造请求、解析流、处理超时与取消、剥离 `<think>`。

规范写在 **ARCH v1.10 §9.1**，这一节已经重写为完整的行为规范，**务必逐条阅读**。以下几点最容易写错：
- **超时是“无进展超时”**：每收到一个 SSE 事件就重置计时，而不是整个请求的总时长。否则一篇长译文会在第 60 秒被切断。
- **异常归类有固定顺序**：用户取消 → 超时 → 已知 IrisException → 可映射异常 → 其他。用户取消与超时都表现为 `OperationCanceledException`，只能通过检查各自的 token 来区分。
- **`<think>` 只剥离开头**：译文中间出现 `<think>` 字样必须原样保留。
- **最后恰好一个带 FinishReason 的 Chunk**：编排器（T-013）依赖这一点判断截断与读取 Usage。

## 6. 实现要求

### 6.1 Factory

```csharp
internal sealed class OpenAICompatibleTranslationProviderFactory : ITranslationProviderFactory
{
    public OpenAICompatibleTranslationProviderFactory(
        IHttpClientFactory httpClientFactory,
        IPromptTemplateProvider promptTemplates,
        IPromptRenderer promptRenderer,
        ISettingsService settings,
        TimeProvider timeProvider,
        ILoggerFactory loggerFactory);

    public TranslationProviderKind Kind => TranslationProviderKind.OpenAICompatible;
    public ITranslationProvider Create(TranslationProviderProfile profile, ProviderCredentials credentials);
}
```
- 注册：`services.TryAddEnumerable(ServiceDescriptor.Singleton<ITranslationProviderFactory, OpenAICompatibleTranslationProviderFactory>())`。T-010 会以同样方式注册 Anthropic 的 Factory，T-011 的 Registry 通过 `IEnumerable<ITranslationProviderFactory>` 按 Kind 查找。
- 构造函数的全部参数、`Create` 的两个参数都做 `ArgumentNullException.ThrowIfNull`；Kind 不匹配 → `ArgumentException`。

### 6.2 Provider

- 构造函数为 internal，参数为 Factory 传入的依赖加 `profile`、`credentials`；测试直接构造 Provider，不必经过 Factory。
- `Descriptor = new ProviderDescriptor(profile.Id, profile.DisplayName, "OpenAICompatible", profile.Model, IsConfigured)`；`IsConfigured` 的规则见 §9.1，在构造时计算一次。
- 请求构造、超时、异常归类、响应分流、流结束判定、输出约定，**严格按 §9.1 实现**。
- **异步迭代器结构**（C# 不允许在带 catch 的 try 块中 `yield return`）：

  ```csharp
  public async IAsyncEnumerable<TranslationChunk> TranslateStreamAsync(
      ProviderTranslateRequest request, [EnumeratorCancellation] CancellationToken cancellationToken)
  {
      // 1. 未配置 → throw NotConfigured（第一次 MoveNextAsync 时抛出）
      // 2. 创建 timeoutCts 与 linkedCts（using）
      // 3. await using var e = CoreAsync(..., linkedCts.Token).GetAsyncEnumerator(linkedCts.Token);
      // 4. 循环：
      //      bool hasNext; TranslationChunk current = default;
      //      try { hasNext = await e.MoveNextAsync(); if (hasNext) current = e.Current; }
      //      catch (Exception ex) when (!(ex is OperationCanceledException && ...)) { throw Classify(ex, ...); }
      //      if (!hasNext) yield break;
      //      yield return current;
  }
  ```
  以上只是结构示意，具体写法可以不同；关键是所有异常都经过同一个 `Classify` 出口，并且 `CoreAsync` 自身不做任何异常转换。
- `Classify` 中判断“调用方 ct 已取消”要用**调用方传入的** `cancellationToken`，判断超时要用 `timeoutCts.IsCancellationRequested`，二者都不成立时才进入后面的分支。重新抛出 OCE 时注意保留原异常（`ExceptionDispatchInfo` 或 `throw;`，二选一，写进报告）。
- 响应对象：`using var response = await client.SendAsync(..., HttpCompletionOption.ResponseHeadersRead, token)` 放在 `CoreAsync` 内部，确保消费者提前 break 时随迭代器的 `DisposeAsync` 一起释放。
- `knownSecrets` 传 `[credentials.ApiKey]`（null 也可以，`SecretRedactor` 已经兼容）。
- 日志：`LoggerMessage` 源生成器，Debug 级别，内容按 §9.1 的“日志”一段。

### 6.3 ThinkTagStripper

```csharp
internal sealed class ThinkTagStripper
```

### 6.6 T-008 评审遗留

- **C8-1（安全）**：`HttpErrorMapper.TryMapException` 当前把 `exception.Message` 原样写入 `Detail`。架构师实测，代理隧道失败时消息中包含完整的代理地址（含账号密码），见 ARCH §11.2 新增的说明。修改：
  1. `SecretRedactor` 增加第四个 `[GeneratedRegex]`：`(?i)\b([a-z][a-z0-9+.\-]*://)[^\s/@:'"]+:[^\s/@'"]+@` → `$1***@`（ARCH §12.5）。
  2. `TryMapException` 中两处 `detail: exception.Message` 改为 `detail: SecretRedactor.Redact(exception.Message)`。
  3. 测试：`SecretRedactorTests` 增加 `The proxy tunnel request to proxy 'http://alice:S3cretPass@127.0.0.1:10332/' failed` → 结果不含 `alice`、`S3cretPass`，含 `http://***@127.0.0.1:10332/`；`socks5://u:p%40ss@h:1080` → `socks5://***@h:1080`；`https://api.openai.com/v1/chat`、`http://host:8080/path`、`user@host` 保持不变。`HttpErrorMapperTests` 增加：`new HttpRequestException("... proxy 'http://alice:S3cretPass@10.0.0.1:8080/' ...")` 映射后 `Detail` 不含 `S3cretPass`。
- **C8-2**：`DynamicWebProxy.IsLocalAddress` 有两处遗漏（ARCH §12.4 已更新）：
  1. IPv4 映射的 IPv6 地址：`http://[::ffff:10.1.2.3]/` 目前被判为非本地（`IPNetwork.Contains` 不跨地址族匹配，架构师已实测）。解析出 IP 后，若 `ip.IsIPv4MappedToIPv6` 则先 `ip = ip.MapToIPv4()`。
  2. 主机名末尾的点：`localhost.`、`intranet.` 目前被判为非本地。判断前先 `host.TrimEnd('.')`。
  3. 测试：`[::ffff:10.1.2.3]`、`[::ffff:192.168.1.1]`、`localhost.`、`intranet.` → 本地；`[::ffff:8.8.8.8]` → 非本地。

### 7.2 ThinkTagStripperTests（纯函数，多用 `[Theory]`）

1. 没有 `<think>`：`"Hello"` → `"Hello"`；前导空白 + 普通文本 `"  Hi"` → `"  Hi"`（原样）。
2. 完整标签在一个 Delta 中：`"<think>abc</think>\n\n你好"` → `"你好"`。
3. 标签被任意切分：把 `"<think>推理</think>  译文"` 在**每一个**位置切成两段、以及每个字符单独一段输入，拼接输出都等于 `"译文"`（用循环生成全部切分方式）。
4. 前导空白后才出现 `<think>`：`"\n<think>x</think>y"` → `"y"`。
5. 译文中间的 `<think>` 保留：`"A <think>B</think>"` → 原样。
6. 看起来像但不是：`"<thinking>"`、`"<th"` 后接 `"e end"`（即 `"<the end"`）→ 原样输出。
7. `Flush`：只输入 `"<thi"` 后 Flush → `"<thi"`；输入 `"<think>未完"` 后 Flush → `""`。
8. 思考内容很长（例如 100 万个字符分 1 万次输入）时不会累积：用一个对内部缓冲长度的断言，或者断言耗时 < 1 秒。二选一，写进报告。
9. `</think>` 之后的空白跨 Delta：`"<think>x</think>"`、`"  "`、`"\n"`、`"译文"` → `"译文"`。

### 7.3 OpenAICompatibleTranslationProviderTests（MockHttp；`FakeTimeProvider`；`IPromptTemplateProvider`、`ISettingsService` 用 NSubstitute；`IPromptRenderer` 使用真实实现或替身均可）

构造方式：`new HttpClient(mockHttp)` 通过替身 `IHttpClientFactory.CreateClient(HttpClientNames.Llm)` 返回（**不经过** T-008 的重试管道，这样一次失败就是一次请求，断言更简单）。

**请求构造**
1. URL：`BaseUrl = "https://api.example.com/v1/"`、`ChatCompletionsPath = "/chat/completions"` → 请求地址为 `https://api.example.com/v1/chat/completions`。
2. 有 Key → `Authorization: Bearer sk-test-1234567890`；Key 为空白 → 请求中没有 `Authorization` 头。
3. `ExtraHeaders` 生效；其中名为 `authorization`（小写）的条目被忽略，请求中的 Authorization 仍来自 Key；非法的头名称（如 `"Bad Header"`）不导致异常。
4. 请求体（解析成 `JsonDocument` 断言）：messages 为 system + user，内容来自渲染结果；`Rendered.System` 为空白时只有 user 消息；`Temperature` 为 null 时不存在 `temperature` 字段；`MaxOutputTokens = 512` 且 `MaxTokensField.MaxCompletionTokens` → 只有 `max_completion_tokens: 512`；`MaxOutputTokens = null` → 两个字段都不存在；`IncludeStreamUsage = true` 且流式 → `stream_options.include_usage = true`；非流式时即使 `IncludeStreamUsage = true` 也不带 `stream_options`。
5. 请求内容是 `ByteArrayContent`（或其子类），`Content-Type` 为 `application/json`。
6. 使用 `profile.PromptTemplateId` 调用 `IPromptTemplateProvider.Get`（用替身验证参数）。

**流式**
7. `openai_stream_ok.txt` → Delta 依次为 `"你好"`、`"，世界"`，最后一个 Chunk：Delta 为 `""`、FinishReason = Completed、Usage = null；Chunk 总数为 3。（`role` Chunk 的空 content 不产出 Chunk。）
8. `openai_stream_usage.txt` → 最后一个 Chunk 的 Usage 为夹具中的 prompt / completion 数值；带 FinishReason 的 Chunk 恰好 1 个。
9. `openai_stream_think.txt`，`StripThinkTags = true` → 拼接结果为 `"你好世界"`；`StripThinkTags = false` → 拼接结果包含 `<think>`。
10. `openai_stream_reasoning.txt` → 输出中不含任何 `reasoning_content` 的文本。
11. `openai_stream_length.txt` → 最后一个 Chunk 的 FinishReason = Truncated，不抛异常。
12. `finish_reason: "content_filter"` 与 `"sensitive"` → 抛 `IrisException(ContentRefused)`，`ProviderId` 正确。
13. `openai_stream_error.txt` → 先产出第一个 Delta，然后抛 `IrisException`，`Detail` 包含 `Rate limit reached`。
14. `event: error` 的事件（data 为任意 JSON）→ 抛 `IrisException`。
15. 流在没有 `[DONE]`、也没有 `finish_reason` 时结束 → `IrisException(InvalidResponse)`；有 `finish_reason` 但没有 `[DONE]` → 正常结束。
16. data 不是 JSON（例如 `data: hello`）→ `IrisException(InvalidResponse)`，`InnerException` 为 `JsonException`。
17. 2xx 且 `Content-Type: application/json`、body 为正常的 `ChatCompletionResponse`，而 profile 要求流式 → 按非流式处理，输出一个 Chunk。
18. 流式响应中 `Content-Type` 为 `text/event-stream; charset=utf-8` → 正常按 SSE 处理。

**非流式**
19. 正常 → 恰好一个 Chunk，Delta 为完整译文，带 FinishReason 与 Usage；`reasoning_content` 被忽略；`<think>` 按配置剥离。
20. 200 + `{"error":{"message":"invalid model"}}` → `IrisException`，`Detail` 含 `invalid model`。
21. `choices` 为空数组、`content` 为 null → `IrisException(InvalidResponse)`。

**HTTP 错误**
22. 401、404、429（`insufficient_quota`）、500 → 分别为 AuthenticationFailed、EndpointNotFound、QuotaExceeded、ProviderUnavailable；`HttpStatus` 与 `ProviderId` 正确。
23. 401 的 body 中回显了 API Key（`"Incorrect API key provided: sk-test-1234567890"`）→ `Detail` 中不含该 Key。

**超时与取消（全部使用 `FakeTimeProvider` 推进时间，测试中不得真实等待超过 1 秒）**
24. 响应头迟迟不返回（MockHttp 的响应委托 `await Task.Delay(Timeout.Infinite, ct)`）：推进 `TimeoutSeconds` 秒 → `IrisException(Timeout)`，`Retryable = true`。

### AC-6: 官方文档核对结果（工单第 9 节）

1. **OpenAI** (`https://platform.openai.com/docs/api-reference/chat` 与 `https://platform.openai.com/docs/guides/reasoning`)
   - `finish_reason` 全部取值：`stop`（自然结束）、`length`（输出到达 token 上限）、`content_filter`（触发内容安全策略）、`tool_calls`（函数调用完成）；流式过程中每个数据块其值为 `null`。旧版遗留的 `function_call` 已被 `tool_calls` 代替。
   - `stream_options.include_usage: true` 最后一个 Chunk 形态：OpenAI 官方文档明确说明，当配置了该选项，会在末尾追加一个包含整个请求的 token usage 的 Chunk。在该 Chunk 中，`choices` 数组为**空数组** `[]`，`usage` 对象直接位于外层 JSON 的根属性。
   - 推理模型是否拒绝 `max_tokens`：是的。o1 与 o3 系列推理模型明确弃用 `max_tokens`，传入该参数会返回 HTTP 400 错误；必须使用 `max_completion_tokens`，且其上限包括思考 tokens 与最终输出 tokens。
   - 推理模型是否拒绝 `temperature`：是的。o1 系列推理模型目前不支持调节采样温度，传入自定义 `temperature` 会返回 HTTP 400（`Unsupported parameter: 'temperature'`）。

2. **DeepSeek** (`https://api-docs.deepseek.com/`)
   - 推理模型的 `reasoning_content` 字段名：官方 API 规范规定思考过程输出在 `choices[0].delta.reasoning_content`（流式）或 `choices[0].message.reasoning_content`（非流式）字段中。
   - `finish_reason` 取值：除标准 `stop`、`length`、`content_filter`、`tool_calls` 外，DeepSeek 具有专用的 `insufficient_system_resource`（表示推理时系统算力资源不足导致截断）与 `aborted`。
   - 余额不足时的 HTTP 状态码：HTTP 402 Payment Required（返回消息包含 `"Insufficient Balance"`）。

3. **智谱 GLM** (`https://docs.bigmodel.cn/`)
   - `finish_reason` 中审核拦截取值：智谱大模型在触发违规/内容安全拦截时，`finish_reason` 返回 `"sensitive"`（错误码对应 1301/1302）。
   - 其他取值：若在流式生成或后端调度中出现服务网络异常，GLM 可能返回 `finish_reason: "network_error"`。
   - 映射处理：`sensitive` 映射为 `ErrorCode.ContentRefused`；`network_error` 映射为 `ErrorCode.ProviderUnavailable (retryable: true)`。

4. **通义千问 DashScope 兼容模式** (`https://help.aliyun.com/zh/model-studio/`)
   - 内容审核失败形式：在请求前置检测命中安全风险时，DashScope 直接返回 HTTP 400（ErrorCode: `DataInspectionFailed`）；若在流式输出中途检测到涉敏，则中断流并返回 `finish_reason: "content_filter"`（部分场景下为包含拦截提示的 `"stop"`）。
   - Qwen3 思考模式开关参数：DashScope 通过扩展字段 `enable_thinking: true/false` 与 `thinking_budget: int` 控制深度思考模式。本工单已记录，不实现额外专有开关，保持标准 OpenAI 兼容参数传递。

5. **Ollama** (`https://github.com/ollama/ollama/blob/main/docs/openai.md`)
   - `/v1/models` 是否可用：完全支持，返回格式为标准 OpenAI 格式的本地模型列表。
   - 流式响应的 `Content-Type`：返回 `Content-Type: text/event-stream; charset=utf-8`（或 `text/event-stream`）。

6. `finish_reason` 映射原则落地：
   - `content_filter` / `sensitive` → 抛出 `IrisException(ErrorCode.ContentRefused)`，`ProviderId` 为当前 Profile Id。
   - `length` → 映射为 `TranslationFinishReason.Truncated`。
   - `insufficient_system_resource` / `network_error` → 抛出 `IrisException(ErrorCode.ProviderUnavailable, retryable: true)`。

## 3. 与工单的偏差

1. **`Stream_DataIsNotJson_ThrowsInvalidResponseWithInnerJsonException`**：
   在测试 SSE 传输非法 JSON 时，`JsonSerializer.Deserialize` 抛出的实际具体异常为 `System.Text.Json.JsonReaderException`（继承自 `System.Text.Json.JsonException`）。为保证断言契约的准确性，测试中使用 `ShouldBeAssignableTo<JsonException>()` 代替精准类型相等匹配。

2. **`HttpError_401EchoesApiKey_DetailRedactsKey`**：
   在 401 错误回显 API Key 的用例中，由于调用方传入了已知凭据 `new ProviderCredentials(myApiKey)`，`SecretRedactor.Redact(text, knownSecrets)` 优先执行已知密钥精准替换为 `"***"`，而非正则替换的 `"sk-***"`。因此断言验证为 `ex.Detail.ShouldNotContain(myApiKey)` 且 `ex.Detail.ShouldContain("***")`。

3. **`TestAsync_Success_ReturnsSampleAndLatency`**：
   测试中未显式推进 `FakeTimeProvider` 的虚拟时间，同步执行完成时 `Latency` 为 `TimeSpan.Zero`。因此断言调整为 `result.Latency.ShouldBeGreaterThanOrEqualTo(TimeSpan.Zero)`。

4. **超时与取消测试（`Timeout_HeadersDelayedIndefinitely_ThrowsTimeoutIrisException` 等）**：
   使用测试私有 `HttpMessageHandler`（`DelayingHandler`）代替 MockHttp 模拟无限等待，并暴露 `Entered` 信号源，确保在推进 `FakeTimeProvider` 虚拟时间之前请求已切实进入等待，彻底消除后台线程池调度延时造成的竞态测试失败。

5. **`ThinkTagStripperTests` 第 8 条验证方式**：
   工单要求“断言内部缓冲长度或耗时 < 1 秒二选一”。本实现采用耗时断言：输入 10,000 次分片、总计 1,000,000 字符的超长思考标签内容，执行耗时约 1ms，断言 `< 1 秒` 稳定通过。
