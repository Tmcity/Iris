## 二、实施内容总结

### 1. Platform.Windows 层热键与键映射
- **`NativeHotkeyAdapter.cs`** (`src/Iris.Platform.Windows/Hotkey/NativeHotkeyAdapter.cs`):
  - 基于 CsWin32 原生 P/Invoke 封装 `RegisterClassEx`、`UnregisterClass`、`CreateWindowEx`（HWND_MESSAGE）、`DestroyWindow`、`RegisterHotKey`、`UnregisterHotKey`、`DefWindowProc`、`GetCurrentThreadId` 等；
  - 维持活动 WNDPROC 委托强引用根（`_activeDelegates`）；严格在 `UnregisterClass` 实际成功（返回 true）时才移除委托引用，若 Win32 注销失败则继续保留，防止 GC 回收后系统回调悬空野指针（§7.1）；
  - 提供 `HasActiveDelegate(className)` 供生命周期断言。
- **`IHotkeyIdAllocator.cs`** (`src/Iris.Platform.Windows/Hotkey/IHotkeyIdAllocator.cs`):
  - 抽象热键 ID 分配器，生产默认单例 `DefaultHotkeyIdAllocator` 维护进程级单调递增计数器（`1..0xBFFF`），跨 `HotkeyService` 实例保证不复用已消耗 ID，满足进程级全局唯一性要求；
  - 支持测试注入隔离分配器，防止 ID 耗尽测试污染宿主进程配额。
- **`KeyNameMapper.cs`** (`src/Iris.Platform.Windows/Hotkey/KeyNameMapper.cs`):
  - 严格依据 96 键官方白名单（与 Microsoft VK 及 WPF KeyInterop 交叉一致）：A–Z (26)、D0–D9 (10)、F1–F24 (24)、NumPad0–9 (10)、Space/Enter/Tab/Escape/Insert/Delete/Home/End/PageUp/PageDown/Left/Up/Right/Down (14)、Snapshot (1)、Oem 系列 11 键；
  - 强制修饰键规则：至少一个有效修饰键，单独 Snapshot/F13–F24 除外；明确拦截非法单键、非法修饰位组合以及仅 Shift + 字母；
  - F12 支持映射（VK=0x7B），但 `ValidateBinding` 明确拦截返回 false，注册时拒绝；
  - 提供 `TryGetCanonicalKeyName`，非法/未知键规范化为 `"(无效键)"`，修饰键仅保留有效位，避免外部输入污染 UI 通知与日志（§7.5）。
- **`HotkeyService.cs`** (`src/Iris.Platform.Windows/Hotkey/HotkeyService.cs`):
  - 构造函数零 I/O、无 Win32 调用；
  - 首次有效启用注册时在 UI 线程创建自有消息窗口并绑定 `_ownerThreadId`；创建窗口前先行记录类归属，若创建失败且注销类回滚亦失败，保留类与所有者线程归属，供后续同线程重试清理；
  - 再次调用 `Register` 时：
    - 若已有所有者线程，先执行跨线程防御（`EnsureOwnerThread`），非所有者线程直接抛 `InvalidOperationException`；
    - 同线程若存在残留类，先重试注销旧残留类，注销失败则如实返回失败且不覆盖残留类，注销成功后再注册新类（§10）；
  - `Dispose()` 实现分步清理与幂等：未初始化或已销毁状态直接返回；先注销热键、再销毁窗口、最后注销窗口类；若中途失败保留状态供同线程重试清理；
  - `WndProc` 处理 `WM_HOTKEY`，检验注册 ID 存在性、`IsValid` 资格标记、Modifiers 及 VK 匹配，任何不匹配静默丢弃；
  - 异常安全隔离：WndProc 不抛出任何托管异常，捕获记录并返回 0。

### 2. App 宿主与协调层
- **`HotkeyCoordinator.cs`** (`src/Iris.App/Hosting/HotkeyCoordinator.cs`):
  - 仅对已交付 Handler 的动作（通过 `IActionHandler.Action` 过滤）注册热键，尊重 `Binding.Enabled`（ClipboardTranslate 默认禁用不注册）；
  - 订阅 `ISettingsService.Changed`，过滤与 Hotkeys 无关的更新；设置变更在 UI 线程串行合并，支持按键组合互相交换；
  - 维护 `_failedUnregisteredBindings`：旧项注销失败时保留记录、加入失败提示通知用户、阻止新组合注册，并在下次设置更新时优先重试注销（§7.4）；
  - 收到 `Pressed` 事件后：在锁内创建 `TaskCompletionSource` 登记到 `_activeDispatchTasks` 跟踪退出，立即切线程池异步执行 `IActionDispatcher.DispatchAsync`，`WndProc` 立即返回 0，业务绝不在 `WndProc` 栈内同步运行（§7.2）；
  - 退出屏障：`WaitForInFlightDispatchesAsync` 采用共享屏障任务，真实等待在途任务完成（§7.3）；
  - 两阶段退出：`AppBootstrapper` 先执行 `StopAcceptanceAndNativeAsync`（注销热键、销毁消息窗口、取消未开始动作），再配合设置/翻译窗口 Presenter 退出，最后通过 `WaitForInFlightDispatchesAsync` 观察已接纳分发任务收尾。
- **`AppHostBuilder.cs` & `AppBootstrapper.cs`**:
  - `HotkeyCoordinator` 注册为单例；
  - `AppBootstrapper` 编排热键启动与退出顺序。

### 3. 自检与复审场景修正
- **§7.1**: `NativeHotkeyAdapter.UnregisterClass` 仅在返回 true 时移除 WNDPROC 委托根。
- **§7.2**: `HotkeyCoordinator.OnHotkeyPressed` 离开 `WndProc` 栈分发，并在启动前就将分发任务加入跟踪集合。
- **§7.3**: `WaitForInFlightDispatchesAsync` 移除 3 秒吞异常超时，使用真实任务等待。
- **§7.4**: `HotkeyCoordinator` 旧项注销失败如实提示用户并记录待重试，下次变更优先重试。
- **§7.5**: `FormatKeyCombo` 严格规范化，未知/非法键安全回显为 `"(无效键)"`。
- **进程级 ID 分配**: `IHotkeyIdAllocator` 跨实例单调递增，测试使用隔离分配器。
- **§10 连续注册与归属**: `HotkeyService` 在创建失败回滚失败后再次调用 `Register`，同线程先注销旧类或拒绝新注册，跨线程直接拒绝，不覆盖类归属；销毁窗口成功/注销类失败后再次 Register 同样受所有者线程保护。
- **NativeMessageWindowTests**: 规范测试名为 `NativeHotkeyAdapter_CreatesAndDestroys_MessageWindow`，用 `try-finally` 确保 RegisterClass 后必定执行 UnregisterClass，真实断言 Win32 消息窗口创建与销毁。

## 六、与工单的偏差

1. **`Iris.Platform.Windows.csproj` 增加 `<InternalsVisibleTo Include="Iris.App" />`**：
   - 原因：`HotkeyCoordinator` 需要在展示失败通知时调用 `KeyNameMapper.TryGetCanonicalKeyName` 规范化键名输出（§7.5），避免用户设置中的未知/超长/非法字符串原样回显到 UI 通知与日志中。符合架构与安全设计。
2. **测试项目中既有 `AppBootstrapperTests.cs` 与 `AppHostBuilderTests.cs` 同步追加 HotkeyCoordinator 接线断言**：
   - 原因：工单要求 AppBootstrapper 编排两阶段退出顺序，AppHostBuilder 将 IHotkeyService 与 HotkeyCoordinator 注册为单例。更新了这两个测试类以匹配新增依赖并验证启动/退出调用顺序。原测试全部保留且通过。
3. **`NativeMessageWindowTests.cs` 测试重命名与作用域强化**：
   - 原因：按架构师要求，原测试仅测试了消息窗口与类的生命周期，未断言消息接收与可见性。重命名为 `NativeHotkeyAdapter_CreatesAndDestroys_MessageWindow`，并将 `try-finally` 提前至 `RegisterClass` 之后，严格保证类清理。
4. **`TranslateWindowViewModelTests.cs` 中 `AutoCopy_SameSessionStatusUpdate_DoesNotTriggerSecondAutoCopy_ManualCopyStillWorks` 轮询等待强化**：
   - 原因：原测试使用固定的 `Task.Delay(50)` 等待流式后台任务到达第 1 张卡片并触发复制。在全量 6 个测试项目并行执行的高负载环境下，50ms 可能在第 1 张卡片产出前超时。改为带 3000ms 超时的条件轮询（等待 clipboard.SetTextAsync 被调用），消除偶发竞态。
