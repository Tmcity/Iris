## 1. 目标

用户可以从托盘选择“输入翻译”或“剪贴板翻译”，通过真实 IActionDispatcher → Handler → 已验收 Presenter 进入翻译窗口；托盘左键单击执行输入翻译。完成通用 TranslateText 的 Payload 入口，为后续命令行/拖放复用。

T-015 已通过，保留会话、复制、布局和退出成果。本单不实现全局热键（T-017）、命令行解析/IPC（T-037）、划词、截图/OCR、悬浮球或历史 UI，也不提前宣称 M2/全产品完成。

## 2. 实施要求

1. Core/Workflows 新增 InputTranslateHandler、ClipboardTranslateHandler、TranslateTextHandler，实现已有 IActionHandler；AddIrisCore 幂等注册对应动作，保留 OpenSettingsHandler。不改公开签名或枚举，不注册未来动作占位类。
2. 按 TRANSLATION_ENTRYPOINTS.md 实施三个分支：InputTranslate 可见且活跃时 Hide，其余聚焦展示；Clipboard 先租约后读取，成功/空/安全错误均沿同租约发布；TranslateText 验证 Payload 并按 Trigger 映射 Origin，始终显式提交而不切换隐藏。
3. 取消、前置读取和租约 finally 遵循已验收生命周期；未接纳不工作，false 发布不兜底重开；不要让旧剪贴板异常经无身份的全局通知污染新会话。
4. TrayIconController 新增菜单项和实际左击命令接线，统一调用 Dispatcher；优先使用已核对的 TaskbarIcon.LeftClickCommand，不同时绑定重复入口。Trigger 使用现有 TrayMenu，无新枚举。菜单字符串走 UiText/资源约定。
5. 观察新增异步命令/事件完整 Task，固定安全日志；Dispose 后旧命令/菜单不再分发，事件解绑，构造/初始化不提前创建翻译窗口或访问剪贴板。正常退出期间已接纳的 Handler 读取由 Presenter 租约屏障继续持有。

空剪贴板规则、错误发布参数、来源映射等准确细节以正式 TRANSLATION_ENTRYPOINTS.md 为准，不另行猜测产品行为。没有新的 CCR 要求；遇到确需改公开端口的情况先列明，不能自行变更已落地契约。

## 二、实施内容

### 1. 三个 Core 动作 Handler 落地（`src/Iris.Core/Workflows/`）
1. **`InputTranslateHandler.cs`**：
   - 处理动作：`IrisAction.InputTranslate`；
   - 切换与展示逻辑：当 `_presenter.IsVisible && _presenter.IsActive` 时，调用 `await _presenter.HideAsync()` 退出；其余情况通过 `_presenter.TryBeginOperation(cancellationToken)` 获取租约；
   - 发布参数：`Text = context.Payload`（原样保留空白与换行，不手工 Trim）、`Origin = TextOrigin.Input`、`Anchor = context.Anchor`、`FocusInput = true`、`AutoTranslate = context.Payload != null`；
   - 租约生命周期：`using var operation` 确保调用方在 `TryShowAsync` 结束后安全归还调用所有权。
2. **`ClipboardTranslateHandler.cs`**：
   - 处理动作：`IrisAction.ClipboardTranslate`；
   - 严格先租约后读取：先调用 `_presenter.TryBeginOperation(cancellationToken)`，租约若为 null 则直接退出且绝不调用剪贴板；
   - 租约内读取与取消级联：向 `_clipboardService.GetTextAsync(operation.CancellationToken)` 传入租约取消令牌；
   - 三种结果安全发布：
     - 成功非空白文本：`Text = text`、`Origin = TextOrigin.Clipboard`、`AutoTranslate = true`、`FocusInput = false`；
     - `null` 或纯空白文本：`Text = string.Empty`、`Origin = TextOrigin.Clipboard`、`AutoTranslate = false`、`FocusInput = true`、`Error = new ErrorInfo(ErrorCode.InputEmpty, ErrorMessages.GetDefault(ErrorCode.InputEmpty))`；
     - 异常分支（`IrisException` 或未知异常）：仅记录安全日志（EventId = 1，包含 `ErrorCode` 和 `ExceptionType`，不记录正文、敏感信息或异常对象），发布 `Text = null`、`Origin = TextOrigin.Clipboard`、`AutoTranslate = false`、`FocusInput = false`、`Error = new ErrorInfo(...)`；
   - 安全边界：`TryShowAsync` 调用置于剪贴板读取的 `try-catch` 之外，杜绝发布失败被二次捕获为剪贴板错误而导致递归；未接纳时不分配新操作、不弹多余全局通知。
3. **`TranslateTextHandler.cs`**：
   - 处理动作：`IrisAction.TranslateText`；
   - 校验：`context.Payload` 为 null 或空白字符串时直接抛出 `IrisException(ErrorCode.InputEmpty, ...)`；
   - 来源映射：
     - `ActionTrigger.CommandLine` → `TextOrigin.CommandLine`；
     - `ActionTrigger.DragDrop` 或 `ActionTrigger.FloatingBall` → `TextOrigin.FloatingBall`；
     - 其余 Trigger → `TextOrigin.Input`；
   - 发布参数：`Text = context.Payload`（原文原样传递，保留换行与空格）、`AutoTranslate = true`、`FocusInput = false`、`Anchor = context.Anchor`。

### 2. 依赖注入注册（`src/Iris.Core/DependencyInjection/CoreServiceCollectionExtensions.cs`）
- 使用 `TryAddEnumerable` 将 4 个动作 Handler 以单例形式注册到 `IActionHandler`：
  - `OpenSettingsHandler` (`IrisAction.OpenSettings`)
  - `InputTranslateHandler` (`IrisAction.InputTranslate`)
  - `ClipboardTranslateHandler` (`IrisAction.ClipboardTranslate`)
  - `TranslateTextHandler` (`IrisAction.TranslateText`)
- 保证注册操作的幂等性，不注册占位类，不修改公开契约签名。

### 3. 托盘菜单与左键入口接线（`src/Iris.App/Tray/TrayIconController.cs`）
- 字符串约定：在 `src/Iris.App/UiText.cs` 中增加 `TrayMenuInputTranslate = "输入翻译"` 与 `TrayMenuClipboardTranslate = "剪贴板翻译"`；
- 菜单布局：在原有设置菜单项前依次插入“输入翻译”与“剪贴板翻译”菜单项并绑定 Click 事件；
- 左键入口：直接绑定 `TaskbarIcon.LeftClickCommand = _leftClickCommand`，执行输入翻译动作；
- 统一分发：通过 `IActionDispatcher.DispatchAsync` 分发对应动作，Trigger 标记为 `ActionTrigger.TrayMenu`；
- 异步观察与生命周期安全：
  - 在 `AsyncRelayCommand`（`src/Iris.App/Settings/RelayCommand.cs`）中暴露 `public Task? ExecutionTask { get; private set; }`，支持对分发任务的完整观察；
  - `TrayIconController.Dispose()` 中解绑菜单 Click 事件、解绑 `TaskbarIcon.LeftClickCommand` 与 ContextMenu，清空引用并刷新 `RaiseCanExecuteChanged`；
  - 构造与初始化阶段绝不触碰剪贴板服务，绝不提前创建或显示翻译窗口。

## 四、与工单的偏差

1. **`TranslationEndToEndTests` 中设置窗口配置 `HideOnDeactivate = false`**：
   - 原因：在全量自动化测试套件执行期间，多个测试类在同一 STA Dispatcher 线程并发交替执行，其他测试窗体激活导致原生 Windows 失焦事件（`Deactivated`）偶然派发给 TranslateWindow。根据规范，默认的 `HideOnDeactivate = true` 会在窗口失焦时触发 `HideAsync()`。在测试初始化阶段将 `s.TranslateWindow.HideOnDeactivate` 显式设为 `false`，确保在无头/并发测试套件中窗口状态不受外部焦点波动影响。
2. **`TranslationEndToEndTests` 中轮询条件修正**：
   - 原因：`cardToRetry.RetryCommand.Execute(null)` 及二次手动 `vm.TranslateCommand.Execute(null)` 触发后，后台协调器任务为异步调度，在 `i = 0` 时 `vm.IsTranslating` 尚未被后台线程置为 `true`。若仅以 `vm.IsTranslating` 为继续等待条件，循环将在第 0 次迭代过早退出。将等待条件补充为文本未就绪或正在翻译（`string.IsNullOrWhiteSpace(cardToRetry.Text) || vm.IsTranslating`），排除了微秒级竞态。
3. **既有测试中的 Mock 补全**：
   - `OpenSettingsHandlerTests.cs`、`TranslationOrchestratorIntegrationTests.cs`、`CoreRegistrationTests.cs` 等在构造或断言中增加了对 3 个新 Handler 及其依赖项（`ITranslateWindowPresenter`、`IClipboardService`）的注入支持，未删除任何原有业务断言或架构校验。
