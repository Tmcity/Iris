## 1. 范围与实施要点

本工单严格按照 `PROVIDER_SETTINGS_UI.md`、`SETTINGS_EDITING.md`、`PROVIDER_EDITING.md` 及 `tasks/current_task.md` 规范实现：

### 1.1 页面开放与导航
- 开放 `general` 与 `translation` 两页，未知或未开放的 pageKey（如 `ocr`、`hotkeys`）统一回退规范化为 `general`。
- 在 `SettingsWindow.xaml` 中完整接入两页导航切页逻辑，保留窗口全部草稿，窗口关闭或重新打开保持单实例。

### 1.2 翻译服务草稿与字段管理
- 实现 `TranslationProfileDraftViewModel`：
  - 维护单一 Profile 的完整草稿状态，跟踪字段 Dirty、版本号（`Revision`）。
  - 支持预设模板新建（含 CCR-012 批准的 DeepSeek 预设，BaseUrl 为 `https://api.deepseek.com`，SuggestedModel 为 `null` 保持手输/待选）。
  - 密码框安全隔离：仅在用户显式选择 `Replace` 时启用密码框录入，密码明文不进入日志、配置对象或异常。切换 Profile 或保存成功时自动清空密码框文本。
  - 校验区分：精确实现 `ValidateForSave()`、`ValidateForTest()` 与 `ValidateForListModels()`。模型列表仅校验端点/凭据/头字段，不受未完成的生成字段（如 Temperature/MaxOutputTokens/ChatCompletionsPath/Effort）阻止；保存与测试连接则严格校验模型与必要参数。
  - Claude 3.5 Haiku 选择时自动清空 `Effort` 并给出提示条；Anthropic 反代 BaseUrl 以 `/v1` 结尾时提示去除尾缀。

### 1.3 进程级待应用状态管理（`SettingsApplyReceiptManager`）
- 注册为 App 单例，最多容纳 32 个槽位（在途提交预留 + 待重试回执）。
- 提交前原子预留配额，满额时拦截 Core 调用并保留草稿提示用户重试；提交完成根据状态转化为待应用回执或释放槽位。
- 跨窗口会话持久保留回执，提供独立的“重试服务应用”与“重试开机启动”重试入口，重试成功安全移除回执。

### 1.4 异步草稿操作节流队列（`SettingsDraftOperationQueue`）
- 每个窗口会话拥有独立的草稿操作队列：最多 1 个在途测试/模型列表任务 + 最多 1 个最新等待项。
- 新请求自动取消旧等待项并等待在途任务退出，避免无限制任务排队。
- 每次操作关联会话代次、Profile ID、Revision 与自增请求序号，丢弃所有过期、切项或删除产生的迟到回调。
- 完整接入窗口与应用退出生命周期，退出前通过 `DrainAndCancelAllAsync()` 排干并取消所有排队与在途工作。

### 1.5 全窗口联合保存接线（`GeneralSettingsSaveCoordinator` & `SettingsViewModel`）
- 彻底废除直接调用 `ISettingsService.UpdateAsync` 的独立常规保存路径。
- 统一组装 `SettingsEditPlan`，包含常规设置字段补丁（Theme、LaunchAtStartup、ShowStartupNotification、LogLevel）、Profile 增删改集合、凭据编辑意图（Keep/Replace/Clear）与顺序调整变更（`TranslationOrderChange`），委托 `ISettingsEditCoordinator.CommitAsync` 联合提交。
- 保存前抓取未失焦输入（`FlushFocusedBinding()`），冻结界面入口，排干草稿队列。
- 提交后根据 Core 结果统一处理：`Applied` 重建基线清明文，`ApplyPending` 登记进程回执并保留重试，`Uncommitted` 保留本地草稿并标明冲突或错误原因。
