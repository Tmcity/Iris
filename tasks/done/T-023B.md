## 2. 实施范围

### Core 五字段增量与一次提交

将 specs/CONTRACTS.cs 预置的 SelectionSettingsPatch 和 SettingsEditPlan.Selection 同步到 Core SettingsEditingModels。保留原 positional 构造/解构、公开方法和安全 ToString；不修改持久化 DTO/JSON/default/schema/normalizer。

在实际 SettingsEditCoordinator 的现有流程中增加 selection 捕获、Target 校验/规范化、staging 前冲突检查、UpdateAsync mutate 内冲突复验及字段应用。两个列表 Base/Target 均在首次 await 和获取 gate 前独立复制。Base/Current 保留实际原始语义，进程比较忽略大小写/顺序/重复，但不 Trim，null 与 [] 不等；ReadOrder 顺序重要。只有显式进程 Target 才 Trim、校验文件名、去重并保留首项顺序/大小写；不将路径转换为文件名，不过滤非法目标后冒称成功。

五字段只覆盖明确编辑项，在最新 Selection 上应用，保留鼠标/其它字段；未编辑坏值不阻止其它页。Current 已等于目标时返回原实例，避免无意义版本/Changed。Selection 与 General/Provider/凭据/排序/Hotkey 共用一次现有 UpdateAsync；selection-only 及非 Provider 混合不做凭据 staging、Provider 观察者刷新或 pending 配额操作，不触发 Reader/按键/UIA。

### App 草稿、页面与快捷键

新增 SelectionSettingsDraftViewModel 管理五字段独立 Base/Target/dirty、文本数字验证、错误、合并与冻结。超时和进程列表以文本绑定，PropertyChanged 立即将输入纳入草稿，避免未失焦输入被外部 Current 更新覆盖；保存前仅刷新存在待提交值的 binding，避免将未更新的控件旧值写回新的草稿。整数校验针对当前文本，空/非整数/越界不会保存旧整数。

SettingsViewModel 将 Selection 纳入 IsDirty/no-op、同步 UI 计划捕获、全页冻结/解冻、外部 Changed 合并、Reload，以及所有已保存状态的基线推进。Uncommitted 保留草稿；Provider/自启已保存待应用也更新 selection 基线；重试不清除后续未保存 selection 草稿。复用现有 GeneralSettingsSaveCoordinator、SettingsWindowSession 的完整退出屏障，无独立页面写盘路径。

启用 selection 导航，提供四种读取顺序、复制后等待时间、恢复剪贴板、每行一个的禁止复制进程及无选区时打开输入框。显示复制安全、外部更新保护和关闭恢复的影响；不开放鼠标字段或测试读取按钮。内容纵向滚动，数字/进程错误使用页内和共享状态。

快捷键草稿增加已交付 SelectionTranslate 行，复用实际 HotkeyItemDraftViewModel / HotkeyRecordingCoordinator / HotkeyCaptureService。该行不再被旧“未开放预留动作”分支视为与自身冲突；其它预留规则保持。未修改默认 Ctrl+Alt+D。
