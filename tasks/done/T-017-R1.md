## 2. R1-1：设置队列最后一次更新不能丢失

基线 HotkeyCoordinator.cs:257–272 存在明确交错：处理线程在锁内取到 pending=null，退出锁；后台 Changed 此时写入新 pending，但看到 isProcessing=true 而不调度；原线程 finally 再设 false。最后一份配置留在 pending 中，无任何消费者，直到后续额外变更才可能处理。这是静态可达交错，未声称已经做运行时复现。

将“确认没有待处理快照”与“交还处理资格”置于同一锁内原子转移；停止、异常及任务调度失败同样不能遗留永远为 true 的处理标记。当前 InvokeAsync 的返回 Task 被丢弃，回调执行前的调度失败没有收尾路径；须观察、安全记录类型并保留可恢复状态，不使用无限自动重试。正常路径继续保持最多一个消费者和一个最新快照，原生操作仍在 owner UI 线程。不能用全局禁用并行或等待固定时长来规避竞态。

回归要覆盖：消费者即将空闲时后台提交最后一份；多次后台变化仅最新快照最终生效；调度首次失败后下一次有效变化能够应用；停止后待处理快照不注册。测试接缝应足够窄，不在测试里另写参考实现替代实际协调器。

## 二、整改实施详情

### 1. R1-1：设置更新队列原子状态转移与代次隔离（`HotkeyCoordinator.cs`）
- **原子交还处理资格**：
  - 彻底重构 `ProcessPendingSettingsAsync` 消费循环，消除“退出锁取得 null 后、进入 finally 清除标记前”的交错窗口。
  - 在 `lock (_gate)` 中同步判断 `_isStopped || _dispatchGeneration != generation || _pendingSettings == null`；若确认已无待处理快照，原子置 `_isProcessingSettings = false; _dispatchedSettings = null;` 并直接 return。
- **代次保护（Generation Tracking）与并发隔离**：
  - 引入 `long _dispatchGeneration` 单调递增计数器与 `_lastStartedExecutionGeneration`；
  - 每次调用 `ScheduleProcessingLocked()` 时原子递增代次，并将调度代次传递给消费任务；
  - 挂接 `dispatchTask.ContinueWith(t => OnDispatchCompleted(generation, t))`：
    - 若 `_dispatchGeneration != generation`（已有更新的代次接管），旧任务的回调直接安全退出，绝不误清除新消费者的 `_isProcessingSettings` 标记；
    - 对未开始执行即发生故障或取消的任务（`wasExecutionStarted == false`），记录安全脱敏日志 `LogDispatchSettingsFailed`（EventId=6，仅记录异常类型名）；
    - 若有积压的待处理快照且与已调度快照不同，自动拉起新快照调度；若无新快照，安全清除资格并释放标记，绝不无限重试同一失败快照。
- **停止清理**：
  - `StopAcceptanceAndNativeAsync` 与 `StopSynchronousFallback` 均在锁内推进代次、清空 `_pendingSettings` / `_dispatchedSettings` 并重置 `_isProcessingSettings = false`，保证停止后待处理快照不被调度。

### 2. R1-2：真实组件端到端集成测试与健壮退出屏障
- **提取通用共享测试替身**：
  - 新建 `tests/Iris.App.Tests/TestSupport/FakeNativeHotkeyAdapter.cs`，供 `HotkeyCoordinatorTests` 与 `AppBootstrapperTests` 共享复用，消除重复声明。
- **真实组件链路集成测试（`HotkeyCoordinatorTests.cs`）**：
  - `RealIntegration_HotkeyTrigger_RunsOnOwnerUiThread_AfterLeavingWndProc`：
    - 组合：真实 `HotkeyCoordinator` + 真实 `HotkeyService` (带 fake native) + 真实 `WpfUiDispatcher` + 真实 `ActionDispatcher` + 真实交付的 `InputTranslateHandler` + 真实 `TranslateWindowPresenter`（fake operation）；
    - 验证点：触发合成 `WM_HOTKEY` 进入分发链路，严格断言 `ActionContext.Trigger == ActionTrigger.Hotkey`，Handler 确实在 WPF UI 调度线程上执行（`executedOnUiThread == true`），并且 Handler 开始执行时已彻底离开 `WndProc` 调用栈（`executedInsideWndProc == false`）。
- **非合作前置读取与退出顺序屏障测试（`AppBootstrapperTests.cs`）**：
  - `StopAsync_RealClipboardTranslateHandlerAndPresenter_WithUncooperativeClipboard_HoldsHostStopUntilReleased`：
    - 组合：真实 `AppBootstrapper` + 真实 `HotkeyCoordinator` + 真实 `ClipboardTranslateHandler` + 真实 `TranslateWindowPresenter` + 模拟挂起不合作的 `IClipboardService`（忽略取消令牌直到显式 release）；
    - 验证点：触发剪贴板热键后，剪贴板读取进入并挂起；发起 `bootstrapper.StopAsync()`：
      1. 第一阶段：原生热键与准入立即注销（`fakeNative.UnregisteredHotkeys.Count > 0`）；
      2. 屏障拦截：在剪贴板放行前，`Host.StopAsync` 绝不执行，`bootstrapper.StopAsync()` 保持挂起；
      3. 拒绝重开：在 Presenter 退出阶段，迟到/排队的动作尝试 `presenter.TryBeginOperation(...)` 严格返回 null，绝不重开窗口；
      4. 放行收尾：放行剪贴板后，整个退出序列全部顺利执行完成，`hostStopFinished == true`。
  - `StopAsync_StopsHotkeyCoordinatorFirst_AndDrainsDispatchesBeforeHostStop`：
    - 真实注入在途分发任务并在其执行期间挂起；
    - 启动退出，验证调用顺序严格为 `hotkey_native_dispose` 先完成，但在途任务未放行前 `host_stop` 与 `app_shutdown` 绝不提前执行；放行后严格按序全部完成。
- **资源与闸门健全性保障**：
  - `AppBootstrapperTests` 中所有阻塞闸门（`release.Set()`、`inFlightRelease.TrySetResult()`、`clipboardRelease.TrySetResult()`）与清理操作均放在 `finally` 块中执行，并 await 退出任务收尾，杜绝未处理异常与资源泄漏导致测试假死或脏状态泄漏。
