## 2. 唯一阻断问题：失效图标保持可见且到期不消失

实际 Controller + monitor + Coordinator + Composite + WPF Window，fake 仅在 external placement 的第二次 SetWindowBounds(show=true) 返回 false。首次定位、真实 Window.Show 已成功。当前 VisualLoop catch 清空 candidate/visible 标记并报告错误，却没有收起已经显示的窗口；timer 回调发现 candidate=null 后不隐藏。

PARTIAL_SHOW_RETRY windowsClosed=True nativeHandles=0 threadAlive=False

## 3. 修复与回归

1. 任一显示/定位步骤在实际可见之后失败，须在 UI 线程收起本次失败显示，撤销其缓存和期限责任，再发布稳定失败状态。不能只清托管标记，也不能依赖用户再次点击/切换模式或一次早已失效的 timer 才隐藏。
2. 失败清理只撤销自己的候选/显示代次。若期间已有新候选/配置，不得无条件清空新候选、覆盖新状态或误取消新翻译；先收起旧失败显示，再允许后续合法请求展示。
3. Hide/Close 等收尾也失败时，保留该 view/尚未完成的 timer/UI 责任与可操作重试；安全保留原显示失败和清理阶段，不泄露正文/标题/原始异常。不得遗忘 HWND 或无限排队自动 Show 重试。
4. 补实际 Window/Controller 与 fake external native 的对照：第一步定位失败（未显示）、Show 后异常、第二次定位失败；错误状态发布后与超过 IconAutoHideMs 后均无失效可见图标；旧 Click 不翻译；清理失败责任保留、同实例重试、后续新候选/Mode.Off/应用退出正常。
5. 保留原独立反例逻辑。测试门闩先确认 entered，finally 先放行再等全部实际任务/线程/窗口退出，同时保留主/清理异常。若局部清理新增期望失败，不能在 finally 提前 await 一个仍需要未释放门闩的任务。
