### 3.1 初始代次与生命周期序列
- `Generation_InitialState_IsZero_ForEnabled_Disabled_AndZeroCapacity`：验证初始启用、初始禁用、初始容量 0 三种情况下 `cache.Generation == 0`。
- `Generation_LifecycleSequence_Clear_CapacityZero_AndToggle_IncrementGeneration_AndRejectStaleWrites`：验证首次 `Clear()` 递增至 1、过期代次 0 写入被拒、容量从 500 变 0 递增至 2 并清空、容量从 0 变 500 递增至 3、禁用缓存递增至 4 并清空、重新启用递增至 5 的完整代次序列。

### 3.2 单条边界与总字节预算淘汰
- `SingleEntry_ExactMaxEntryBytes_IsAdmitted_AndOverByOneCodeUnit_IsRejected`：验证成本恰好等于 `MaxEntryBytes (1,048,576 字节)`（文本长度 524,095 字符）可被接纳，超出一个 UTF-16 code unit（524,096 字符，1,048,578 字节）返回 `false` 且不影响原缓存。
- `TotalByteBudget_ExactMaxTotalBytes_IsRetained_AndAdditionalEntryEvictsLruTail_BeforeCapacityReached`：在 `CacheCapacity = 500` 下插入 16 条 1 MiB 项，总成本恰好达到 `MaxTotalBytes (16 MiB = 16,777,216 字节)`。条数（16）远未达到容量（500），16 条全部保留；插入第 17 条小项时，容量未满，仅因总字节超额触发 LRU 淘汰最久未访问的第一条项。
