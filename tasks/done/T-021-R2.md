## 一、实施概况与测试收尾修复

严格遵循工单要求，生产代码（`src/`）与公共契约（`specs/CONTRACTS.cs`）保持**严格零改动（0 diff）**，仅调整测试中的资源所有权与清理作用域：

### 1. 修复隐式 await using 与闸门放行死锁
- **根本原因**：在 `KeyboardSimulatorUiDispatcherTests.cs` 中，`simulator` 原本通过 `await using var simulator = ...` 在 `try` 块内声明。当测试体抛出异常或断言失败展开时，编译器生成的 `DisposeAsync()` 优先于外层 `finally` 执行。`DisposeAsync()` 内部调用 `StopAsync()` 等待在途的 `copyTask`，而 `copyTask` 正在 `SendInput` 中同步等待 `SendReleaseTcs`。由于 `SendReleaseTcs.TrySetResult()` 位于外层 `finally` 中，形成了循环等待死锁。
- **修复方案**：
  - 彻底移除 `await using var simulator` 隐式清理。
  - 在内部委托的 `finally` 块中严格按确定顺序执行收尾：
    1. **优先放行闸门**：`fakeNative?.SendReleaseTcs.TrySetResult();`
    2. **等待在途任务结束**：`if (copyTask != null) await copyTask; if (stopTask != null) await stopTask;`
    3. **显式释放模拟器**：`if (simulator != null) await simulator.DisposeAsync();`
    4. **结束 Dispatcher**：`dispatcher.BeginInvokeShutdown(DispatcherPriority.Background);`
  - 若测试体与清理过程均抛出异常，使用 `new AggregateException(caughtEx, ex)` 组合，确保原测试体错误与清理错误同时可见，不被吞没。

### 2. 外层超时路径与 STA 线程强退出保证
- 在测试主线程的 `finally` 块中加入兜底放行：`fakeNativeRef?.SendReleaseTcs.TrySetResult();`。
- 随后执行 `thread.Join(3000).ShouldBeTrue("WPF STA 线程应在完成调度后正常退出");`，保证即使发生超时也不会将活跃线程残留给进程退出。

### 3. 补充确定性失败路径回归测试
在 `KeyboardSimulatorUiDispatcherTests.cs` 中新增 2 个确定性失败路径用例：
1. `CopyAsync_WhenTestBodyFailsWhileNativeSendBlocked_ReleasesGateAndExitsCleanlyWithoutDeadlock`：在 `SendEnteredTcs` 触发后、闸门仍关闭时主动抛出测试体异常，验证捕获到的异常确为注入的异常（不被 `TimeoutException` 替代），STA 线程在 3 秒内安全退出，不发生死锁。
2. `StopAsync_WhenTestBodyFailsWhileNativeSendBlocked_ReleasesGateAndExitsCleanlyWithoutDeadlock`：在 `SendEnteredTcs` 触发后、`StopAsync()` 正在等待时主动抛出测试体异常，验证捕获到的异常为原异常，STA 线程安全退出。
