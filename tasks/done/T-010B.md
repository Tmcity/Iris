## 1. 背景与目标

当前 ISettingsService.Current 只在接口上只读。架构审查已实测：UpdateAsync 后修改原 ExtraHeaders 字典会悄悄改变 Current，不触发 Changed、不写盘；`Current with { }` 的浅草稿也能通过底层字典修改热键。

目标是让服务发布的所有版本成为稳定的深度不可变快照，保证磁盘、Current 与 Changed 事件内容一致，为后续 Registry 构建提供可信输入。本单不实现 Registry、配置/密钥联合提交、设置 UI 或事件派发重构。

## 2. 必读规范与授权

## 4. 快照构建要求

### 4.1 复制所有可变集合，封装前先取得所有权

构建器接收已经满足现有规范化规则的 AppSettings，创建可安全发布的对象图。它不负责修复坏值、不写文件、不发事件、不记修复日志。

| 集合路径 | 要求 |
|---|---|
| Hotkeys | 复制字典后只读封装；保留绑定与枚举顺序 |
| Translation.Providers | 复制列表；隔离每个 Profile 中可能存在的 ExtraHeaders |
| Translation.CustomPrompts | 复制列表；PromptTemplate 的不可变叶节点可以共享 |
| Translation.Providers[*].OpenAIOptions.ExtraHeaders | 非 null 时复制并只读封装，按 Ordinal 键规则；即使当前 Kind 为 Anthropic，也不能漏掉存在的集合；null 保持 null |
| Ocr.Providers | 复制列表；只含不可变值的 Profile/Options 允许共享 |
| Selection.ReadOrder | 复制列表，保留顺序 |
| Selection.ExcludedProcesses | 复制列表，保留顺序 |
| Selection.ClipboardUnsafeProcesses | 复制列表，保留顺序 |

- 输入即使已经是 IReadOnlyList/ReadOnlyDictionary，也不能据此认定底层无人可改；须复制。只在普通 List/Dictionary 外套一层只读包装会保留外部别名，不满足本单。
- 字符串、readonly 值类型以及只含不可变值的 record 可共享，不要求无意义地复制所有叶节点。
- 推荐 `Array.AsReadOnly(复制后的数组)`、`ReadOnlyDictionary(复制后的字典)`；不暴露底层数组/字典。不要引入生产反射、序列化往返克隆或新的序列化转换器。
- 不排序、不合并键、不折叠大小写，不把可空字段替换为空集合；正常配置的序列化字节与本单前保持一致。

### 4.2 覆盖五处发布位置

以下位置均在当前 JsonSettingsService 中真实存在，必须逐一接入：

1. 构造函数的 `_current = new AppSettings()`：LoadAsync 之前的默认 Current 也必须只读，不产生 I/O。
2. 文件不存在的首次加载：序列化、写入和发布使用同一默认快照。
3. 正常加载：Normalize 后捕获快照，再生成 formattedJson 并发布；包括发生修复/迁移以及较新版本不回写的既有分支。
4. 损坏恢复：默认值先构建快照，再按既有顺序发布/写入；保留原来的 SettingsCorrupted 与恢复失败语义。
5. UpdateAsync：Normalize 后捕获快照，再序列化、比较、写盘、发布，Changed 的 NewSettings 必须是实际发布的对象。

快照捕获必须在序列化和 await 写盘之前完成，不能“先写 raw DTO，之后才复制成 Current”。保持 Volatile.Read/Write、锁、取消、回滚及事件顺序。

### 4.3 保持既有无操作与读访问语义

- Current getter 继续读取已发布引用；同一版本重复读取为同一实例，不按访问次数分配快照。
- mutate 返回同一 Current 实例时仍直接返回；深度等值、序列化结果完全相同时不写盘、不发事件，并保留原 Current 引用。
- SettingsNormalizer 在无需修复时返回原输入的行为保持不变；只读封装由独立快照构建器完成，不能破坏其已有测试。
- 以后要编辑的草稿集合应重新创建；对已发布集合通过可变接口尝试实际修改必须失败或不可表达，且不能影响状态。
- 本单不承诺在调用方并发改写输入 DTO 的情况下完成无锁捕获；调用方应在 UpdateAsync 完成前保持草稿稳定。完成后可随意修改原输入集合，不影响已发布快照。

## 5. 必须验证的行为

1. **输入别名隔离**：用调用方持有的 List/Dictionary 构造设置并 UpdateAsync；成功后更改所有原列表、热键字典和 ExtraHeaders，断言 Current、已保存的事件快照与文件内容不变，Changed 数量不增加。包含 ReadOnlyDictionary 包着调用方字典的输入。
2. **不可原地编辑**：通过集合支持的可变接口尝试替换/增加/移除元素，不能改写已发布值；不把某个具体集合实现类型写成契约。
3. **生命周期覆盖**：Load 之前、首次生成文件、已有正常文件、挽救后加载、损坏恢复（捕获 SettingsCorrupted 后）、普通更新后的 Current 均检查相关集合。较新版本加载仍不回写原文件。
4. **旧版本稳定**：保留第一次 Current 和 Changed.OldSettings/NewSettings 后再次更新；旧版本值不变，新版本按新值发布；修改尝试不能影响后续订阅者。
5. **无操作更新**：相同引用与相同 JSON 两种情况都无写盘、无事件、Current 引用不变；不要改成 record.Equals 作为内容相等判断。
6. **失败路径**：复用现有临时文件锁/取消测试验证 UpdateAsync 失败时 Current 和文件不变；额外覆盖 mutate 内尝试修改旧集合或抛异常，后续合法更新仍成功。
7. **序列化兼容**：同一有效 DTO 在快照化前后的 IrisJson 输出一致；文件往返后数值/集合顺序正确；null ExtraHeaders 仍为 null，空集合仍为空集合。
8. **字段覆盖**：测试可用反射维护 AppSettings 可达集合路径清单，避免今后增加集合却漏冻；生产实现不使用反射。测试以行为与覆盖范围为准，不镜像私有实现代码。

现有 SettingsNormalizer 的“无修复返回原引用”、设置加载/挽救/迁移、50 路更新及事件顺序等测试应继续通过。只有确因旧测试依赖非法原地修改行为而需要调整时，才改对应测试并在报告中逐项说明，不能弱化事件/持久化断言。

### 3.2 五处发布位置接线详情

1. **位置 1（构造函数默认值）**：
   `_current = SettingsSnapshot.Create(new AppSettings());`
   确保在调用 `LoadAsync` 之前，默认 `Current` 即为深度不可变对象，不触发 I/O。
2. **位置 2（文件不存在首次加载）**：
   `var defaults = SettingsSnapshot.Create(new AppSettings());`
   默认快照先构建，再统一用于序列化写入磁盘与 `Volatile.Write(ref _current, defaults)`。
3. **位置 3（正常加载 / 挽救 / 迁移 / 较高版本不回写）**：
   规范化后执行 `var snapshot = SettingsSnapshot.Create(normalized);`，再序列化为 `formattedJson`。
   磁盘回写（如有必要）、`Volatile.Write(ref _current, snapshot)` 及日志均使用快照。
4. **位置 4（损坏恢复）**：
   备份损坏文件后执行 `var defaultSettings = SettingsSnapshot.Create(new AppSettings());` 并发布。
5. **位置 5（UpdateAsync）**：
   在互斥锁保护下：
   - 执行 mutate 与 Normalize；
   - 执行 `var snapshot = SettingsSnapshot.Create(normalized);`；
   - 序列化 snapshot 并与 `_currentJson` 比较（无操作则退出）；
   - 原子写盘；
   - `Volatile.Write(ref _current, snapshot);`；
   - 同步派发 `new SettingsChangedEventArgs(oldSettings, snapshot)`。
