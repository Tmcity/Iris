## 1. 范围与实施要点

本轮修改严格限定在 `src/Iris.Core/Settings/SettingsEditCoordinator.cs` 的捕获、错误隐私、校验与重试屏障收尾，未修改任何公共契约签名，不改动配置格式或预设，不扩大到 UI / T-018，测试中禁止真实联网。

### 1.1 R2-1：持有编辑权直到真实 Get 完成
- 在 `ResolveDraftCredentialsAsync` 中，将后台异步读取 `Task.Run` 包含在短串行锁 `_gate.WaitAsync` 保护区内。
- 只有在后台 `ProviderCredentialResolver.Resolve`（即底层 `SecretStore.Get`）真实完成并取得独立 `ProviderCredentials` 后，才释放 `_gate`。
- 取消时观察后台读取任务退出后，再释放所有权。
- 瞬态 Provider 创建（`CreateTransientAsync`）与网络调用保持在锁外，避免长时间持有编辑锁。
- 彻底消除了 Keep 读取与合法 Replace 提交之间的竞争（探针中挂起 Get 时并发提交被阻塞，网络阶段并发提交成功完成）。

### 1.2 R2-2：所有草稿错误路径脱敏与安全错误边界
- `TestDraftAsync` 脱敏：解析异常与底层异常绝不将 `ex.Message` 直接作为 `ErrorInfo.Message`；使用固定安全文案（如“服务凭据解析失败”、“无法创建服务实例”），`Detail` 仅包含操作名称或异常类型（如 `ex.GetType().Name`）。
- `ListDraftModelsAsync` 脱敏：结构校验、草稿校验、凭据解析及 Provider 模型发现调用均置于安全错误边界中。包装抛出 `IrisException` 时，剥离 `InnerException`（置为 `null`），确保异常链与 `ToString()` 绝不外泄敏感 marker。
- 日志安全：异常日志仅记录异常类型名称，不把原始异常对象传入可能格式化敏感内容的日志槽位。

### 1.3 R2-3：补默认值保留未编辑字段，校验按操作区分
- `WithDefaultOptions` 修复：移除强制将另一 Kind 的 Options 置 `null` 的赋值，仅补齐并深拷贝当前 Kind Options，完整保留未编辑的隐藏配置字段。
- 草稿准入校验（`ValidateDraftStructure` & `ValidateDraft`）：
  - 拒绝空草稿 ID；新草稿（`BaseProfile == null`）严格按 `NewProfileIdRegex()`（`^tp-[0-9a-f]{12}$`）校验且禁止指定 `CredentialSetId`。
  - 已有草稿严格核对 `draft.Profile.Id == draft.BaseProfile.Id` 以及 `draft.Profile.CredentialSetId == draft.BaseProfile.CredentialSetId`，防止任意篡改引用或偷换身份。
- 按操作区分校验：
  - 翻译测试（`isTranslationTest == true`，即 `TestDraftAsync` 与 `CommitAsync`）：必须校验模型非空、生成参数合法性、显式 `PromptTemplateId` 存在性，以及 Haiku 模型对 Effort 参数的限制（必须显式为 `null`）。
  - 模型列表发现（`isTranslationTest == false`，即 `ListDraftModelsAsync`）：跳过模型名、PromptTemplateId 及生成参数校验，允许合法端点与凭据的 Haiku 服务正常执行模型发现。

### 1.4 R2-4：未完成的清理重试重新建立当前屏障
- `RetryApplyAsync` 修复：对于未彻底完成的回执，无论其历史上 `ObserversCompleted` 是否为 `true`，每次重试均无条件调用 `RefreshObserversAsync()` 重新建立当前观察者屏障。
