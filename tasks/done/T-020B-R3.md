## 2. R3-01：普通开始/录入失败不能锁住设置窗口

**真实反例**：让当前 BeginAsync 失败而 StopAsync 回滚成功，实际 VM 最终为 IsAnyRecording=true、录入控制器 IsRecording=false、HasFailedRecordingCleanup=false、CanEdit=false、重试命令不可用。原因是 StartRecordingAsync 以 caughtEx!=null 一律保留活动行/任务，把普通错误等同于清理未完成。

1. 区分开始/逻辑录入失败和物理清理失败。清理已成功的失败应释放本次 VM 活动身份与任务，保留此前草稿，显示安全错误，允许用户在**同一窗口**再次录入；不能要求关窗重开，也不能仅修改提示文本而仍冻结。
2. 真正清理失败继续保留当前 owner、结果和重试资格，不能为了修普通错误回退到吞掉清理失败或提前释放 scope。
3. 平台已返回 session 之后的失败按正式结果协议发布 HotkeyCaptureResult(Outcome=Failed, Binding=null, Error=安全错误)，不能用 Completion.TrySetException(ex) 代替 Failed，也不能把原始异常对象/消息暴露给结果消费者。Begin 自身未能开始时仍按既有安全异常规则处理。
4. 验证 Begin 原生失败/前台校验失败、已开始后的逻辑 Failed、取消与真实清理失败分别收尾；普通失败后立即在同窗口成功录入，旧草稿不被错误修改。测试至少一次使用真实平台 service + fake native 的失败结果，而非只用一个已成功 fake session。

## 3. R3-02：重试只能应用本次 context 的结果

**真实反例**：InputTranslate 成功录入 Ctrl+Shift+X；随后 ClipboardTranslate 的 Begin 失败且回滚首次失败；撤除故障后执行 VM 的重试命令，ClipboardTranslate 被写入上次 InputTranslate 的 Ctrl+Shift+X。R2 的 RetryCleanupAsync 已返回本次 nullable 结果，但 VM 忽略返回值，清理后读取全局 LastCapturedResult，回放了旧值。

1. VM 使用本次重试返回的、与仍有效 owner/session 关联的结果。没有本次 Captured/Cleared 就不修改本行；不能从全局历史 LastCapturedResult 补值。
2. 清理成功与候选发布之间再次校验窗口/行/录入身份。关闭或换 owner 后只清理资源，不能回写旧草稿；重试过程不得允许新 context 偷换目标。
3. 给出两个动作/两个 context 的真实 VM 回归：前次成功 → 本次 Begin 失败+回滚失败 → 重试成功，本次原草稿保持；另验证同一 context 的有效 Captured/Cleared 经清理重试后仍正确应用一次。

## 4. R3-03：服务级停止和所有消息循环终态

**真实反例**：订阅者已进入且被闸门阻塞时，IHotkeyCaptureService.StopAsync 已成功返回，但订阅者尚未退出；session.Dispose 的等待修好了，服务级 Stop/DisposeAsync 仍只等 native 清理。另在尚未请求停止时模拟 GetMessage=0，线程退出后 Completion 仍 pending、hook 仍活跃。

1. 服务 StopAsync/DisposeAsync 与 session.DisposeAsync 共享本次完整收尾屏障，覆盖 native、回调、通知 worker 和已安排的自有收尾工作；全部结束之前不释放 active owner 或允许新 Begin。不能令 service.Stop 与 session.Dispose 相互等待形成环。
2. GetMessage=0/WM_QUIT 只有在本次已请求正常停止时才属于正常退出；否则结束逻辑结果并按安全失败协议启动/观察清理，不遗留 pending Completion 与 hook。
3. 保留 R2 的安装屏障、失败投递检查、委托阶段释放和不重复卸载。GetMessage=-1/抛异常的清理成果保留，只补齐 Failed 结果与全部终态的一致性。
4. 用实际服务验证：慢订阅者阻塞时服务 Stop/Dispose 都 pending，新 Begin 不被接纳；放行后全部完成；正常停止的 0 返回、异常 0、-1、异常、失败后重试分别有真实退出断言。finally 放行并 await 被测任务，不能用测试进程结束代替清理。

2. R2 的 W04 当前生成的 Light 图出现近白字叠近白底、局部深色资源残留，虽然全部哈希不同且测试通过。纠正测试主题设置，使用产品同款资源与明确主题生命周期，检查实际文字对比度；测试专用 window resource 覆盖不能掩盖全局资源污染。

## 二、修复内容详细落实

### 1. R3-01：普通开始/录入失败恢复（不锁死设置窗口与 ViewModel）
- **区分逻辑失败与物理清理失败**：
  - 在 `src/Iris.App/Settings/SettingsViewModel.cs` 中，`StartRecordingAsync` 捕获异常后，仅在 `HasFailedRecordingCleanup == true`（即物理卸载/停止原生资源失败）时保留活动项与任务供重试；
  - 若物理清理已成功（`!HasFailedRecordingCleanup`），在 `finally` 块中重置 `_activeRecordingItem = null`、`_activeRecordingTask = null`、`workTcs.TrySetResult()`，恢复 `CanEdit = true`、`CanSave` 与所有命令的可执行性，原草稿保持完好，并在该项上显示安全错误信息（`item.DraftError`），允许用户在**同一窗口**中直接再次点击录入；
  - 真正物理清理失败时，继续保持 `HasFailedRecordingCleanup == true`、保留活动项与 DI 作用域，展示重试按钮供用户重试清理。
- **平台会话正式 Failed 协议**：
  - 在 `src/Iris.Platform.Windows/Hotkey/HotkeyCaptureSession.cs` 中，`Fail(Exception ex)` 从原有的 `_completionTcs.TrySetException(ex)` 改为正式契约结果协议：
    `_completionTcs.TrySetResult(new HotkeyCaptureResult(HotkeyCaptureOutcome.Failed, Binding: null, Error: errorInfo))`；
  - 规范包装 `ErrorInfo`，提取安全错误码（`IrisException.Code` 或 `ErrorCode.Unknown`）及安全提示，不向外部结果消费者泄漏底层平台原生细节；
  - 区分 Begin 未返回 session 时的原生/校验异常，与已返回 session 后的逻辑 Failed 结果。

### 2. R3-02：重试结果严格归属于本次 Context（消除跨动作旧结果回放）
- **隔离全局历史结果**：
  - 在 `src/Iris.App/Hosting/HotkeyRecordingCoordinator.cs` 的 `PerformRetryCleanupAsync` 中，当 `context == null || !context.HasFailedCleanup` 时直接返回 `null`，绝不回退读取全局 `_lastCapturedResult`；
  - 在 `src/Iris.App/Settings/SettingsViewModel.cs` 的 `ExecuteRetryHotkeysAsync` 中，直接消费 `_recordingCoordinator.RetryCleanupAsync()` 返回的 nullable `retryResult`；
  - UI 回调中严格比对 `_recordingSessionSeq == targetSeq` 与 `ReferenceEquals(_activeRecordingItem, targetItem)`，仅当 `retryResult?.Outcome == HotkeyCaptureOutcome.Captured`（带有效 Binding）或 `Cleared` 时才应用到项草稿；
  - 清理重试成功后，调用 `targetItem.SetRecordingState(false, false, null, null)` 恢复正常非录入状态，清空活动项引用 `_activeRecordingItem = null`，恢复 `_isStopped = false`，使窗口状态与所有命令完全恢复。

### 3. R3-03：服务级停止屏障与消息循环终态收尾
- **服务级共享完整等待屏障**：
  - 在 `src/Iris.Platform.Windows/Hotkey/HotkeyCaptureSession.cs` 中提供 `internal Task WaitForProgressWorkerAsync()`；
  - 在 `src/Iris.Platform.Windows/Hotkey/HotkeyCaptureService.cs` 的 `PerformCleanupAsync` 中，在原生钩子卸载之后、清空 `_activeSession` 之前，执行 `await session.WaitForProgressWorkerAsync().ConfigureAwait(false)`；
  - `BeginAsync` 准入增加对未完成 `_cleanupTask` 的排斥检查，确保慢进度订阅者退出之前服务 Stop/DisposeAsync 均保持 pending，且拒绝接纳新的 Begin 调用。
