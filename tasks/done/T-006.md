## 1. 背景

M1 从语言模块开始。每次翻译前都要回答两个问题：**原文是什么语言**、**应该翻译成什么语言**。例如，用户的主目标语言是简体中文，划选了一段中文时，Iris 应该自动改译成英文（`AutoSwapTarget`）。

本工单全部是 `Iris.Core` 中的纯逻辑：不涉及 UI、网络和文件，可以完全由单元测试覆盖。规则已写进 **ARCH v1.7 §7.3（7.3.1 目录、7.3.2 检测、7.3.3 解析）**，每条规则都精确到阈值和 Unicode 范围，实现时逐条对照即可。

## 6. 实现要求

### 6.1 LanguageCatalog

- 严格按 ARCH §7.3 的语言表（14 种，顺序固定）与 §7.3.1。
- 数据用 `static readonly LanguageInfo[]` 保存；按代码查找用 `FrozenDictionary<string, LanguageInfo>`（`StringComparer.OrdinalIgnoreCase`）。
- 这个类没有状态，可以用无参构造函数。

### 6.2 ScriptLanguageDetector

- 严格按 ARCH §7.3.2 的 5 个步骤。
- 结构建议：`private enum Script { Other, Kana, Hangul, Han, Cyrillic, Thai, Arabic, Latin }` + `private static Script Classify(Rune r)`（用 `switch` 配合范围模式 `>= 0x3040 and <= 0x309F` 等，每个范围一行，并按 ARCH 表格的顺序排列，便于评审对照）；一次遍历完成全部计数。
- 停用词表放在 `static readonly FrozenSet<string>`（`StringComparer.OrdinalIgnoreCase`）中，内容与 ARCH §7.3.2 **完全一致**（68 个）。
- 判定用的阈值写成具名常量（`KanaThreshold = 0.05` 等），不要在代码中直接写魔法数字。
- 比较 ratio 时使用 `>=`，并用整数运算避免浮点误差：比如“汉字 ≥ 0.30”写成 `hanCount * 100 >= letterCount * 30`。
- 纯函数，不持有状态，线程安全。

### 6.3 TargetLanguageResolver

- 构造函数：`(ISettingsService settings, ILanguageDetector detector, ILanguageCatalog catalog)`。
- 严格按 ARCH §7.3.3 的 4 个步骤；每次调用都读取 `settings.Current`，不缓存。
- 需要检测时才调用 `detector.Detect`（requestedSource 已指定时**不得**调用，测试会验证这一点）。

### 6.4 AddIrisCore
