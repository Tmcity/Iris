## 2. R1-1：信号量必须晚于所有生产者退出

当前 `using var concurrencySemaphore` 声明在外层 try 内，其隐式 Dispose 发生在外层 finally 取消/等待 workerTasks 之前。并发 1、一个运行项和一个等待项时提前退出，信号量先被释放，活动任务 Release 抛 ObjectDisposedException，排队等待可能无法完成，外层 Task.WhenAll 永久等待且租约不释放。

- 明确每请求 CTS、Channel、Semaphore、workers 和租约的清理所有权。提前结束/取消时先取消工作，再观察并等待所有任务清理退出，之后才释放同步对象和租约。
- 不得以捕获并吞掉 ObjectDisposedException、忽略挂起任务、加 WaitAsync 超时后提前释放租约等方式绕过。
- 正常完成仍在全部任务/枚举器退出后、Finished 之前释放租约；不重复终态，不把内部清理异常直接从 Channel 以原始 AggregateException 泄漏。

必须有受控回归：MaxConcurrentProviders=1，至少两个已选择服务；运行项进入带清理门闩的流，另一项等待名额；消费者在 ProviderStarted/Delta 后结束。证明清理门闩未放行时同步对象仍有效、租约未释放；放行后 DisposeAsync 能结束，等待项未调用 Provider，所有任务已观察，缓存/历史未写入。另覆盖取消排队和背压中退出。门闩有超时和 finally 收尾。

## 3. R1-2：收尾写缓存也遵守快照开关

目前读缓存检查 translationSettings.CacheEnabled，正常收尾写缓存却未检查。快照 CacheEnabled=false 时仍调用 TrySet，不能依赖缓存内部的实时开关替代本次快照策略。

写入条件增加本请求快照的 CacheEnabled；保持 Generation 在首个 await 前捕获、BypassCache 只跳过读取、截断/失败/提前退出不写的已有语义。测试使用记录调用的缓存端口，证明关闭时 TryGet/TrySet 均不调用，而 Provider 翻译仍成功；不要只用真实 Cache 内部拒绝写入掩盖编排器错误调用。

## 4. R1-3：释放异常不能被转换为成功

当前无条件吞掉 enumerator.DisposeAsync 异常并继续 Completed，导致仅释放失败时仍写入缓存和历史。

明确执行顺序：先确定流处理/校验的主要结果，再完成枚举器释放，最后才能发布终态。若已有主失败，保留它，释放异常只安全记录；若没有主失败，释放异常按该 Provider 的失败出口处理（未知异常为 Unknown），不得 Completed 或写该项缓存/历史。请求取消仍优先按取消清理，不产生失败卡片。

增加两个用例：正常正文+合法结束标志+仅 DisposeAsync 抛错 → 一次失败、无成功/缓存/历史；主 Timeout 加释放异常 → 仍为 Timeout、无双重终态。其它 Provider 继续正常执行。此规则已在规范中明确，不改变公开契约。
