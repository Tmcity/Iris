# 工单 T-021A-R2 完成报告

## 1. 修复与收尾概要

### 1.1 R2-1 复合错误优先级与清理日志补齐
- **GetText 复合错误**：在 `ExecuteGetTextAttempt` 中增加 `readFailed` 状态跟踪。当文本块无 NUL 终止符抛出 `InvalidResponse` 时，`finally` 中的 `GlobalUnlock` 失败将作为次要清理失败由 `s_logCleanupFailure(_logger, "GlobalUnlock", unlockErr, null)` 记录 Warning 日志，且保留主失败 `InvalidResponse`，不被 `StorageFailure` 覆盖；当读取本身成功但 `GlobalUnlock` 失败时，`GlobalUnlock` 成为主失败抛出 `StorageFailure`；若紧随其后的 `CloseClipboard` 也失败，则作为次要清理失败记录日志。
- **SetText / SetImage 复合错误**：在 `ExecuteWriteAttempt` 中，当 `primaryFailed` 为 false 且 `CloseClipboard` 失败时，`closeFailed` 被置为 true 并作为主失败向外抛出；紧随其后的 `DestroyWindow` 若也失败，在 `finally` 中检测 `(primaryFailed || closeFailed)` 并通过 `s_logCleanupFailure(_logger, "DestroyWindow", destroyError, null)` 记录 Warning 日志，彻底解决二次清理失败丢失问题；当 `CloseClipboard` 成功但 `DestroyWindow` 失败时，`DestroyWindow` 成为主失败抛出 `StorageFailure`。在 `CoreSetTextAsync` 与 `CoreSetImageAsync` 中同样对内存拷贝与 `GlobalUnlock` 异常执行了相同的优先级与日志处理。
- **新增回归测试**：
  1. `Ownership_GetText_WhenInvalidTextAndGlobalUnlockFails_PreservesInvalidResponse_AndLogsGlobalUnlockCleanupFailure`：断言主错误为 `InvalidResponse`（文本块缺失 NUL），且 Warning 日志明确包含 `GlobalUnlock` 与错误码 `6`；
  2. `Ownership_SetText_WhenCloseAndDestroyBothFailWithoutPrimaryError_ThrowsCloseError_AndLogsDestroyCleanupFailure`：断言主错误抛出 `StorageFailure` 且 Detail 包含 `CloseClipboard error 1418`，同时 Warning 日志包含 `DestroyWindow` 与错误码 `1400`。

### 1.2 R2-2 提取实际 Helper 协调代码与消除手写假自验
- **提取实际协调器**：新建 `tests/Iris.Clipboard.IsolatedHelper/IsolatedStationCoordinator.cs`（链接至 `Iris.Platform.Windows.Tests`），定义 `IIsolatedStationEnvironment` 窄适配接口与 `IsolatedStationCoordinator.Run` 共享协调方法；
- **Helper 生产与测试同一份实现**：`Iris.Clipboard.IsolatedHelper/Program.cs` 的 Dedicated MTA 线程入口直接实例化 `RealIsolatedStationEnvironment` 并调用 `IsolatedStationCoordinator.Run(env, RunIsolatedBody)`；
- **统一所有出口清理与协议**：`IsolatedStationCoordinator` 统一在 `finally` 检查所有恢复/关闭结果（`SetThreadDesktop`、`CloseDesktop`、`SetProcessWindowStation`、`CloseWindowStation`）。若发生清理失败，一律记录 `[ISOLATED_CLIPBOARD] CLEANUP_FAIL:`，且将原本预期的 `PASS` 或 `SKIP` 强制转为 `FAIL`（退出码 1）；已有业务失败则保留业务失败同时追加清理日志；
- **图像读取与占用测试收尾**：Helper 内部读取 DIBV5 的 `GlobalUnlock` 与 `CloseClipboard` 返回值均作严格断言与错误处理；占用测试的 `OpenClipboard(0)` 若返回 false 则直接判定测试失败，严禁静默跳过占用测试；
- **删除手写列表自验证**：彻底删除旧的 `HelperProtocol_StationRestorationOrder_AndFailureProtocol_VerifiedDeterministically` 字符串自写列表测试，替换为由 `FakeIsolatedStationEnvironment` 真实驱动的 7 项确定性协议与变异测试：
  1. `HelperProtocol_SuccessFlow_ExecutesActualCoordinator_RestoresInOrder_AndReturnsSuccess`：真实调用协调器，断言退出码 0、`[ISOLATED_CLIPBOARD] PASS`，并验证 `CallLog` 中原窗口站恢复（`SetProcessWindowStation(100)`）严格早于原站序列号最终采样（`GetClipboardSequenceNumber() -> 1000 (Station=100)`）；
  2. `HelperProtocol_CreateWindowStationConflict_ReturnsSkip_AndRestoresCleanly`：模拟错误码 183，断言跳过流程、返回退出码 2，不进入业务测试；
  3. `HelperProtocol_BodyFailure_PreservesFailure_AndRunsCompleteRestoration`：模拟业务测试失败，断言返回退出码 1，保留原业务失败日志，且原站/桌面恢复完整执行；
  4. `HelperProtocol_RestorationFailure_ConvertsToFailure_AndLogsCleanupFail`：模拟业务成功但窗口站恢复失败，断言退出码由 0 转为 1，记录 `CLEANUP_FAIL` 与 `FAIL`，不发布 PASS；
  5. `HelperProtocol_SkipFlowWithRestorationFailure_ConvertsSkipToFailure`：模拟环境跳过流程中清理失败，断言退出码由 2 转为 1，禁止将清理失败包装为正常 SKIP；
  6. `HelperProtocol_PrematureSampling_MutationIsRejected`：变异隔离验证——证明若采样发生在恢复之前，采样将获得隔离站序列号（2000）而非原站序列号（1000），被序列号校验拒绝；
  7. `HelperProtocol_SuppressedRestoreFailure_MutationIsRejected`：变异隔离验证——证明若协调器试图压制恢复失败，会被断言严格拒绝。

## 4. 与工单的偏差

1. **Try-Finally 中避免提前 return**：在实现 `IsolatedStationCoordinator.Run` 时，原初实现若在 `try` 块内执行 `return ExitCodeSkip;`，会导致 C# 运行时在进入 `finally` 前就已锁定了返回值槽，致使 `finally` 中将 `exitCode` 改写为 `ExitCodeFailure` 的操作无法改变最终返回结果。因此改为在 `try` 块内使用分支守卫控制后续步骤不执行，统一在 `finally` 之后返回 `exitCode`，确保清理失败时能够坚决覆写退出码为 1。该改动完全符合工单“清理失败不能保留正常环境 SKIP”的要求。
