## 1. 返工范围与实现总结

针对工单 T-021A-R1 列出的 6 项返工要求，全部按规范实施完成：

1. **R1-1（P1）：纠正服务的释放所有权与串行门生命周期**
   - 移除了 `Win32ClipboardService` 的 `IDisposable` 实现，类级别添加 `[SuppressMessage("Design", "CA1001")]`（标注说明：`SemaphoreSlim` 未创建 `AvailableWaitHandle`，且运行中释放会导致正在执行或排队的调用抛 `ObjectDisposedException` 或任务悬挂）；
   - 在 `Win32ClipboardServiceConcurrencyAndOwnershipTests` 中新增受控回归测试 `ContainerDisposal_WithActiveAndQueuedOperations_ActiveCompletes_QueuedCancelsCleanly_WithoutObjectDisposedException`：证明活动项进入原生帧、排队项等待门时，DI 容器释放不会将门提前销毁，活动项放行后正常成功，排队项取消后按 OCE 干净退出，两项任务均被观测且无 `ObjectDisposedException`。

2. **R1-2（P2）：准备与解码全部移入后台且受同一串行门约束**
   - `SetTextAsync`：在门前仅进行轻量参数初检，通过 `await _gate.WaitAsync(cancellationToken)` 取得门后，在 `Task.Run` 中执行所有的 `GlobalAlloc`、`GlobalLock`、内存拷贝、`GlobalUnlock` 及写入重试循环；
   - `SetImageAsync`：参数初检后首先获取 `_gate`，在 `Task.Run` 内部调用 `WindowsImageDecoder.DecodeToDibV5Async`。排队图像调用在门外等待，绝不提前进入解码或分配大像素缓冲区；
   - 检查令牌并确保 WinRT 异步调用（`StoreAsync`、`CreateAsync`、`GetSoftwareBitmapAsync`）使用 `.ConfigureAwait(false)` 且传递取消令牌，OCE 不转为 `ImageInvalid`；
   - 新增 STA 线程执行验证测试 `SetTextAsync_WhenCalledFromStaThread_PerformsGlobalAllocAndLockOnBackgroundThread`（断言 `GlobalAlloc` 与 `GlobalLock` 的托管线程 ID 绝非调用方 STA 线程）；
   - 新增排队解码拦截测试 `SetImageAsync_WhenQueuedBehindActiveOperation_DoesNotStartDecodingUntilGateAcquired`（证明排队项在门释放前取消直接抛 OCE，未执行解码）。

3. **R1-3（P2）：显式忽略 EXIF 旋转，像素布局与 DIB 头严格一致**
   - `WindowsImageDecoder` 显式调用 `decoder.GetSoftwareBitmapAsync(BitmapPixelFormat.Bgra8, BitmapAlphaMode.Straight, new BitmapTransform(), ExifOrientationMode.IgnoreExifOrientation, ColorManagementMode.ColorManageToSRgb)`，严格忽略 EXIF 旋转；
   - 解码后显式核对 `softwareBitmap.PixelWidth == actualWidth` 且 `softwareBitmap.PixelHeight == actualHeight`，并校验像素缓冲字节数与 DIB 宽高完全一致；
   - 在 `Win32ClipboardServiceImageTests` 中新增非方形 2×3 JPEG 包含 EXIF Orientation=6 和 Orientation=8 的真实编码与解码测试 `SetImageAsync_WithSyntheticNonSquareJpeg_ExifOrientation_IgnoresExifOrientation_AndMatchesDibHeader`，验证 DIB 宽高严格为 2×-3 且像素排列未被旋转。

4. **R1-4（P2）：原生读取失败与清理失败处理**
   - `GetTextAsync` 中，当 `IsClipboardFormatAvailable == true` 但 `GetClipboardData == 0` 时，判定为原生读取失败，抛出 `IrisException(ErrorCode.StorageFailure)`；
   - 主操作失败时优先抛出主异常；在 `finally` 块中若清理操作（`CloseClipboard`、`DestroyWindow`、`GlobalFree`）失败，通过 `LoggerMessage` 委托安全记录警告日志，绝不吞没主异常；若无主失败而清理失败，则抛出 `StorageFailure`；
   - 原生适配器接口 `INativeClipboardAdapter.DestroyWindow` 返回 `bool`；
   - `GlobalUnlock` 返回 0（`FALSE`）时，检查 `GetLastError() == 0`（`NO_ERROR`，表示锁计数降为 0 的正常成功返回），仅在错误码非 0 时判定为失败；
   - 包含旧测试纠正与新增测试：`GetTextAsync_WhenHandleIsZero_ThrowsStorageFailure`、`Ownership_PrimaryFailureAndCleanupFailure_PreservesPrimaryFailure_AndLogsWarning`、`Ownership_DestroyWindowFailsWithoutPrimaryError_ThrowsStorageFailure`、`Ownership_GlobalUnlock_WhenReturnsFalseWithNoError_Succeeds`、`Ownership_GlobalUnlock_WhenReturnsFalseWithRealError_ThrowsStorageFailure`。

5. **R1-5（P2）：修复 Helper 逻辑与进程隔离退出观察**
   - `Iris.Clipboard.IsolatedHelper` 使用专用 MTA 线程执行测试主体，保证 `SetThreadDesktop`、测试逻辑与恢复操作均在同一线程执行；
   - 包含真实 2×2 BMP 图像写入后通过 Win32 API 读回 CF_DIBV5 并进行头及像素比对，以及 owner 销毁后文本读回、占用冲突取消验证；
   - 在恢复原桌面与原窗口站后，才读取原交互窗口站的最终序列号；
   - 成功协议 `[ISOLATED_CLIPBOARD] PASS` 延后至所有测试验证与桌面/站清理均成功完成后才输出；
   - 父测试 `Win32ClipboardIsolatedIntegrationTests` 在超时时仅杀子进程并等待子进程实际退出；新增纯逻辑测试 `HelperProtocol_StationRestorationOrder_AndFailureProtocol_VerifiedDeterministically` 验证恢复顺序与协议。

6. **R1-6（P2）：完成 C14-1 与报告更正**
   - `ActionDispatcherTests.cs`：所有真实 STA 线程的关闭改为异步 `staDispatcher.BeginInvokeShutdown(DispatcherPriority.Normal)` 请求，并在 `finally` 块中显式断言 `staThread.Join(5000).ShouldBeTrue("STA 线程应在有界时间内退出")`，彻底消除未断言的 `Join(1000)` 和同步死锁隐患；
   - `Win32ClipboardServiceRetryAndCancellationTests.cs`：实现 `ControllableTimeProvider`，基于内部信号量感知 `CreateTimer` 注册，替换原 `Task.Delay(5)` 和 `Task.Delay(15)` 轮询猜测；
