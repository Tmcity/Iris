## 2. 详细返工实现

### 2.1 注册表测试清理隔离收窄
- 在 `tests/Iris.Platform.Windows.Tests/SystemIntegration/AutoStartServiceTests.cs` 中，`RealRegistry_IsolatedSubKey_FullLifecycleWorks` 的 `finally` 块由原删除父键 `Software\IrisTests` 修改为仅删除 `Software\IrisTests\{isolatedSubKey}`。
- 确保测试不影响任何其它测试数据或系统环境，全量测试套件安全无筛选运行。

### 2.2 自启路径判定强化
- 在 `src/Iris.Platform.Windows/SystemIntegration/AutoStartService.cs` 中，`ValidateExecutablePath` 将路径校验替换为 `Path.IsPathFullyQualified(appHostPath)`。
- 严格拒绝 `C:iris.exe`、`\iris.exe` 等驱动器相对路径，同时保留双引号格式、`dotnet.exe` 拦截与 260 字符长度限制；类型维持 `internal sealed`。

### 2.3 R1-1 保存输入冻结与基线同步
- `SettingsViewModel`：
  - 增加 `CanEdit => !IsSaving && !_disposed;` 属性。
  - 在 `Theme`、`LaunchAtStartup`、`ShowStartupNotification`、`LogLevel` 4 个编辑属性的 setter 中增加前置防护：若 `IsSaving` 为 true 则直接忽略并返回，杜绝保存期间并发输入被纳入草稿。
  - `SettingsWindow.xaml`：所有 4 个编辑控件（`ThemeComboBox`、`LaunchAtStartupCheckBox`、`ShowStartupNotificationCheckBox`、`LogLevelComboBox`）及所在表单卡片均绑定 `IsEnabled="{Binding CanEdit}"`。
  - 在保存成功后调用 `SyncBaselineFromCurrent()`，从 `_settingsService.Current` 读取真实最新配置重建基线与 VM 属性，确保外部并发修改不被陈旧草稿覆盖。
  - `CanRetryAutoStart` 属性直接绑定 `_saveCoordinator.IsAutoStartPending()`。自启注册失败后，用户保存其它无关字段或触发 Reload 均不抹掉待重试状态。

### 2.4 R1-2 真实后台等待与退出所有权
- `GeneralSettingsSaveCoordinator`：
  - 引入内部 `TaskCompletionSource _executionTcs`。实际工作 Task 在 `SaveAsyncCore` 与 `RetryAutoStartAsyncCore` 的 `finally` 块（释放 `_gate` 之后）才设置完成。
  - `WaitForActiveWorkAsync` 优先等待正在执行的后台任务完成，随后排干并确认内部锁释放。
- `SettingsWindowSession`：
  - `ShutdownCoreAsync` 首先调用 `_saveCoordinator.CancelPreCommitWork()` 取消提交前工作。
  - 随后 `await _saveCoordinator.WaitForActiveWorkAsync().ConfigureAwait(false)`，等待真正的后台保存/重试任务完整退出。
  - 在 UI 线程上设置 `window.ForceClose = true`，使窗口在 `IsSaving` 状态下也能被关停逻辑正常关闭。
  - 在窗口真正关闭、后台工作完全退出后，才调用 `Dispose()` 释放 scoped 依赖容器。
- `SettingsWindowPresenter`：
  - `ShowAsync` 在调用窗口工厂或解析 ViewModel 失败时，在 `catch` 块中立即将 `_activeSession` 置 null 并调用 `scope.Dispose()`，杜绝 scoped 资源悬挂泄漏。
  - 并发调用 `ShutdownAsync` 时复用并等待同一个关停 Task。
- `SettingsViewModel`：
  - 关停后释放自身，并在异步 continuation 处检查 `_disposed`，迟到结果不再修改界面或预览。

### 2.5 R1-3 主题预览一致性与安全诊断
- `SettingsViewModel`：
  - 在 `Theme` setter 中，当用户将主题选回与当前基线相同时（`_targetTheme == _baseTheme`），立即调用 `_themeService.ClearPreview(_sessionOwner)` 释放活动预览。
  - 在接收到外部 `Changed` 事件且当前无脏主题时，调用 `_themeService.ClearPreview(_sessionOwner)` 并更新基线。
- `ThemeService`：

  - 在主题应用异常捕获中，通过 `[LoggerMessage] LogThemeApplyFailed` 记录 Warning 日志诊断，不再静默吞异常。

## 3. 与工单的偏差及修改已有测试说明（严格遵守 Rule 10）

1. **`tests/Iris.App.Tests/Hosting/ActionDispatcherTests.cs`**：
   - **修改原因**：在测试 `WpfUiDispatcher_RealDispatcher_QueuedCallCancelled_ExitsSilentlyAndDoesNotInvokeHandler` 中，首个 Handler 原代码为 `await firstCallRelease.Task;`。由于 `await` 会向 Dispatcher 出让控制权，导致 STA 消息循环在测试线程调用 `cts.Cancel()` 之前提前调度并执行了队列中的第二个调用，产生偶发竞态。
   - **修改内容**：将首个 Handler 的等待方式由异步 `await` 调整为同步阻塞 `firstCallRelease.Task.Wait(TimeSpan.FromSeconds(5), ct);`，真正实现测试注释所注明的“启动第一个调用，占住 STA 线程”，消除了并发调度时的竞态偶发失败。
2. **`tests/Iris.App.Tests/Tray/TrayIconControllerSettingsTests.cs`**：
   - **修改原因**：原测试每次新建裸 `Thread` 并设为 STA。在全量测试并行执行时，若 `Application.Current` 已在另一 STA 线程初始化，创建 WPF `ContextMenu` 会跨线程访问其资源字典中未冻结的 `SolidColorBrush`，触发 `InvalidOperationException`。
   - **修改内容**：将测试调度统一迁移至 `WpfTestRunner.RunAsync`，与 WPF 全局 Application 保持在同一 STA Dispatcher 消息循环内执行。
3. **`tests/Iris.App.Tests/Hosting/AppBootstrapperTests.cs`**：
   - **修改原因**：单测运行 `bootstrapper.StopAsync` 时，默认的 `AppShutdowner` 委托会调用全局 `Application.Current.Shutdown()`，导致后续创建 WPF Window 的单测由于 Application 处于关闭中而崩溃。
   - **修改内容**：在测试类构造函数中将 `AppBootstrapper.AppShutdowner` 临时重设为空操作委托 `_ => { }`，并在 `Dispose` 中复原。
