## 3. 必须达到的最终行为

1. **停止是当前窗口会话的单向生命周期状态。** 普通热键重试和清理重试不得清除 `_isStopped` 或重新开放已停止的 VM。回调在实际 UI 执行点检查会话身份与停止/关闭意图；迟到结果只完成自有收尾，不能解冻或发布新草稿。
2. **普通未关闭窗口的录入失败重试继续可用。** 此类 VM 没有进入 StopAcceptance，不需要重置停止标志；成功后正确清除本次录入/失败状态，恢复原有编辑和正常保存。保留 R3 的同窗口错误恢复与一次结果应用。

4. 后继关闭不能在重试内部等待包含本重试的 WaitForActiveWorkAsync，避免等待自身；按现有 session/presenter 所有权安排收尾，并传播实际关闭失败。若之后再次打开设置，应创建新的正常作用域。
5. 普通运行状态重试遇到窗口/Host 停止时，不撤销准入、不更新停止后的 UI、不恢复系统热键；保持真实工作被等待及既有应用退出顺序。不要以去掉停止校验来让测试通过。

## 二、核心修复方案与实现细节

### 1. 停止状态单向生命周期铁律（One-way Stopped Lifecycle）
- 彻底移除 `src/Iris.App/Settings/SettingsViewModel.cs` 中 `ExecuteRetryHotkeysAsync` 两个 UI 回调中的 `_isStopped = false` 赋值：
  - 清理重试回调（原约 2034 行）：移除 `_isStopped = false`，增加 `if (!_isStopped)` 保护草稿回写，已停止会话绝不再接受新捕获键写入草稿，仅重置录入/失败状态。
  - 普通运行态重试回调（原约 2085 行）：移除 `_isStopped = false`，恢复 `if (_disposed || _isStopped) return Task.CompletedTask;`，遇到已停止窗口直接退出，不更新快照、不修改 UI 状态。
- `CompleteSaveOrRetryOperationAsync` 在 `_isStopped` 为 `true` 时保持 `isAlive = false`，草稿维持冻结状态，`CanEdit` 维持 `false`。

### 2. 挂起关闭流程的安全续跑与无死锁释放（Resume Pending Close without Deadlock）
- 在 `ExecuteRetryHotkeysAsync` 方法入口记录初态 `wasStoppedInitially = _isStopped;`。
- 在 `finally` 块中：
  - 先执行 `CompleteSaveOrRetryOperationAsync` 完成内部状态结算；
  - 在 `lock (_admissionLock)` 内从 `_activeWork` 移除当前工作 `workTcs.Task`，并调用 `workTcs.TrySetResult()` 完成该任务；
  - 若 `wasStoppedInitially && !HasFailedRecordingCleanup && !_disposed`，调度 `_uiDispatcher.InvokeAsync(() => RequestClose?.Invoke())`。
- 关键消除死锁设计：由于本重试任务在调度 `RequestClose` 前已从 `_activeWork` 移除并 SetResult，后续由关闭请求触发的 `ShutdownAsync -> CleanupCoreAsync -> WaitForActiveWorkAsync` 绝不会等待本重试任务自身，消除了循环等待死锁风险。
- `SettingsWindowSession` 构造时订阅 `_viewModel.RequestClose += OnViewModelRequestClose`，并在 `DisposeInternal()` 中解绑。当 ViewModel 请求关闭且清理已无失败时，安全驱动窗口关闭与 `_scope.Dispose()`，旧作用域彻底释放。

### 3. 普通未关闭窗口错误恢复保持可用
- 对于未请求关闭的常规录入窗口（`wasStoppedInitially == false` 且未调用 `StopAcceptance()`），录入失败后点击重试，清理成功后经正常的 `CompleteSaveOrRetryOperationAsync` 恢复 `CanEdit = true`，用户可正常修改并保存配置至持久化层。
