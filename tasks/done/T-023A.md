## 2. 实施结果

### Handler、设置捕获和默认热键

新增 Core `SelectionTranslateHandler`，以 TryAddEnumerable 注册单例 IActionHandler。构造仅保存依赖；执行先验证 context/取消并取得唯一 operation，整个读取/发布任务结束后才归还调用方持有。后台只捕获一次 Settings.Current.Selection，独立复制 ReadOrder 和 ClipboardUnsafeProcesses，同时固定 RestoreClipboard、ClipboardTimeoutMs、OpenInputWhenEmpty；同步桌面查询不在 App UI 线程执行。

确认前台 ProcessId 为 Environment.ProcessId 时，以同一租约显示 Text=null / Origin=Input / AutoTranslate=false / FocusInput=true，保留原文、不重新分配意图、不读取选区或执行 InputTranslateHandler 的可见窗口切换。外部来源使用 operation.CancellationToken 调用 Reader，不使用 Payload 作为缓存选区。

正常分支：非空白原文原样交给 TryShow，Origin=Selection、AutoTranslate=true、FocusInput=false；无结果且允许输入时明确 Text="" 并给 SelectionEmpty 默认错误；无结果且不打开输入窗时调用同操作 TryNotify(Warning, SelectionEmpty)。前置设置/桌面/读取异常只映射安全 Code/默认文案，取消安静结束。TryShow/TryNotify 的失败不递归发布或兜底，交给 Dispatcher 既有边界。

没有改默认配置。HotkeyCoordinator 从真实注册 Handler 派生已交付动作，因此已有 Ctrl+Alt+D 开放；没有新增托盘划词菜单、鼠标入口、T-023B 设置或 T-024 行为。

### CCR-018 与即时通知路径

将架构师已预置的唯一 `TryNotifyAsync(ITranslateWindowOperation operation, NotificationLevel level, ErrorCode code)` 声明同步到 Core PresentationPorts，并实现实际 TranslateWindowPresenter。验证 null/外来租约和非法枚举在副作用前完成；Show/Notify 复用同一操作发布持有与准入容量。

通知通过实际 UI 调度，在最终 UI 接受点持状态锁复核最新身份、取消、caller Dispose 和退出状态后，立即调用 TrayNotificationService.TryNotifyNow → TrayIconController.TryShowNotificationNow。正文只取 ErrorMessages.GetDefault，标题固定 UiText.AppName。不调用旧 Notify，不进入普通待通知队列，不创建 Window/scope/VM；无托盘、未就绪、已释放或原生调用异常返回 false。

TranslateWindowOperation.EndTryNotify 只归还本次发布持有，不改变已有 `_hasSessionOwnership` 或翻译工作槽。通知成功或 false 后，既有 VM 会话仍有效，调用方归还后仍可正常重试。UI 排队/执行责任结束前状态不退休，Shutdown 等待同一操作屏障。UI 调度异常安全可见，不递归通知。

App 内部 `ITrayNotificationNative` 仅为通知的外部 shell 边界，测试注入；产品默认使用现有 TaskbarIcon。既有普通 Notify 队列与托盘创建/重试代码保持。即时路径捕获原生通知调用异常并返回 false，成功表示调用已提交，不保证 Windows 实际显示气泡。
