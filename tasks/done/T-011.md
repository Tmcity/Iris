## 4. 实现要求

### 4.1 凭据解析与构造

- 只对已启用 Profile 构造常驻实例；按 Order 稳定排序，相同时保持设置列表顺序。Snapshot.Settings 直接持有服务发布的不可变 Current，不复制整个设置图。
- CredentialSetId=null 读取 legacy ApiKey/SecretKey；非 null 仅读取指定凭据集，不得回退。严格检查引用格式及设计中的四个 JSON 字段，拒绝重复属性/错误类型/未知版本。
- 不可用的显式引用表现为该项未配置，不能被当作本地服务的合法空凭据；其他项继续可用。合法空凭据与普通缺 Key 的判定交给真实 Factory/Provider，不能统一判所有无 Key 服务不可用。
- Factory 按 Kind 索引，重复 Kind 拒绝；缺少必要 Factory/构造发生编程错误时，本次发布失败并清理新建对象，不发布半张表，不把原始消息/配置/凭据挂进异常或日志。
- 不调用 ISecretStore.Set/Remove 或 ISettingsService.UpdateAsync。读取器的错误输出只包含安全分类，不输出凭据 JSON 或非法引用内容。

### 4.2 实例复用与版本

- 比较实际 Profile 内容及 ProviderCredentials 值；不能因 T-010B 为无关设置创建了新集合引用而重建全部实例。
- Order 变化只重排视图，InstanceId 保持；DisplayName、协议参数、地址、模型、凭据或其它构造相关值变化时创建新实例及新 Guid。
- 禁用/删除使实例退休；重新启用可创建新代。每次 Factory.Create 都应返回新实例，测试替身也不要错误地为不同构造调用复用同一个对象。
- CreateTransientAsync 捕获草稿中可能可变的 ExtraHeaders，只生成单项租约；不进入缓存、不写盘、不通知，即使 Enabled=false 也能用于测试连接。

### 4.3 生命周期和并发

- Registry 持有当前条目的所有权引用，快照增加使用引用；退休且使用数为零时恰好释放一次。非 IDisposable Provider 正常支持。
- Snapshot.Dispose 幂等；所有子任务结束后再释放。旧快照跨重建继续有效，Registry.Dispose 后旧租约仍可安全释放，新操作则失败。
- 实际 Provider.Dispose 在注册表锁之外执行，一个实例的释放异常不能中断其余释放，日志只记录安全元数据。
- 刷新、取得快照和退休发布要有明确的原子边界。同步捕获/构造在后台执行，UI 线程不做凭据解密或批量 Factory 构造；不得在设置 Changed 回调里同步重建或等待。
- 变化通知可合并；处理过程中到来的新变化不能丢；后台失败不能对未变化的配置无限重试。Acquire/显式 Refresh 必须重新读取当前状态，不能把旧事件参数发布回去。
- RefreshAsync 是未来配置提交后的清理屏障，调用完成后不能还有尚未结束的旧引用解析。消费者已有实例不受旧密文删除影响，因为 Provider 的凭据在构造时已经捕获。

### 4.4 事件、DI 与启动

- Changed 只对有效注册项/顺序/Descriptor/实例代次变化发出，锁外触发；主题/窗口位置等无关变化不发 Changed，不更换 Provider。
- Core 只有一个注册表实例；观察者端口转发到它，重复 AddIrisCore 不重复注册或订阅。观察者适配器不拥有也不单独释放 Registry。
- 构造不读凭据、不创建 Provider；AppBootstrapper 在设置 Load 成功或损坏恢复后 await RefreshAsync，再继续托盘启动。补齐受影响的测试替身，不注册未来未实现服务。
- 明确 Dispose 与排队/正在执行的刷新、迟到事件、重复释放之间的行为；不能销毁仍供旧租约释放使用的同步状态。

## 4. 关键设计实现说明

1. **凭据解析与坏引用隔离**（`ProviderCredentialResolver`）：
   - `CredentialSetId == null`：严格读取 legacy `provider/{id}/api-key` 与 `secret-key`。
   - `CredentialSetId != null`：严格使用正则 `^cs-[0-9a-f]{32}$` 校验，非法时直接判定为显式未配置；读取指定 `credential-set/{id}`，使用 `Utf8JsonReader` 进行流式解析，拒绝重复属性、未知版本（只接受 version = 1）、格式不为 `"iris-provider-credentials"` 或属性类型错误。
   - 显式坏引用绝不回退至 legacy 凭据，使用 `UnavailableTranslationProvider` 占位，其 `IsConfigured` 为 false，`TestAsync` 返回 `ErrorCode.NotConfigured`，流式翻译在首次迭代时抛出 `IrisException(NotConfigured)`。
2. **实例复用与指纹机制**（`ProviderConstructionFingerprint`）：
   - 比较实际相关 Profile 字段（Id, Kind, DisplayName, BaseUrl, Model, Options, Timeout, CredentialSetId 等）以及解密后的 `ProviderCredentials`。
   - 仅仅修改 `Order` 时只重排视图，保留原有实例与 `InstanceId`；修改无关全局设置（如 Theme）时完全复用原实例；修改 Model、BaseUrl、ExtraHeaders 或凭据时分配新 Guid 并创建新实例。
3. **租约管理与原子退休释放**（`TrackedInstance` & `TranslationProviderSnapshot`）：
   - 注册表持有活跃实例的基础引用，每次 `AcquireSnapshotAsync` 产生的新快照持有独立使用引用。
   - 配置更新使实例退休时，从活跃表中摘除并标记退休；只有当持有旧快照的全部消费者释放完毕（引用归零）后，才执行实际的 `IDisposable.Dispose()`。
   - 实际释放逻辑在注册表锁之外执行，一个实例的释放失败不会影响其它实例的释放。
   - `CreateTransientAsync` 独立深拷贝草稿 Profile 中的 `ExtraHeaders`，生成独立的单项租约，不进入注册表缓存，不触发事件。
4. **并发与发布屏障**（`TranslationProviderRegistry`）：
   - 构造函数不加载设置、不读凭据、不创建实例。
   - `RefreshAsync` 使用 `SemaphoreSlim` 确保并发重建原子性；若部分实例构造失败，自动清理本次已新建的所有实例，保留并回滚至旧的已发布活跃状态。
   - 订阅 `SettingsService.Changed` 与 `SecretStore.Changed` 时异步排队处理，不阻塞事件发布方，不持有写锁执行解密。
   - `Changed` 事件在注册表锁外触发，且仅在有效项、顺序、Descriptor 或 InstanceId 发生变化时触发。
5. **隐私与安全**：
   - 构造失败、凭据解析失败、释放失败与事件异常时，日志只记录结构化安全元数据（ProfileId、Kind、异常类型名称 `ex.GetType().Name`），绝不将包含敏感 Key 或 JSON 的原始异常对象与消息写入日志，对外抛出的 `IrisException` 断开内部异常链。

### 1. 修复摘要（R1-1 至 R1-5）

- **R1-1（P1）：不可变快照集合**
  - `TranslationProviderSnapshot.cs`：`_providers` 与 `_trackedInstances` 均使用 `ReadOnlyCollection<T>`（`Array.AsReadOnly(providers.ToArray())`）包装独立数组副本，禁止外部或消费者通过 `(IList)` 或 `(IList<T>)` 强转修改内部集合（调用 `Clear()`/`Add()` 均抛出 `NotSupportedException`）。后续租约不受任何外部修改尝试影响。
  - `TranslationProviderRegistry.cs`：内部常驻与瞬态注册项集合发布前均固定为 `ReadOnlyCollection<T>`，内部 `List<T>` 绝不向外暴露。

- **R1-2（P1）：刷新屏障与失效状态机**
  - `TranslationProviderRegistry.cs`：建立代次同步状态机，维护 `_targetVersion`、`_publishedVersion`、`_failedVersion`、`_lastFailure` 及串行重建锁 `_rebuildLock`。
  - `AcquireSnapshotAsync` 遇到未就绪或进行中的刷新时，在 `_rebuildLock` 上等待目标版本完成，禁止绕过正在构建的刷新借出陈旧旧代。

  - 待恢复（配置或凭据更新使 `_targetVersion > _failedVersion`）或显式 `RefreshAsync` 时重试并成功取得新配置。
  - 后台刷新遇到失败版本时中断循环，避免在未变配置上无限忙轮询；刷新中到来的新设置事件不被异常 catch 清零，保证后续代次不丢失。

- **R1-3（P1）：统一构建、发布、取消与 Dispose 所有权**
  - 构建过程用 `try ... finally { if (!committed) { foreach (var inst in newlyCreated) inst.DisposeProvider(_logger); } }` 严格包裹。
  - 同步 Factory 返回后、锁前检查以及锁内提交前，均检查 `cancellationToken.ThrowIfCancellationRequested()` 与 `ThrowIfDisposed()`，取消或关闭时立即清理全部本次新建实例并中止发布，绝不泄露实例也不发布取消的配置。
  - `TrackedInstance.DisposeProvider` 增加 `Interlocked.Exchange(ref _providerDisposed, 1)`，确保任何回滚或释放路径下 Provider 的 `Dispose()` 恰好执行一次。
  - 每次访问、复用、退休及清空 `_activeInstances` 均在 `_stateLock` 保护下进行，杜绝无锁并发读写与已退休实例复用。
  - `CreateTransientAsync` 同样覆盖 Factory 创建后、取消、Registry.Dispose 与快照构建交错，未成功转交前统一在 `finally` 中安全 Dispose。

- **R1-4（P2）：后台执行与元数据正确性**
  - `RefreshAsync`、首次 `AcquireSnapshotAsync` 以及 `CreateTransientAsync` 的凭据读取和 Factory 构造均通过 `Task.Run` 调度到后台线程池执行，不再占用调用线程。

- **R1-5（P2）：凭据与占位 Provider 边界**
