## 二、逐项实施与修复明细

### 2.1 R1-01：平台开始、取消、停止与失败资源所有权
1. **取消与开始生命周期**：在 `HotkeyCaptureService.BeginAsync` 中，取消令牌在会话初始化完成后继续绑定到捕获生命周期，Begin 返回后的取消信号仍可停止当前捕获；
2. **初始化与停止竞态**：`StopAsync` 与 `DisposeAsync` 共享在途屏障，严格等待正在进行的 `SetWindowsHook` 与初始化完成，避免在句柄记录前返回成功导致遗留活跃 hook；
3. **初始读取异常安全收尾**：hook 安装后若状态读取抛出异常，进入同一清理路径并确保物理卸载已安装的 hook 句柄；
4. **异常边界与委托保活**：`LowLevelKeyboardProc` 将所有托管异常在 native 边界转换为安全错误结果或通道完成；native adapter 保留委托根直至回调/线程物理屏障完成；
5. **消息循环与退出握手**：区分 `GetMessage` 返回值（正数、0、-1），检查 `PostThreadMessage` 返回，失败不无限悬挂，等待工作线程安全退出。

### 2.2 R1-02：按键状态与通知生命周期
1. **物理键与修饰键语义**：初始状态一致按左右物理键维护，避免 generic 和左右键重复记录导致无法 Ready；
2. **首次 KeyDown 与 Repeat 去重**：主键首次 KeyDown 固定候选组合，重复按键去重，释放阶段不重算修饰位；
3. **终态统一与 Worker 收尾**：所有 Captured/Cleared/Canceled/Failed 统一走一次性终态路径，通过 `Complete()` 正常关闭通知管道，等待 worker 收尾，不遗留悬挂 TCS；
4. **非法组合与无修饰键**：按规范正确拦截 F12、单独 Esc/Backspace 及系统保留键，App 显示真实非法键错误。

### 2.3 R1-03：App 录入控制器、重试与窗口/Host 退出
1. **CancelRecordingAsync 屏障**：撤销捕获并等待实际开始/捕获/清理流程完成，回滚捕获服务；
2. **清理失败资源所有权保留**：卸载失败时，`HotkeyRecordingCoordinator` 保留 active context、捕获结果、session 与 pause lease，标记 `HasFailedCleanup = true` 并拒绝新录入；提供 `RetryCleanupAsync()` 在重试成功后返回保留的捕获结果；
3. **VM 活动任务与退出屏障**：`SettingsViewModel` 的活动工作在清理失败时不伪报成功，`WaitForActiveWorkAsync` 将清理失败异常传播给 `SettingsWindowSession.ShutdownAsync()`，抛出 `InvalidOperationException` 阻止窗口关闭并完整保留 DI scope；重试成功后方可安全关闭与释放；
4. **AppBootstrapper 退出顺序**：先关闭热键准入与录入准入，等待捕获和原生热键收尾，保护正在执行的用户翻译操作。

### 2.4 R1-04：真实运行状态、恢复调度与迟到消息
1. **代次保护与调度收尾**：`HotkeyCoordinator` 在 `OnDispatchCompleted` 中增加代次保护（`_dispatchGeneration != generation` 时早退），防止旧调度清除新消费者的 `_isProcessingSettings` 标记；
2. **丢弃失败调度，避免无限重试**：调度自身失败且无更新快照排队时丢弃该次失败配置（`_pendingSettings = null`），不执行无限重试；若在失败期间到达了新快照，转交启动消费新快照；
3. **暂停退出与标记释放**：旧 settings 调度因暂停推进代次而退出时，正确释放 `_isProcessingSettings`，确保暂停恢复后及后续 Changed 能够正常消费；
4. **不可变快照与旧消息丢弃**：ViewModel 在 UI 执行点校验 SnapshotId，丢弃旧代次通知。

### 2.5 R1-05：草稿、联合保存与真实控件
1. **已编辑行乐观冲突保护**：`HotkeyItemDraftViewModel.UpdateBaselineFromExternal` 修正为：未编辑行跟进最新外部值，已编辑行保留原 base 与 target，由 Core 在保存时进行乐观并发冲突校验（修正了原 V03 的错误预期）；
2. **Cleared 终态内部应用**：Captured/Cleared 结果应用为控制器内部动作，清空正确写入 `(None, "", false)`，普通用户的 Clear guard 不挡住合法终态；
3. **保存按钮与清理状态联动**：录入中、准备中或清理失败未恢复时禁用保存按钮；程序性保存等待录入与清理完成，失败则阻止提交；
4. **录入按钮 Style Trigger**：移除 `HotkeyRecorderBox.xaml` 中按钮本地设置的 `Content` 和 `Command`，使得 Style Trigger 能够在 `IsRecording=True` 时正确切换为“取消”文本并绑定 `CancelRecordCommand`。

### 2.6 R1-06：证据与测试维护
1. **A03 重构为真实 Handler**：使用已交付的真实 `ClipboardTranslateHandler` + mock `ITranslateWindowPresenter` + fake `IClipboardService`，断言 handler 真实 entered 且 pause 不取消正在执行的用户动作；
2. **W02 真实窗口/session/scope 路径**：使用真实 `SettingsWindow`、`SettingsWindowSession`、真实 `SettingsViewModel` 和 scope mock，断言 Begin 发生、清理失败抛出 `InvalidOperationException` 阻止关闭并保留 scope，重试成功后再次关闭成功释放 scope；
3. **A06 补齐真实清理失败与重试**：验证清理失败期间 `recorder.HasFailedCleanup == true`、拒绝新 `RecordAsync` 录入并成功通过 `recorder.RetryCleanupAsync()` 恢复；
4. **W04 真实加载双主题与长组合断言**：调用 `ApplicationThemeManager.Apply(wpfTheme)` 分别加载 Light 与 Dark 真实主题字典，设置长组合 `"Ctrl+Alt+Shift+Win+F10"`，断言 8 组离屏截图 SHA256 哈希全部互不相同，文案无裁切。
