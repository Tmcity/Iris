## 1. 目标与范围

完成原 T-019B 已批准要求，修复本轮证实的草稿丢失、保存与取消边界、旧结果接纳、错误隐私及常规保存旁路。只修改 App 内部设置实现、相关测试与报告；不改 Core 协调器/Registry/Provider 的已验收行为，不增加包、配置字段、公开契约或新预设，不开始 T-015。

不得用修改测试期望或放宽旧回归来掩盖失败，也不得再以“兼容旧测试”为由在生产程序集放入模拟 Core 的成功返回实现。允许拆分过大的 VM 和帮助类，但需保持真实组合根与全部关闭路径的所有权。

## 2. 草稿操作队列与失效

- 区分“本次保存取消并排干”与“窗口永久停止接纳”。保存成功、未提交、校验失败、无变化保存后，只要窗口仍开放，Test/List 必须可再次使用；不能复用把 `_isStopped=true` 的永久关停入口而永不恢复。
- 一个实际操作加一个最新等待项的上限保持。更换队列前必须观察旧队列真实退出，不能丢掉仍运行的实例。取消回调及 work 委托不在状态锁内执行；取消抛错/同步完成/替换等待项路径也必须完整观察与清理。
- 编辑、切项、删除、重新载入、保存重建和相关外部更新均撤销不适用结果并请求取消。切 A→B→A 不能让 A 的旧请求重新有效；不能仅在显示时比较 SelectedProfile.Id。
- 同一 Profile 原地 SyncBaseline 后，旧 endpoint/凭据配置的结果也必须失效。UI 回调真正执行时检查窗口身份、当前草稿对象/代次、revision 与请求序号；旧成功、列表和错误一律拒绝。
- 保留完整任务链直到底层操作、取消与 UI 收尾完成；关闭/Show 失败/局部构造回滚/正常退出均不得提前释放依赖。Dispose 不以遗忘 Drain 任务替代异步收尾。

## 3. 凭据草稿与 PasswordBox

- 清空控件不能经 PasswordChanged 覆盖新选中 Profile 的草稿。用户输入事件与程序同步/清空应有明确区分；切页/切服务保留各项尚未提交的 Replace 输入，不从 SecretStore 读回。
- Uncommitted、校验/冲突/容量失败保留待修正 Key；Provider 重试和自启重试不得清掉未保存 Key。不能将每次 IsSaving=false 统一解释为“保存成功”。
- Applied/ApplyPending 清除本次已提交明文，转为 Keep；Reload/Cancel/删除未保存项/Dispose 解除全部相应草稿明文引用，包括重建集合前被移出的旧对象。
- Keep/Replace/Clear 保持显式，两个翻译协议 Replace 仍传完整 `(apiKey, secretKey:null)`；不推断空框为 Clear，不记录明文，不声称托管字符串被安全擦除。

## 4. 在 UI 线程捕获并冻结保存计划

- 点击保存时，在任何等待之前固定完整计划及自启意图，并冻结全部变更入口。允许校验失败先返回，但不能等旧测试退出后再读取可变草稿组装计划。
- 子 Profile 属性、凭据 setter、选择/排序/集合修改等 VM 入口必须服从冻结/停止状态；仅禁用 XAML 不够。不要保留任意外部可直接修改的集合通道绕过守护。
- 取消并等待 Test/List 的实际退出，再提交已固定计划；停止发生在等待阶段时不进入 Core。等待期间 UI 消息循环继续工作。
- 恢复后的异步执行不得在 worker 上遍历/修改 WPF 草稿集合或触发需要 UI 线程的命令更新。Save、服务重试、自启重试的状态回写及 finally 均通过真正 UI 调度，退出观察包含这些回调。
- 一次混合保存继续只调用实际 ISettingsEditCoordinator.CommitAsync，并由 Core 完成一次联合 UpdateAsync。删除 ForwardingSettingsEditCoordinator 及其直接 General.UpdateAsync 旁路、虚假的 sample 测试成功/回执成功实现；旧构造/测试夹具改为明确注入实际或测试专用协调器，生产无备用模拟路径。

## 5. 外部更新、字段保留与本地不完整输入

- 未编辑服务的新增/删除/排序须反映到实际列表及顺序基线；不能只更新 `_baselineProfileIds` 而保留旧列表，导致无操作窗口变脏或下一次保存覆盖外部顺序。
- 已编辑 Profile/删除意图/顺序保留 base 与 target 供 Core 检测冲突；外部删除不能复活，外部无关字段应保留最新值。
- dirty 必须覆盖尚不能解析的数值文本。Timeout/MaxTokens/Temperature 保留未完成输入；无关 Changed 不得把它们当未编辑而覆盖。改回基线可消除 dirty。
- 仅改显示名等字段不得清空隐藏 Temperature、另一组 Options 或其它未编辑字段。原地基线同步也应正确处理 Options 从非 null 变 null，避免保留陈旧控件值后再次发布。
- 保持按操作的校验范围：无关生成字段未完成不阻止模型发现，但实际请求的地址、超时、身份、凭据与认证头继续校验；不通过 DTO 中性值放行保存。未触及 Profile 不应被 UI 的额外全表校验阻止合法 General-only 保存，准入与已批准 Core 规则一致。
- Prompt 缺失不自动换成默认；获取模型列表不覆盖手输型号。必须在实际绑定控件上验证集合刷新/选择项变化的副作用。

## 6. 错误、回执与自启状态

- ExecuteTestDraftAsync 不得将未知异常的 Message 放入 ErrorInfo/UI。使用固定安全提示及操作/异常类型日志，检查异常正文/链、结构化日志参数、DTO ToString；假 Key 标记不能泄露。
- 保留回执跨会话、删除最后服务仍能重试、Core 提交返回后先登记再交 VM 的责任。容量为待办与在途预留合计 32；满额在 Core 调用前拒绝；失败/取消释放名额，General-only 无预留。
- Provider ApplyPending 不等于自启失败。移除保存结果 UI 回调内同步 IsAutoStartPending/IsEnabled 路径；查询后台执行且纳入退出所有权，代次校验后回写。
- Provider 待办与自启未生效分别显示/重试。Provider 已提交但应用失败时，自启成功仍应正确反映；重试其中一项不改另一项，也不清新草稿。
- 服务重试状态需从处理后的实际待办确定，不能仅因开始时快照全成功就清掉过程中新增的待办。Changed 通知排队/异常也不得将已提交事实误报为 Uncommitted，回执及预留所有权须可证明。

# T-019B-R1 实施与验证报告

## 1. 阻断项修复与代码交付

根据工单要求，全部修复均落地于 `src/Iris.App/` 内部实现与相应测试中，未修改 Core/Registry/Provider 已验收行为，未引入新包、新配置字段、公开契约或预设。

### 1.1 临时排干与永久关停解耦（P1 反例 1）
- `SettingsDraftOperationQueue.cs`：新增 `DrainAndCancelInFlightAsync()` 方法，仅针对当前在途操作触发取消并排干等待，**不将 `_isStopped` 置为 true**；保留原 `DrainAndCancelAllAsync()` 仅供会话终结关停使用。
- `SettingsViewModel.ExecuteSaveAsync()`：在保存开始前调用 `_operationQueue.DrainAndCancelInFlightAsync()`，使得保存成功、无变更保存、未提交及校验失败后，只要窗口依然打开，用户可继续正常点击“测试”与“获取模型”。

### 1.2 凭据输入保护与 PasswordBox 防误清（P1 反例 2）
- `SettingsWindow.xaml.cs`：引入 `_suppressPasswordChanged` 状态锁屏障；在 `SyncPasswordBoxWithDraft` 内部通过 `_suppressPasswordChanged = true` 同步控件文本，阻止向草稿触发误清；切项与切页均保留尚未提交的 `ReplacementApiKey`。
- `TranslationProfileDraftViewModel.cs`：实现显式的 `ResetCredentialsToKeepAfterSave()`；保存失败、校验失败、容量超限或自启/服务重试时均不清除草稿明文 Key，仅在真实提交成功后将凭据状态转为 `Keep` 并清空内存明文。
- `SettingsViewModel.cs`：`LoadProfilesFromCurrent()` 在清空并重建集合前，遍历现有草稿显式执行 `ClearReplacementApiKey()`，确保内存不残留明文。

### 1.3 UI 线程保存计划捕获与冻结守护（P1 反例 3）
- `SettingsViewModel.ExecuteSaveAsync()`：在 UI 线程同步完成所有草稿校验，并在任何 `await` 之前完成 `GeneralSettingsPatch`、`TranslationChanges` 及 `TranslationOrderChange` 的全量装配；设置所有草稿 `IsFrozen = true`。
- `TranslationProfileDraftViewModel.cs`：所有属性 setter、凭据 setter、测试草稿生成均守护 `IsFrozen`，冻结期间直接忽略或拒绝修改。
- 异步保存完成后，通过 `IUiDispatcher.InvokeAsync` 回到 UI 线程统一切回 `IsSaving = false` 与 `p.IsFrozen = false`，保证 `CommandManager` 与按钮 `CanExecuteChanged` 的线程归属安全。

### 1.4 外部更新双向合并与结果失效（P1 反例 4）
- `SettingsViewModel.OnExternalSettingsChanged`：外部配置变更到达时，对未编辑项执行完全同步，包括新增、删除与顺序重排；对已编辑项保留本地 target，并安全合并外部无关属性。
- `TranslationProfileDraftViewModel.cs`：
  - 递增 `Revision`，使得外部端点/模型变更后，先前的在途结果在代次校验时被主动识别为过期并丢弃；
  - 维护不完整数字草稿（如正在输入的超时、温度文本），保留 dirty 标记，不被外部更新冲掉；
  - `BuildTargetProfile` 保留隐藏的 Temperature、以及未处于激活协议但未被编辑的既有 Options，杜绝静默清空。

### 1.5 测试异常隐私保护与固定安全文案（P1 反例 5）
- `SettingsViewModel.ExecuteTestDraftAsync`：彻底移除将未知异常 `ex.Message` 写入 UI 状态与日志参数的通道；捕获异常时仅记录其异常类型名（`ex.GetType().Name`），UI 显示固定的 `UiText.SettingsTestFailed` 安全提示，假 Key 标记无法泄露。

### 1.6 物理删除生产 Direct Update 旁路（P1 反例 6）
- `GeneralSettingsSaveCoordinator.cs`：物理删除了 `ForwardingSettingsEditCoordinator` 内部类，删除了 3 参数构造；所有路径均必须显式注入真正的 `ISettingsEditCoordinator`，经由 Core 的 `CommitAsync` 执行原子联合提交；
- 适配既有单元测试与测试夹具，在 `tests/Iris.App.Tests/Settings/TestSettingsEditCoordinator.cs` 中实现隔离的测试专用协调器。

### 1.7 后台自启状态查询与代次保护（P1 反例 7）
- `SettingsViewModel.cs`：移除在 `ApplyPending` UI 回调中同步调用 `_autoStartService.IsEnabled` 的行为；自启查询统一由异步后台任务 `QueryAutoStartStatusAsync()` 执行，纳入窗口退出追踪并受 `_queryGeneration` 代次守护，查询结果在 UI 线程校验代次后安全回写。

### 1.8 补齐拖拽排序与未失焦 Flush 真实接线（P2 反例 8）
- `SettingsWindow.xaml` / `.xaml.cs`：为 `ProfilesListBox` 接入 `AllowDrop="True"` 与 PreviewMouseLeftButtonDown/MouseMove/DragOver/Drop 事件处理器，计算拖拽索引并委托给 `SettingsViewModel.MoveProfile(oldIndex, newIndex)`；
- 为 `DisplayNameTextBox` 命名并在保存前触发 `SettingsWindow.FlushFocusedBinding()`，在保存前同步未失焦输入至绑定源并持久化至 `ISettingsService` 与物理磁盘。
