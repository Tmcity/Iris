## 4. 验收场景

### A. 快照与实际 Prompt

- 持有配置 A，令 Current 改为 B（并可配置 getter 抛异常），显式重载仍按 A 预处理、选语言、查模板；旧重载仍按 B 工作，原测试保持通过。
- 为两个 Provider 提供 PreparedPrompt A，模板服务和 Renderer 均配置为抛出以证明没有访问；断言发送体中的 system/user 精确等于 A，覆盖 Anthropic 普通/beta 及 OpenAI 流式/非流式的共用构造。无 PreparedPrompt 时保留原路径。
- 带 PreparedPrompt 获取序列和枚举器不提前发请求，取消/未配置时也保持原边界。仅比较模型回复不足以证明 Prompt 正确，必须检查发出的请求体。

### B. 执行键

- 同一 InstanceId 与五字段得到相同键；分别改变实例代次、Text、SourceLanguage、TargetLanguage、System、User 都改变键。
- 同 ProviderId/Model 的新注册代次不复用旧值；旧请求写入旧键不会命中新代。
- 包含 NUL 的字段边界反例、非 ASCII、孤立代理项与固定输入的独立哈希向量；证明完整 64 位小写十六进制。键对象不含原文/Prompt/凭据。

### C. 缓存

- 真实 LRU：命中提升、覆盖提升、未命中不改变顺序；容量、字节预算、单条上限分别触发，恰好等于边界可接纳，超过边界不接纳。
- 替换扣除旧成本；拒绝超大单项时只移除同键旧项，不淘汰其它条目。覆盖空字符串及 null text。
- 捕获 G，Clear，写入新代条目，再让旧请求 TrySet(G)：返回 false，新条目/顺序/预算不变；使用门闩控制顺序，不用并发快循环冒充该交错。
- 关闭/开启缓存及容量零/正切换隔离代次；正容量缩小即时按 LRU 修剪；无关设置不清空。事件与公开操作交错时不允许用陈旧事件参数回退限制。
- 多线程读写/清空/设置更新后结构与预算均正确；Dispose 幂等并拒绝操作；重复 AddIrisCore 获得同一实例/订阅，不泄漏事件。
- 组合根在新增缓存后仍能构建，不提前创建未来服务。

## 3. 关键设计实现说明

### 3.1 显式设置重载与快照隔离
- `TargetLanguageResolver`、`TextPreprocessor`、`PromptTemplateProvider` 的显式重载均对入参 `settings` 执行非空校验（`ArgumentNullException.ThrowIfNull(settings)`）。
- 旧重载均通过读取单次 `_settings.Current.Translation` 变量保存快照，随后单跳委托至显式重载，杜绝多次访问 `Current` 引发的瞬态不一致。
- 显式重载中完全不访问 `_settings.Current`。测试中即使将 `ISettingsService.Current` getter 配置为抛出异常，显式重载也能正常工作。

### 3.2 Provider 直出 PreparedPrompt 与流延迟
- `OpenAICompatibleTranslationProvider`：
  - `var rendered = request.PreparedPrompt ?? _promptRenderer.Render(_promptTemplates.Get(_profile.PromptTemplateId), request);`
  - 构造 `messages` 时，若 `rendered.System` 非空则添加 system 角色消息，随后添加 user 角色消息。流式（SSE）与非流式（JSON）共用该请求体构造逻辑。
- `AnthropicTranslationProvider`：
  - `var rendered = request.PreparedPrompt ?? _promptRenderer.Render(_promptTemplates.Get(_profile.PromptTemplateId), request);`
  - 普通流式 `ReadNonBetaStreamAsync` 与 beta 降级流式 `ReadBetaStreamAsync` 均直接消费 `rendered.System` 与 `rendered.User`。
- 流延迟执行：创建 `TranslateStreamAsync` 的 `IAsyncEnumerable` 与获取 `IAsyncEnumerator` 期间绝不发送任何网络请求；仅在首次 `MoveNextAsync()` 时发起网络调用。

### 3.3 TranslationCacheKeyFactory 与安全执行键
- 执行键包含：`ProviderId`（取自 `registration.Descriptor.Id`）与 `RequestFingerprint`。
- 哈希计算严格遵照 TRANSLATION_EXECUTION §2：
  - 5 个字段顺序：`request.Text`、`request.SourceLanguage`、`request.TargetLanguage`、`rendered.System`、`rendered.User`。
  - 每个字段先写入 4 字节小端无符号整数 `(uint)field.Length`，再写入其 UTF-16LE 字符的 2 字节小端编码（`ushort`）。
  - 支持字段内包含 NUL 字符、非 ASCII 字符、任意孤立代理项（不进行 UTF-8 解码或转义，避免 Unicode 降级失败或跨字段边界碰撞）。
  - 输出使用 `Convert.ToHexStringLower(hash)` 产生严格 64 位小写十六进制字符串。
  - `TranslationCacheKey` 自身只保存 `ProviderId` 与 64 位十六进制哈希，绝不驻留原文、Prompt 或凭据信息。

### 3.4 LruTranslationCache 有界 LRU 实现
- 数据结构：使用 `Dictionary<TranslationCacheKey, LinkedListNode<CacheEntry>>` 结合双向链表 `LinkedList<CacheEntry>` 保证 O(1) 查找、插入与更新。
- 线程安全：使用内部 `lock (_gate)` 互斥锁保护所有读写、修剪与状态同步操作。
- Generation 控制：
  - 初始代次为 1；调用 `Clear()`、禁用缓存或将容量切换为 0 时递增代次。
  - `TrySet(key, text, generation)` 校验入参 `generation == _generation`；若代次陈旧，直接拒绝写入并返回 `false`，不改动缓存链表与成本预算。
- 成本统计与逐出：
  - 每项成本严格为 `256 + 2 * (key.ProviderId.Length + key.RequestFingerprint.Length + text.Length)`。
  - 单项成本超出 `MaxEntryBytes (1 MiB)` 时，若存在同键旧项则将其移除，拒绝新项写入并返回 `false`，不淘汰其它无关项。
  - 逐出策略：当总条数超过容量上限或总成本超出 `MaxTotalBytes (16 MiB)` 时，从链表尾部（LRU 项）循环逐出，直至满足双重约束。
- 动态设置监听：
  - 订阅 `ISettingsService.Changed`。
  - 当容量上限缩小时，立即在锁内修剪超出容量的 LRU 项；若容量缩为 0 或缓存被禁用，则清空缓存并递增代次。
