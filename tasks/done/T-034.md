## 1. 目标与范围

为翻译编排器提供可实际保存、检索和维护的历史库。实现 DatabaseInitializer、SqliteHistoryRepository、连接/迁移内部帮助类型与启动/DI 接线；精确同步 CCR-005。历史 UI 与编排器仍不在本单。

## 2. 交付要求

1. **契约**：HistoryResult.Truncated、HistorySummary、QueryAsync 摘要返回、GetAsync 详情、HistorySettings.MaxEntries 注释以及初始化契约，按 CCR-005 同步 CONTRACTS.cs 与两个落地 Core 文件。不得自行修改其它签名。
2. **迁移**：按 DB_SCHEMA.sql 顺序实施 V1→V2，每迁移一个事务；V1 原数据及 Id 保留，旧结果 Truncated=false。脚本中的 BEGIN/COMMIT 可交由 SqliteTransaction 管理，但不能嵌套重复 BEGIN。版本仅成功提交后递增；未来版本、损坏库、不兼容表结构保留原件并安全失败。
3. **仓储**：按 HISTORY_STORAGE.md 的输入捕获、UTC、精确去重/收藏保护、非收藏修剪、结果顺序、FTS 同事务与 CRUD 幂等规则实施。禁用 History 不在仓储中偷偷丢弃已提交 Add 请求，记录策略由后续编排器负责。
4. **查询**：默认 50、最大 200 条摘要，全文/译文通过 GetAsync 按需读取；Total/页和头/结果分别在一致读事务中。FTS 按 Unicode 标量数路由，MATCH 与 LIKE 都使用字面量转义参数；检索词不作为 SQL/FTS 指令。
5. **线程和取消**：整个 SQLite 操作在后台同步工作单元中执行，不把数据库 async 方法当作切换线程；串行写门闩与立即写事务保护去重/修剪。提交前取消回滚，提交后不伪报取消。所有失败均释放连接和事务，安全异常/日志不泄漏记录内容。
6. **接线**：Infrastructure 注册 initializer/repository 单例，构造无 I/O；AppBootstrapper 设置加载后、用户入口启用前等待初始化。Host 校验及启动顺序测试覆盖成功和安全失败，不注册未实现的界面服务。

## 4. 验收场景

- **初始化**：新空库到 V2；带数据的 V1 升级到 V2；重复/并发初始化；取消后可重试；未来版本/损坏/只读失败且原件不被删除覆盖；运行连接实际开启外键和 WAL。
- **写入一致性**：原文/语言相同且最新非收藏时更新同 Id；改源语言或目标语言不合并；最新收藏永不被覆盖；结果替换及 Truncated 正确；输入结果列表调度后被修改不影响保存。
- **检索**：中文、emoji、引号、OR/NEAR、%、_、反斜杠、空白与 NUL、空结果；FavoritesOnly 组合；Total、稳定时间/Id 排序、偏移边界正确；摘要不包含完整长译文，GetAsync 返回全文/完整有序结果。
- **维护**：收藏、取消收藏、删除、Clear 两种模式和非收藏容量修剪后，主表/子结果/FTS 无孤儿且检索同步。收藏不占 MaxEntries 额度。
- **事务与并发**：受控的中途 SQL 失败或提交前取消不留下半条记录；并发 Add/Query/Clear 满足事务边界，Total/页和详情头/结果来自同一快照。不要只跑快速 Task.WhenAll 后声称验证了指定交错。
- **线程/资源**：专用调用线程证明打开连接和 SQL 在后台；失败/取消后连接释放，数据库可重开。记录文本/搜索词/模拟异常包含假敏感值时，对外错误及日志不回显。
- **组合根**：Release Host 能构建；数据库初始化完成前托盘/业务入口不会启动，存储失败走既定安全出口。

     - 线程与并发安全（`SemaphoreSlim` 与 `Task.Run` 后台工作单元）；

     - 版本 0 时检查已有表避免掩盖不兼容结构；未来版本（`version > 2`）或损坏文件保留原件，安全抛出 `IrisException(StorageFailure)`，不覆盖用户文件；
     - 迁移完成后核验关键列与 FTS 完整性。

   - 调用边界参数校验与输入捕获（深拷贝 `Results` 生成不可变列表，防止调度后台后调用方修改引发并发竞态）；
   - UTC ISO-8601（`"O"`）时间戳；UTF-8 SHA-256 小写十六进制哈希；
   - 串行写门闩（`_writeLock`）配合立即写事务（`BEGIN IMMEDIATE`）；
   - 精确去重规则：仅当最新一条记录未收藏且 `text_hash`、`source_text`、`source_lang`、`target_lang` 四项完全匹配时更新原有 Id 的主记录、结果与 FTS；最新一条已收藏则不覆盖，插入新记录；
   - 非收藏容量修剪：`MaxEntries` 仅限制非收藏条数，收藏额外保留；在 `AddAsync` 与 `SetFavoriteAsync(id, false)` 后同事务执行修剪；
   - 摘要分页（`QueryAsync`）：默认 50 条、最大 200 条；在单一一致读事务中聚合 `Total`、`result_count`、`has_truncated_results` 与 `raw_preview`；`SourcePreview` 取前 200 个 Unicode 标量（Rune），超出追加 `…`；
   - 搜索路由与字面量转义：Trim 后 Unicode 标量数 >= 3 走 FTS5 MATCH（以双引号包裹且内部双引号转义为两个双引号），< 3 走 LIKE（反斜杠转义 `%`、`_`、`\` 并使用 `ESCAPE '\'`）；禁止包含 NUL；检索词完全作为字面量匹配，无法注入 SQL 或 FTS 操作符；
   - 详情读取（`GetAsync`）：在读事务中读取完整原文与按 `sort_order ASC, id ASC` 排序的结果列表；正 Id 不存在返回 null，非正 Id 抛出参数异常；
   - CRUD 幂等维护：删除/清空通过级联与同事务语句同步 FTS 虚表；异常安全映射为 `ErrorCode.StorageFailure`，不回显用户原文、搜索词或模拟异常中的敏感信息。

## 4. 关键验收场景与受控测试证据

### A. 数据库初始化与迁移（DatabaseInitializerTests，7 项）
- `InitializeAsync_FreshDatabase_MigratesToV2_AndCreatesAllTablesAndIndices`：空库直接执行完整迁移至 V2，`user_version = 2`，外键、索引与 FTS 均就绪。
- `InitializeAsync_FromV1Database_PreservesDataAndId_AndAddsV2ColumnsAndIndices`：预先用 V1 结构写入历史记录与子结果，执行迁移后验证数据及自增 Id 原样保留，且原有结果的 `is_truncated` 默认值为 0（`Truncated = false`）。
- `InitializeAsync_RepeatedAndConcurrentCalls_SucceedsIdempotently`：并发 10 个 Task 同时调用 `InitializeAsync`，单一门闩与内部检查确保执行幂等且不发生锁冲突。
- `InitializeAsync_Cancellation_CanRetryAndSucceed`：传入已取消的 Token 抛出 `OperationCanceledException`，后续重新以未取消 Token 调用成功完成建库。
- `InitializeAsync_FutureVersion_ThrowsStorageFailure_AndDoesNotOverwriteOrDeleteFile`：`user_version = 99` 的数据库抛出 `IrisException(StorageFailure)`，原文件内容与修改时间未被删除或覆盖。
- `InitializeAsync_CorruptedDatabase_ThrowsStorageFailure_AndPreservesOriginalFile`：写入 1024 字节伪随机乱码数据模拟损坏文件，`quick_check` 失败抛出 `IrisException(StorageFailure)`，原文件被完整保留。
- `InitializeAsync_VersionZeroWithExistingTables_ThrowsStorageFailure_AndDoesNotOverwrite`：手工注入已有表但未设定版本的异常数据库，初始化器识别不兼容结构并安全失败。

### B. 历史写入、去重、收藏保护与隔离（SqliteHistoryRepositoryTests，18 项）
- `AddAsync_ValidEntry_InsertsHistoryAndResults_AndUtcCreatedAtPreserved`：验证 UTC ISO-8601 时间戳及 UTF-8 SHA-256 小写十六进制哈希生成。
- `AddAsync_DuplicateTextAndLanguages_WhenLatestNonFavorite_UpdatesExistingId`：连续插入原文与语言对相同的记录，因最新记录未收藏，更新同 Id 的时间戳、结果与 FTS 索引，不分配新自增 Id。
- `AddAsync_DuplicateTextDifferentLanguages_InsertsNewRecord`：改变源语言或目标语言时，拒绝去重合并，插入新记录。
- `AddAsync_DuplicateText_WhenLatestIsFavorite_NeverOverwritesFavorite_InsertsNewRecord`：最新一条记录为收藏状态时，绝不覆盖，安全分配新 Id 插入新记录。
- `AddAsync_DefensiveCopy_CallerModifyingListAfterCall_DoesNotAffectSavedResults`：调用方在调用 `AddAsync` 传入列表后修改原列表内容，仓储保存的内容仍为调用时刻的不可变捕获副本。
- `AddAsync_Pruning_NonFavoritesPruned_FavoritesKeptRegardlessOfMaxEntries`：设置 `MaxEntries = 3`，写入 3 条收藏记录与 5 条非收藏记录，非收藏修剪至最新的 3 条，全部 3 条收藏记录原样保留，总记录数 6 条。
- `SetFavoriteAsync_Unfavorite_TriggersPruningOfNonFavorites`：取消收藏导致非收藏条数超出 `MaxEntries` 时，同事务触发容量修剪。
- `DeleteAsync_DeletesHistoryAndCascadeResults_AndRemovesFromFts`：删除主记录，级联删除子结果，并通过触发器同步删除 FTS 虚表对应记录。
- `ClearAsync_KeepFavoritesTrueAndFalse_CleansUpCorrectly`：验证 `keepFavorites: true` 保留收藏记录，`keepFavorites: false` 物理清空所有主表、子表及 FTS 虚表。

### C. 检索、Unicode 字面量与摘要详情分离
- `QueryAsync_SourcePreview_TruncatesAt200Scalars_WithEllipsis`：测试包含 205 个中文字符的文本，`SourcePreview` 精确截取 200 个 Unicode 标量并追加 `…`。
- `QueryAsync_PagingAndSorting_OrdersByCreatedAtDescIdDesc_AndPaginatesCorrectly`：按时间倒序与 Id 倒序稳定排序，支持基于 `Offset` 与 `Limit` 的精确分页。
- `QueryAsync_KeywordRouting_FtsAndLike_LiteralEscaping_AndEmoji`：
  - 检索词为中文/emoji 且 Unicode 标量数 >= 3 时走 FTS5 trigram MATCH，包含引号、`OR`、`NEAR` 等特殊字符均被视为字面量转义，不引发语法错误；
  - 检索词标量数 < 3 时走转义 LIKE 查询，包含 `%`、`_`、`\` 均正确转义。
- `QueryAsync_MatchesOnResultText_ReturnsSummary`：译文命中检索词时亦正确返回摘要。
- `GetAsync_ReturnsCompleteEntry_WithOrderedResults`：通过 Id 读取完整无截断原文与按 `sort_order` 有序排序的子结果列表；`Truncated` 标记准确。

### D. 事务原子性与回滚保证
- `AddAsync_ControlledSqlFailure_RollsBackEntireTransaction_LeavesNoOrphans`：通过在 `translation_result` 表上创建受控的 `BEFORE INSERT RAISE(ABORT)` 触发器，模拟子结果插入失败，验证主表未产生孤儿记录，FTS 虚表亦无残留，事务完全回滚。
- `AddAsync_CancellationBeforeCommit_RollsBackEntireTransaction`：在写入过程中触发取消，验证事务回滚无脏数据，连接安全释放。

### E. C12-1 纯测试补强
- `Concurrency_SettingsUpdateAndWriteInterleaving_MaintainsLatestSettingsCapacityAndCost`：
  - 使用拦截型设置服务在读取当前配置（容量 3）时触发事件门闩并暂停任务 1；
  - 任务 2 动态发布缩容配置（容量 2）并进入 `Changed` 回调；
  - 释放门闩放行任务 1，等待两任务完成；
  - 断言最终缓存状态严格符合最新缩容配置（条数 2，LRU 尾部项被修剪，内存成本与键集合精确符合）。
