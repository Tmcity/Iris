## 2. R3-01：RealUiaProcessSession 的实际失败重试

已复现：使用真实已退出的自有宿主 Process，只将 stdin writer 替换为一次关闭失败的受控 writer；首次 Dispose 故障后解除故障，第二次 Dispose 返回同一个 faulted Task，未重新尝试关闭。原因是 `DoDisposeAsyncCore` 同步失败时先将 `_disposeTask=null`，外层随后又把失败 Task 写回。stderr 已故障的 Task 也被永久当成“尚未排空”，重试重复旧错误。

1. 预登记完整的共享 Dispose 尝试，在成功/失败后以统一方式更新状态；避免同步完成/失败和 `_disposeTask` 赋值竞争。在途调用共享真实等待；失败后的下一尝试仅处理未完成的实际责任。不能通过吞掉首次异常修复。
2. 区分 stderr 仍在运行、已成功结束、已故障但终态已观察。首次故障安全报告，保留历史错误；完成流/句柄释放后，后续清理不能把同一个已观察 faulted Task 当成永远未结束的资源。仍运行的 drain 必须真实等待，不能直接标记完成。
3. 真实 runner 的 stderr 循环仍 catch 所有 IOException/ObjectDisposedException 当正常结束。只允许明确的正常 EOF/自有关闭条件，意外 I/O 故障必须经过实际 runner 到 session/reader 可见。检查真实路径，不仅给 session 构造一个 faulted Task。
4. 保存每个自有流的引用和阶段，释放一个失败仍尝试其它资源；Process.Dispose 后不能因只剩 Process 属性访问而失去尚未清完的流。已启动但会话包装失败的回滚必须持有并确认退出，不能只 Kill/Dispose 并空 catch；启动失败前的 Process 对象也须配对释放。
5. 补实际 session/runner 的首次同步失败、异步失败、故障解除后重试、并发 Dispose、stderr 终态与管道释放测试。外部流/进程边界可以注入；被测协调逻辑必须是产品真实实现。保持 P1 级失败责任与错误正文脱敏要求。

## 3. R3-02：停止入口、接纳预算与安全完成

已复现：真实 WPF Dispatcher 调用 Stop，Start token 注册的取消回调在 UI 上、持 reader `_gate` 执行；前置目标查询内推进 1600ms 后仍启动宿主并 Success；目标查询抛出虚构私有正文后，异常 ToString 通过 InnerException 原样泄露。

1. Stop 入口在锁内仅同步撤销准入/发布、登记共享停止尝试。将取消回调执行移出共享锁和 UI，并持有/等待该工作；不能只是把取消后的 ExecuteStopCoreAsync 放进 Task.Run。同步 Dispose 对活跃资源仍明确失败，不能在锁内执行外部取消回调。
2. 从操作接纳时记录单调起点，Ready 的 1500ms 包含前置查询/排队/启动/握手；后台执行检查剩余预算。前置校验已耗尽预算时，不继续启动或发送请求。保持请求 300ms 与退出预算常量，不延长时间掩盖缺口。

## 4. R3-03：截断尾流不能被第二层 EOF 捕获接受

已复现：合法 Reply 后再输出未完成 JSON，然后抛 `IOException(HRESULT=0x8007006D)`。frame reader 因已有部分字节正确拒绝，但 `SessionCleanupCoordinator` 又将所有 IsPipeClosedException 当正常关闭，最后返回 Success/Text。

1. 正常 EOF 的判断由掌握本帧字节状态的读取层完成。父端清理不得再仅凭 HRESULT 吞掉已向上传播的断管错误；同样覆盖 `0x800700E8`。有截断/额外帧/非法尾流时必须拒绝文本并真实收尾。
2. 保留空缓冲正常断管、零字节 EOF、合法完整 Reply 成功，以及 R2 的数值 Status/普通 IOException 拒绝成果。
3. 增加实际 frame reader + reader 回归：合法 Reply 后部分 JSON + 两种断管错误、纯截断 EOF、合法正常 EOF 对照；不能只测 codec 或只用无字节 IOException。

## 5. R3-04：COM 失败释放仍须保有责任

已复现：RealUiaAutomationSession 在检查 owner thread 之前先置 `_disposed=true`；错线程 Dispose 抛错后，回到 owner thread 的合法 Dispose 直接返回，失去释放机会。静态复核还发现 range 数组 finally/部分 ranges 与初始化失败仍有空 catch，CoInitializeEx 的 RPC_E_CHANGED_MODE 被容许继续。

1. 先验证 owner thread，再改变释放状态；错线程拒绝不消耗释放责任。释放失败按实际完成阶段保留责任，正确线程能够重试剩余部分。
2. CoInitializeEx 只有成功（包括 S_FALSE）才进入匹配 MTA 生命周期，失败不继续做 UIA 创建；失败不调用不属于本次的 CoUninitialize。保持同一无窗口 MTA 初始化/使用/释放，配对每次成功初始化。
3. 完成 R2 已要求但尚未落实的真实 adapter 释放错误处理：array、部分 range、创建后超时设置失败/类型获取失败均逐项尝试释放，错误不能空 catch 假装成功。保留 BSTR finally、祖先继续释放和错误分类成果。
4. 提供实际 COM 生命周期/释放边界接缝，测试 S_OK/S_FALSE/失败、错线程拒绝后 owner 重试、初始化中途失败、array/partial range 释放失败继续其余资源。仅 `IsComObject=false` 的托管替身测试或虚构 ownerThreadId 的一次拒绝，不能证明释放已完成。无需真实读取用户选区。

# 实施技术报告（T-022B-R3）

## 8. 技术实现细节与架构闭环

### 8.1 R3-01：RealUiaProcessSession 实际失败重试与 stderr 终态闭环
- **共享 Dispose 竞争与重试状态机**：在 `RealUiaProcessRunner.cs` 中重构 `RealUiaProcessSession.DisposeAsync`，使用 `TaskCompletionSource`（`RunContinuationsAsynchronously`）预先注册 Task 并赋值给 `_disposeTask`。在途调用一律共享等待同一任务；失败时在锁内清除 `_disposeTask = null` 并保留阶段未完成标记；再次调用创建新 TCS 仅重试未完成的释放阶段；彻底消除原 `_disposeTask` 被外层返回值覆盖写回导致无法重试的反例。
- **stderr 终态已观察记录**：引入 `_stderrDrainObserved` 标志，在首次 await 或 `WaitForExitAsync` 捕获异常后标记为已观察；第二次重试不再将同一已终态的 Task 当作未完成资源反复阻塞或重复旧异常。
- **自有流与句柄独立解耦持有**：`RealUiaProcessSession` 保存 `_stdinDisposable`、`_stdoutDisposable` 与 `_processDisposable` 引用，支持独立阶段追踪，`Process.Dispose()` 失败不影响流的关闭。
- **异常精确可见**：stderr drain 循环中仅捕获明确管道关闭与对象释放异常，意外 I/O 故障向上传播至 Task；进程启动回滚显式等待退出（1000ms）并配对调用 `_process.Dispose()`。

### 8.2 R3-02：停止入口、接纳预算、异常脱敏与完成屏障
- **停止取消移出共享锁与 UI**：在 `UiaSelectionReader.cs` 中，`StopAsync` 在 `lock (_gate)` 内仅同步标记 `_isStopped = true` 并启动后台任务；`_stopCts.Cancel()` 执行移入 ThreadPool 后台任务的首要步骤，持锁期间绝不执行外部取消回调；`ExecuteStopCoreAsync` 显式持有并等待活动操作的 `WorkerTask`。
- **接纳预算前置检查**：`ReadOperationContext` 记录操作准入单调时间戳 `AdmissionTimestamp`；在后台工作线程启动前计算已消耗时间，若前置目标校验已超过 1500ms Ready 预算，直接返回 `TimedOut`，不再调用 `_processRunner.StartAsync`。
- **目标校验异常隐私脱敏**：前置与最终目标校验失败的 catch 块中，统一构造安全的 `IrisException(ErrorCode.CaptureFailed, errorCode)`，其 `InnerException` 为 null，杜绝宿主窗口私有文本通过内部异常的 `ToString()` 泄漏。
- **完成屏障与活动槽收尾覆盖**：`ExecuteReadCoreAsync` 的结果与异常发布（`TrySetResult` / `TrySetException` / `TrySetCanceled`）延迟至 `finally` 块最末尾，确保在 `LinkedCts.Dispose()` 和清除 `_activeOperation` 之后才向调用方交回结果。

### 8.3 R3-03：尾流截断严格拒绝与真实收尾
- **第二层 EOF 泛吞断开**：`SessionCleanupCoordinator` Stage 4 移除 `catch (IOException ex) when (IsPipeClosedException(ex))` 的吞异常逻辑；`ReadLineWithLimitAsync` 已在字节层面准确区分干净 EOF 与截断断管（截断时 `IsCleanEof` 为 false 并重抛异常）；Stage 4 捕获异常后严格记录 `_op.TailIoError = true`，Stage 5 继续物理释放 session，最终返回 `PROTOCOL_ERROR`。
- **测试回归覆盖**：`UiaProtocolCodecTests` 新增 5 项单测覆盖截断+0x8007006D、截断+0x800700E8、截断+EOF、干净 0x8007006D 与干净 0x800700E8；`UiaSelectionReaderTests` 新增 3 项端到端 reader 测试验证 Reply 后的截断与正常 EOF 表现。

### 8.4 R3-04：COM 释放责任、MTA 边界与错误分类
- **所有者线程校验前置**：`RealUiaAutomationSession.Dispose` 在修改 `_disposed` 状态之前严格校验 `Environment.CurrentManagedThreadId == _ownerThreadId`；非所有者线程抛出 `InvalidOperationException` 且不改变释放状态，所有者线程可在后续合法重试。
- **RPC_E_CHANGED_MODE 严格拒绝**：`RealNativeUiaAdapter.CreateSession` 检查 `hrCoInit.Failed`，不再特判放行 `RPC_E_CHANGED_MODE`；初始化失败时不调用不属于本次的 `CoUninitialize()`。
- **Range 数组与部分 Ranges 回滚安全**：`RealUiaTextPattern.GetSelection` 中 range 创建失败逐项释放已建 range 并聚合异常；`finally` 块中释放 safe array 杜绝空 catch。提供内部 COM 接缝支持完整的生命周期与异常测试。

### 8.5 测试失败路径加固与历史报告补正
- **慢启动测试**：在 `ReadAsync_WhenStartTakesTooLong_TimesOutUnderReadyBudget` 中将 `startTcs.TrySetResult(session)` 置于 `finally` 块中，即使在断言后注入异常，Start 门闩也能得到放行，消除死锁。
- **STA 测试加固**：`StopAsync_And_RetryCleanupAsync_WhenCalledFromStaThread_ExecuteOffStaThread` 保证进入 Ready 读取后再推进虚拟时钟，异步释放 reader 并严格断言线程退出。
- **历史报告纠正**：纠正 R2 报告第 3.1 节关于慢启动超时的描述，第 2.3 节关于 Status 非法抛出异常的描述，按客观事实归档。
