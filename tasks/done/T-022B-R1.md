## 2. 变更实施要点

### 2.1 R1-01：原子准入、后台执行、预算起点与发布取消 (`UiaSelectionReader.cs`)
1. **单原子活动上下文**：在任何 native/进程操作之前，在 `_gate` 锁内原子登记唯一 `ReadOperationContext`（含 RequestId、目标 HWND/PID、启动/读取/清理共享 Task）。若已有操作未完成，立即返回 `Busy`，杜绝旧请求 finally 误清理新槽。
2. **纯参数同步校验与 UI 离开**：调用线程仅做参数空值/零值校验；目标 native 前置/后置校验、`_processRunner.StartAsync`、管道 I/O 及退出等待全部通过 `Task.Run` 在后台线程池执行，真实 STA 测试（`ReadAsync_WhenCalledFromStaThread_ExecutesTargetValidationAndProcessStartOffStaThread`）验证通过。
3. **Ready 预算 1500ms 覆盖启动**：Ready 预算计时器在 `_processRunner.StartAsync` 发起前即行创建并作为链接 token 传入；若启动超时，通过 `CleanupDelayedStartAsync` 后台跟踪并保证迟到进程被安全 Kill 与 Dispose，绝不向超时请求发送 Request。
4. **响应已到但未退出期间的 Cancel / Stop 门闩**：在 Reply 已接收、等待退出完成之后，再次强制核验 `CallerToken` 与 `_isStopped` 标志及前台目标有效性；清理期间发生取消或 Stop 绝不泄露文本。

### 2.2 R1-02：失败保留资源、共享清理与物理退出等待 (`UiaSelectionReader.cs`, `RealUiaProcessRunner.cs`)
1. **统一共享清理**：`PerformCleanupAsync` 通过 `op.CleanupTask` 共享在途清理，`Read`、`Stop`、`RetryCleanup`、`Dispose` 均等待同一物理清理，杜绝并发 Kill / 重复 Dispose。
2. **保留未完成清理所有权**：物理退出确认超时、Kill 异常或 Dispose 异常均记录在 `_failedCleanupSession` 中，后续 `Read` 强制抛出 `IrisException(ErrorCode.CaptureFailed)` 阻断新请求；通过 `RetryCleanupAsync` 显式重试清理成功后方可解除。
3. **stderr 排空任务持有与观察**：`RealUiaProcessSession` 持有 `_stderrDrainTask`，在退出等待与 Dispose 时一并观察，避免未捕获后台 Task 异常。
4. **严格核查退出码**：Reply 成功后必须等待宿主进程正常退出（宽限 1000ms），只有在 `session.ExitCode == 0` 时才发布 Success；非零退出码安全映射为 `PROCESS_EXIT_UNEXPECTED`。
5. **同步 Dispose 保护**：若有活跃读取或失败清理未完成，同步 `Dispose()` 明确抛出 `InvalidOperationException`。

### 2.3 R1-03：严格、有界协议 (`UiaProtocol.cs`, `UiaSelectionResult.cs`)
1. **wire 必需字段强制校验**：`UiaProtocolCodec` 基于 `JsonDocument` 严格反序列化，禁止借助 DTO 默认值兜底，强制校验 `protocolVersion == 1`、非空 `requestId`、受支持的 `status` 枚举及字段排他性约束。
2. **文本预算与错误码消毒**：选区文本必须非空白且长度 `<= 65,536`；非成功状态禁止附带文本；`SanitizeErrorCode` 将所有非法或超长错误码映射为安全的 `"INVALID_ERROR_CODE"`（仅允许 `[A-Z0-9_]` 及十六进制 `0x[0-9a-fA-F]`），防止私有信息或异常堆栈渗入 ToString。
3. **真实 wire 字节记账与严格 UTF-8**：`UiaProtocolFrameReader` 逐字节记账（1MB 严格上限），包括每行每个 CR 与 LF；检测连续 1MB CR 泛滥直接拒绝；使用 `new UTF8Encoding(false, throwOnInvalidBytes: true)` 严格拒绝损坏的 UTF-8。
4. **退出后安全 EOF 排空**：在确认子进程物理退出后，排空 `session.StandardOutput` 校验尾部干净 EOF；若有重复 Reply 或额外帧，标记 `op.ExtraLineDetected = true` 并返回 `"PROTOCOL_ERROR"`。

### 2.4 R1-04：真实 COM 适配器降级、预算与释放 (`RealNativeUiaAdapter.cs`, `UiaSelectionWorker.cs`)
1. **TextPattern2 安全降级至 TextPattern**：`RealUiaElement.GetTextPattern()` 在尝试 `UIA_TextPattern2Id` 抛出不支持异常（如 `0x80040204`）时，自动回退查询经典 `UIA_TextPatternId`；其它不可恢复的 COM 异常正常抛出由 worker 转换为安全错误码，绝不静默吞为 null。
2. **32 选区范围硬上限提前拦截**：`RealUiaTextPattern.GetSelection()` 在分配 List 与逐个取回元素前，先校验 `arr.Length > 32`；超限时立即释放原生 `arr` 并抛出 `IrisException(RANGE_COUNT_EXCEEDED)`，避免无界 COM 查询。
3. **COM 对象成对与保护释放**：`walker`、`patternObj`、`bstr`（通过 `Marshal.FreeBSTR`）均在 `finally` 中可靠释放；所有 `Marshal.ReleaseComObject` 均通过 `Marshal.IsComObject(obj)` 保护，确保在单元测试与托管代理替身下不抛出 `ArgumentException`。
4. **worker 处置故障安全保护**：worker 在 `finally` 中处置所有 COM 包装对象；若任一对象处置抛错，最终状态覆盖为 `Failed` 并报告 `"COM_CLEANUP_FAILED"`，确保不返回脏选区。
