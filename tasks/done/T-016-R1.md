## 2. 托盘异常不得把原始 Exception 交给日志（P1）

`DispatchInputTranslateAsync` / `DispatchClipboardTranslateAsync` / 当前修改的设置分发路径仍调用带 `Exception ex` 参数的 LoggerMessage；左击命令的错误回调也使用该日志路径。即使日志模板本身没有正文，logger 仍收到携带原始 Message、InnerException、Data 和堆栈的异常对象，日志后端可以输出这些内容。

独立探针通过真实菜单 Click 与真实 LeftClickCommand，令 Dispatcher 返回含合成标记的异常；实际 logger 收到原始异常，标记可读。原始输出见 tasks/done/T-016.md 的独立复审节，临时目录 `iris-t016-review`。

- 本单相关托盘分发边界仅记录固定动作/异常类型及必要安全元数据；生成的日志方法和调用点均不得传原始异常。不要只更换日志模板或替换探针字符串。
- 保持异步错误已观察、用户操作不崩溃、Dispose 后不分发；不重复追加无身份的错误通知。
- 补真实菜单与左击失败测试，使用可捕获 exception 参数和格式化消息的 logger；分别检查两者，不能用 NullLogger 证明脱敏。覆盖输入翻译、剪贴板翻译和本轮修改的设置分发入口。
- 不要求扩大修改托盘创建/通知等本单未改路径，也不要求重构共享命令执行模型。

## 3. 迟到读取测试及失败清理
