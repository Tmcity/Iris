# T-040后续分段2A：缓存与卡片重试

候选0.2.11的关闭窗口后45秒内存检查点核对完成、且助手确认合成服务已恢复后，才执行本段；目前仅准备材料。沿用同一候选、T040 OpenAI fixture和原输入，不修改服务、语言或Prompt，以保持缓存键条件。此前两种复制已经由用户明确确认准确，不再要求记事本截图。

1. 候选安装重启已清空进程内缓存，先从托盘打开输入翻译，输入 `Iris T040 input 01`，点击“翻译”一次并等待完成，再运行 `C:\IrisT040CacheCheckpoints\Save-Cache-Prime-State.cmd` 保存建立缓存的独立时点。结果应为 `Iris T040 synthetic translation`；这次预期新增合成服务请求，不把它计作缓存命中。
2. 同一输入/服务/语言/Prompt不变，再点击主“翻译”一次，等待完成。结果仍正确，卡片应出现“缓存”标记。用同目录 `Capture-Feature-View.cmd` 手工截图卡片，再运行 `Save-Cache-Hit-State.cmd`。助手比较这两次保存之间没有新增该文本请求及实际去重历史；相同结果本身不足以证明缓存。
3. 回该结果卡片，点击卡片中的“重试”一次，等待完成；该按钮也可用于已成功的终态卡片。结果正确后再次截图并运行同目录 `Save-Card-Retry-State.cmd`，独立核对新增实际请求、去除缓存标记且历史不新增。

实际入口不是一个独立“刷新”按钮；TranslateWindow.xaml绑定RetryCommand，中文资源为“重试”。OnCardRetry构造单卡请求时BypassCache=true、RecordHistory=false，所以本步期待新增网络请求并更新卡片，**不期待新增历史**。主“翻译”请求仍可写历史，二者须分别核对。

实际发执行步骤时请反馈建立缓存的首次翻译、第二次“缓存”标记与第三次“重试”的结果或错误原文。窗口、输入、点击和截图均由用户完成，助手只读对照服务日志和历史快照。HTTP重试/取消与错误提示另外分段，避免多个行为的证据混在同一次保存中。未完成当前内存检查点时不要提前操作本清单。

三个入口分别保存prime/cache/retry标记、同一PID476和候选四项代码身份指纹、配置/秘密哈希/只读历史、日志与实际存活合成服务的完整行请求前缀。服务缺失时保留失败并拒绝该功能阶段；标记不等于界面动作通过。工具准备实测只运行baseline和独立HTTP模型探针，没有操作Iris或证明真实缓存。原始准备结果见 `T-040.evidence/cache-checkpoint-preparation-review-20261107-1/binding.json`。
