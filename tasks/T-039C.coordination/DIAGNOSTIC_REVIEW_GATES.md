# T-039C：首轮 CI 失败定向诊断复审检查项

2026-10-27 · 架构师。适用于已签发的 `CI_FAILURE_SCOPE_APPROVAL_20261025.md`，仅明确独立复审需要的证据，不扩大产品或远端操作权限。

## 已知事实与本轮检查点

run40193113435 在成功建立隔离窗口站后实际执行原生剪贴板用例，结果为 3728 total / 3726 passed / 1 failed / 1 skipped。失败是 `Expected cancellation/busy when occupied.`，package/publish 未执行。原 archive 与 51 份解包原件已独立匹配；原 tag v0.2.0/source 必须保留。

当前源在 `Program.cs:247` 由协调线程 `OpenClipboard(NULL)` 建立占用，随后同步等待服务；服务在后台 Task.Run 中执行原生帧，并在重试帧之间 await。只读源码不能证明占用线程与每次服务原生线程属于同一桌面，也不能由 NULL HWND 推出锁持有者身份。暂不判定夹具或产品根因。

## 1. 修前实测与原始输入

- 冻结修前 commit、相关源文件、实际 helper/Platform/Core 程序集及完整依赖清单，保留长度与 SHA256；来宾实际输入和执行日志逐项绑定，不只绑定源码。
- 只在自有 Sandbox 执行可能访问真实剪贴板的诊断。记录 Sandbox ID、配置、运行时来源与版本、实际执行文件/参数/退出码以及最终销毁状态。测试工具准备运行时属于诊断条件，不能充作 C 的默认无缓存安装引导。
- 先保存原 helper 在该来宾的真实结果；若未复现原失败，明确记为未复现，并用记录完整的受控对照建立因果证据，不能把一次绿色当作原因已查明。

## 2. 实际原生身份与占用协议

- 记录 PID、Win32 TID、协调/占用/服务各原生帧的窗口站与线程桌面身份；每个重试帧均需可归属，不能用 managed thread ID 或进程窗口站代替线程桌面证据。
- 占用者先确认同一自有站/桌面及 Open 的实际成功，再发 ready；在被测服务实际工作与清理结束前保持占用，最后由占用者原线程 Close、销毁自有 HWND 并退出。参与者完整 join 后才恢复/关闭自有桌面与窗口站。
- 区分 `GetClipboardOwner`（数据 owner）和 `GetOpenClipboardWindow`（Open 所传窗口）。NULL opener 的观测值可为 NULL；任何单个 owner 值均不能代替 Open 返回值和协议时序。用独立参与者对真实独占条件做对照，禁止 fake native 结果。
- 若通过测试 adapter 记录真实服务调用，保留原产品程序集，并委托真实 NativeClipboardAdapter。记录 Open/Close 返回值与错误码时，在其它 P/Invoke、桌面查询或日志之前保存原错误，不因记录动作改变产品观察到的错误语义。
- 日志只使用合成内容。线程绑定应先于该线程可能创建 HWND 或访问剪贴板的操作；绑定失败必须在接触交互剪贴板前终止当前验证。

## 3. 取消、工作结束与失败清理

- 分别记录取消请求/接受、服务任务实际完成、原生 Close/Destroy 完成、占用者 release 和线程/进程 join。不能由令牌已取消或外层 Wait 超时推断真实工作已结束。
- 保留原取消/ClipboardBusy 断言及文本、DIBV5、序列变化和隔离恢复断言。正常返回、错误桌面、ready 未建立、清理失败或 join 失败均不能计通过。
- 异常/取消/父进程超时路径也要证明自有参与者已结束。不得静默吞掉清理失败后再报成功；仅结束自己实际启动且身份匹配的子进程。
- 不新增已运行失败转 skip 的分支，不过滤原失败测试，不仅增加 sleep 或超时预算。

## 4. 根因裁定与后续材料

若证明夹具条件无效，只在获批测试范围修正；用同一未改产品、明确有效的占用协议及修前/修后对照验证。若有效同桌面占用下产品仍违反契约，先提交最小实证与产品范围建议，由架构师批准后实施。任何结论都应说明原失败为何发生及所用证据的实际边界。

修后适当定向、Release 零警告/错误和未过滤全量测试必须保留原始汇总。宿主环境准入跳过只说明该宿主未执行；需要来宾的真实已执行通过证据。架构师独立建测与工程师串行，不同时运行。
