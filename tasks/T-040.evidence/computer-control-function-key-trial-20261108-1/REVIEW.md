# One function-key control trial

The child used the absolute official wrapper in the existing owned Sandbox, opened Iris settings through the actual tray menu and selected Hotkeys. All watched modifier and ordinary keys were released before recording. The original persisted InputTranslate binding was enabled Ctrl+Alt+F. After starting its draft recorder and waiting 1100 milliseconds, the child sent `sky.press_key({window, key: 'Ctrl+Alt+F5'})` exactly once at 11:31:24.675 through 11:31:24.803 UTC. The actual recorder and separately captured guest PNG both displayed **Ctrl+F5**, without Alt.

The child cancelled the whole settings page and sent no further chord or translation. The independent guest capture confirms the settings window closed; settings.json retained identical bytes and SHA256 `70b6aeb7abde4733528df5cba58bdc641ba8225588e99a8e91521dfbf278296b`, including the original enabled Ctrl+Alt+F binding. Final watched keys were all released. Host WPF test windows appeared in the later CU cancellation screenshot and were excluded: the independent guest screenshots contain only the owned guest desktop and show the recorded result and cancellation.

The parent's earlier letter-key trace is copied as an explicitly separate comparison. It shows Ctrl down, Alt down, an extra Alt up before F down, then final releases. This single F5 endpoint comparison also lacked Alt, so it does not support a failure limited to printable letter keys. It does not establish the native parser or remote-session cause, repair direct modifier delivery, or validate other function keys. The known initial Ready notification issue remained in the installed 0.2.15; its parent source fix was not installed here. The child used no OSK chord, extra recording attempt, wrapper/product patch, private bridge, helper launch, product CLI action or installer. Control was returned to the parent immediately after cancellation; remaining collection was read-only.
