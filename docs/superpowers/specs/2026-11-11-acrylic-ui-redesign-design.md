# Iris 亚克力界面重构设计

2026-11-11 · 状态：用户已批准（正文与实现方式一）· 工单号 T-041 · 分支 `codex/t041-acrylic-ui`

## 1. 目标与范围

把 Iris 的 WPF 界面改成 Windows 11 风格：亚克力窗口底、半透明卡片、图标和开关。除了材质，界面元素和布局也重做。业务逻辑尽量不动。

**范围内**：设置窗口、翻译弹窗、翻译历史窗口、划词图标、托盘菜单、更新失败窗口、截图遮罩上的标签。

**范围外**：
- 不新增设置字段，不改设置文件格式、数据库结构和契约（`specs/CONTRACTS.cs`）。
- 不引入新的依赖包，不升级 WPF-UI（现用 4.3.0）。
- 不改翻译、OCR、截图、划词、快捷键、更新的业务流程。唯一新增的行为是翻译弹窗的“停顿后自动翻译”（§5.3）。
- 系统消息框（安装更新确认）保持原样。
- 不处理 T-040 记录的内存超标（§9.4）。

样张在 `.superpowers/brainstorm/2075-1794245329/content/`（不入库）：`translate-layout-v3.html`、`settings-services.html`（选 B）、`history-layout.html`（选 A）、`small-surfaces-v2.html`（划词图标选 3）。样张里的图标、示例文字和像素尺寸是示意，以本文档为准。

## 2. 已确认的决定

| 项目 | 决定 |

## 3. 主题层与窗口材质

### 3.1 共用样式资源

新建 `src/Iris.App/Themes/`（`ARCHITECTURE.md` 要求颜色和间距放在这里，目前不存在）：

- `Iris.Styles.xaml`：样式和数值。
  - 卡片、行卡片（左边标题和说明，右边控件）。
  - 开关外观的 `CheckBox` 样式。控件类型不变，只换模板。
  - 图标按钮样式：保留字符串 `Content` 作为辅助名称和测试定位依据，界面只显示图标，鼠标提示显示文字。
  - 小标签、导航项、分组标题、药丸形筛选框（`CheckBox`）。
  - 间距、圆角数值。
- `Iris.Light.xaml`、`Iris.Dark.xaml`：只放 WPF-UI 没有的颜色键，由 `ThemeService` 随主题切换。能用 WPF-UI 现有画刷的地方直接引用。

约束：
- 不覆盖 `ApplicationBackgroundBrush`、`TextFillColorPrimaryBrush` 等 WPF-UI 已有的键，现有对比度测试依赖它们。
- 在 `App.xaml` 合并；`tests/Iris.App.Tests/TestSupport/WpfTestRunner.cs` 和 `UpdateRecoveryRenderingTests.cs` 自己搭的资源环境里加同一份。
- 图标一律用 WPF-UI 的 `SymbolIcon`（自带字体，Windows 10 可用）。不用 `Image`，不依赖 Windows 11 才有的 Segoe Fluent Icons。
- `src` 里不新增中文字面量和中文注释（本地化检查）。新文字进 `Strings.resx`、`Strings.en-US.resx`、`build/localization/app-catalog.json`，经 `UiText` 取用。

### 3.2 窗口材质服务

一个小服务，接口只有“给这个窗口应用亚克力或纯色”和“当前是否支持亚克力”。

- 亚克力：`SettingsWindow`、`TranslateWindow`、`HistoryWindow`。这三个窗口设 `ExtendsContentIntoTitleBar="True"`（WPF-UI 要求，否则抛异常）。
- 纯色：`UpdateRecoveryWindow`、`ScreenshotOverlayWindow`、`SelectionIconWindow`。服务不碰它们。
- 支持条件：系统版本号不低于 22621（Windows 11 22H2）。不满足时三个窗口用纯色背景，卡片改用不透明颜色（合并一份覆盖颜色键的小字典），布局不变。
- XAML 里窗口默认是纯色背景。服务在窗口句柄创建后才应用亚克力，所以离屏渲染测试和低版本系统看到的都是纯色。
- 窗口失去焦点时系统把亚克力显示为纯色，属系统行为，不处理。

### 3.3 主题切换

`ThemeService.cs:186` 现在调用 `ApplicationThemeManager.Apply(theme)`，默认带 Mica 并作用于 `Application.MainWindow`。Iris 没有设置主窗口，被改的是碰巧先创建的窗口。子代理单独试验 WPF-UI 时确认了这一点，在运行中的 Iris 里**未验证**。

改为：切换主题时明确传入“无材质”，材质只由 §3.2 的服务管理；主题切换后服务对已打开的亚克力窗口重新应用一次。加一条测试：切换主题后，纯色窗口的背景仍是不透明的 `SolidColorBrush`。

## 4. 设置窗口

### 4.1 窗口与导航

- 默认 760×520，最小 600×440，不变。
- 导航八项不变，每项加图标；选中项有浅底色和强调色短线。导航仍用 `Border` 实现（测试把 `NavScreenshot` 转成 `Border`）。
- 导航宽度：窗口宽度不小于 680 时 176；小于 680 时只显示图标（约 48 宽），鼠标提示和辅助名称是页面名。现状是固定 140。
- 页面仍全部写在 `SettingsWindow.xaml` 一个文件、一个命名范围里，不拆成 `UserControl`。

### 4.2 各页通用排法

- 每项设置一张行卡片。现有说明文字全部保留，放在标题下面（`LOCALIZATION.md:37`）。
- 勾选框保持 `CheckBox`，用开关样式。
- 数字输入保持 `TextBox`，保留未完成或不合法的文字。不用 `ui:NumberBox`。
- 密码框保持 `System.Windows.Controls.PasswordBox`，只换外观。不用 `ui:PasswordBox`。
- 常规、快捷键、划词翻译、截图、网络与代理、翻译历史六页：内容和功能不变，只换排法。常规页的更新控件、凭据的保留 / 替换 / 清除、划词的四种读取方式等规范要求的文字都保留。

### 4.3 翻译服务页

**列表页**
- 顶部“添加服务”：保持 `ui:Button` + `ContextMenu`（四个预设），英文界面下宽度大于 70。
- `ProfilesListBox` 保持 `ListBox`（拖动排序的代码依赖 `ListBox` 和 `ListBoxItem`）。每行：拖动把手、启用开关、名称和模型、“⋯”按钮、右箭头。
- “⋯”菜单：上移、下移、删除服务。点开时先选中该行，再调用现有命令。
- 点一行的名称区域或右箭头，或在选中行上按 Enter，进入详情。点拖动把手、启用开关、“⋯”按钮不进入详情。上下键只移动选中项。

**详情页**
- 标题“翻译服务 › 服务名”，点“翻译服务”返回列表。
- 四组：基本信息、凭据管理、请求参数、高级选项。高级选项保持 `Expander`（可用 `CardExpander`），默认收起。
- 详情里的控件保留现有 `x:Name`，不放进模板，折叠时绑定仍然有效（保存时刷新焦点文本框、切换服务清空密码框等现有逻辑和测试依赖这些）。

**状态与规则**
- “是否显示详情”是 `SettingsViewModel` 上的一个界面状态属性。不保存，不新增页面编号（未知页面编号仍回到常规页）。
- 切换导航页、当前服务被删除时回到列表。
- Esc 仍是放弃修改并关闭设置，不用作返回（`SETTINGS_EDITING.md:86`）。
- 保存进行中，列表里的开关、“⋯”菜单、“添加服务”、拖动全部禁用（`PROVIDER_SETTINGS_UI.md:52`）。
- 原来窄于 680 时列表和详情上下叠放的列定义和代码删除。

### 4.4 OCR 页

- 上方是整页设置：首选服务、备用服务、版面、语言提示、自动复制、通知。
- 下方是服务列表，点进详情，排法同 §4.3。`OcrProfilesListBox` 保持 `ListBox`。
- 没有拖动把手和上移 / 下移（`OCR_SETTINGS_UI.md:17` 不新增排序）。内置的两个服务可以禁用，不能删除。

### 4.5 底栏

状态文字、各“重试”按钮、取消、保存都留在底栏，列表页和详情页都可见。600×440 下六个按钮加状态文字不横向溢出；保存、取消宽度不小于 70，仍是字符串 `Content`。

## 5. 翻译弹窗

### 5.1 布局

- 默认宽 460，范围 280–1200；高 480，最小 300。不变。
- 顶栏：左边 `SourceLangComboBox`（外观像按钮），右边 `PinButton`、`SettingsButton`（图标按钮）。中间空白处拖动窗口。没有图标、标题和关闭按钮。
- 原文卡片：`InputTextBox`（最高 200 后滚动）。左下角是状态文字和 `StopButton`，右下角是字数。
- 目标语言栏：`SwapLanguagesButton`、“译为”加 `TargetLangComboBox`。
- 结果区：`CardsScrollViewer` 里每个服务一张卡片：名称 · 模型、耗时、缓存标记、复制和重试图标按钮、截断提示、只读译文；出错时显示错误和“去设置”。
- 整次翻译的错误（如未配置服务）在结果区显示一条提示，带“去设置”。
- 宽度变化只影响换行，`TranslateWindow.xaml.cs` 里窄于 420 时重排控件的代码删除。高度小于 440 时结果区的最小 / 最大高度规则保留（280×300 下结果区可视高度不小于 160，复制按钮可点）。
- 隐藏方式：未固定时失去焦点（现有 `HideOnDeactivate`），或 Esc。固定后只有 Esc 或取消固定。

### 5.2 显示上补的两处

规范已有要求，现状未实现：
- 源语言为“自动检测”时，翻译后在源语言按钮后面用灰字显示检测出的语言（来自视图模型已有的解析结果）。
- 改了原文或语言后，旧卡片变淡并标“上一次结果”，新翻译开始时替换。

### 5.3 自动翻译（新行为）

在 `TranslateWindowViewModel` 里加一个防抖计时，计时来源可注入，测试用假时钟。

- 触发：用户修改原文、源语言、目标语言，或点交换按钮后，静止 1000 毫秒。常量，不做成设置。
- 效果：等同调用 `ExecuteTranslateFromUser()`，包括写历史、用缓存。
- 按 Enter（或按 `EnterToTranslate=false` 时的 Ctrl+Enter）立即翻译，并取消等待中的计时。
- 不触发：
  - 预处理后原文为空（不报错，也不显示“请输入”提示；该提示只在按 Enter 时出现）。
  - 输入法正在组字。组字结束后重新开始计时。
  - 原文和语言与上一次已发起的翻译完全相同。
  - 用户点了“停止”，直到下一次修改。
  - 程序写入的文字（划词、剪贴板、截图、历史重译）：这些入口照旧立即翻译，不经过计时。
- 原文超长：不发请求，字数变红并显示现有的超长提示。
- 窗口隐藏、关闭、应用退出时取消等待中的计时。
- 修改会取消进行中的翻译，这是现有行为，不变。

### 5.4 停止

`StopButton` 保持独立的 `ui:Button`，只在翻译进行中可见。点击后同一位置显示“已停止”，已出来的译文保留。`TranslateButton` 删除。

## 6. 翻译历史窗口与小界面

### 6.1 翻译历史窗口

- 800×640，最小 280×240，不变。
- 实际宽度不小于 640 时左右分栏，小于 640 时单列。按实际宽度判断，因为 `PlaceInWorkArea` 会在代码里改最小尺寸。只用界面代码和现有属性（`SelectedRow`、`HasSelection`、`HasDetail`、`IsDetailLoading`、`HasConfirmation`），不改视图模型逻辑。
- 左栏（约 324 宽）：`SearchTextBox`、“仅看收藏”（`FavoritesCheckBox`，药丸样式）、刷新、清空；占满高度的 `HistoryList`；底部翻页（图标按钮加页码文字）。
- 列表项：两行原文预览；一行时间 · 来源 · 语言 · 结果数；“收藏”“结果已截断”小标签。
- 右栏：收藏 / 取消收藏、“按当前设置重新翻译”（保留文字）、删除此记录；原文卡片；每个服务一张译文卡片（`ResultsList`，不虚拟化）。右栏有自己的滚动区。
- 未选中记录时右栏显示现有提示“选择一条记录查看全文和全部服务结果”。
- 加载中、空列表、出错的文字显示在列表位置。
- `ConfirmationPanel`（`Border`）横跨两栏，在内容区最上方；单列时放在滚动区内。“保留收藏”仍是 `CheckBox`，默认勾选。
- 两种复制都是卡片右上角的图标按钮，鼠标提示分别是“复制原文全文”“复制此服务译文”。`CopySourceButton` 移进原文卡片，因此全文读取中或读取失败时不显示。
- 底栏：`Status` 和 `CloseButton`，不变。Esc 关闭、截图时隐藏、关闭时的排空流程不变。
- 保留现有行为：每次查询和每次写入完成后清除选中。
- 测试依赖的名称和类型全部保留：`HistoryScroll`（单列时的滚动区）、`HistoryList`、`PreviousButton`、`RetranslateButton`、`SourceTextBox`、`ResultsList`、`ConfirmationPanel`、`CopySourceButton`、`ClearButton`、`ConfirmButton`、`KeepFavoritesCheckBox`、`CloseButton`。右栏滚动区新增一个名称。

### 6.2 划词图标

- 24×24 DIP，位置、自动隐藏、不激活、不进任务栏，都不变。
- 透明窗口（`AllowsTransparency`，在构造函数里、创建句柄之前设置），里面一个圆角 `Border`：不透明的卡片底色、细边框、强调色翻译图标。无阴影。
- 整个 24×24 方块都要能点（`MOUSE_SELECTION_INTERACTION.md:26`）。完全透明的像素会让点击穿透，所以圆角外的四个角用几乎透明但不为零的填充。这一点没有自动化测试覆盖，需要真实点击验证。
- `TranslateButton` 仍是触发 `Click` 的 `Button`。鼠标提示、辅助名称、窗口标题仍是“翻译选中的文本”。“译 / T”字符资源不再显示。

### 6.3 托盘菜单

每个 `MenuItem` 加 `Icon`（`SymbolIcon`），在 `CreateContextMenu` 里创建。顺序、文字、功能不变。

### 6.4 更新失败窗口

保持纯色背景和现有结构（`StackPanel` 直接包含一个 `WrapPanel`，按钮直接在其中）。只调间距和按钮样式。所有画刷仍是 `SolidColorBrush`，文字对比度不低于 4.5；不使用 `TextFillColorTertiaryBrush`（浅色下对比度 3.28）。

### 6.5 截图遮罩

- 窗口保持不透明（`SCREENSHOT_INTERACTION.md:23`）。遮罩、画面、放大倍率（15×15 → 120×120）不变。
- 提示、尺寸、坐标三个标签改成圆角矩形，底色不透明，颜色仍随 Iris 主题。圆角半径乘以 DPI 缩放。
- 内边距在 `ScreenshotOverlayWindow.cs` 里写了四处，改为一个常量。
- 选区边框和放大镜中心方块用系统强调色（进入截图时取一次），不随 Iris 主题变化；中心方块加白色外圈；放大镜加细边框。

## 11. 已知风险

- **划词图标的可见性**：底色和下面的内容接近时，只靠细边框区分。用户已知并接受。
- **自动翻译的费用**：每次停顿都会向所有启用的服务发请求，并记一条历史。缓存默认开启，相同内容不重复请求。
- **透明窗口**：划词图标改成透明窗口后，显示延迟和点击行为要真机验证。有问题就退回不透明的直角方块，只保留新的底色和图标。
- **翻译服务页的测试改动量最大**：布局测试是断言最多的一组，重写时逐条对应，不能只删不补。
- **导航在窄窗口下只显示图标**：依赖鼠标提示和辅助名称，两者都必须有。
