# OCR与截图设置页面

2026-10-07 · T-032B · ARCH v1.51 · 已定稿。

## 1. 范围和导航

在现有SettingsWindow/SettingsViewModel中完整开放`ocr`和`screenshot`页面，沿用现有导航、主题、UiText、草稿/保存/关闭协议。复用已验收T-032A的增量保存与草稿测试会话，不新增Core端口、不另建设置窗口。不恢复独立OCR结果窗口或截图预览；OCR结果仍写翻译原文框，M6延迟实现。

OCR页提供：已配置Profile列表/选择与编辑、主服务和可选备用服务、文本布局、语言提示、普通OCR原文自动复制、静默OCR成功通知。主备显示安全名称并以稳定ID保存；备用可选“无”，不能与主服务相同。未配置凭据允许保存，显示名称/引用存在不等于服务可用。

截图页提供全部现有字段：松开鼠标确认、放大镜、截图前隐藏Iris窗口、确认时复制图片、遮罩透明度。透明度范围0..0.9；其余默认值保持。编辑只改变草稿，保存后后续截图采用新快照，不在正在进行的截图中途改变行为；打开页面/切换选项不得捕获桌面或写剪贴板。

## 2. OCR Profile表单

显示/编辑名称、启用、超时5..120秒及Kind对应选项。百度支持四种现有模式、方向检测、段落信息、可选显式LanguageType、BaseUrl；Windows支持可选BCP-47 LanguageTag。不展示不存在的OCR模型列表、不增加Provider种类、不安装语言包。

支持添加已支持的百度/Windows自定义项，创建一次稳定唯一ID；编辑不允许改ID或Kind。列表顺序沿用配置顺序，新项按A协议追加，不新增排序协议。删除只允许非内置项；内置ocr-baidu/ocr-windows可禁用但不可删除。删除当前主/备自定义项时明确要求在同一草稿调整主备，不能隐式选其它服务。已有自定义项和未编辑字段必须保留。

数值使用文本草稿保留未完成/非法输入；保存与测试前显式刷新当前控件文本，不能悄悄沿用最后合法值。错误就地安全显示。保存前校验全部脏数据；测试只校验被测Profile/凭据的实际输入，不因截图透明度等无关未完成字段阻止测试。

## 3. 凭据

复用Keep/Replace/Clear编辑意图，文案为“保持现有凭据（如有）”“替换凭据”“保存后清除凭据”。百度Replace用两个PasswordBox输入完整ApiKey/SecretKey；空框不是Clear。Windows不接纳替换凭据，保留/清除意图按A处理。

UI不得直接Get/Set/Remove SecretStore，不回填存储密钥、不根据CredentialSetId声称密钥有效。仅构造ProviderCredentialEdit交给已验收协调器。切换Profile不串用密码或测试结果。已提交（Applied/ApplyPending）后清空本次明文输入与引用并恢复Keep；未提交失败保留供修正，Reload/放弃草稿/删除新增项/Dispose解除引用，不声称擦除托管字符串。

不把密钥写入普通配置、日志、异常正文、调试ToString或渲染图。自动化用合成值，截图密码应保持遮蔽；不使用用户真实密钥测试。

## 4. 一次联合保存和外部变化

向既有GeneralSettingsSaveCoordinator提交同一SettingsEditPlan，包含原通用/翻译/热键/划词与新增Ocr/OcrChanges/Screenshot。只生成实际编辑字段/Profile增量，不能把整份陈旧设置覆盖Current，不重复stage或实现第二条保存通路。

与原设置页一致处理dirty基线和外部变化：干净字段可合并最新值，脏字段保持原Base与用户Target，冲突安全提示并保留草稿；新增/删除/选择变化不得让旧异步结果写到新项。Profile和全局字段按各自责任校验，不用未编辑旧快照重置其它页面。

点击保存时同步固定全窗口计划并冻结再次编辑/提交。先取消并等待所有草稿测试和清理责任，再调用CommitAsync；关闭/停止先发生则不再提交。清理失败保持未提交事实及原测试会话，允许重试清理，不再Test或重新创建Provider。

Applied重建基线并清空已提交密码；ApplyPending也明确已保存，把原回执交给现有进程级receipt manager再重建基线，保留“重试应用”。它只调用RetryApplyAsync，不能重新提交计划或重复写密钥。原回执容量、开机自启独立应用、热键部分失败等已有规则不变。OCR/截图有实际编辑时必须按A的观察者/回执路径处理，不能仍误判为纯通用或纯划词提交而绕过配额。

## 5. 草稿测试与完整收尾

只有显式点击“测试连接”才创建A的IOcrDraftTestSession并调用RunAsync。保存所选Profile/基线/凭据快照与窗口会话、领域、Profile ID、输入修订、请求序号；测试通过只说明该快照的Test通过，不代表已保存或完成真实图像识别。未保存、禁用草稿可测试，失败保留用户输入并显示安全默认消息。

OCR任务键与翻译任务键必须区分领域，即使两者Profile.Id相同也不互相替换。沿用既有有界操作队列；同一OCR项至多一个真实运行，重复触发不得无限堆积。提供取消/处理中状态；取消必须等待实际Provider退出。编辑、切换、删除、Reload、外部替换和关闭使旧结果失效，不能用完成先后决定可见结果。

VM必须将测试会话保留为字段直至DisposeAsync成功。RunAsync返回结果后仍要等待Dispose完成才报告“测试完成”；清理失败时保留原会话、原测试结果及安全收尾状态，提供明确可点击的“重试结束测试/重试清理”入口。重试只能Dispose同一会话，不再次Run或创建Provider，不遗弃正在取消的任务。结果失败与清理失败都不能静默丢失。

窗口关闭、保存、放弃草稿、App退出都覆盖这些会话和取消回调。先封闭新操作，取消/排空测试，重试真实清理成功后才清除引用/释放窗口scope。失败保有原窗口及会话，显示可操作关闭/清理重试入口；重复关闭共用在途责任，不创建第二窗，不在Closing事件同步等待或抛未处理异常。不得先等待OCR Registry.Stop而仍持其瞬态租约造成循环。维持现有截图准备对设置窗口的临时隐藏/条件恢复行为。

UI状态使用用户可理解的“测试中”“正在结束测试”“结束测试失败，请重试”等，不向用户暴露快照/租约或实现细节。不因页面导航自动发请求或修改注册表/系统设置。

## 6. 验证与交付

测试必须接真实SettingsWindow/VM/GeneralSettingsSaveCoordinator/SettingsEditCoordinator及实际OCR Registry；存储、SecretStore、Provider的外部通信用窄fake。覆盖导航、全部字段/两种Provider选项、增删及内置保护、数值非法输入、主备冲突、联合多页一次提交、未编辑最新值、ApplyPending原回执、配额与密码清空/保留。

覆盖未保存与禁用草稿测试、仅Test不Recognize、当前输入修订、同ID跨域任务隔离、取消非合作任务、Run结束但Dispose失败、可点击原会话重试、保存等待/关闭失败/退出重试、订阅与密码/Provider引用清理。异常夹具先开所有门闩，再等待任务和释放；不删除旧业务断言、不以全部mock生命周期证明完成。

实际查看离屏Light/Dark、两个页面、长标签/英文/中文、项目既有小工作区边界、非法值/测试中/测试失败/清理失败/保存待应用状态。画布尺寸与实际布局一致；文本和控件可读、可滚动到达，不仅检查文件生成。不得运行真实用户截图/剪贴板/全局输入/真实云请求/性能脚本，既有获准SDK smoke保持。发布为当前开发本地提交，不push；后续真实桌面兼容性与NFR仍在后续验收。

本单不改变Core公开契约、默认配置/schema/包或已验收后端算法。若实际接口不足，先提供复现实证和窄变更建议，由架构师处理，不自行扩展。
