# T-015 窗口会话、旧结果与单卡重试准备稿

> 2026-09-30，Codex；针对架构审查 A07。基线 e61fb8d。
> **设计草案，不是已批准契约或当前实施范围。** T-021A 继续原工单；公开接口提案须在 T-015 签发前另走 CCR。

## 1. 要解决的具体反例

- 截图/OCR 或剪贴板读取尚未结束时，用户开始输入；旧 Handler 结束后调用现有 ShowAsync，会覆盖新输入甚至重开已隐藏窗口。
- 只取消旧翻译 CTS，已经排入 UI 队列的 Delta/Completed/刷新回调仍可能改写新卡片。
- 重试单卡时出现新的 TranslationStarted；沿用“每个 Started 重建全部卡片”会清掉其它结果，取消全局 CTS 则会中断其它 Provider。
- 旧调用已经进入 T-013 历史收尾，或自动复制已进入 T-021A 原生写入提交阶段；窗口取消不能回滚这些已承诺的副作用。

T-014 的按 Action 防重入只决定是否接纳重复动作，不负责上述窗口结果归属。不要通过全局串行化所有 Action 来规避问题。

## 2. 推荐身份模型

| 身份 | 生命周期 / 作用 |
|---|---|
| 窗口 SessionId | 一次被接纳的输入/剪贴板/截图翻译意图；在异步取文本/OCR 前取得，替换、用户编辑或隐藏使其失效 |
| RequestId | 一次实际 Orchestrator 调用，使用既有 TranslationRequest.RequestId；主请求和每次重试各不相同 |
| 卡片当前绑定 | (SessionId, ProviderId, RequestId)，决定哪些事件可以更新这张卡片；无需修改 Provider 事件签名 |
| 发布资格 | 当前会话仍有效、窗口允许展示，且目标卡片绑定仍匹配；每次在 UI 真正执行回调时重新检查 |

建议用不复用的 Guid 作为会话身份，不将用户文本、时间戳或 ProviderId 当成操作身份。新意图的生效顺序取协调器的接纳顺序，不以服务完成顺序决定。

隐藏后可以保留最后显示内容供下一次打开查看，但保留内容不等于恢复旧操作的发布资格。旧 Show/刷新/错误不能再次把窗口显示出来。

## 3. 展示端口的候选调整

现有 TranslateWindowRequest 没有身份，现有 ShowAsync 同时表达“新意图”和“旧流程的后续更新”。推荐分开开始操作与尝试更新，不增加一个缺省为空、忘记填写就被当作新意图的 SessionId 字段。

以下是供 CCR 审议的**接口草图**，不写入当前 CONTRACTS.cs：

```csharp
public interface ITranslateWindowOperation : IDisposable
{
    Guid Id { get; }
    CancellationToken CancellationToken { get; }
}

public interface ITranslateWindowPresenter
{
    bool IsVisible { get; }
    bool IsActive { get; }
    ITranslateWindowOperation BeginOperation(CancellationToken cancellationToken = default);
    Task<bool> TryShowAsync(ITranslateWindowOperation operation, TranslateWindowRequest request);
    Task HideAsync();
}
```

需要同时定稿的所有权：

- BeginOperation 同步、线程安全地接纳新身份；不创建 WPF 对象、不在锁内取消或通知。先使旧身份失效，再在锁外取消旧工作并观察清理。
- 返回的 operation 是 Handler 的工作租约。Dispose 表示这个 Handler 已经退出，不应立即取消 VM 正在进行的翻译或清除窗口；App 为当前会话及其 VM 消费任务分别持有所有权。
- 新会话/隐藏使旧根失效并请求取消；旧 Handler/消费者、取消回调和枚举器清理全部退出后才释放对应 CTS。不得 Dispose CTS 后让仍运行的工作继续使用，也不得为了立即返回而遗忘旧任务。
- TryShowAsync 在 UI 回调内校验身份和租约；失效更新返回 false，不创建/显示窗口，不提示过期错误。真正参数/执行失败保持已知错误边界。成功更新返回 true 后也不授予未来无限发布权。
- 所有耗时前置操作都先获取租约，包括 ClipboardTranslate 的 GetTextAsync，而不只覆盖截图 OCR。
- 单纯重新展示保留的内容、手动编辑、再次 Enter 的会话关系须写进正式工单。建议用户编辑立即废弃旧发布资格并取消旧工作，保留旧结果作为只读历史显示；输入期间不必每个字符创建新的 CTS，提交时才创建执行会话。

该提案把协调器放在 App 的翻译窗口范围内，Core Handler 只依赖小型展示端口；不改 T-014、不增加全局任务总线。IDisposable 的精确释放顺序和异步取消观察必须先用受控测试证明，再批准公开签名。另一个可选方案是单独的操作协调端口，但不应同时维护两套会话状态。

## 4. 截图的临时隐藏不能等同用户关闭

截图服务会隐藏 Iris 窗口避免被截入图像。如果它调用会使会话失效的普通 HideAsync，将把自己刚取得的截图会话取消。

建议 App 内部区分 UserHide 与 CaptureSuppression。后者只暂时改变可见性，使用内部作用域，不经公共“用户隐藏”入口，不触发失焦取消。恢复时同时校验会话身份与可见性版本；如果期间用户已有新操作/关闭，不恢复旧窗口或抢回焦点。T-026/T-031 复用这条规则，不要求 T-015 提前实现截图窗口。

ScreenshotTranslate 使用翻译窗口的会话；ScreenshotOcr 使用独立 OCR 窗口会话，不能被普通输入翻译无差别清理。Silent OCR 的剪贴板效果另有自己的操作归属，后续沿用同样的“取得身份 → 检查资格 → 进入副作用提交点”规则。

## 5. 单卡重试

推荐规则：

1. 主请求的 TranslationStarted 创建有序卡片。重试只能操作已有的目标 ProviderId，retry Started 仅更新该卡片的 descriptor/状态，不清空全部集合、不改变其它卡片的绑定。
2. 仅终态卡片开放重试；运行中卡片不通过重试按钮取消整个主请求。重复点击同一张正在重试的卡片忽略。
3. 重试生成新的 RequestId，绑定只替换目标卡片。所有旧 RequestId 的目标卡片事件都丢弃，但主请求中其它 Provider 的事件仍继续接收。
4. 保持既有参数 `ProviderIds=[id]`、`BypassCache=true`、`RecordHistory=false`；BypassCache 仍只跳过读，不能误改为禁止新结果写缓存。
5. 重试使用会话原始文本/Origin、主请求已解析的语言对，服务/Prompt 使用发起重试时的当前 Registry 快照。它是“重新请求”，不承诺字节级重放原请求；配置改动后只更新本卡实际 descriptor。原始正文和已解析语言必须在会话中明确保存，不从当前编辑框临时取值。
6. 目标服务已删除或被禁用时，按 T-013 既有显式选择规则显示本卡失败；不悄悄换成别的服务。
7. 请求级错误/尚无 Started 的失败只影响对应主请求区域或重试卡片。全窗口忙碌状态从仍有效的工作/排队状态推导，不能因某个旧主请求 Finished 就把新重试标为空闲。
8. 建议重试不触发 FirstResult 自动复制；用户可显式点击复制。自动复制的一次资格只用于本会话初始主请求。

并发上限在 T-015 前必须冻结：建议每窗口最多一个活动主调用和一个活动单卡重试，重试排队对每卡最多一项。新整窗请求替换等待项，只保留最新待启动请求；若旧调用尚未清理退出，不无限创建替代调用。用户可以立即编辑和看到“等待旧请求结束”的状态，UI 线程不等待清理。此处是前端调用准入，不改变 T-013 每请求的 Provider 并发语义。

## 6. UI 刷新与副作用

**刷新**：保留约 33ms 刷新节奏，但不能对每个 Delta 无限制 BeginInvoke；Orchestrator 的有界 Channel 并不能约束后续 Dispatcher 队列。建议一条后台消费任务累积受预算约束的卡片缓冲，每会话最多一个待执行刷新回调。回调携带 SessionId/卡片绑定并在 UI 端再校验。Completed 用权威全文替换并清除本 attempt 的旧缓冲，随后迟到刷新不能再拼接旧 Delta；Failed/取消也清除对应待刷新内容。所有可观察集合和属性只由 UI 线程改写。

**自动复制**：仅当前会话、当前卡片 attempt 的非截断 Completed 有资格；缓存命中可有资格。首次在 UI 接纳的完整结果原子领取一次资格，后续结果不重复复制。把会话取消令牌传给 IClipboardService，排队期间失效应在写入提交前停止。已进入 T-021A 提交阶段的复制不能回滚；不能承诺取消在任意机器指令点都能撤销原生发布，也不自动“恢复旧剪贴板”。

**历史/缓存**：T-013 一旦进入正常收尾，不因迟到窗口取消撤销缓存/历史或变成失败。UI 可以拒绝旧 Finished 更新，但不能删除已经合法保存的历史来模拟取消。单卡重试 RecordHistory=false 保持现有规则。

**显示请求**：Text=null 仅表示保留当前正文；不因此自动翻译当前旧正文。Text="" 明确清空。带 Error/StatusMessage 的阶段更新不因 AutoTranslate 的默认 true 误触翻译；正式契约应明确自动翻译只在本次显式提供有效正文且无错误/加载状态时发生。

## 7. 必须具备的受控回归

| 交错 | 预期 |
|---|---|
| 旧剪贴板读取/OCR 挂起 → 新输入提交 → 放行旧结果 | 新文本和新卡片不变，旧更新不能显示窗口或复制 |
| Delta 刷新已排队 → 新会话/隐藏 → 执行旧回调 | 丢弃旧回调，不重开、不改新绑定 |
| Completed 后仍有旧缓冲刷新排队 | 最终文本保持权威值，不重复拼接 |
| A 失败、B 仍流式 → 重试 A → 旧主请求结束 | B 连续输出，A 接收重试结果，集合与全窗忙碌状态正确 |
| 重试 A → 再点 A / 点另一卡 → 新整窗请求 | 无重复同卡调用；准入与排队上限明确，旧请求真正退出后释放槽位 |
| 前一个调用忽略取消 → 连续提交新文本 | 不堆积无限旧消费者，只保留最新等待请求，UI 可继续响应 |
| 非当前 / 截断 / 同会话第二个成功 / 重试成功 | 无不合格自动复制；合格初始结果最多领取一次 |
| 副作用进入 T-013/T-021A 提交点后才取消 | 承认已提交结果，UI 拒绝迟到展示，不产生虚假回滚 |
| 临时截图隐藏 → 用户关闭或新意图 → 截图 finally | 不恢复旧窗口，不抢回焦点 |

本轮只对“旧 OCR、新输入、隐藏后刷新、单卡绑定、一次完整结果复制”的四个规则例子运行了内存模型，均符合预期；该模型不包含 WPF、取消回调、CTS 生命周期、实际编排器或剪贴板，**不是产品测试通过证据**。正式实现必须以受控任务/枚举器和真实 UI 调度补齐。

## 8. 签发前决策清单

- 批准窗口操作端口及租约所有权，明确取消 callback/CTS 释放与 UI 根生命周期，不能只新增一个 Guid 字段就宣布 A07 解决。
- 固定前端主调用/重试准入上限与等待状态；单卡重新请求采用当前配置的语义要在 UI 中合理呈现。
- 在 ARCH §6、§7.2 与 CONTRACTS/落地文件同步替换旧流程，给未来 Core Handler 一套无歧义示例。
- 把临时隐藏与用户隐藏的不同语义交给 T-026/T-031；T-015 只提供必要内部边界，不提前实现 OCR。
- 复核 T-018/T-019 的 Presenter 和安全配置入口已交付，再签发 T-015；不通过空 Settings Presenter 或直接手工编辑 DPAPI secrets 绕过依赖。
