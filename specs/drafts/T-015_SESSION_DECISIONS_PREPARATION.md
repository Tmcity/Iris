# T-015 会话设计签发前补充

> 2026-10-01，Codex；阅读基线 7e993b3 与当前架构 v1.24。
> 配合 TRANSLATION_SESSIONS_DRAFT.md；仅候选决策与审查准备，未批准公开契约、未签发 T-015。当前唯一实施单仍为 T-019B。

## 1. 本次核对的事实

- 已落地展示接口在 src/Iris.Core/Presentation/PresentationPorts.cs，仍为无操作身份的 ShowAsync(TranslateWindowRequest) / HideAsync。修改需 CCR 同步 CONTRACTS.cs，不能只改 App 私有调用。
- TranslationRequest 已有 RequestId；TranslationStarted 提供本请求解析语言及有序 descriptor。Provider 事件不需要再增加一个窗口 SessionId。
- T-013 在 TranslationFinished 之前已等待全部 Provider 工作并释放 Registry 租约。消费者仍必须读到 EOF 并完成枚举器 DisposeAsync，以及自己的 UI/复制收尾，才能宣布 App 调用槽位退出。不得把这一区别写成“Core 到 Finished 还持有 Provider 租约”。
- T-013 每次请求 Channel 为 128 项，单 Delta 最多 4096 个 UTF-16 code unit，每 Provider 正文最多 1,048,576、每请求累计最多 4,194,304。它们约束单次编排，不能自动约束跨重试保留的 UI 文本和 Dispatcher 队列。
- IUiDispatcher.InvokeAsync 等待异步委托完整 Task，但并不替业务保证回调执行时的会话有效性。
- 已验收设置窗口的完整退出与局部构造回滚提供参考；翻译窗口普通隐藏可能保留内容，不应机械套用“每次隐藏立即销毁窗口”。B 交付后再核对可复用内部实现。

## 2. 推荐收敛的身份与生命周期

沿用原草稿的会话 SessionId、调用 RequestId、卡片绑定三层关系。将三个时点分开：意图失效、业务事件终结、实际工作退出。

| 触发 | 立即生效 | 必须继续持有的工作 | 后续展示资格 |
|---|---|---|---|
| 新整窗提交 | 旧 SessionId 无效，旧主调用/重试及等待项取消 | 尚未退出的消费者、取消回调、复制任务、UI finally | 仅最新会话可更新；排队回调执行时再校验 |
| 手动编辑原文 | 废弃旧发布资格，取消旧工作；标记旧卡片仅供查看 | 与上相同；不要每次按键创建新执行 CTS | Enter 才创建新的翻译执行；旧输入会话不得迟到覆盖正文 |
| 用户隐藏 / Esc / 失焦隐藏 | 撤销旧操作的显示与复制资格 | 已接受而尚未退出的工作，含提交后的副作用 | 再展示保留内容不能恢复旧操作资格 |
| 单卡重试 | 只替换目标卡片 RequestId | 主请求其它卡片仍继续，重试有独立工作所有者 | 仅目标卡片接收新 attempt；主请求其它事件仍有效 |
| TranslationFinished | 标记本次业务计数完整 | 消费者 EOF/DisposeAsync 与 App 收尾 | 不能用该事件清掉其它重试的忙碌状态 |
| 应用退出 | 停止所有新准入、废弃全部发布资格 | 观察所有实际任务及 UI 收尾，再关窗口/释放 scope | 不再允许 Show；失败所有权保留以供退出策略处理 |

截图临时隐藏单独使用 CaptureSuppression，不走用户隐藏入口；恢复同时检查意图与可见性代次。该规则须在正式规范中为 T-026/T-031 留边界，不要求 T-015 实现截图功能。

## 3. 端口租约尚须定稿的细节

原稿的 BeginOperation / TryShowAsync / ITranslateWindowOperation 仍是候选，不在本次改签名。推荐在 CCR 中一次明确：

1. BeginOperation 接纳顺序决定意图优先级；已取消调用不得淘汰当前有效会话。进入 Presenter 关闭状态后拒绝接纳。不在状态锁内取消或调用外部订阅者。
2. 租约由所属 Presenter 创建，TryShowAsync 不能接收另一个 Presenter 的租约；租约释放后禁止继续发布。失效租约与真正参数错误分别定义返回 false / 参数失败的语义，不允许匿名 Show 绕过身份检查。
3. Handler Dispose 只归还前置读取/OCR 工作所有权，不取消已移交给 VM 的翻译。VM/Presenter 必须在接受发布时先取得自己的所有权，避免 Handler 的 finally 把 CTS 提前释放。
4. 明确调用方令牌持续生效的期限。推荐其对同一会话已移交工作的取消继续生效，Handler Dispose 不等于取消；相关 registration 在会话全部工作退出后释放，不能无限链接已结束会话。
5. 同步 Dispose 本身不能在 UI 等待取消回调或异步枚举器。取消可使用受跟踪的异步工作，但数量随实际活动所有者受限；不能每个新意图 fire-and-forget 一个取消任务。
6. BeginOperation 接纳身份不等于准入耗时读取。未来多入口的前置读取也要有有界所有权；T-014 按 Action 防重入不能作为窗口结果身份或所有未来调用的总容量证明。

HideAsync 的返回含义推荐为“可见性/失效操作已完成”，不是所有底层 I/O 已退出；退出/重开准入仍由 App 内部完整工作屏障处理。正式规范必须避免 Handler 为等待一个不响应取消的旧 I/O 而卡住普通隐藏。

## 4. 推荐准入上限及反例

原草稿建议“每卡最多一个等待重试”，其总量仍随卡片数增长。本次建议改为更易验证的候选：全窗口一个实际主调用、一个实际重试、一个最新待启动主请求、一个最新待启动重试。新整窗意图清掉等待重试；同卡重复重试忽略，不同卡等待请求取最新。该选择需 T-015 签发前批准并反映到按钮状态。

实际槽位跨会话/隐藏保留，直到旧工作真正退出；换 SessionId 不能把旧调用从计数中遗忘。新主请求推荐等旧会话的主调用及重试均退出后再开始，以免旧重试占据新会话资源。等待期间可更新输入和等待状态，UI 不同步阻塞。

| 闸门场景 | 应证明的候选行为 |
|---|---|
| 旧主调用忽略取消；连续提交多次；最后关闭 | 只保留最新等待描述；关闭取消等待；没有无限消费者/CTS/排队 UI 回调 |
| A 卡终态、B 卡仍输出；重试 A | B 连续输出；A 的新绑定只接收新 RequestId；主请求 Finished 不结束 A |
| 重试流已结束但 DisposeAsync 挂起，再重试其它卡 | 旧重试仍占实际名额；新项等待，直到真实释放 |
| 隐藏后立即显示/提交，但旧工作还在 finally | 可见性恢复不恢复旧资格；旧工作仍被同一个应用所有者计数 |
| 流结束，UI finally 挂起，启动退出 | scope 保持存活，退出等待 UI finally；Dispatcher 不提前关停 |

超时只取消等待不能硬终止底层工作。对不合作的 fake 用测试闸门最终释放；产品不通过遗忘任务维持表面活性。

## 5. UI 缓冲与重试文本预算需要单独决策

已知单请求正文上限不能推出跨重试显示总量上限：主请求可先为多张卡留下较短结果，再逐卡重试得到更长结果。即使每次只重试一张，保留的全部卡片文本仍可超过主请求总额。

建议正式设计分别记账当前可见正文、后台待刷新增量、已排队快照，按 UTF-16 长度计数而不声称等于堆内存。约 33 ms 刷新时最多一个待执行回调；在回调被阻塞时继续合并有预算的缓冲，不对每个 Delta BeginInvoke。切换会话时也保留对旧待执行回调的所有权，避免每次换身份又排一个回调。

预算满时的策略仍须明确选择：有限预览并标明本地显示截断，或对展示消费施加背压；不能悄悄丢字后把预览当权威全文用于复制。若采用有限预览，全文存储/复制来源也必须有界且明确。不要为避开此设计而改 T-013 已验收协议，或擅自把模型 Truncated 与本地显示限制混为一谈。

Completed 应使对应 attempt 的增量缓冲失效，再以权威全文更新；Failed/取消不能让旧刷新把已终止状态改回流式。模型截断结果继续保留其真实 Truncated 标记。

## 6. 自动复制、重试与配置变化

- 首次有效初始主请求的完整、非截断 Completed 才能领取一次自动复制资格；cache hit 可参与，重试默认不参与。领取在 UI 接受事件时发生，而非网络完成时。
- 剪贴板提交前取消可以阻止写入；T-021A 已进入原生提交阶段后不承诺撤回。旧请求没有复制资格，不代表可以删除其已经合法写入的历史/缓存。
- 单卡重试使用原会话文本/Origin、主请求已解析语言，以及发起重试时的当前 Registry/Prompt。不声称精确重放旧请求；配置更新可能改变预处理，须明确保留原输入与已解析语言的不同来源。
- 如果主请求在 TranslationStarted 之前失败，没有解析语言及卡片集合，应提供整次重新提交路径，不构造一个伪单卡重试。
- Text=null 保留输入不代表自动翻译；Text="" 明确清空。Status/Error 更新与有效正文提交的准入应在 CCR 中拆清楚，防止 AutoTranslate 默认值触发旧正文。
