## 1. 复审入口与证据要求

先核对交付提交、完整 diff、报告与既有测试修改原因，再检查真实组合根。当前可复用入口为 SettingsWindowPresenterTests、SettingsViewModelTests、GeneralSettingsSaveCoordinatorTests 和 TranslationOrchestratorIntegrationTests；B 允许重构内部类型，不能仅因旧测试名称/文件变化判回退。

两层验证各司其职：

- App 边界使用可控协调器/调度器，精确阻塞取消、完成和 UI 回调，验证所有权及状态机。
- 接线使用实际 Core 协调器、JsonSettingsService、Registry 与临时目录，替换 SecretStore、Provider Factory/HTTP、自启端口。一次混合保存必须观察实际 UpdateAsync 次数、Current 与引用，不能用 fake Commit 返回 Applied 代替接线证据。

Barrier/TCS 控制事件顺序；超时仅用于探针失败退出，不以短暂 Delay 后“尚未完成”作为唯一并发证据。释放所有测试闸门，再观察实际任务、窗口和 scope 退出；故障断言也走 finally 清理。

## 3. 回执和调度特别检查

- 应用级状态的持有图只含 opaque 回执及安全摘要；订阅窗口退出后解除。检查闭包、事件 handler、队列节点是否意外留住原计划、VM 或 PasswordBox。WeakReference/GC 可作辅助诊断，不能代替明确的持有关系检查。
- 取待办快照后发生新增/重试成功时，移除必须针对完成的原回执，不能 Clear 整表；正在重试的待办也仍占名额。
- 草稿取消若发生于 Factory/SecretStore 返回之前，不能因为 UI 已不显示就释放 scope。实际 Core 的捕获/租约规则已验收，B 只须正确等待。
- 真实 Dispatcher 用于线程归属/绑定验证；可控队列用于复现“排队时有效、执行时过期”。立即执行回调的 fake 无法单独证明后一种边界。
- 一次性 Dispose/Task 标志不等同资源已释放。构造尚未组装会话时的局部所有权也应覆盖 B 新增任务，复用 T-018-R6 的失败路径思路。
