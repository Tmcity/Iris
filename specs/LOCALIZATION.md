# 中英文界面与语言设置

2026-10-08 · T-038 · ARCH v1.56 · CCR-038。

## 1. 完整范围

交付 zh-CN / en-US 的完整 Iris 界面资源及现有 General.UiLanguage 设置。包括设置各页、翻译窗口、历史窗口、托盘/菜单、划词图标提示、截图覆盖层、通知/错误/验证、辅助说明、可访问性名称、命令行帮助与启动期固定反馈。已延期功能的可见标签也资源化，不恢复 M6 功能。不是只把 UiText 常量搬入文件或只翻译导航。

保留现有 UiText/AppResources 等调用入口可减少改动，但它们必须在使用时读取实际语言资源，不能互相 fallback 形成递归。使用 .resx 与 ResourceManager 等现有 .NET 能力，中文为默认/中性资源，英语有对应卫星资源。允许 App/Core/Platform 中必要的内部纯托管资源与语言帮助类，现有内部友元足够；无新增 NuGet 包或 Core 公共本地化端口。

## 2. 启动语言与一次运行的一致性

主实例加载设置后、显示正常启动通知/托盘菜单/窗口/错误提示之前，选择规范化的 General.UiLanguage。当前应用会话的界面语言固定，后续保存或外部设置变化不切换本次 UI。已保存不同语言时提示下次启动生效。未读设置之前的帮助、非法参数和致命错误可以按当前系统 UI 语言选择支持语言（英语→en-US，其余回退zh-CN），不能为第二实例或错误参数读取用户设置。

语言选择必须在真实 UI Dispatcher 与后台工作路径上一致。不能只改变一个 async 方法的 CurrentUICulture，使返回到旧 ExecutionContext 后又显示中文；不能仅让某个测试线程变成英文。使用明确的本次运行语言作为资源依据，并验证其它线程具有不同环境 Culture 时仍得到所选 Iris 文案。数值解析、JSON、协议、日志不因 UI 语言改变而变化。

启动前构造的服务、静态 readonly 格式串、Action 名称映射、菜单工厂等不得永久缓存早期语言文本。启动损坏恢复/只读通知在可确定本次语言后构造；无法读取设置时的原生固定反馈遵循启动期回退。设置更新不能触发文化全局重置、重建整个 Host 或自动重启进程。

Core 的 ErrorMessages.GetDefault 及实际返回 UI 的验证/安全错误同样资源化，签名与 ErrorCode 保持；未知错误码仍回退 Unknown。不通过把所有错误改为一条泛化提示来回避翻译，不丢失原来的字段与修正语义，不输出原始异常或秘密。可保留系统/第三方控件由 OS 控制的标准按钮语言，明确其边界，Iris 自有文本须完整覆盖。

## 3. General.UiLanguage 联合编辑

常规页提供“简体中文 / English”两项，值仅为 zh-CN / en-US，说明保存后重启生效。既有设置默认 zh-CN、N11 正规化、JSON字段和 schema 保持。

CCR-038 兼容给 GeneralSettingsPatch 增加可选 init 属性 `SettingsFieldEdit<string>? UiLanguage`，默认 null；原四参数构造/解构不变。精确声明已预置 CONTRACTS。字段进入真实 Core 计划复制/验证/冲突/合并/空计划判定，以及 App 草稿基线、IsDirty、计划捕获、冻结、外部未编辑字段合并、Reload/取消和只读控制。

显式 Target 只接受规范值 zh-CN 或 en-US；null 补丁保留提交时最新语言。Base 与 Target 按现有字段协议比较，外部变为同一 Target 可合并，不覆盖其它页的新设置。仅语言修改也必须真实提交一次；与网络/Provider/OCR等一起修改仍同一计划、原配额与回执语义，不直接 Settings.UpdateAsync。

语言延后生效是正常 Applied 行为，不因此制造 ApplyPending。原网络/Provider ApplyPending 和原回执 RetryApply 保持；RetryApply 不保存后来新选的语言，也不切换本次运行语言。未提交保留草稿，成功后重建保存基线；重开设置窗口仍正确说明保存语言与当前语言不同。future 只读模式禁编辑/保存并能正常关闭。

## 4. 文案、格式与稳定数据

英文逐条保持原动作、状态和安全含义，尤其凭据 Keep/Replace/Clear、空密码、清理失败重试、已保存但待应用、HEAD 响应不代表 API/业务可用、OCR 原文/截图翻译/静默复制和退出失败。日期/数量/占位符采用资源格式，键与参数类型稳定；两语言的键、复合格式参数和必须非空项保持一致，资源不可返回裸 key 或未展开占位符。

只翻译界面。协议枚举/Action名、设置键、错误码、Provider/模型/语言ID、快捷键、URL、用户原文和译文、历史内容、用户自定义名称及已保存默认名称不改。提示词正文和 LanguageInfo.EnglishName 用于 Prompt 的语义不改；UI 的“自动检测”等动作标签要翻译，语言本名可作为有来源的语言数据展示。选择英文界面不能改变翻译/OCR语言、模型或默认提示词。

启动前后的用户原文/错误细节仍按原隐私边界处理。缺失资源/格式故障要安全回退，验证应暴露遗漏，不能依靠中文 fallback 让英文页面表面通过。适当调整宽度、换行、滚动与可访问性，使英文长标签在已有小工作区仍可用；不借此重新设计业务流程或移除说明。

## 5. 源码扫描与资源审计

提供可执行的扫描/验证脚本及实际日志，覆盖 src 内 C#、XAML 和 Iris 自有 UI 文案入口，检查残余硬编码中文 UI、两语言资源键/占位符一致和实际资源可解析。不能仅扫描 UiText 或仅在少数示例里查字。

非 UI 中文（注释、诊断日志模板、提示词、固定数据、语言本名等）可按语义排除，但交付可审核清单：文件/具体文字或稳定指纹/原因。不要整目录或整服务文件放行，也不能把遗漏的 UI 文案改标成日志/数据。新增未说明的命中应使检查失败。英语资源中的品牌/用户样例/语言本名等有意保留项单独注明，不把界面漏译藏在清单里。
